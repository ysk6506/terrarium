# Terrarium

**IT 인프라를 운영하는 AI 에이전트와 하네스를, 현실 장비를 건드리지 않고 정확하고 일관되게 평가하는 사내 실험장.**

## 한 문장으로

데이터센터를 흉내 내는 세계를 만들고, 거기에 고장을 일으켜서, 에이전트가 원인을 찾아 고치는 과정을 기록하고 채점해요. 진짜 장비는 건드리지 않아요. 같은 상황을 몇 번이고 똑같이 되풀이할 수 있어서, 에이전트나 하네스를 바꿨을 때 정말 나아졌는지 견줄 수 있어요.

사용자가 얻는 것은 "이 점수를 믿어도 된다"예요. 그러려면 셋이 서야 해요([제품 설계 한 장](docs/design-docs/product-design.md)).

1. **현실을 닮은 세계.** 서버·네트워크·스토리지·전원·냉방이 상태를 가지고 시간에 따라 변하고, 고장을 넣으면 현실처럼 번져요.
2. **에이전트가 그 세계에서 실제 운영을 해요.** 현실과 같은 모양의 툴로 진단하고 고쳐요.
3. **채점이 늘 맞고 같아요.** 같은 답안은 언제 채점해도 같은 점수예요.

## 지금 되는 것

| 무엇 | 내용 |
|---|---|
| 세계 짓기 | 사업장 프리셋으로 한 번에 만들거나, 서비스에서 시작하거나, 3D로 직접 지어요 |
| 시나리오 | 템플릿(냉방기 정지, 차단기 연쇄 트립, 설정 실수 …)에서 시작하거나 블록을 이어 만들어요. 그 세계에서 못 쓰는 템플릿은 까닭을 알려 줘요 |
| 실험 | 하네스 × 에이전트 × 툴 조합을 여러 상황에서, 같은 상황을 여러 번 돌려요 |
| 결과 | 점수와 채점 항목, 에이전트가 한 일, 세계에 일어난 일을 보고 링크로 공유해요. 조건만 바꿔 다시 돌리고, 벤치마크에서 견줘요 |
| 연결 | OpenCode, LangGraph, OpenClaw 전용 연결과 범용 HTTP · A2A · MCP · 명령 |

## 지금 단계와 아직 없는 것

지금은 **알파**예요. 로그인 없이 혼자 띄워 써요. 클로즈 베타는 세 번에 나눠 열어요([차수 계획](docs/exec-plans/active/beta-rounds.md)).

| 아직 없는 것 | 언제 |
|---|---|
| 권한: SSO 프록시가 넘겨준 신원, 공개 범위, 관리자, 감사 기록 ([설계](docs/design-docs/permissions.md)) | 클로즈 베타 1차 (만드는 중) |
| 실험 결과 화면 다시 설계 | 클로즈 베타 1차 (만드는 중) |
| 현실의 데이터로 세계 짓기: 엑셀·Splunk에서 받아 정제·매핑·링크 정의 → 세계 → 실험용 복사본 ([설계](docs/design-docs/reality-data-and-ontology.md)) | 클로즈 베타 2차 |
| 대회 모드·칭호, 기본 물리 v2 | 클로즈 베타 3차 |
| 운영 세계의 고가용 저장소, 수천만 규모 | 오픈 베타 |

## 처음 10분

필요한 것: Node 22.12 이상, pnpm 10.

```
pnpm install
pnpm dev          # 서버(:8787)와 웹(:5173)이 같이 떠요
```

Windows에서도 같은 명령이에요(PowerShell·cmd 모두). 브라우저에서 `http://localhost:5173`을 열면 이름을 한 번 물어봐요. 설정 파일이 없어도 내장 기준 에이전트가 있어서 아래를 그대로 해 볼 수 있어요.

1. **세계**: "새 세계"에서 사업장 프리셋과 규모를 골라 만들어요. 3D로 열리면 건물이나 서버룸을 두 번 눌러 들어가요.
2. **시나리오**: 세계를 골라 템플릿(예: 냉방기 정지)에서 시작해요. "미리 돌려 보기"와 "점검하기"로 문제가 변별력이 있는지 봐요.
3. **실험**: 시나리오 · 하네스 · 에이전트 · 툴을 고르고, 상황을 몇 개, 같은 상황을 몇 번 돌릴지 정해요.
4. **결과**: 점수, 채점 항목, 상황마다의 결과를 보고 "조건 바꿔 다시 돌리기"로 견줘요.

내 에이전트를 붙이려면 **연결** 메뉴에서 연결을 더해요. 자세한 것은 [연결 화면](docs/design-docs/web-ui-connections.md)에 있어요.

## 알려진 한계

- **로그인이 없어요.** 지금은 이름만 묻는 방식이라 남의 것도 고칠 수 있어요. 여러 사람이 쓰는 곳에는 권한이 들어간 뒤에 띄워요.
- **공기 흐름은 CFD가 아니에요.** 냉방기 풍량과 랙 발열로 방향과 세기를 계산한 그림이에요.
- **첫 화면이 커요.** 3D 때문에 처음에 약 0.8 MB를 받아요(예산 0.7 MB, 줄이는 중).
- **한국어만 지원해요.**
- **진짜 모델로 돌린 기록은 아직 없어요.** 하네스가 끝까지 도는 것은 대본 모델로 확인했고, 모델의 판단력은 못 쟀어요.
- **현실의 데이터를 넣는 길은 아직 없어요.** 세계는 지어낸 것뿐이에요.

## 사내 서버로 띄우기

```
pnpm build
TERRARIUM_CONFIG=/etc/terrarium/terrarium.json pnpm start
```

설정 항목과 신원(SSO 프록시) 설정은 [서버 운영](docs/design-docs/operations.md)에 있어요. 비밀 값은 파일에 쓰지 않고 환경 변수 이름만 적어요.

## 코드를 고치는 사람에게

기여하는 에이전트는 [AGENTS.md](AGENTS.md)부터 읽어요. 제품의 값과 원칙, 지금 유효한 결정은 [제품 설계 한 장](docs/design-docs/product-design.md), 요구사항은 [requirements.md](docs/product-specs/requirements.md), 문서 전체는 [docs/index.md](docs/index.md)에 있어요.

```
pnpm check   # 린트 · 타입 · 테스트 · 구조 검사. 합치기 관문은 CI예요
```

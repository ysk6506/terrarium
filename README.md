# Terrarium

사내 Agent/Harness 평가용 스테이트풀 IT 인프라 시뮬레이터이자 실험 플랫폼.

## 한 문장으로

**데이터센터를 흉내 내는 작은 세계를 만들고, 거기에 장애를 일으켜서, 에이전트가 원인을 찾아 고치는 과정을 기록하고 채점해요.**
진짜 장비는 건드리지 않아요. 같은 상황을 몇 번이고 똑같이 되풀이할 수 있어서, 에이전트나 하네스를 바꿨을 때 정말 나아졌는지 비교할 수 있어요.

- **세계 짓기**: 타이쿤 게임처럼 부지 → 건물 → 층 → 서버룸 → 컨테인먼트 → 랙 → 장비, 설비·전원·케이블을 3D로 짓거나 FalkorDB KG에서 가져온다.
- **시나리오 설계**: 장애 주입, 부하 변화, 에이전트 과업, 채점 기준을 드래그 앤 드롭 워크플로로 만든다.
- **실험**: 하네스 × 에이전트 × 툴 조합을 여러 사람이 동시에 돌린다. 공정 스케줄러가 자원을 나눈다.
- **결과**: 오라클 점수, 하네스 트레이스·메트릭·로그(ClickStack), 툴 호출을 종합해 분석하고 링크·HTML·텍스트로 공유한다. 벤치마크 대시보드에서 비교하고, 조건만 바꿔 바로 다시 돌린다.

## 처음 10분

필요한 것: Node 22.12 이상, pnpm 10.

```
pnpm install
pnpm dev          # 서버(:8787)와 웹(:5173)이 같이 떠요
```

브라우저에서 `http://localhost:5173`을 열면 이름을 한 번 물어봐요. 설정 파일이 없어도 내장 기준 에이전트가 있어서, 아래 순서를 그대로 해 볼 수 있어요. 처음에는 세계가 하나도 없으니 1번부터 해요.

1. **세계**: "새 세계"에서 방법을 골라요. "사업장으로 생성"은 사업장 프리셋(화성·평택·기흥 …)과 규모를 정하면 한 번에 만들어 줘요. "직접 짓기"는 땅을 그려서 사고, 건물을 올리고, 서버룸은 "채우기"로 랙·서버·냉각·전원을 한 번에 채울 수 있어요.
2. **시나리오**: 세계 하나를 골라 템플릿(팬 고장, 냉방기 정지, 차단기 연쇄 트립 …)에서 시작하거나 빈 캔버스에서 블록을 이어요. 세계에 없는 장비가 필요한 템플릿은 왜 못 쓰는지 알려 줘요.
3. **실험**: 시나리오 · 하네스 · 에이전트 · 툴을 고르고 몇 번 돌릴지 정해요. 끝나면 점수, 에이전트가 한 일, 세계에 일어난 일을 한 화면에서 볼 수 있어요.

내 에이전트를 붙이려면 **연결** 메뉴에서 "연결 추가"를 눌러요. OpenCode, LangGraph, OpenClaw는 전용 연결이 있고, 그 밖의 에이전트는 범용 HTTP · A2A · MCP · 명령 가운데 맞는 것으로 붙여요. 자세한 것은 [서버 운영](docs/design-docs/operations.md)과 [하네스 프로토콜](docs/design-docs/harness-protocol.md).

## 사내 서버로 띄우기

```
pnpm build
TERRARIUM_CONFIG=/etc/terrarium/terrarium.json pnpm start
```

설정 파일에 사내 시스템 주소(SSO 프록시 헤더, FalkorDB, ClickStack)를 적으면 가짜 대신 진짜가 붙어요. 비밀 값은 파일에 쓰지 않고 환경 변수 이름만 적어요. 항목은 [서버 운영](docs/design-docs/operations.md)에 있어요.

## 코드를 고치는 사람에게

기여하는 에이전트는 [AGENTS.md](AGENTS.md)부터 읽는다. 요구사항은 [requirements.md](docs/product-specs/requirements.md), 문서 전체는 [docs/index.md](docs/index.md).

```
pnpm check   # 린트 · 타입 · 테스트 · 구조 검사 · 화면 품질(UX) 측정. 통과해야 끝난 것
pnpm ux      # 화면을 바꿨다면 다시 재요. 브라우저가 필요하고 몇 분 걸려요
```

# Terrarium

**IT 인프라를 운영하는 AI 에이전트와 하네스를, 현실 장비를 건드리지 않고 정확하고 일관되게 평가하는 사내 실험장.**

## 한 문장으로

**데이터센터를 흉내 내는 작은 세계를 만들고, 거기에 고장을 일으켜서, 에이전트가 원인을 찾아 고치는 과정을 기록하고 채점해요.**
진짜 장비는 건드리지 않아요. 같은 상황을 몇 번이고 똑같이 되풀이할 수 있어서, 에이전트나 하네스를 바꿨을 때 정말 나아졌는지 비교할 수 있어요.

- **세계 짓기**: 타이쿤 게임처럼 부지 → 건물 → 층 → 서버룸 → 컨테인먼트 → 랙 → 장비, 설비·전원·케이블을 3D로 짓거나 FalkorDB KG에서 가져온다.
- **시나리오 설계**: 고장 발생, 부하 변화, 에이전트 과업, 채점 기준을 드래그 앤 드롭 워크플로로 만든다.
- **실험**: 하네스 × 에이전트 × 툴 조합을 여러 사람이 동시에 돌린다. 공정 스케줄러가 자원을 나눈다.
- **결과**: 오라클 점수, 하네스 트레이스·메트릭·로그(ClickStack), 툴 호출을 종합해 분석하고 링크·HTML·텍스트로 공유한다. 벤치마크 대시보드에서 비교하고, 조건만 바꿔 바로 다시 돌린다.

## 처음 10분

필요한 것: Node 22.12 이상, pnpm 10.

```
pnpm install
pnpm dev          # 서버(:8787)와 웹(:5173)이 같이 떠요
```

Windows에서도 같은 명령이에요(PowerShell·cmd 모두). WSL이 없어도 돼요.

브라우저에서 `http://localhost:5173`을 열면 이름을 한 번 물어봐요. 설정 파일이 없어도 내장 기준 에이전트가 있어서, 아래 순서를 그대로 해 볼 수 있어요. 처음에는 세계가 하나도 없으니 1번부터 해요.

1. **세계**: "새 세계"에서 방법을 골라요. "사업장으로 생성"은 사업장 프리셋(화성·평택·기흥 …)과 규모를 정하면 한 번에 만들어 줘요. "직접 짓기"는 땅을 그려서 사고, 건물을 올리고, 서버룸은 "채우기"로 랙·서버·냉각·전원을 한 번에 채울 수 있어요.
2. **시나리오**: 세계 하나를 골라 템플릿(팬 고장, 냉방기 정지, 차단기 연쇄 트립 …)에서 시작하거나 빈 캔버스에서 블록을 이어요. 세계에 없는 장비가 필요한 템플릿은 왜 못 쓰는지 알려 줘요.
3. **실험**: 시나리오 · 하네스 · 에이전트 · 툴을 고르고 몇 번 돌릴지 정해요. 끝나면 점수, 에이전트가 한 일, 세계에 일어난 일을 한 화면에서 볼 수 있어요.

내 에이전트를 붙이려면 **연결** 메뉴에서 "연결 추가"를 눌러요. OpenCode, LangGraph, OpenClaw는 전용 연결이 있고, 그 밖의 에이전트는 범용 HTTP · A2A · MCP · 명령 가운데 맞는 것으로 붙여요. 자세한 것은 [서버 운영](docs/design-docs/operations.md)과 [하네스 프로토콜](docs/design-docs/harness-protocol.md).

## 클로즈 베타 사용 안내

데이터센터·AI센터의 몇 팀이 먼저 써 보는 단계예요. 설치와 실행은 위의 [처음 10분](#처음-10분)과 같아요. 아래는 그 다음, 베타에서 꼭 해 봐 주셨으면 하는 것과 미리 알아 두실 것이에요. 쓰는 말은 [용어집](docs/design-docs/glossary.md)을 따라요.

### 처음 10분에 해 볼 것

1. **샘플 사업장 열기**: 세계 → "새 세계" → "사업장으로 생성"에서 화성 같은 사업장을 골라 "생성하기"를 눌러요. 3D로 사업장이 열리면 건물이나 서버룸을 두 번 눌러 안으로 들어가 봐요.
2. **서버룸에서 냉방기 멈춰 보기**: 데이터 홀 안에서 왼쪽 아래의 "온도와 공기 흐름 보기"를 누르고, 카드의 "돌려 보기"를 눌러요. 냉방기 목록에서 하나를 "멈춰 보기"로 멈추면 랙 문 색이 달라져요.
3. **공기 흐름 보기**: 위쪽 선택에서 "위에서 본 지도"와 "공기 흐름"을 골라 보고, 시간 막대를 끌어서 온도가 어떻게 변하는지 봐요. 가장 더운 랙은 경고선과 심각선까지 얼마나 남았는지 알려 줘요.
4. **시나리오 템플릿으로 하나 만들기**: 시나리오 → "새 시나리오"에서 템플릿(예: 냉방기 정지)을 골라요. 블록은 누르면 이어 붙고, 흐린 블록은 왜 못 쓰는지 적혀 있어요. "미리 돌려 보기"로 세계에 무슨 일이 일어나는지 봐요.
5. **변별력 점검**: 편집기 오른쪽의 "점검하기"를 눌러요. 아무것도 안 하는 에이전트, 찍는 에이전트, 정답만 아는 에이전트로 점수를 재 보고, 정답만 아는 에이전트가 만점을 받으면 좋은 조합을 가려내지 못하는 시험지라고 알려 줘요. 경고 옆의 "조치 항목 더하기"로 고쳐 봐요.
6. **하네스 연결해 실험 돌리기**: 연결 → "연결 더하기"로 쓰는 하네스(OpenCode, LangGraph, OpenClaw, 그 밖에는 HTTP · A2A · MCP · 명령)를 붙이고 "연결 확인"을 해요. 그다음 시나리오의 "이 시나리오로 실험"에서 에이전트를 고르고 돌려요. 진짜 하네스를 설치하고 모델에 이어서 끝까지 돌리는 순서는 [진짜 하네스로 끝까지](docs/design-docs/harness-e2e.md)의 런북에 있어요. 하네스 없이 해 보고 싶으면 내장 기준 에이전트로 먼저 돌려 봐도 돼요.

### 알려진 한계

- **공기 흐름은 CFD가 아니에요.** 냉방기 풍량과 랙 발열로 방향과 세기를 계산한 그림이에요. 유체 해석이 아니라서, 칸막이나 구조물 사이로 도는 실제 바람을 보여 주지는 못해요. 화면에도 이 말이 늘 떠 있어요.
- **서버룸의 사람은 장식이에요.** 알람이 나면 걸어가서 일하는 척을 하지만 고장을 고치지 않아요. 고치는 것은 시나리오의 복구 블록과 에이전트뿐이에요.
- **첫 화면이 커요.** 3D 때문에 처음에 약 0.7 MB를 받아요. 공기 흐름, 시나리오 편집기, 실험·연결 화면은 처음 열 때 따로 받아서 그때 잠깐 걸려요.
- **한국어만 지원해요.** 화면과 오류 문장이 모두 한국어예요.
- **진짜 모델로 돌린 기록은 아직 없어요.** 세 하네스가 끝까지 도는 것은 대본 모델로 확인했고, 모델의 판단력은 못 쟀어요. 실제 모델 실행은 모델이 닿는 사용자 PC에서 돌려야 해요.
- **로그인은 자리만 있어요.** 지금은 이름만 묻는 공유 수준이라, 남의 실험도 고칠 수 있어요.
- 일부 블록(예: 네트워크 품질 저하)은 아직 시뮬레이터가 지원하지 않아 꺼져 있고, 이유가 적혀 있어요.

### 피드백 남기는 방법

막히거나 이상한 곳이 있으면 아래 네 가지를 이슈로 적어 주세요. 화면 캡처가 있으면 가장 빨리 고칠 수 있어요.

```
무엇을 하려 했나:
무엇이 됐나:
기대한 것:
캡처: (화면 캡처나 화면 주소, 쓴 브라우저와 화면 크기)
```

## 사내 서버로 띄우기

```
pnpm build
TERRARIUM_CONFIG=/etc/terrarium/terrarium.json pnpm start
```

설정 파일에 사내 시스템 주소(SSO 프록시 헤더, FalkorDB, ClickStack)를 적으면 가짜 대신 진짜가 붙어요. 비밀 값은 파일에 쓰지 않고 환경 변수 이름만 적어요. 항목은 [서버 운영](docs/design-docs/operations.md)에 있어요.

## 코드를 고치는 사람에게

기여하는 에이전트는 [AGENTS.md](AGENTS.md)부터 읽는다. 요구사항은 [requirements.md](docs/product-specs/requirements.md), 문서 전체는 [docs/index.md](docs/index.md).

```
pnpm check   # 린트 · 타입 · 테스트 · 구조 검사 · 화면 품질(UX) 측정. 통과해야 끝난 것
pnpm ux      # 화면을 바꿨다면 다시 재요. 브라우저가 필요하고 몇 분 걸려요
```

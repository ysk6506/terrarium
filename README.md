# Terrarium

**IT 인프라를 운영하는 AI 에이전트와 하네스를, 현실 장비를 건드리지 않고 정확하고 일관되게 평가하는 사내 실험장.**

## 왜 만들었나

인프라 운영을 에이전트에게 맡기려면 먼저 "이 에이전트를 믿어도 되나"에 답해야 해요. 그런데 답을 얻을 방법이 마땅치 않아요.

- **진짜 장비에서는 시험할 수 없어요.** 냉방기를 일부러 멈추거나 스위치 설정을 틀리게 바꿔 볼 수는 없어요.
- **고장은 되풀이되지 않아요.** 같은 고장이 같은 순서로 두 번 일어나지 않으니, 에이전트를 바꾼 뒤 나아졌는지 견줄 수 없어요.
- **"잘하는 것 같다"는 근거가 못 돼요.** 몇 번 써 본 인상으로는 하네스나 모델을 고를 수 없어요.

테라리움은 데이터센터를 통째로 흉내 낸 세계를 만들고, 거기에 고장을 일으키고, 에이전트가 원인을 찾아 고치는 과정을 기록해 채점해요. 같은 상황을 몇 번이고 똑같이 되풀이할 수 있어서 점수를 견줄 수 있어요.

## 어떻게 쓰나

| 순서 | 하는 일 |
|---|---|
| 1. 세계를 지어요 | 사업장 프리셋으로 한 번에 만들거나, 떠받칠 서비스에서 시작해 필요한 인프라를 고르거나, 3D에서 부지부터 직접 지어요 |
| 2. 시나리오를 만들어요 | 템플릿에서 고르거나 블록을 이어요: 고장 발생, 부하 변화, 에이전트에게 맡길 일, 채점 기준. 부품 고장뿐 아니라 누군가 잘못 바꾼 설정도 만들어요 |
| 3. 실험을 돌려요 | 하네스 × 에이전트 × 툴 조합을 골라, 여러 상황에서 같은 상황을 여러 번 돌려요. 여러 사람이 동시에 돌려도 스케줄러가 공평하게 나눠요 |
| 4. 결과를 읽고 견줘요 | 점수와 채점 항목, 에이전트가 부른 툴, 세계에서 일어난 일을 봐요. 조건 하나만 바꿔 다시 돌리고, 벤치마크에서 다른 조합과 견줘요 |

## 세계는 얼마나 깊은가

고장이 현실처럼 번지려면 층이 다 있어야 해요. 냉방기 하나가 멈추면 온도가 오르고, 서버가 스스로 느려지고, VM이 옮겨 가고, 서비스 응답이 늦어져요.

| 층 | 들어 있는 것 |
|---|---|
| 사업장과 건물 | 지도에서 옮긴 부지와 건물 배치, 층, 서버룸, 컨테인먼트, 랙. 3D로 보고 들어가요 |
| 전원 | 수전 → 변압기 → 발전기·ATS → UPS → 분전반 → PDU → 장비. 콘센트 하나까지 끄고 켜요 |
| 냉방 | 공랭, 후면도어, 직접수랭, 액침. 열이 랙에서 칠러까지 가는 길과 서버룸의 온도·공기 흐름 지도 |
| 네트워크 | VLAN 기반의 레거시 망, 리프-스파인 패브릭, GPU 백엔드 망. 스위치는 2·3계층을 알아요 |
| 서버와 GPU | 제조사와 모델별 사양, 전원 장치, 팬, 펌웨어 |
| 가상화와 컨테이너 | 클러스터와 자동 재배치, 쿠버네티스, SDN 오버레이 |
| 스토리지와 DB | 이중화 구성의 단계별 차이(단일 + 백업부터 다중 사이트까지) |
| 서비스와 애플리케이션 | 서비스가 무엇에 기대는지, 서비스끼리 어떻게 부르는지 |
| 호스트의 OS | 파일시스템, 프로세스, 로그, 셸 명령. 로그는 세계에서 일어난 일로 실제로 쌓여요 |
| 사이트와 DR | 주 사이트와 복구 사이트, 복제, 전환 |

세계의 설비는 **현실의 말로 답해요.** 서버와 PDU는 Redfish로, 가상화는 vCenter와 vROps의 응답 모양으로, 스위치는 EOS나 NX-OS의 명령으로, 호스트는 리눅스 셸로 답해요. 에이전트는 현실에서 쓰는 것과 같은 모양의 툴 96개로 진단하고 고쳐요.

## 에이전트는 현실처럼 일해요

- **툴 범위**: 실험마다 에이전트에게 어떤 툴을 줄지 정해요. 현실의 운영팀이 흔히 가진 것만 줄 수도 있어요.
- **도메인과 넘기기**: "내 도메인"을 정하면 그 밖의 일은 다른 팀에 넘겨야 해요. 가상의 담당자가 답하고, 작업 티켓이 남아요.
- **사람에게 묻기**: 에이전트가 사람의 확인을 구하면 실행이 멈춰 기다려요.
- **절차서**: 절차서를 주지 않거나, 주거나, 찾게 하고 그 차이를 재요. 절차서를 지켰는지도 채점해요.
- **운영 모드**: 고장 하나가 아니라 긴 시간의 운영을 맡겨요. 고장이 시간대와 바쁜 정도에 따라 생기고, 실시간이나 빨리 감기로 돌려요.

## 점수를 믿을 수 있는 이유

테라리움이 파는 것은 점수가 아니라 **믿을 수 있는 점수**예요.

- **같은 입력이면 같은 결과예요.** 시간도 우연도 세계 안에 있어서, 같은 실험은 언제 돌려도 같아요.
- **정답 풀이가 만점을 받는 시나리오만 내요.** 그 세계에서 정답대로 풀어도 만점이 안 나오는 문제는 이유와 함께 빼요. 지금은 대표 세계들에서 확인하고, 만들 수 있는 모든 세계 모양으로 넓히는 중이에요.
- **문제가 실력을 가르는지 먼저 봐요.** 아무것도 안 하는 에이전트, 찍는 에이전트, 정답만 아는 에이전트로 시나리오를 재 보는 변별력 점검이 있어요.
- **복구를 먼저 채점해요.** 서비스를 얼마나 빨리 되살렸나, 순서가 맞았나, 더 나빠지게 하지 않았나, 그다음이 진단이에요.
- **같은 상황을 여러 번 돌려요.** 에이전트는 같은 상황에서도 흔들려요. 그 흔들림과 상황이 달라서 생기는 차이를 나눠 보여 줘요.
- **지금 세계의 결과를 테스트가 붙잡고 있어요.** 시뮬레이터를 고쳐도 기존 실험의 점수가 바뀌지 않는지 확인해요.

## 결과로 무엇을 하나

- **하네스와 모델 고르기**: 같은 조건으로 돌린 조합을 벤치마크에서 견줘요. 오차 범위가 겹치면 차이가 있다고 말하지 않아요.
- **에이전트 고치기**: 어느 채점 항목에서 점수를 잃었는지, 그때 무슨 툴을 불렀는지 따라가요.
- **업무 방식 바꾸기**: 시나리오마다 "지금 사람이 하는 방식"(몇 단계, 몇 명, 얼마나)을 적어 두면, 에이전트가 했을 때 단계와 사람 손이 얼마나 줄었는지 나란히 보여 줘요.
- **나누기**: 링크 하나로 보고서를 보여 주고, 실행 기록을 내보내 다른 분석에 써요.

## 테라리움이 지키는 것

요구사항이 새로 올 때마다 이 여섯에 대 봐요([제품 설계 한 장](docs/design-docs/product-design.md)).

1. **모델은 하나예요.** 지어낸 세계든 현실의 데이터로 지은 세계든 같은 모델이에요.
2. **시나리오·툴·채점은 세계를 가리지 않아요.** 어느 세계에서나 그대로 돌아요.
3. **버전을 고정하면 결과가 같아요.** 실험은 세계와 시나리오의 버전을 붙잡아 둬요.
4. **못 하는 것은 못 한다고 말하고, 고칠 길을 같이 줘요.** 흉내가 닿지 않는 곳을 화면과 결과가 밝혀요.
5. **사람은 규칙을 정하고, 건별로 손대지 않아요.** 수천 건을 하나씩 고치게 하지 않아요.
6. **현실에는 읽기만 해요.** 실험장이 현실 장비를 바꾸는 길은 없어요.

요구가 서로 부딪치면 "채점이 늘 맞고 같다"가 이겨요. 그리고 화면은 쓰기 쉬워야 해요: 화면 하나에 물음 하나, 버튼은 다음에 일어날 일을 말하고, 숫자에는 단위가 붙어요.

## 지금 단계

지금은 **알파**예요. 혼자 띄워 쓰는 단계이고, 클로즈 베타는 세 번에 나눠 열어요([차수 계획](docs/exec-plans/active/beta-rounds.md)).

| 차수 | 열리는 것 |
|---|---|
| 클로즈 베타 1차 | 여러 사람이 쓰기 위한 권한(SSO 로그인, 공개 범위, 관리자, 감사 기록), 다시 설계한 실험 결과 화면 |
| 클로즈 베타 2차 | 현실의 데이터(엑셀, Splunk)로 세계를 짓고, 그 세계를 복사해 같은 실험을 돌리기 |
| 클로즈 베타 3차 | 대회 모드와 칭호, 더 자세한 기본 물리 |
| 오픈 베타 | 운영 세계의 고가용 저장소, 수천만 규모 |

## 이 점수가 말해 주지 않는 것

평가 도구는 자기가 무엇을 재지 못하는지 말해야 해요.

- **현실과 몇 % 다른지는 말하지 않아요.** 물리는 "그럴듯함"까지예요. 유체 해석(CFD)이나 전기의 과도 현상은 다루지 않아요. 실제 센서 이력으로 보정하기 전에는 수치의 정확도를 약속하지 않아요.
- **호스트는 커널이 아니에요.** 정해 둔 명령과 문법만 답해요. 에이전트가 흉내 밖의 명령을 쓰면 실패하고, 그 횟수와 목록이 결과에 남아요. 그런 실행의 점수는 에이전트의 실력이 아니라 흉내의 한계일 수 있어요.
- **네트워크는 아직 장비에서 장비로 이어져요.** 포트, 포트 그룹(LACP), 세션 단위의 이중화는 모델에 넣는 중이에요.
- **세계 하나의 크기에 한도가 있어요.** 지금은 객체 10만 개까지예요.
- **현실의 데이터로 지은 세계는 아직 없어요.** 지금의 세계는 모두 지어낸 것이라, 점수는 "우리 데이터센터에서도 그럴 것"까지 말해 주지 않아요.
- **사람과 일하는 능력은 일부만 재요.** 넘기기와 승인은 재지만, 보고의 질이나 설득 같은 것은 재지 않아요.

## 처음 10분

필요한 것: Node 22.12 이상, pnpm 10.

```
pnpm install
pnpm dev          # 서버(:8787)와 웹(:5173)이 같이 떠요
```

Windows에서도 같은 명령이에요. 브라우저에서 `http://localhost:5173`을 열면 이름을 한 번 물어봐요. 설정 파일이 없어도 내장 기준 에이전트가 있어서 끝까지 해 볼 수 있어요.

1. **세계**: "새 세계"에서 사업장 프리셋과 규모를 골라 만들어요. 3D로 열리면 건물이나 서버룸을 두 번 눌러 들어가요.
2. **시나리오**: 그 세계에서 템플릿(예: 냉방기 정지)을 골라요. "변별력 점검"으로 문제가 실력을 가르는지 봐요.
3. **실험**: 하네스 · 에이전트 · 툴을 고르고, 상황을 몇 개, 같은 상황을 몇 번 돌릴지 정해요.
4. **결과**: 점수와 채점 항목을 보고 "조건 바꿔 다시 돌리기"로 견줘요.

**내 에이전트 붙이기**: 연결 메뉴에서 더해요. OpenCode, LangGraph, OpenClaw, Hermes, GoClaw는 전용 연결이 있고, 그 밖에는 HTTP · A2A · MCP · 명령 가운데 맞는 것으로 붙여요([연결 화면](docs/design-docs/web-ui-connections.md)).

## 사내 서버로 띄우기

```
pnpm build
TERRARIUM_CONFIG=/etc/terrarium/terrarium.json pnpm start
```

여러 사람이 쓰는 곳에는 SSO를 맡은 프록시 뒤에 띄워요. 설정 항목과 신원 설정은 [서버 운영](docs/design-docs/operations.md), 권한의 설계는 [권한](docs/design-docs/permissions.md)에 있어요. 비밀 값은 파일에 쓰지 않고 환경 변수 이름만 적어요.

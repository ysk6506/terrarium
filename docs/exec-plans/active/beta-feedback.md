# 클로즈 베타 피드백 장부

### 5·7을 어떻게 반영했나 (작업 #88)
- 느림 기준을 25 ms, 아주 느림을 50 ms로 조였고, 그리는 픽셀 수에 상한(높음 300만, 낮음 200만, 최소 120만)을 둬서 큰 모니터가 자동으로 낮은 배율로 그린다.
- 틸트시프트 흐림 세기를 품질 단계에 넣었다(높음 0.5, 낮음 0.5, 최소 0). 0이면 패스를 뺀다.
- 사람·방문객·공기·자동 회전은 멈추지 않고 줄인다: 4단계(입자 600 → 300 → 150 → 75, 사람은 한 명 이상 걷는다). 자동 회전만 2단계부터 쉰다.
- 설정 화면(`/settings`)에 "그래픽: 자동 · 높음 · 가볍게". 저장은 브라우저, 주소의 `?quality=`가 앞선다. 1번(화면 색)이 같은 화면에 줄을 더한다.
- 품질이 스스로 내려가면 "그래픽을 가볍게 바꿨어요. 설정에서 되돌릴 수 있어요"가 화면 아래에 뜬다.
- 자세한 값은 [웹 화면](../../design-docs/web-ui.md)의 "그래픽 품질과 줄이기".

### 11을 어떻게 반영했나 (작업 #89)
- 연결 확인과 목록이 `census`로 "몇 개 중 몇 개를 왜 숨겼나"를 데이터로 준다. 화면은 "에이전트 37개 중 1개가 보여요 · 36개는 상태가 'inactive'라 숨겼어요 · 모두 보기"로 말하고, 0개면 하네스가 준 원인을 그대로 쓴다. GoClaw는 페이지 처리를 따라가고, OpenCode의 도우미·서브에이전트도 같은 구조다.
- 연결마다 "말 걸어 보기"(`POST /api/connections/:id/try`): 한 턴, 툴 없음, 60초. 답과 걸린 시간·툴 호출 수·트레이스 이어짐을 한 줄로 보여 주고, 실패는 "401 — 토큰이 거절됐어요"처럼 원인 그대로 말한다.
- HTTP API 연결은 "OpenAI 호환 채팅"과 "간단 JSON" 프리셋부터, 나머지는 고급에 접었다.
- 텔레메트리는 연결마다 어댑터(ClickStack, Langfuse)로 고르고, 서버 설정의 `telemetry`는 기본값이다.
- 남은 확인: 실제 GoClaw의 `GET /v1/agents` 응답(공식 문서에 모양이 없다)과 실제 Langfuse(자체 호스팅 v3과 v4)로 본 적이 없다.

### 1·3·4·10·12를 어떻게 반영했나 (작업 #90)
- 1 화면 색: 설정에 "화면 색: 시스템 · 밝게 · 어둡게". 저장은 그래픽과 같은 방식이고 `<html data-theme>`로 건다. 시스템은 속성 없이 컴퓨터 설정을 따른다.
- 3·12 화면 폭: `.page`는 1,200~1,440 px, 세계 보기와 실험 결과는 가득, 홈 세계 보기는 폭 가득·높이 60vh 이상. 1,920 × 1,080과 2,560 × 1,440(배율 125%)에서 확인했다.
- 4 새 세계: 결과 카드 둘, 작은 샘플 사업장, 첫 방문 "둘러보기 할까요?"와 다음 할 일 칩 ([ADR-0083](../../design-docs/adr/0083-world-making-redesign.md)).
- 10 실험 3단계: 항목마다 한 줄 설명과 "권장", 고급은 접힘. 기본 횟수는 권장 5번.

### 6·8·9를 어떻게 반영했나 (작업 #91, [ADR-0101](../../design-docs/adr/0101-rack-containment-firmware-amend-tests.md))
- **6 랙 안**: 눈금(5U마다 굵게), 종류별 전면(1U·2U·GPU 서버, 스토리지, 스위치: 베젤 색, 드라이브 베이, 전원·네트워크 LED), 빈 U의 블랭크 패널과 맨 위 ToR 자리, 뒤쪽 좌우 트레이의 케이블 두 다발(네트워크 파랑, 전원 빨강·검정). 서버를 누르면 서버가 나오고 랙이 0.6초 돌아 뒷면(PSU·팬·포트·전원선)이 보이고, 다시 누르면 앞면, Esc는 서버를 넣는다. 한 랙이 그리기 호출 34회(42U가 다 찬 랙, 그림자 포함)이고 예산은 60회다. 줄이기 단계 1부터 LED는 깜빡이지 않는다. 자세한 모양은 [웹 화면](../../design-docs/web-ui.md)의 "랙 안".
- **8 컨테인먼트 안**: 컨테인먼트를 누르면 그 지붕과 문이 투명해지며 카메라가 0.6초 동안 복도 눈높이로 들어간다. 양쪽 랙 전면이 보이고 찬 복도와 더운 복도는 바닥 색이 다르다. 나가기는 Esc나 "복도 나가기", 경로 줄에 "컨테인먼트 … 안". 이 모드에서만 엔지니어가 그 복도를 걷는다.
- **9 펌웨어 템플릿**: 서버에 BMC·BIOS 버전과 재부팅 중 상태, Redfish `UpdateService`(SimpleUpdate → 2분 뒤 재부팅 → 4분 뒤 새 버전, 실패는 고장 발생 블록이 정함), 재부팅 중 서버의 VM이 멈춤. 툴은 기존 `redfish_request`다. 템플릿 묶음 "펌웨어 작업" 셋: 한 대 올리기, 랙 단위 차례로 올리기, 올리다 실패했을 때. 기준 에이전트로 점검하면 셋 모두 아무것도 안 함 0점, 찍기 0점, 정답만 앎 40점이고 제대로 일하면 100점이다 ([설정 변경 시나리오](../../design-docs/config-scenarios.md)).
- **한계**: 소프트웨어 렌더링 브라우저에서만 보았다(그래픽 카드 PC의 모양과 속도는 사람이 다시 본다). 빌더에서는 컨테인먼트를 눌러도 들어가지 않는다. 펌웨어 버전 비교는 글자 비교이고, BMC 올리기도 서버를 재부팅한다.

## 우선순위
- **P0 (쓰기 자체를 막는 것)**: 5·7 성능과 멈춤(반영), 11 연결(반영).
- **P1 (첫 10분을 좌우)**: 4 새 세계 기본 길과 안내, 10 실험 설정 설명, 3·12 화면 폭, 1 색 설정.
- **P2 (보기 좋게)**: 2 아이콘, 6 랙 실장(반영), 8 컨테인먼트 안(반영).
- **P2 (내용)**: 9 펌웨어 템플릿(반영).

## 확인이 필요한 것
- 모니터 해상도와 Windows 배율(3·12), 브라우저 종류(5).
- GoClaw 버전과 `GET /v1/agents` 응답의 `status` 값 분포, 페이지 처리 여부(11). 화면의 숫자가 이것을 알려 준다.

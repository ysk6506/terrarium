# 클로즈 베타 차수 계획

2026-11-05 연수 님과 나눈 설계(ADR-0083~0096)는 전부 클로즈 베타에 들어간다. 오픈은 프로덕션 레디(로그인·권한, 백업·복구·업그레이드, 부하·용량, 보안)만 남는다. **차수마다 구현 → tsc·lint·구조 검사 → 바뀐 테스트만 → push**하고 피드백을 받는다(연수 님 결정, 2026-11-06). 전체 검사(`run-all`)·UX 측정·래칫은 3차까지 push한 뒤 **한 번만** 돌리고, 깨진 것을 고쳐 마지막 push를 한다. 구현은 Sonnet이 둘씩 나란히(별도 worktree).

**2026-11-06 연수 님 결정: 클로즈 베타는 셋으로 나눈다.** 1차는 이미 push된 것(옛 1·2차), 2차는 지금 돌고 있는 묶음과 오늘 승인한 세계 만들기 재설계(ADR-0107), 3차는 나머지와 마감이다.

## 단계별 일정: 알파 → 클로즈 베타 → 오픈 베타 (2026-11-11)

연수 님은 목표와 요구사항만 정하고 설계 결정은 설계 담당이 내린다(ADR-0138). 그에 따라 단계의 경계를 이렇게 정한다. 기준은 "누가 쓰는가"다.

| 단계 | 누가 쓰나 | 들어가려면 | 묶음 | 상태 |
|---|---|---|---|---|
| 알파 | 연수 님과 설계 담당(로그인 없음) | 지금 | IAP 빼기·화면 ③ 숫자·짓기 겹침(REQ-111) | 구현 끝, UX 검사 중 |
| | | | 프로세스 비교(REQ-112) | 구현 끝, UX 검사 대기 |
| | | | 물리 이음매·숫자·곡선·지문(REQ-113, 화면 없음) | 구현 끝, 시험 중 |
| | | | 시드당 반복(같은 조건의 흔들림과 조건 사이의 차이를 나눠 봄) | 대기 |
| | | | "이 세계의 물리" 화면(목업 먼저) | 대기 |
| 클로즈 베타 | 초대한 사내 사용자 | 권한·SSO, 전체 검사와 UX 재측정 통과 | 권한·SSO(내 것·공유 범위, 역할 둘, 파트 그룹, 감사 기록, OIDC) | 대기 |
| | | | 칭호 교체(다섯 축 13개) · 사람들 메뉴 · 대회 모드와 계급 | 대기 |
| | | | 현실 데이터로 세계 짓기(REQ-115, ADR-0150~0152): 관리자 기능, 엑셀 양식 → Splunk(SPL) → vROps, 소스별 주기와 안전장치, 관계 표에서 그리는 판, 복사해서 실험 | 설계 끝, 견본 시험 대기 |
| | | | 기본 물리 v2의 앞 셋(차단기 곡선·돌입 전류, 방 안의 위치, 팬 되먹임) | 대기 |
| | | | 옛 3차: 벤치마크 실패 유형·버전 세트·비용, 데이터 화면·표준 내보내기 (홈 = 경영진 한 장은 뺐다: 2026-11-12 연수 님 "당장 필요 없다") | 대기 |
| | | | 마감: 전체 검사, UX 재측정(그래픽 가속이 있는 환경)·래칫, 마감 보고 | 대기 |
| 오픈 베타 | 사내 전체 | 운영 준비 통과 | 운영 준비: 백업·복구·업그레이드, 부하·용량, 보안 점검 | 대기 |
| | | | 운영으로 바꾼 세계의 고가용(REQ-116, ADR-0153): 독립된 저장소와 거기에 이어진 파이프라인, 실험 쪽과 분리 | 요구사항만, 설계는 오픈 베타 전에 |
| | | | 기본 물리 v2의 나머지 다섯 | 대기 |
| | | | 사람이 만든 모델 꽂기(파이썬 사이드카)·모델 대 모델 | 대기 |
| 오픈 뒤 | | 요구가 확정되면 | 센서 이력 보정(쌍둥이 ②), CCTV 자리 A~D(ADR-0139), 3D 조명·재질, 쌍둥이 ③④ | 설계만 |

- 시드당 반복을 알파에 둔 이유: 제품 목표의 3번(채점이 늘 맞고 같다)에 닿는다. 사용자를 받기 전에 있어야 한다.
- 권한·SSO를 클로즈 베타의 문으로 둔 이유: 사용자가 둘 이상이면 "누구의 세계·실험인가"가 먼저 있어야 한다.
- 대회 모드를 클로즈 베타에 둔 이유: 순위·메달은 전체 공개 전에 초대 사용자로 검증한다.
- 일정의 병목: 화면 묶음은 UX 검사를 전부 통과해야 합치는데(한 번에 약 40분, 한 번에 하나), 구현 에이전트의 주간 사용 한도가 한 번 찼다(2026-11-07~10).

## 클로즈 베타를 여는 순서 (ADR-0170의 순서를 차수로 나눔)

한 번에 다 만들고 열지 않는다. 초대한 사용자에게 꼭 필요한 것부터 연다. 빼는 것은 없고 순서다(경영진 한 장 홈만 연수 님이 뺐다).

| 차수 | 들어가는 것 | 열 수 있다는 증거 |
|---|---|---|
| 1 | 권한(내 것·공유 범위·관리자 역할, 신원은 SSO를 맡은 프록시가 넘겨줌), 실험 경험 다시 설계(ADR-0171), 채점 신뢰(제공되는 시나리오는 정답 풀이가 만점, ADR-0172), 마감 검사 | 초대받은 사람이 지어낸 세계에서 실험을 돌리고 결과를 읽고 점수를 믿는다 |
| 2 | 바탕(전파 엔진 하나, 포트를 핵심 모델로) → 현실 세계 한 줄(REQ-115), 벤치마크 실패 유형·비용, 데이터 내보내기 | 왕복한 세계에서 기존 시나리오의 점수가 같다 |
| 3 | 대회 모드·칭호·사람들 메뉴, 기본 물리 v2의 앞 셋, "이 세계의 물리" 화면 | |

- 동시에 돌리는 구현 에이전트는 다섯까지다(2026-11-12 연수 님 결정. 그전에는 사용 한도 때문에 둘이나 셋).
- 문서만 바뀐 변경은 가벼운 CI 경로를 탄다(ADR-0173, 만드는 중).

## 차수마다 지키는 것
- 목업 먼저(화면이 있는 묶음은 승인 뒤 구현): 서비스부터 세 화면·직접 짓기(승인됨, ADR-0107), 경영진 한 장, 데이터 화면, 운영 모드 타임라인.
- 글의 잣대(`world-builder-review.md` "두 번째 검토"): 해요체, 한 문장 한 정보, 아라비아 숫자+단위, "~할 수 있어요" 겹치기 금지, 시스템·개발자 말 금지("벽시계" → "실제 시간"), 버튼은 결과.
- 실험에 들어가는 정보가 앞, 돈은 사고 비용·전기요금에서만 의미.
- 정직한 한계를 문서에.

## 오픈 단계에 함께 가는 것
- OIDC(사내 SSO) 로그인·권한 위에 **사용자 등급**: 연수 님 결정(2026-11-06, ADR-0122)으로 Kaggle식 **계급은 대회 메달 수로만** 정한다(새싹 → 참가자 → 전문가 → 마스터 → 그랜드마스터, 낸 사람의 것). 메달·계급 함수와 대회 포트는 끝났고, **프로필·리더보드에 계급을 보이는 일은 대회 모드와 함께** 한다. 활동·기여는 계급이 아니라 **칭호**가 말한다(끝). 사람의 답(에스컬레이션·평가 라벨)을 기여로 세는 일은 남아 있다. 칭호와 계급은 사용자 ID 기준으로 설계해 SSO가 붙으면 그대로 잇는다.

**2026-11-06 연수 님 결정: 3차는 뒤로 미루고, 오픈 뒤 로드맵에 있던 ADR-0107 결정 6(점선 칩 전부)과 깊은 OS 흉내(ADR-0117)를 지금 한다.** 순서: 컨테이너 층(o1) · SDN 네트워크(o2) → 애플리케이션 층(**끝**, REQ-100) → 사이트·DR(**끝**, REQ-106) → 스토리지 지역 복제·분산 SQL·멀티 AZ(**끝**, REQ-106) → 깊은 OS 흉내(**끝**, REQ-098). **점선 칩은 0개다**(2026-11-07 연수 님 결정: "점선인 거 없이 현실세계와 모순되지 않게 전부 설계해서 구현해줘", [설명](../../design-docs/site-dr-layer.md), [ADR-0129](../../design-docs/adr/0129-site-dr-geo-storage-distributed-db.md)).

## 오픈 뒤 로드맵(베타 밖)
사이트·DR, 지역 복제, 분산 SQL, 관리형 멀티 AZ(**끝**, REQ-106, [설명](../../design-docs/site-dr-layer.md)), 서비스 메시·애플리케이션 층(**끝**, REQ-100, [설명](../../design-docs/application-layer.md)), 깊은 OS 흉내(**끝**, REQ-098, [설명](../../design-docs/service-os-layer.md)), SDN·클라우드 네이티브 네트워크(**끝**, REQ-097, [설명](../../design-docs/sdn-network-layer.md)), LLM API 등록(**끝**, REQ-099), 세계 인기·좋아요·칭호(**끝**, REQ-101, [설명](../../design-docs/ranking-and-titles.md)) — 계급 모델(메달·계급 함수와 대회 포트)은 준비됐고 화면은 대회 모드와 함께, 서버리스 컴퓨트(컨테이너 오케스트레이션·DRS·멀티클러스터는 끝 — REQ-096), 지역 복제 스토리지, DR 사이트·멀티 사이트, 서비스 메시(ADR-0107 결정 6), 파워 캐핑(ADR-0096: Redfish 전력 제한·전기요금·시나리오 3), 모델 플러그인·모델 대 모델(ADR-0095), 대회 모드(참가 등록·비공개 세트·리더보드 공개 시점), 쌍둥이 ②~④, 진짜 VM 섞기, 가져오기(ADR-0084 조건).

# 클로즈 베타 차수 계획

2026-11-05 제품 책임자와 나눈 설계(ADR-0083~0096)는 전부 클로즈 베타에 들어간다. 오픈은 프로덕션 레디(로그인·권한, 백업·복구·업그레이드, 부하·용량, 보안)만 남는다. **차수마다 구현 → tsc·lint·구조 검사 → 바뀐 테스트만 → push**하고 피드백을 받는다(제품 책임자 결정, 2026-11-06). 전체 검사(`run-all`)·UX 측정·래칫은 3차까지 push한 뒤 **한 번만** 돌리고, 깨진 것을 고쳐 마지막 push를 한다. 구현은 Sonnet이 둘씩 나란히(별도 worktree).

**2026-11-06 제품 책임자 결정: 클로즈 베타는 셋으로 나눈다.** 1차는 이미 push된 것(옛 1·2차), 2차는 지금 돌고 있는 묶음과 오늘 승인한 세계 만들기 재설계(ADR-0107), 3차는 나머지와 마감이다.

## 클로즈 베타를 여는 순서 (ADR-0170의 순서를 차수로 나눔)

한 번에 다 만들고 열지 않는다. 초대한 사용자에게 꼭 필요한 것부터 연다. 빼는 것은 없고 순서다(경영진 한 장 홈만 제품 책임자가 뺐다).

| 차수 | 들어가는 것 | 열 수 있다는 증거 |
|---|---|---|
| 1 | 권한(내 것·공유 범위·관리자 역할, 신원은 SSO를 맡은 프록시가 넘겨줌), 실험 경험 다시 설계(ADR-0171), 채점 신뢰(제공되는 시나리오는 정답 풀이가 만점, ADR-0172), 마감 검사 | 초대받은 사람이 지어낸 세계에서 실험을 돌리고 결과를 읽고 점수를 믿는다 |
| 2 | "맡겨도 되나"에 답하는 실험 → 바탕(전파 엔진 하나, 포트를 핵심 모델로) → 스냅샷 한 줄(REQ-121), 벤치마크 실패 유형·비용, 데이터 내보내기 | 왕복한 세계에서 기존 시나리오의 점수가 같다 |
| 3 | 대회 모드·칭호·사람들 메뉴, 기본 물리 v2의 앞 셋, "이 세계의 물리" 화면. 대회는 종목이 둘이다: 사건 하나(한 일을 끝까지)와 운영(여러 시간에서 여러 날 동안 맡기). 순위와 칭호를 두 종목 사이에 섞지 않는다(2026-11-12 제품 책임자) | |

- 문서만 바뀐 변경은 가벼운 CI 경로를 탄다(ADR-0173).

## 지금의 순서 (날짜 없이)

2026-11-12 제품 책임자 결정: 날짜를 두고 관리하지 않는다. 모두 되는 대로 빨리 하고, 무엇이 먼저인지만 정한다. 위에서 아래가 순서이고, 자리가 나면 위의 것부터 넣는다.

1. **권한**: 공개 범위 → 감사 기록 → 권한 화면 → 프록시와 SSO를 끝에서 끝까지. 클로즈 베타 1차를 여는 조건이다.
2. **검사 시간 줄이기**: UX 측정을 조각으로(ADR-0175). 시험과 커버리지를 한 번에 돌리는 길은 재 보니 가장 긴 조각이 두 배 넘게 느려지고 시험이 깨져서 접고, 커버리지 작업을 열둘에서 넷으로 줄였다(ADR-0195). 다른 모든 일의 속도를 정한다.
3. **채점 신뢰**: 셸과 awk를 진짜 구현으로 바꾼다(ADR-0196, 아래 이슈 47의 2a·2b), 실험장 한계 힌트와 한계 순위 목록, 유틸리티 시험(2c).
4. **"맡겨도 되나"에 답하는 실험과 실험 경험**([설계](../../design-docs/trust-experiments.md), ADR-0197): 설계는 끝. 만드는 차례는 조치 관문과 권한 수준과 규칙 → 승인 → 운영 실험의 깊이 → 묶음과 판정 → 화면. 새 실험, 진행 중, 나란히 보기 화면의 목업은 이 설계에 맞춰 그린다.
5. **공개 저장소 정리**: 끝. 제3자 라이선스 고지와 검사(ADR-0185), 내부 사실 걷어내기(ADR-0187, 0188).
6. **부채와 걷어내기**: 장부가 가득 차 있다. 기한이 가까운 것부터. 이미 만든 현실 연결 코드(그래프 소스를 읽는 창, 가져오기)를 걷어낸다(ADR-0192).
7. **바탕과 스냅샷 한 줄**: 전파 엔진 하나, 포트 모델, 그다음 지어낸 세계를 스냅샷으로 내보내고 다시 받기(REQ-121).

## 이슈 47: 직접 만든 파서의 유지보수 부담 (우선순위)

이슈 47은 UNIX 유틸리티와 장비 CLI를 직접 흉내 내는 코드의 유지보수 부담을 줄이자는 제안 넷이다. 기준은 제품 목표다: 세계는 현실을 닮아야 하고, 채점은 늘 맞고 같아야 한다. 날짜는 두지 않는다(2026-11-12 제품 책임자 결정: 모두 되는 대로 빨리 하고, 순서만 관리한다). 표의 위에서 아래가 순서다.

**4단계를 앞에 둔 까닭.** 1단계에서 나온 첫 한계 목록에 셸의 `if` 같은 문법, awk의 `getline`·`gensub`, sed의 `n`·`w`, `xargs -P`, `find -print0`, `cp`·`mv`의 디렉터리가 있다. 기술 부채 TD-0010(깊은 OS 흉내가 GNU와 다른 곳)과 같은 목록이다. 힌트는 에이전트가 손해 보지 않게 막는 안전망이지 고치는 것이 아니다. 손으로 쓴 흉내를 한 줄씩 메우는 길은 끝이 없으므로, 범용 도구를 진짜 구현으로 바꾸는 실험(4단계)을 맨 앞으로 당긴다.

**나누는 선.** 흉내는 둘로 나뉜다.

- 범용 유저랜드(셸 문법, coreutils, awk, sed, grep, find, xargs): 세계의 상태와 무관하게 글과 파일만 다룬다. 진짜 구현을 가상 파일시스템과 가상 시계 위에서 돌리는 것이 목표다. 손으로 쓴 파서는 없앤다.
- 세계를 읽고 바꾸는 명령(`ip`, `systemctl`, `kubectl`, 장비 CLI, 하드웨어 관리 도구): 출력이 세계 상태에서 나오므로 계속 흉내 낸다. 선언형 스키마(3단계)와 한계 힌트(1단계)는 여기에 쓴다.

| 순서 | 단계 | 하는 것 | 좁힌 범위와 이유 | 상태 |
|---|---|---|---|---|
| 1 | 1 | 실험장 한계일 때만 힌트 | 실제 도구는 되는데 실험장이 못 흉내 낸 실패에만 `terrarium:` 줄을 준다. 실제 도구도 거절할 입력에는 실제와 같은 오류만 준다(힌트를 다 주면 시험이 현실보다 쉬워진다). 한계는 실행 기록에 남기고 결과 화면에 "실험장 한계"로 보인다 | 만드는 중 |
| 2 | 4 | 범용 유저랜드를 진짜 구현으로 바꾸는 실험 | 셸(mvdan/sh)과 awk(goawk)를 WASM으로 돌려 봤다. 셸 언어의 빈틈 11개와 awk의 4개가 닫혔고, 기존 시험의 97%가 그대로 통과하고, 점수는 그대로였다. 유틸리티는 바꾸지 않았다 | 끝 (ADR-0196) |
| 2a | 4 | 셸 엔진을 꺼진 채로 들이기 | 포트와 엔진 패키지와 일꾼 풀. 결과를 가르는 한도는 세는 것만(단계·출력·메모리, awk 안쪽 포함), 한도에 걸린 줄은 0으로 끝나지 않기, `sleep`은 세계 시간, 한 줄 안의 환경 상속, goawk를 gawk에 맞추는 패치, .wasm을 저장소에 넣고 CI가 해시를 확인(ADR-0196의 2·3·4·6번) | 대기 |
| 2b | 4 | 기본을 바꾸고 옛 셸 파서와 awk를 지우기 | `run_command`를 쓰는 시험 전부를 새 엔진으로 돌리고, 옛 한계를 박아 둔 잠금 시험만 고친다. CI의 시험 시간이 10% 넘게 늘면 안 된다 | 대기 |
| 2c | 4 | 유틸리티(sed, sort, find, cp 등)를 진짜 구현으로 바꿀지 조사하고 시험 | GPL이 아닌 구현만. 그때까지 TS 구현을 쓰고 GNU와 다른 곳은 한계로 알린다 | 대기 |
| 3 | 1b | 한계 순위 목록 | 여러 실험에서 모은 한계를 많이 부딪힌 순으로 관리자에게 보인다. 권한의 감사 기록 단계가 끝나야 시작할 수 있다 | 대기 |
| 4 | 2 | 구조화된 출력 | 실제 도구에 있는 것만 넣는다(예: `ip -j`, `lsblk -J`, `kubectl -o json`, 장비 CLI의 json 출력). 실제에 없는 `--json`은 넣지 않는다(현실에서 못 쓰는 습관을 가르치게 된다) | 대기 |
| 5 | 3 | 선언형 CLI 스키마 | 세계를 읽는 명령에만 쓴다. 장비 CLI 한 계열로 먼저 해 보고(골든 시험의 출력이 한 글자도 바뀌지 않아야 한다) 코드가 줄어드는 양을 잰 뒤 나머지를 정한다 | 대기 |

- 4단계의 결정은 "셸과 awk는 바꾼다, 유틸리티는 따로 시험한다"다(ADR-0196). 셸 파서와 awk를 손으로 고치는 일은 멈춘다. TD-0010 가운데 셸과 awk의 항목은 2b로 닫히고, 유틸리티의 항목은 2c의 결정까지 남는다. 그 사이에는 1b의 목록 순서로 한계를 알리는 것까지만 한다.
- 한계에 부딪힌 호출을 "툴 사용 효율" 채점에서 뺄지는 1단계에서 정하지 않는다. 기록이 쌓인 뒤 따로 결정한다.

## 차수마다 지키는 것
- 목업 먼저(화면이 있는 묶음은 승인 뒤 구현): 서비스부터 세 화면·직접 짓기(승인됨, ADR-0107), 경영진 한 장, 데이터 화면, 운영 모드 타임라인.
- 글의 잣대(`world-builder-review.md` "두 번째 검토"): 해요체, 한 문장 한 정보, 아라비아 숫자+단위, "~할 수 있어요" 겹치기 금지, 시스템·개발자 말 금지("벽시계" → "실제 시간"), 버튼은 결과.
- 실험에 들어가는 정보가 앞, 돈은 사고 비용·전기요금에서만 의미.
- 정직한 한계를 문서에.

## 오픈 단계에 함께 가는 것
- OIDC(SSO) 로그인·권한 위에 **사용자 등급**: 제품 책임자 결정(2026-11-06, ADR-0122)으로 Kaggle식 **계급은 대회 메달 수로만** 정한다(새싹 → 참가자 → 전문가 → 마스터 → 그랜드마스터, 낸 사람의 것). 메달·계급 함수와 대회 포트는 끝났고, **프로필·리더보드에 계급을 보이는 일은 대회 모드와 함께** 한다. 활동·기여는 계급이 아니라 **칭호**가 말한다(끝). 사람의 답(에스컬레이션·평가 라벨)을 기여로 세는 일은 남아 있다. 칭호와 계급은 사용자 ID 기준으로 설계해 SSO가 붙으면 그대로 잇는다.

**2026-11-06 제품 책임자 결정: 3차는 뒤로 미루고, 오픈 뒤 로드맵에 있던 ADR-0107 결정 6(점선 칩 전부)과 깊은 OS 흉내(ADR-0117)를 지금 한다.** 순서: 컨테이너 층(o1) · SDN 네트워크(o2) → 애플리케이션 층(**끝**, REQ-100) → 사이트·DR(**끝**, REQ-106) → 스토리지 지역 복제·분산 SQL·멀티 AZ(**끝**, REQ-106) → 깊은 OS 흉내(**끝**, REQ-098). **점선 칩은 0개다**(2026-11-07 제품 책임자 결정: "점선인 거 없이 현실세계와 모순되지 않게 전부 설계해서 구현해줘", [설명](../../design-docs/site-dr-layer.md), [ADR-0129](../../design-docs/adr/0129-site-dr-geo-storage-distributed-db.md)).

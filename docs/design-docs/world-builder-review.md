# 세계 만들기 검토 (베타 피드백 4·12, ADR-0083 예정)

## 왜 다시 보나
클로즈 베타 첫 사용자가 "세계 만들 때 설정이 너무 많고 어디에 뭐가 있는지 모르겠어서 포기했다"고 했다. 가이드(둘러보기)는 따로 만들지만, **가이드가 필요하다는 것 자체가 설계의 실패**다. 기준은 시나리오 편집기 검토와 같다. 테라리움을 처음 보는 인프라 엔지니어가 설명 없이 **3분 안에 돌아가는 세계를 열 수 있는가.**

## 지금 흐름을 그대로 적으면
1. 세계 목록 → "새 세계" → 대화상자. 맨 위에 "만드는 방법: 직접 짓기 · 사업장으로 생성 · 현실에서 가져오기". **기본이 "직접 짓기"** 다.
2. 직접 짓기: "사업장의 모양: 사업장 모양 따라 하기 · 크기로 정하기 · 직접 그리기", 사업장 선택, 가로·세로, "사업장 바깥에 팔고 있는 땅도 두기", 땅값 기준, 이름. 만들면 **빈 땅**이 열리고, 왼쪽 도구 상자에 땅·건물·건물 밖 설비·방·전원·랙과 복도·냉방과 전원이 **한꺼번에** 보인다.
3. 사업장으로 생성: 사업장 선택 + 숫자 칸 10개(데이터센터 건물, 반도체 팹, 팹당 서버룸, 연구동 타워, 건물당 데이터 홀 층, 층당 데이터 홀, 홀당 컨테인먼트(보통), 랙 채움 비율, 상세 모델링 비율, GPU 서버 비율) + 선택 3개(컨테인먼트, 냉방 이중화, 전원 계통) + 시드. 2열 격자로 **열네 칸**.

## 원칙으로 따진 결과

| # | 어긋난 원칙 | 무엇이 문제인가 | 고칠 것 |
|---|---|---|---|
| 1 | One Thing, Easy to Answer | 첫 화면이 "방법"을 묻는다. 처음 온 사람은 방법을 모른다. 알고 싶은 건 **"뭐가 나오나"** 다. | 첫 화면은 **결과 카드 셋**: "사업장 그대로"(추천, 실제 비례·랙 1만 대·1분), "작게 시작"(서버룸 하나짜리, 직접 늘려 감), "내 데이터로"(현실 자산 가져오기). 카드마다 그림과 한 줄 결과. |
| 2 | Simple Policy | 기본이 "직접 짓기"인데, 직접 짓기는 가장 어려운 길이다. | 기본(첫 포커스)을 "사업장 그대로"로. |
| 3 | Easy to Answer, Casual Concept | 열네 칸을 한 번에 묻는다. "홀당 컨테인먼트(보통)", "상세 모델링 비율", "랙 채움 비율"은 시스템의 말이다. 시드는 아무도 모른다. | 사업장 그대로 = **사업장 고르기 + 규모 하나**("작게 · 보통 · 실제 그대로", 랙 수와 걸리는 시간이 바로 보임) + 만들기. 나머지는 "더 정하기"에 접고 세 묶음(건물 / 서버룸 / 서버)으로, 칸마다 쉬운 말 한 줄. "상세 모델링 비율"은 성능 손잡이라 화면에서 없애고 자동으로. 시드는 "같은 세계 다시 만들기 번호"로 고급에. |
| 4 | Value First | 만들기 전에 무엇이 나오는지 숫자 한 줄이 없다("랙 n개 (최대 m개)"뿐). | 규모를 고를 때마다 "**랙 10,502대 · 서버 1만 7천 대 · 전력 90 MW — 실제 화성 HPC센터와 비슷해요**"처럼 결과 문장. |
| 5 | Context Based | 직접 짓기는 빈 땅에서 시작한다. 빈 땅은 다음 할 일을 말하지 않는다. | "작게 시작"은 빈 땅이 아니라 **작은 샘플 사업장**(땅 하나, 건물 하나, 서버룸 하나에 컨테인먼트 둘)에서 시작한다. 화면 위에 **다음 할 일 칩** 하나("다음: 서버룸 채우기")가 떠 있고 누르면 그 자리로 간다. 다 하면 칩이 "다음: 돌려 보기"로 바뀐다. |
| 6 | One Thing, Minimum Features | 도구 상자가 일곱 묶음 스물몇 개를 한꺼번에 보여 준다. 어디에 뭐가 있는지 모를 수밖에 없다. | 도구 상자는 **지금 있는 자리에서 놓을 수 있는 것만**(이미 `toolsFor(level)`이 있으니 묶음을 더 좁힌다): 사업장에서는 땅·건물, 건물 안에서는 방, 방 안에서는 랙·컨테인먼트·냉방·전원. 묶음마다 **큰 버튼 하나**("건물 올리기")와 그 아래 종류 목록. 빈 자리에는 빈 상태 문장과 그 버튼("여기엔 아직 건물이 없어요 · 건물 올리기"). |
| 7 | Explain Why | "직접 그리기"의 점 찍기는 무엇을 그리는지(땅 경계) 말하지 않는다. "사업장 바깥에 팔고 있는 땅도 두기"는 왜 있는지 모른다. | 그리기 위에 "땅의 경계를 찍어요. 마지막 점은 처음과 이어져요". 팔고 있는 땅은 기본 켬 + "나중에 넓힐 때 살 땅이에요" 한 줄, 고급으로. |
| 8 | Clear Action | 만들기 버튼이 "만들기"다. | "화성사업장 만들기", "작은 사업장 만들기"처럼 결과를 말한다. |
| 9 | No More Loading | 생성이 수십 초 걸릴 때 진행이 안 보인다. | 진행 문장("건물 7동 올리는 중 · 랙 6,200대…")과 끝나면 바로 세계 열기. |
| 10 | Casual Concept | "데이터 홀", "DSR", "컨테인먼트"가 설명 없이 나온다. | 용어집대로: 데이터 홀 → 서버룸, DSR 타워 → 연구동, 컨테인먼트는 첫 등장에 "(랙 줄을 덮는 칸)" 한 줄. |

## 두 번째 검토 — 글도 UX다
첫 안을 토스 테크니컬 라이팅의 잣대(한 문장 한 정보, 숫자는 아라비아 숫자와 단위, "~할 수 있어요" 겹치기 금지, 시스템 말 금지, 버튼은 결과를 말함)로 다시 읽고 고친 것.

| 전 | 후 | 이유 |
|---|---|---|
| 하나를 고르면 바로 만들 수 있어요. 세부는 나중에 바꿀 수 있어요. | 골라서 바로 만들어요. 세부는 나중에 바꿔요. | "~할 수 있어요"가 두 번. 할 수 있다가 아니라 한다. |
| 화성·평택·기흥을 실제 비례로. 랙 1만 대 | 실제 크기 그대로. 랙 10,000대 | "비례"는 설계자의 말. 숫자는 아라비아 숫자 + 단위. |
| FalkorDB 같은 현실 자산 목록을 가져와요 | 지금 운영 중인 장비 목록을 가져와요. FalkorDB를 붙여요. | "현실 자산"은 우리 말. 사람은 "운영 중인 장비"라고 한다. |
| 연구동 3 / 빈 터 2 / 데이터센터 2 | 연구동 3동 / 빈 터 2곳 / 데이터센터 2동 | 단위가 빠지면 숫자가 떠 있다. |
| 랙 10,502대 · 서버 1만 7천 대 … 실제 화성 HPC센터와 비슷해요 | 랙 10,502대 · 서버 17,300대 … 실제 화성사업장 규모예요 | 한 문장 안에서 숫자 표기가 둘. 사업장 전체 수치인데 HPC센터와 비교하면 틀린 말. |
| (도구 상자 제목) 이 건물에 놓을 것 → 버튼 "서버룸 만들기" | 이 건물에서 할 일 | 제목의 동사(놓다)와 버튼의 동사(만들다)가 달랐다. 방은 만들고 장비는 놓는다. |
| 이 층엔 서버룸이 하나 있어요. 아직 비어 있어요. 서버룸을 누르고 "채우기"를 하면 … | **서버룸이 비어 있어요** + 한 줄 설명 + [서버룸 채우기] 버튼 | 빈 상태는 상황 한 줄 + 할 일 버튼 하나. 설명 속 따옴표 버튼 이름은 사람이 찾게 만든다. |

판단: 방향(카드 셋 → 사업장+규모 → 작은 사업장+다음 할 일 칩)은 그대로 간다. 두 번째 검토에서 구조는 바꿀 것이 없었고 글이 일곱 군데 고쳐졌다. 구현 때 **모든 새 문장은 이 표의 잣대로 다시 읽는다**(용어집 `glossary.md`에 "숫자와 단위" 절을 더한다).

## 세계를 연 다음 — 빌더 화면
새 세계 대화상자만이 아니라 그 다음 화면까지가 "세계 만들기"다. 화성 HPC센터 2층, 꽉 찬 서버룸, 조각 붙인 방의 캡처를 한 장씩 놓고 같은 잣대로 따졌다.

지금 화면은 세 칸이다. 왼쪽 "놓을 것"(카탈로그 전부 + 값) 아래 "조작"(키 설명 여덟 줄이 늘 보임), 가운데 3D(왼쪽 위 숫자 네 개, 아래에 늘 떠 있는 "끌면 화면이 움직여요"), 오른쪽 패널(큰 숫자 셋 → 자동 배선 → 크기 → 조각 덧붙이기 → 채우기 → 넓히기 → 고칠 곳 → 냉방·전력 어디서… 한 줄로 길게).

| # | 어긋난 원칙 | 무엇이 문제인가 | 고칠 것 |
|---|---|---|---|
| 11 | One Thing, Clear Action | 오른쪽 패널이 고른 것에 대해 **할 수 있는 모든 것**을 한 줄로 쌓는다. 지금 해야 할 일이 어디인지 모른다. 사용자의 말 그대로 "어디에 뭐가 있는지 모르겠다". | 패널 맨 위를 **고른 것 카드**로: 이름 · 상태 한 줄("서버룸 A · 랙 48 · 비어 있어요") · **주된 버튼 하나**(상태가 정한다: 비었으면 채우기, 꽉 찼으면 넓히기, 다 됐으면 돌려 보기). 그 아래는 접힌 절 셋: 크기와 모양 / 냉방과 전력 / 돈. 고칠 곳은 카드 아래 한 줄("고칠 곳 2 ▸")로. |
| 12 | Value First | 왼쪽 위 숫자 네 개(들인 돈·랙·서버·발열)와 오른쪽 패널의 큰 숫자 셋이 **같은 것**이고, 그중 맨 앞·맨 크게 있는 것이 **돈**이다. 테라리움에서 돈은 타이쿤의 양념이지 목적이 아니다. 목적은 **실험할 데이터센터를 만드는 것**이고, 그래서 중요한 숫자는 랙·서버·발열과 냉방 여유·전원 여유처럼 실험에 들어가는 것이다. | 전체 숫자는 3D 위 한 줄만, **랙 · 서버 · 발열/냉방 · 전원 여유** 순. 돈은 그 줄에서 빼고 패널의 접힌 "돈" 절과 값이 붙는 순간(놓을 때 툴팁)에만. 패널은 **고른 것의 숫자**(이 방의 랙·전력·빈 바닥)만. |
| 13 | Explain Why | 막힌 이유가 **세 군데**에 같은 문장으로 뜬다(패널의 빨간 상자, 아래 회색 토스트, 오른쪽 아래 빨간 토스트). | 한 문장은 한 곳에: 손잡이·커서 옆 토스트 한 번, 패널에는 상태 줄만. |
| 14 | Minimum Features, Context Based | "놓을 것"이 자리에 상관없이 카탈로그 전부를 값과 함께 보여 준다(꽉 찬 방에서도). 이름은 모델명("인로우 냉방기 30kW", "분전반 225A", "UPS 500kVA"). | **여기서 할 일** 묶음으로(앞 절의 큰 버튼 + 목록). 목록은 쓰임새 먼저, 모델명은 작게: "냉방기 — 인로우 30kW", "전기 나누기 — 분전반 225A". 놓을 자리가 없으면 목록 대신 한 줄과 버튼("랙 놓을 자리가 없어요 · 서버룸 넓히기"). |
| 15 | Casual Concept | 키 설명 여덟 줄이 늘 보인다. 3D 아래 "끌면 화면이 움직여요"가 영원히 떠 있다. | 키 설명은 "조작법 ?" 버튼 뒤로. 첫 끌기를 하면 안내는 사라진다. |
| 16 | Clear Action | 위 막대에 주된 버튼이 둘("돌려 보기", "저장"). | 저장은 자동. "저장됨 · 방금" 상태 글자만 두고 주된 버튼은 "돌려 보기" 하나. |
| 17 | Casual Concept | "조각 덧붙이기: 왼쪽 · 오른쪽 · 위쪽 · 아래쪽" — 비스듬한 3D에서 "위쪽"이 어디인지 모른다. | 네 버튼을 없애고 3D의 바깥 **+ 손잡이**만 남긴다. 패널엔 "모양을 바꾸려면 테두리의 +를 끌어요" 한 줄. |
| 18 | Casual Concept, 용어 | "2F-B 데이터 홀(공랭)" vs 왼쪽 "서버룸" — 같은 것이 두 이름. "먹이는 설비"는 사람이 안 쓰는 말. "타일 7,104장"은 설계자의 단위. | 데이터 홀 → **서버룸**으로 통일(생성기 이름까지). "식히는 설비 / 먹이는 설비" → "냉방 / 전기". 타일 수는 지우고 면적(m²)만. 용어집에 더한다. |
| 19 | Easy to Answer | 꽉 찬 방의 "서버룸 채우기" 버튼이 꺼져 있고 이유는 아래 회색 글에 있다. "서버 절반쯤" 같은 선택지는 뜻을 모른다. | 꺼진 버튼은 이유를 버튼 자체에(`why`), 선택지는 결과로 말한다: "서버 절반쯤 → 랙마다 서버 7대, 전력 4 kW". |
| 20 | Context Based | 건물·층·방을 오가며 할 일이 이어지지 않는다. 층 탭은 좋다. | 다음 할 일 칩(앞 절)이 모든 자리에서 떠 있고, 누르면 그 자리로 간다. |

## 구현 범위(ADR-0083)
- 새 세계 대화상자를 카드 셋으로; "사업장 그대로"는 사업장 카드 + 규모 셋 + 결과 문장 + 더 정하기; "작게 시작"은 이름 하나 + 샘플 사업장 생성.
- 도구 상자를 자리별 큰 버튼 + 목록으로, 빈 상태 문장.
- 다음 할 일 칩(세계 상태의 순수 함수: 땅 없음 → 건물 없음 → 서버룸 없음 → 비어 있음 → 돌려 보기 안 함).
- 첫 방문 둘러보기는 칩의 연장이다: 처음 "작게 시작"을 열면 "둘러보기 할까요?" 한 번 묻고, 예면 칩이 5단계를 차례로 가리킨다. 아니요면 칩만 남는다.
- 생성 진행 문장.
- 빌더: 고른 것 카드(상태 → 주된 버튼 하나) + 접힌 절 셋, 전체 숫자는 3D 위 한 줄만, 막힌 이유는 한 곳에 한 번, 조작법은 ? 뒤로, 저장은 자동, 조각 네 버튼 삭제(+ 손잡이만), 데이터 홀 → 서버룸·먹이는 설비 → 전기·타일 수 삭제, 꺼진 버튼에 이유, 선택지는 결과로.
- UX 여정 `author`와 같은 식으로 `build-small` 여정(작게 시작 → 채우기 → 돌려 보기, 손 수 예산 8)을 더한다.

## 구현 현황 (2026-11-05, 작업 #90)
ADR-0083 결정 1~11과 피드백 1·3·10·12를 구현했다.
- 1~4번(새 세계): 카드 둘, 사업장 + 규모 + 결과 문장, 더 정하기 세 묶음, 작게 시작(샘플 사업장), 생성 단계 문장. 가져오기 카드는 화면에서만 지웠다(코어와 서버는 ADR-0084).
- 5~9번(빌더): 고른 것 카드(주된 버튼 하나) + 접힌 절 셋, 3D 위 숫자 한 줄(돈 없음), 자리별 큰 버튼 + 쓰임새 목록, 조작법 ?, 저장은 자동, 조각 네 버튼 삭제, 막힌 이유는 한 곳에 한 번.
- 10번: 서버룸(생성기 이름까지), 냉방과 전기, 타일 수 삭제, 꺼진 버튼의 이유, 결과로 말하는 선택지. 용어집에 "숫자와 단위" 절.
- 11번: UX 여정 `build-small`. `import` 여정은 가져오기 카드와 함께 뺐고, `build`·`site`는 새 길로 다시 썼다.
- 시험: `next-step`, `worldgen-scale`, 도구 상자 묶음, 주된 버튼 결정, 글 잣대 검사(모두 REQ-077). 잠긴 시험 둘은 ADR-0086으로 고쳤다.
- 하지 못한 것: `pnpm ux` 재측정(UX004), 시험 전체 실행(`run-all`)은 이 환경의 CPU 때문에 돌리지 않았다.

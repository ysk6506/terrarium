# ADR-0007 카탈로그·프로파일·파사드 분리

## 맥락
에뮬레이트 대상이 바뀌거나 늘어나도 쉽게 대응해야 한다 (REQ-002~004). 세 가지 변화 축이 서로 다른 속도로 움직인다.

## 결정
세 가지를 서로 다른 레이어에 둔다.
- **카탈로그**: 장비 **모델**별 차이(포트 수, 센서 목록, 사양). 데이터다.
- **프로파일**: **제품(버전)**별 동작 변형(같은 모델이어도 펌웨어/버전에 따라 응답과 동작이 다른 것). 프로파일 키는 제품 버전이다.
- **파사드**: Redfish/vCenter/vROps 요청·응답의 모양을 월드 중립 명령과 주고받는 번역+렌더 계층. 웹 프레임워크를 모른다.

`profiles`는 `facades`를 모르고, `facades`는 `physics`를 모른다. 파사드는 월드에 명령을 보내고 상태를 읽을 뿐이다.

## 이유
"어떤 장비인가", "어떤 버전의 동작인가", "어떤 프로토콜로 말하는가"는 독립적으로 바뀐다. 섞이면 새 장비 하나에 세 곳을 고쳐야 한다.

## 버린 대안
장비 클래스 상속 구조: 모델×버전×프로토콜 조합이 폭발한다.

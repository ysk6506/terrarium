# ADR-0151 소스는 주기로 동기화하고, 적용은 안전장치를 거치며, 실험은 세계의 판에 묶인다

## 맥락
제품 책임자(연수 님)의 요구(2026-11-11): 소스마다 동기화 주기를 정할 수 있어야 하고, 그런 기본 관리 기능을 설계한다.

ADR-0150은 "계속 동기화"를 범위 밖에 뒀다. 설계 담당이 "받아서 짓고 그리는 것까지만"을 한 번 가져오기로 좁게 읽은 것이다. 주기 동기화는 소스 관리의 기본이고 요구사항 안이다. ADR-0150의 범위를 그렇게 고친다.

대조한 기존 결정과 코드:
- ADR-0043: 연결의 비밀 값은 봉인해 두고 되돌려 주지 않는다. 고치면 판이 오르고 차이가 남는다. 정리는 서버가 뜰 때와 그 뒤 주기적으로 한다.
- 실험은 시작할 때의 세계·시나리오 판을 스냅샷으로 들고 있다(`experiments.ts`의 `snapshot`). 세계가 바뀌어도 앞선 실험은 그 판으로 남는다.
- 제품 목표 3번 "채점이 늘 맞고 같다"(ADR-0138).

## 결정
1. **동기화 주기는 소스마다 정한다.** 손으로만 / 간격(15분~7일) / 정해진 시각. 프리셋이 기본값을 제안한다. 지금 동기화와 잠시 멈춤이 있다. 한 소스는 한 번에 하나만 돌고, 놓친 주기는 한 번만 따라잡는다.
2. **동기화 한 번은 기록 하나다.** 수집·대응·차이·적용의 걸음마다 수와 시간을 남기고, 결과는 됨 / 멈춤 / 안 됨이다. 멈춤과 안 됨에는 이유와 고치는 법이 붙는다.
3. **자동 적용은 안전장치를 거친다.** 같으면 새 판을 만들지 않는다. 처음과 대응을 고친 뒤 첫 번은 사람이 확인한다. 스키마가 흔들리면 멈춘다. 한 번에 너무 많이 사라지면 멈춘다. 안 보이는 개체는 표시만 하다가 연속으로 안 보이면 지운다. 실패는 간격을 늘려 다시 해 보고 연속 실패는 스스로 멈춘다.
4. **신선도를 보인다.** 소스에는 마지막으로 받은 때와 "낡음", 세계와 판에는 "이 데이터는 몇 시간 전 것".
5. **적용은 세계의 새 판을 만들고, 실험은 판에 묶인다.** 이미 있는 실험 스냅샷을 쓴다. 동기화되는 세계는 손으로 고치지 않고, 바꿔 보려면 떠낸다.
6. **연결의 관리는 ADR-0043을 따른다.** 비밀 봉인, 되돌려 주지 않음, 헤더, 만든 사람만 고침, 판과 차이. 연결 확인은 닿는가·읽기 전용인가·무엇이 있는가를 본다. 쓰이지 않는 연결을 지우는 규칙은 소스 연결에 적용하지 않는다.
7. **지금 하지 않는 것**: 바깥 알림(메일·메신저), 서버 여러 대와 고가용성, 소스에 쓰기.

숫자(15분, 10%, 세 번, 다섯 번, 90일, 10판·30일)는 기본값이고 설정으로 바꾼다.

## 버린 길
- **주기를 전체에 하나로**: 엑셀 대장과 API 소스는 바뀌는 빠르기와 주는 부담이 다르다.
- **받는 대로 바로 적용**: 소스가 빈 답을 주면 세계가 빈다.
- **실험이 늘 최신 세계를 보게 하기**: 같은 실험의 점수가 날마다 달라진다. 제품 목표 3번을 깬다.
- **동기화되는 세계를 손으로도 고치게 하기**: 고친 것이 덮이거나, 덮이지 않게 하려면 속성마다 "사람이 고침" 우선순위가 필요해진다. 떠내기가 더 단순하다.

## 결과
설계는 `docs/design-docs/source-management.md`에 있다. REQ-115에 주기 동기화를 더하고 ADR-0150의 범위와 표를 고쳤다(계속 동기화와 "동기화되는 세계는 손으로 고치지 않는다"가 결정으로 옮겨 갔다. 평면 둘과 고가용성은 제안 그대로다).

# ADR-0003 기술 부채 장부와 래칫

## 맥락
부채는 쌓이는 순간에는 보이지 않고, 갚을 때는 이미 너무 크다.

## 결정
- 부채는 `docs/exec-plans/tech-debt.yaml` 장부에 적어야만 존재할 수 있다. 코드의 `TODO/FIXME/HACK/XXX`는 `TODO(TD-NNNN)`로 장부 항목을 가리켜야 한다.
- 모든 항목에 기한이 있고, 지나면 빌드가 실패한다. 열린 항목 수(12)와 high 항목 수(2)에는 예산이 있다.
- 파일 500줄, 함수 80줄, 복잡도 12, 매개변수 8을 넘으면 실패한다. 이미 넘은 것은 **래칫 기준선**에 기록할 수 있지만 기준선은 줄어들기만 한다 (`--base`와 비교).
- 예외는 장부 항목을 가리키는 `# debt-ok: TD-NNNN` 면제뿐이다. 더 필요 없게 된 면제도 실패한다.
- 주 1회 `entropy` 워크플로가 코드 변경 없이도 기한과 문서 만료를 검사한다.

## 이유
- 갚는 일이 "언젠가"가 아니라 "기한 내"가 된다. 예산 때문에 새 부채를 만들려면 먼저 하나를 갚아야 한다.
- 래칫은 기존 문제를 한꺼번에 고치지 않아도 되게 하면서 악화는 막는다.

## 버린 대안
- 린터 경고만: 경고는 쌓이다 무시된다.
- 월 1회 청소 스프린트: 부채는 한꺼번에 갚기 어렵다. 작게 계속 갚는다.

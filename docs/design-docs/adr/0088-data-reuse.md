# ADR-0088 테라리움의 데이터는 재활용하도록 설계한다

## 맥락
테라리움이 돌면서 나오는 것은 전부 라벨 달린 운영 데이터다: 궤적(프롬프트·툴 호출·세계 반응·점수), 시계열·알람(정답 라벨 포함), 토폴로지·영향 범위, 사람의 답. 제품 책임자: "재활용할 걸 고려해서 데이터 설계가 되면 좋겠다", "내보내기도 어떤 데이터를 어떻게 활용할 수 있는지 UX를 잘 설계해야."

## 결정
1. **불변 사건 기록.** 실행은 사건의 나열(툴 호출·세계 사건·점수 사건·사람 사건)로만 저장하고 덮어쓰지 않는다. 리플레이·학습 데이터·채점이 같은 기록에서 나온다. 세계 시간과 실제 시간을 둘 다 적는다.
2. **모든 것에 버전과 해시.** 실행 ↔ 시나리오 버전 ↔ 세계 시드·해시 ↔ 툴 묶음 ↔ 에이전트 버전 ↔ 절차서 버전이 ID로 묶인다.
3. **표준 내보내기.** JSONL/Parquet. 궤적의 메시지는 OpenAI/Anthropic 메시지 모양과 호환(`tool_use`/`tool_result`), 세계 사건은 별도 열. `terrarium export --as trajectories|timeseries|alarms|topology|runbooks|benchmark`.
4. **라벨은 사건으로.** 사람의 평가·에스컬레이션 답·"정답 궤적" 표시는 덧붙이는 사건이며 원본을 바꾸지 않는다.
5. **데이터 화면은 용도부터.** 카드: 에이전트 가르치기 / 이상 탐지 모델 학습 / 벤치마크 세트 나누기 / 런북 만들기 / 보고서용 요약. 카드 → 범위(기간·세계·세트·에이전트)와 첫 5줄 미리보기·크기 → 받기(버튼은 결과: "궤적 1,240개 받기") → "이렇게 쓰세요" 한 토막과 데이터 사전 링크. 큰 내보내기는 진행과 알림, 내보낸 기록 목록. 사내 밖으로 나갈 땐 "사업장 이름 가리기".
6. 이 설계는 디지털 트윈 1단계(구조 쌍둥이)의 전제이기도 하다(ADR-0095).

## 결과

# ADR-0084 가져오기를 없애고 토폴로지 보기를 둔다

## 맥락
"현실에서 가져오기"(FalkorDB realimport)는 한 그래프 모양만 알고 실제 DB에 붙여 본 적이 없다. 제대로 하려면 교환 형식(JSON Schema + `@context` 호환) · 안정 ID와 출처 · 차이 반영 · 어댑터 레지스트리까지 작은 제품 하나다. 제품 책임자와 따져 본 결론: **지금 테라리움이 증명할 것은 "에이전트를 재는 게 되나"이지 "내 데이터센터를 옮기나"가 아니다.** 어설프게 두면 "된다"고 써 놓고 안 되는 기능이 되어 베타 신뢰를 깎는다.

대신 제품 책임자가 제안한 것: **실험 중에 어디에 문제가 있고, 에이전트가 어디를 만지고, 영향 범위가 어디인지 보이는 토폴로지, 그리고 끝난 뒤 리플레이.** 3D가 "어디에 있나"라면 토폴로지는 "무엇에 기대고 있나"다. 승인된 목업은 타이쿤 보드 위의 장비 타일과 파이프다.

## 결정
### 가져오기
1. 새 세계의 "현실에서 가져오기"와 서버의 가져오기 경로, 코어의 `sources/realimport`를 **지운다**(git에 남는다). 설정의 FalkorDB 항목도 지운다.
2. **다시 꺼낼 조건**: 베타 사용자가 "내 장비 목록으로 실험하고 싶다"고 실제로 요청할 때. 그때 설계는 JSON Schema 표준 + `@context` 호환 + `source/sourceId`와 출처·시각 + 두 번째 가져오기는 차이 반영 + 파일 어댑터 먼저 + 어댑터 인터페이스 discover/preview/pull. 가능하면 사내 온톨로지 코어의 프로파일로.

### 토폴로지 보기
3. **한 세계, 두 눈.** 세계 화면에 3D/토폴로지 전환. 같은 선택·같은 시간을 공유한다(토폴로지에서 누르면 3D가 가고, 반대도).
4. **층은 셋, 한 번에 하나.** 전원(변압기→UPS→분전반→PDU→랙→서버), 냉방(칠러→냉방기→서버룸→랙), 네트워크·가상화(스위치→서버→하이퍼바이저→VM·클러스터).
5. **색은 넷.** 빨강 고장(시나리오가 넣은 것), 주황 알람(세계가 감지한 것), 파랑 맥박 "에이전트가 만지는 곳"(툴 호출이 닿은 장비, 말풍선은 누가·무엇을·언제), 회색 영향 범위(의존 그래프를 거꾸로 따라 계산; 숫자 셋과 "그대로면 n분 뒤" 한 문장).
6. **같은 것은 접고, 다른 것만 편다.** 묶음은 번호가 아니라 **상태**로 만든다(정상 408랙 / 더워지는 중 11랙 / 경고 1랙). 고장·알람·만지는 곳·영향 범위만 펼쳐진다. 묶음 타일은 비율 막대를, 파이프는 두께로 수를 말한다. **화면의 타일은 150개를 넘지 않는다** — 읽기 위한 규칙이고 코어의 `fold`가 보장한다. 펼치는 방향은 질문이 정한다(고장은 아래로, 랙은 위로). 크기 단계는 사업장 → 건물 → 서버룸 → 랙 묶음 → 랙 → 서버이고 들어가기/경로 줄로 오간다.
7. **보드의 생김새.** 아이소메트릭 받침 위에 종류별 글리프(칠러·냉방기·서버룸·랙 묶음·랙·서버), 상태는 받침 테두리 + 바닥 번짐, 파이프 속 방울이 흐름 방향으로 움직인다(찬 쪽 파랑, 더운 쪽 주황, 끊긴 곳은 점). HUD(영향 범위·말풍선·범례)는 유리 카드. 자동 레이아웃만, 손 배치 없음, 패킷 애니메이션 없음.
8. **리플레이.** 실행의 세계 사건과 툴 호출 기록으로 시간 막대를 끌면 그 순간의 토폴로지(와 3D)가 된다. 막대에 고장·알람·조회·조치·회복 표식. 두 실행을 같은 시각에 나란히 비교할 수 있다.
9. **결과 화면 첫 줄.** "고장 1곳 → 알람 14곳 → 짚은 곳 3곳(정답 포함) → 조치 1곳 → 영향 범위 서버 108 → 0". 표식을 누르면 그 시각으로 간다.
10. **측정.** UX 측정에 큰 세계(화성 실제 그대로)에서 토폴로지를 열었을 때 타일 수(≤150)와 첫 그림까지 시간을 더한다.

## 구현 순서
① 코어 `topology/`(층별 그래프 추출, 상태 묶기 `fold`, 영향 범위 `impact`) + 토폴로지 탭 + 세 층 + 고장·알람·영향 범위. ② 에이전트 맥박 + 리플레이 + 나란히 비교 + 결과 첫 줄.

## 결과
- REQ-078(토폴로지)과 REQ-010(가져오기)의 폐기가 요구사항에 적힌다. 가져오기를 확인하던 잠긴 시험은 삭제를 별도 ADR의 `amends_tests`에 적는다.

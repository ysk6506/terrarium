# ADR-0165 데이터셋·정제·온톨로지 매핑·링크 조건을 각자의 층으로 나누고, 객체 종류와 링크 종류는 열려 있다

## 맥락
제품 책임자는 여러 번 같은 것을 요구했다: 데이터가 들어온 다음에 (1) 데이터를 정제하고, (2) 어느 데이터셋을 어느 온톨로지 객체에 매핑할지 정하고, (3) 객체 사이의 링크를 어떤 조건으로 만들지 정하는 층을 따로 둔다. 논리 관계는 이중화·클러스터·BGP 이웃 말고도 얼마든지 있기 때문이다.

지금까지의 설계는 이 요구를 좁게 읽었다.
- 정제(손질)와 링크 규칙을 "대응 단의 앞걸음"으로 접어 넣어, 따로 선 층으로 보이지 않았다(ADR-0144 15번).
- 관계 종류를 닫아 뒀다. 사용자가 만드는 종류는 "기록만, 영향이 넘어가지 않음"이었고 제안 단계였다(ADR-0144 11번, ADR-0150, ADR-0157 2번).
- 관계 잇기 화면의 첫 그림이 "테라리움이 아는 관계 일곱 개의 점검 목록"이었다. 목록에 없는 관계를 사용자가 정할 자리가 없었다.

## 결정
1. **층은 넷이고, 층마다 화면·저장되는 것·판이 따로 있다.**

| 층 | 하는 일 | 저장되는 것 |
|---|---|---|
| 소스 | 잇고, 가져오고, 주기를 정한다 | 연결, 받은 그대로의 데이터셋 |
| 정제 | 데이터셋을 다듬어 새 데이터셋을 만든다(손질 여덟 가지, ADR-0161) | 다듬은 데이터셋과 그 계보 |
| 온톨로지 매핑 | 어느 데이터셋이 어느 객체 종류가 되는지 정한다(키, 속성, 같은 것 알아보기) | 객체 종류마다의 매핑 |
| 링크 정의 | 객체 종류 사이의 링크를 어떤 조건으로 만들지 정한다 | 링크 종류마다의 정의 |

   세계와 토폴로지는 넷째 층의 결과에서 만든다. 뒤의 세 층이 "온톨로지 매니저"다.
2. **데이터셋은 이름과 계보가 있는 것이다.** 받은 그대로도, 다듬은 것도 데이터셋이다. 데이터셋 하나가 여러 객체 종류에 쓰이고, 여러 데이터셋이 한 객체 종류가 된다.
3. **객체 종류는 열려 있다.** 핵심 종류, 현실 표준 종류, 사용자가 만든 종류를 같은 방법으로 매핑한다. 사용자가 만드는 종류는 제안이 아니라 결정이다.
4. **링크 종류는 열려 있다.** 링크 종류 하나는 넷으로 정의한다: 양 끝의 객체 종류, 잇는 조건, 뜻, 이을 수 있는 개수. 사용자는 새 링크 종류를 만든다.
5. **조건은 닫힌 어휘로 적는다.** 속성이 같다(다듬어 견줌), 담긴다, 이음 데이터셋의 한 줄이 두 끝을 말한다, 같은 값끼리 한 무리다, 관례로 채운다. 여기에 고르기 조건을 더하고 "그리고"로 잇는다. 코드와 식은 넣지 못한다. ADR-0144 13번의 잇는 틀 다섯이 이 어휘다.
6. **뜻은 닫힌 목록에서 고른다.** 위에서 돈다, 필요하다, 이어진다, 공급받는다, 묶음(몇 개가 살아야 하나), 수로 말하는 묶음, 기록만. 사용자가 만든 링크 종류도 고른 뜻대로 영향 범위에 들어간다. "사용자가 만든 관계는 영향이 넘어가지 않는다"(ADR-0144 11번의 셋째 층, ADR-0157 2번의 셋째 층)를 이것으로 바꾼다.
7. **내장 링크 종류는 같은 자리에 미리 만들어 둔 정의다.** 뜻은 잠겨 있고 조건은 사용자가 준다. 값이 겹치는 열을 찾아 주는 제안과 프리셋은 이 층들을 미리 채워 주는 도움이지 구조가 아니다.
8. **그대로인 것.** 사용자가 만든 종류와 링크는 시뮬레이터와 채점에 들어가지 않는다(실험의 지문과 점수 분해는 바이트까지 같다). 실험 세계로 복사할 때 "시뮬레이션이 모르는 것"으로 보고한다. 개체 하나를 골라 손으로 잇는 조작은 현실 세계에 없다.

## 이유
- 논리 관계의 목록은 닫을 수 없다. 장비 제조사와 조직마다 다른 이중화·묶음·의존이 있고, 테라리움이 다 미리 알 수 없다.
- 뜻을 닫힌 목록에서 고르게 하면 링크 종류가 늘어도 영향 범위를 한 가지 방법으로 계산하고(ADR-0156 3번) 맞는지를 시험할 수 있다.
- 층을 나누면 정제를 고쳐도 매핑과 링크 정의가 그대로이고, 링크 조건을 고쳐도 데이터를 다시 가져오지 않는다. 층마다 무엇이 언제 바뀌었는지 따로 남는다.

## 버린 길
- **관계의 점검 목록을 늘려 가기**: 목록에 없는 관계마다 테라리움을 고쳐야 한다.
- **조건에 식이나 코드를 허용**: 시험할 수 없는 변환이 쌓인다(ADR-0161과 같은 이유).
- **사용자 링크는 그리기만 하기**: 영향 범위가 사용자가 정한 관계에서 끊긴다. 현실 세계를 짓는 목적(REQ-115·117)에 닿지 못한다.

## 결과
`reality-data-and-ontology.md`와 `model-standards.md`를 이 결정에 맞게 고쳤다. 관계 잇기 화면은 "링크 종류를 정의하는 화면"으로 다시 그린다: 양 끝 고르기 → 조건 → 뜻 → 결과 숫자. 화면 목업은 층마다 한 장씩이다(데이터셋, 정제, 매핑, 링크 정의, 적용 전 확인).

# ADR-0149 소스의 역할은 구성·사건·실측 셋이고, 읽기 전용은 허용 목록과 계정으로 지킨다

## 맥락
제품 책임자의 요구(2026-11-11): Zabbix(5.0 이상), Splunk(SPL), Cisco NSO, vROps, CloudVision 같은 널리 쓰이는 모니터링·구성 소스에서 읽기 전용으로 가져올 수 있어야 한다. 하나씩 따져 보니 ADR-0144에 빈 곳이 둘 있었다.

1. ADR-0144의 시험은 "커넥터가 쓰는 요청을 만들 수 없다"라고만 적었다. 그런데 이 소스들은 읽을 때도 POST를 쓴다. Zabbix는 JSON-RPC이고, Splunk의 검색과 CloudVision의 걸러서 조회도 POST다. HTTP 동사로는 읽기와 쓰기를 가를 수 없다. Splunk의 SPL에는 쓰는 명령이 있고, NSO는 실제 장비의 설정을 바꾸는 도구다. 제품 목표는 "현실 장비를 건드리지 않고"다(ADR-0138).
2. 소스가 주는 것이 다르다. vROps·CloudVision·NSO는 무엇이 있고 어떻게 이어졌는지를 주고, Splunk는 사건을 준다. 사건만 주는 소스를 이어도 세계는 만들어지지 않는데, 그 구분이 설계에 없었다.

## 결정
1. **소스의 역할은 셋이다.** 구성(무엇이 있고 어떻게 이어졌나)은 세계를 만든다. 사건(과거의 일)은 과거 사고를 시나리오로 재현하는 근거로 쓴다. 실측(시간에 따른 값)은 물리 프로필의 숫자와 곡선을 맞추는 데 쓴다(ADR-0137, 제품 목표의 "실측 데이터로 쌍둥이에 가까워짐"). 사건과 실측은 세계의 구조에 쓰지 않는다. 한 소스가 여럿일 수 있다(Zabbix, vROps). 연결 화면은 역할을 먼저 말한다. 이 결정에서 지금 만드는 것은 구성뿐이고, 사건과 실측의 길은 따로 설계한다.
2. **읽기 전용은 세 겹이다.** (가) 프리셋마다 부를 수 있는 것의 허용 목록을 두고, 목록 밖의 요청은 만들어지지 않는다. (나) 소스 쪽 계정이 읽기 전용이어야 이어진다. 연결할 때 권한을 확인한다. (다) 범용 HTTP 커넥터는 GET만 한다. 읽는 POST는 허용 목록이 있는 프리셋 안에만 있다.
3. **쿼리 말을 받는 소스는 정해 둔 검색만 돌린다.** 사용자가 쿼리를 자유롭게 적지 못한다. 소스가 가진 위험 명령 검사를 끄는 선택지를 두지 않는다.
4. **장비를 바꾸는 도구이기도 한 소스는 세 겹이 모두 확인될 때만 잇는다.**
5. **단계 B의 첫 견본 묶음**: vROps, CloudVision, Cisco NSO, Zabbix(5.0 이상), Splunk, 엑셀 자산 대장. 실제 데이터가 아니라 생김새(열 이름과 겹침 구조)를 본뜬 지어낸 데이터로 한다. eXpert Viewer는 넣지 않는다(제품 책임자 결정).
6. 프리셋의 첫 대상은 테라리움이 이미 흉내 내는 말이 있는 vROps다(왕복 시험이 된다, ADR-0144 15번).

## 구현할 때 문서와 대조할 것
이 결정은 소스들의 API를 다음처럼 알고 있다는 전제에 선다. 프리셋을 만들 때 각 제품의 문서와 하나씩 대조해 확정한다.
- Zabbix: 모든 호출이 JSON-RPC POST이고, 5.0은 로그인해 받은 토큰을 쓰며 API 토큰은 그 뒤 판에서 생겼다(이번에 문서로 확인하지 못했다).
- Splunk: 검색은 REST로 돌리고, 위험 명령이 든 요청은 기본으로 거절된다(확인함).
- CloudVision: 장비 목록은 Resource API의 GET으로 받는다(확인함). 이웃(LLDP) 쪽은 확인하지 못했다.
- Cisco NSO: RESTCONF의 GET으로 장비와 설정을 읽는다(확인하지 못했다).
- vROps: 자원과 자원 사이의 부모·자식 관계를 준다(테라리움의 파사드가 흉내 내는 범위에서 확인함).

## 버린 길
- **HTTP 동사로 가르기(GET만 허용)**: 읽을 때 POST를 쓰는 소스를 못 받는다.
- **쿼리 자유 입력 + 쓰는 명령 막는 목록**: 막는 목록은 새 명령이 생기면 뚫린다. 허용 목록이어야 한다.
- **소스 쪽 계정만 믿기**: 계정 설정이 틀리면 막을 것이 없다. 우리 쪽 허용 목록과 겹쳐 둔다.

## 결과
연결 화면에 역할과 읽기 전용 확인이 들어간다. 프리셋은 요청 방법·손질·대응에 더해 허용 목록을 가진 데이터가 된다. 설계 문서 `reality-data-and-ontology.md` 4절에 두 소절을 더하고 시험 표의 "읽기 전용" 줄을 고쳤다.

# ADR-0136 물리가 닿는 열네 자리를 모델 자리로 만들고, 법칙 검사와 프로필 지문으로 채점을 지킨다

## 맥락
제품 요구가 더해졌다(연수 님): 물리 법칙이 적용되는 부분을 전부 찾아 어떻게 구현할지 설계하고, 로드맵의 "사람이 만든 모델을 적용"(ADR-0095, REQ-091)을 함께 고려한다. 지금 물리는 `packages/core/src/physics/`에 직접 쓴 식과 상수이고 갈아 끼울 이음매가 없다. 한편 ADR-0133으로 "같은 답안은 같은 점수"를 시험이 보증하게 됐으므로, 모델을 끼워도 이것이 깨지면 안 된다.

## 결정
1. **전수 조사.** 물리가 닿는 곳은 열네 자리다: 방 공기, 랙 흡기, 칩 온도, 냉방기, 액체 냉각, 열원 플랜트, 날씨, 장비 전력, 전력 변환, 보호, 저장, 고장률, 회선, 일의 속도. 클러스터가 스스로 하는 일·리드타임·돈은 물리가 아니다. 자리마다의 "지금"과 "현실과 다른 점"은 [물리 법칙이 닿는 자리와 모델 자리](../physics-laws.md)에 있다.
2. **법칙과 식을 나눈다.** 에너지 보존·전력 수지·범위·방향은 엔진이 모든 모델(기본 포함)의 출력에 검사한다. 식(얼마나 빨리, 어떤 곡선)은 모델 자리에 둔다.
3. **모델 자리는 세 깊이로 바꾼다.** ① 숫자(상수) ② 곡선(CSV 표, 보간) ③ 모델(사이드카). 자리마다 입력·출력·단위·범위(세계·건물·방·랙·장비 모델)가 계약이다. ADR-0095의 계약 "상태+시간→새 상태"를 자리별로 구체화한 것이다.
4. **난수는 엔진만 뽑는다.** 고장률 모델은 고장률을 돌려주고 추첨은 엔진이 실험 시드로 한다.
5. **채점을 지키는 네 장치.** (가) 물리 프로필의 내용 해시가 지문이고 순위·비교는 지문이 같은 실험끼리만 한다. (나) ③ 모델의 출력은 실험 기록에 남고 다시 채점은 기록을 읽는다. (다) 시간 예산을 넘거나 법칙 검사에 걸린 걸음은 기본 모델로 대신하고 "모델 대체 n회"로 남기며, 대체가 있는 실험은 순위에 올리지 않는다. (라) 프로필을 벤치마크에 쓰려면 정답 풀이(REQ-110)가 그 프로필에서 100점이어야 하고, 아닌 시나리오는 그 프로필의 벤치마크에서 뺀다.
6. **기본 물리는 판으로 남긴다.** 지금 식이 v1이다. v2는 에이전트의 판단을 바꾸는 여덟 가지(차단기 반한시·돌입 전류, 방 안의 위치, 팬 전력 되먹임, 풍량 균형, 배터리 퓨커트·노화, 온도·나이·같은 랙 고장률, 대역폭에 따른 복제 따라잡기, 날씨·이슬점)를 넣는다. 옛 실험은 v1 지문으로 다시 채점된다.
7. **순서.** 0 이음매(동작 변화 없음, physics-golden 비트 동일) → 1 숫자·곡선·지문·화면 → 2 기본 v2 → 3 사이드카·파이썬 도구·기록·모델 대 모델 → 4 센서 이력 보정(쌍둥이 ②).

## 버린 길
- 전산 유체 해석을 기본 모델로: 한 걸음에 수 분이라 실험이 안 된다. 대리 모델을 자리에 꽂는 길을 연다.
- 플러그인 하나가 물리 전체를 대신: 검사할 계약이 없고 방 하나만 바꿀 수 없다. 자리별 계약으로 나눈다.
- 모델이 고장을 직접 내기: 같은 시드가 같은 세계를 내지 못한다.
- 느린 모델을 기다리기: 실험이 멈춘다. 대신하고 표시하고 순위에서 뺀다.
- 기본 물리를 그 자리에서 고치기: 옛 점수가 조용히 달라진다. 판으로 남긴다.

## 결과
REQ-091의 서술을 이 결정에 맞게 넓힌다(열네 자리, 세 깊이, 법칙 검사, 지문). 구현은 단계마다 따로 ADR과 시험을 둔다. 화면 목업은 승인 뒤에 그린다.

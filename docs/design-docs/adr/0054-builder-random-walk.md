# ADR-0054 빌더 무작위 편집 시험

## 맥락
빌더의 편집(땅 사기, 건물, 층, 방, 컨테인먼트, 랙, 설비, 채우기, 옮기기, 돌리기, 크기 바꾸기, 지우기, 되돌리기)은 사람이 눈으로 하나씩 해 보면 잘 돌아간다. 하지만 순서가 섞이면 어떨까? 사용자는 "프로덕트 수준으로 끝까지"를 요구했고, 실제 사용에서는 어떤 순서로든 누를 수 있다.

## 결정
1. **무작위 편집 시험(`fuzz.test.ts`)을 둔다.** fast-check이 편집 열 개에서 육십 개를 아무 순서로 이어 붙이고, 매 걸음마다 둘 중 하나여야 한다고 확인한다.
   - 받아들여졌다면, 만들어진 세계는 검증(`validateBlueprint`)에 오류가 없다.
   - 거절됐다면, `EditError`로 이유를 말하고 세계는 그대로다.
   끝에는 모든 층의 합계가 유한하고, 만든 세계를 돌려 봐도 온도가 유한해야 한다.
2. **땅(부지)은 옮기거나 크기를 바꿀 수 없다.** 건물 밑의 땅을 치워 건물이 남의 땅에 서는 길을 막는다. 땅은 사는 것만 된다.
3. **지면을 차지하는 것(건물, 발전기·변압기·냉동기)은 `groundTakers` 한 곳에서 센다.** 놓을 때, 옮길 때, 돌릴 때, 크기를 바꿀 때 모두 같은 목록과 겹침 검사를 쓴다. 건물 밖 설비를 옮기거나 돌릴 때도 내 땅인지 본다.
4. **건물을 옮기거나 키울 때는 안에 든 방과 설비까지 본다.** 층에는 바깥선이 없으니 건물의 바깥선을 기준으로 한다.
5. **부모가 서로를 가리키는 고리는 오류(W012)다.** 이런 파일을 읽어도 멈추지 않고, 만든 쪽에게 알려 준다.

## 이유
- 사람이 하는 시험은 "이 순서"만 본다. 무작위 시험은 만든 사람이 떠올리지 못한 순서를 찾는다. 처음 돌렸을 때 세 가지가 나왔다: 방이 든 건물을 줄이면 방이 밖으로 나가는 것, 건물과 발전기가 겹치는 것, 땅을 옮기자 건물이 내 땅 밖에 서는 것.
- "거절하되 이유를 말한다"는 화면의 약속(REQ-048)을 기계가 매번 확인하게 된다.

## 버린 대안
- 사람이 쓴 사례만 늘리기: 순서가 늘 때마다 사례가 곱으로 늘어난다.
- 땅 옮기기를 허용하고 건물이 밖에 서면 되돌리기: 사용자에게 "왜 건물이 안 지어져요?" 대신 "왜 땅이 움직여요?"를 묻게 된다.

## 결과
- 시드 네 개로 약 1만 2천 걸음을 돌려 통과를 확인했다. 시험 안의 시드는 고정이라 같은 결과가 나오고, 새 오류를 찾고 싶으면 시드를 바꿔 돌린다.
- 한계: 무작위 시험은 로직 계층(`logic/builder`)만 본다. 마우스로 끄는 동작과 3D 화면은 UX 여정과 단위 시험이 본다.

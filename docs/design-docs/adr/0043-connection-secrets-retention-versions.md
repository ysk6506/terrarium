# ADR-0043 비밀 값 봉인, 헤더, 미사용 연결 정리, 에이전트 버전

## 맥락
ADR-0042로 사람이 화면에서 하네스·에이전트를 연결하게 되자 사용자가 네 가지를 짚었다.
1. API를 쓰려면 토큰이나 비밀번호를 **화면에서 직접 적게** 해야 한다. 서버의 환경 변수 이름만 받는 것은 사용자에게 너무 어렵다.
2. 기업용 게이트웨이는 `Authorization` 말고 **커스텀 헤더**를 요구하는 곳이 많다.
3. **한 달 넘게 실험에 쓰이지 않은** 하네스·에이전트는 자동으로 지우고, 지우기 전에 **미리 안내**한다. 테라리움의 도구를 어떻게 쓰게 하는지도 **연결마다 안내**한다.
4. 실험할 때 에이전트 정보가 전과 달라졌으면 **버전을 올리고 무엇이 달라졌는지 diff로, 날짜와 함께** 남긴다. 사람이 버전 정보를 **추가·삭제·변경**할 수 있어야 한다.

## 결정
### 비밀 값 (REQ-051)
1. **입력 칸 종류 `secret`을 둔다.** 커넥터의 토큰·비밀번호 칸은 화면에서 직접 입력할 수 있다. 서버의 환경 변수 이름을 적는 칸(`env`)도 그대로 둔다. **둘 중 하나만** 쓴다. 둘 다 있으면 입력 오류로 `…Env` 칸을 지목한다.
2. **봉인해서 보관한다.** AES-256-GCM(`SecretBox`, 형식 `v1:<base64>`). 열쇠는 환경 변수 `TERRARIUM_SECRET_KEY`에서 만들고, 없으면 데이터 폴더의 `secret.key`(만든 사람만 읽는 권한 0600)를 만들어 쓴다. 열쇠 없이 뜨는 자리(시험·디스크 없는 실행)는 프로세스 수명 동안만 유효한 임시 열쇠를 쓴다.
3. **되돌려 주지 않는다.** 보기·목록·`meta`·저장소 어디에도 평문이 없다. 화면은 "설정됨"이라는 이름만 받는다(`ConnectionView.secrets`).
4. **고칠 때**: 비워 두면 그대로, 새로 적으면 교체, `null`이면 지움, 환경 변수 이름을 적으면 그쪽으로 바뀐다. 고치기·고치기 시험은 만든 사람만 한다(비밀이 함께 움직이므로).
5. **열쇠가 바뀌면** 그 연결은 "닿을 수 없음"이 되고 "서버의 열쇠가 바뀐 것 같다. 비밀 값을 다시 입력한다"고 말한다. 다른 연결에는 영향이 없다.

### 커스텀 헤더 (REQ-051)
6. 연결마다 헤더(이름, 값, 비밀 여부)를 20개까지 붙일 수 있다. 비밀 헤더는 값을 봉인하고 이름만 보여 준다. 헤더는 그 연결의 **모든 요청**에 붙고(fetch 감싸기), 사람이 적은 값이 커넥터의 기본 헤더(`Authorization` 등)보다 **우선한다**. 같은 이름(대소문자 무시)은 한 번만 쓸 수 있다. 값에는 줄바꿈이 올 수 없다.

### 안 쓰는 연결 정리 (REQ-051)
7. **화면에서 만든 연결**이 **30일** 동안 실험에 쓰이지 않으면 지운다(`connections.retentionDays`, 0이면 끔). 설정 파일의 연결은 대상이 아니다. 마지막으로 쓴 때는 실험을 만들거나 포크하거나 실행을 더할 때 갱신하고, 만든 날이 처음 값이다.
8. **7일 전부터 안내한다**(`connections.warnDays`). 만든 사람의 `meta.expiring`에 남은 날과 함께 실리고, 화면이 배너로 보여 준다. **"계속 쓰기"**(`POST /api/connections/:id/keep`)는 기간을 처음부터 다시 센다. 지우기를 막는 것은 아니라 누구나 눌러도 해가 없다.
9. 정리는 서버가 뜰 때와 이후 6시간마다 한다. **돌고 있는 실행이 있는 연결은 지우지 않는다.** 연결을 지우면 그 연결의 에이전트 버전도 함께 지운다.

### 도구 안내 (REQ-051)
10. 커넥터마다 `toolGuide`(테라리움의 도구가 어떤 길로 에이전트에게 가는지)를 설명에 싣는다. 연결 확인 때 테라리움의 도구 주소가 localhost(이 컴퓨터)인데 연결 대상이 다른 컴퓨터이면 `publicUrl`을 바꾸라고 미리 알린다.

### 에이전트 버전 (REQ-053)
11. **버전은 (하네스, 에이전트) 쌍마다 쌓인다.** 실험을 만들 때와 포크할 때마다 하네스에 에이전트를 다시 물어, 에이전트가 스스로 밝힌 정보(이름·설명·모델·하네스 종류와 이름·도구 전달 방식·하네스가 알린 사실·연결의 메타데이터)를 평평한 기록(스냅샷)으로 만들어 **가장 새 버전과 견준다**.
12. **다르면 새 버전**을 쓴다: 번호, 날짜, 만든 사람, 스냅샷. **무엇이 어떻게 바뀌었는지(이전→이후)**는 저장하지 않고 앞 버전과 견주어 그때그때 만든다. 같으면 새 버전을 쓰지 않고 가장 새 버전의 번호를 쓴다. 실험은 자기가 쓴 버전 번호(`Experiment.agentVersion`)를 지닌다. 포크는 부모의 에이전트가 아니라 **지금 에이전트**를 보고 버전을 정한다(아무것도 바꾸지 않아 거절되는 포크는 버전을 올리지 않는다).
13. **번호는 오르기만 하고 다시 쓰이지 않는다.** 가운데 버전을 지워도 "v3"는 같은 뜻으로 남는다. 지운 뒤의 diff는 남아 있는 앞 버전과 견준다.
14. **사람의 버전**: 테라리움이 볼 수 없는 차이(시스템 프롬프트를 고쳤다 등)를 위해 사람이 버전을 더할 수 있다. 이름표(60자)·메모(500자)·속성(`이름=값`)을 적는다. 속성도 diff에 `속성 …`으로 나온다. 속성은 다음 자동 버전으로 이어진다. 이름표·메모·속성은 어느 버전이든 바꿀 수 있고, 관찰한 스냅샷과 날짜는 바꿀 수 없다. 어느 버전이든 지울 수 있다.
15. **권한**: 화면에서 만든 연결은 만든 사람만 버전을 더하고 고치고 지운다. 설정 파일의 연결은 주인이 없어 누구나 한다(누가 했는지 `by`에 남긴다). 보기는 모두.
16. **동시에 만든 실험은 한 번만 올린다.** 같은 (하네스, 에이전트)에 대한 변경은 한 줄로 세워 처리한다(서버 한 대 기준).

## 이유
- 메타데이터·버전 없이 결과를 견주면 "어느 쪽이 나은가"가 아니라 "무엇이 달랐나"를 모른다. 버전은 결과에 붙는 이름표다.
- diff를 저장하지 않으면 지우기·고치기 뒤에도 항상 맞다. 스냅샷만 있으면 되고, 저장 형식이 단순하다.
- 비밀 값은 적게 하되 되돌려 주지 않으면 화면 유출 위험이 작고, 열쇠가 서버에만 있으므로 저장소 파일만 새면 쓸 수 없다.
- 안 쓰는 연결을 지우지 않으면 토큰이 든 낡은 연결이 계속 남는다. 알리고 나서 지우면 놀랍지 않다.

## 버린 대안
- **비밀 값을 환경 변수로만**: 사용자가 서버에 접근할 수 없으면 연결 자체를 못 한다.
- **비밀 값을 평문으로 저장**: 저장소 파일 하나로 모든 토큰이 샌다.
- **에이전트 정보를 해시 하나로 견주기**: 같다/다르다만 알 수 있고 무엇이 다른지 보여 줄 수 없다.
- **버전을 매번 새로 쓰기**: 같은 에이전트의 실험이 서로 다른 버전이 되어 견줄 수 없다.
- **실험 도중 에이전트가 바뀌는 것도 따라가기**: 실행 추가는 처음 만든 때의 버전을 이어 쓴다. 더 정확하지만 실험 하나가 여러 버전을 가져 결과를 견주기 어려워진다.

## 결과
- 한계: 시스템 프롬프트·도구 설정처럼 하네스가 밝히지 않는 변화는 자동으로 알 수 없다. 사람이 버전(또는 속성)을 더해야 한다.
- 한계: 실행 추가(`addRuns`)는 다시 보지 않으므로 오래 걸린 실험의 뒤쪽 실행은 에이전트가 바뀐 뒤에 돌 수 있다.
- 한계: 같은 변경을 서버 여러 대가 동시에 하면 번호가 겹칠 수 있다(한 줄로 세우는 것은 서버 한 개 안에서만).
- 한계: 열쇠를 잃으면 화면에서 입력한 비밀 값은 다시 입력해야 한다.
- 한계: 봉인은 저장된 파일이 새는 것을 막는다. 서버가 뚫려 열쇠까지 넘어가면 막지 못한다.

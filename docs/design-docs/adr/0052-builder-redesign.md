# ADR-0052 빌더 재설계 (REQ-043~048)

## 맥락
빌더는 사업장 안에 이미 있는 건물 위에 랙을 놓는 도구였다. 사용자는 "땅을 사고, 건물을 새로 짓고, 서버룸을 채우고, 새 사업장도 만드는" 데이터센터 타이쿤을 원했다(REQ-043~048).
결정할 것이 많았지만 사용자는 목표만 주었고, 승인은 시각 디자인(디자인 C)에만 받기로 했다. 그래서 아래를 이 문서에 남긴다.

## 결정
1. **땅은 필지로 판다.** 사업장 바깥에 "팔고 있는 땅"(`parcel`)이 있고, `buyParcel`로 사면 내 땅이 된다. 건물과 설비는 내 땅 위에만 놓을 수 있다. 거절은 이유와 함께 알려 주고 아무것도 바꾸지 않는다.
   3D에서 팔고 있는 땅은 주황 줄무늬 바닥으로 보인다(디자인 C의 색 안에서 정한 값이다).
2. **건물과 방은 용도를 가진다.** 건물은 데이터센터·반도체 팹·유틸리티동·연구동, 방은 서버룸·통신실·전기실·기계실·배터리실·관제실·클린룸이다. 용도가 단가(ADR-0051)와 기본 설비를 정한다.
3. **서버룸 채우기(`fillRoom`)는 빈 방에만 한다.** 랙을 두 줄씩 짝지어 복도를 사이에 두고 놓고, 서버를 넣고, 냉방·분전반·UPS를 맞는 크기로 벽 쪽에 세우고, 전원과 냉각 연결을 모두 이어 준다.
   - 선택은 둘이다: 얼마나 채울지(빈 랙 / 서버 절반쯤 / 서버 가득), 복도를 막을지(없이 / 냉복도 / 열복도).
   - 사람이 놓은 것을 건드리지 않도록 빈 방에만 허용한다. 한 번에 되돌린다.
   - 한계: 방이 14.4 × 10.8 m보다 작으면 거절한다. 설비는 패드 하나에 UPS 최대 3대씩 양쪽까지만 세운다. 채운 방의 랙 배치는 채움 정도와 상관없이 같다.
4. **새 사업장은 세 가지 모양으로 시작한다**: 사업장 모양 따라 하기(지도에서 옮긴 외곽선), 크기로 정하기(가로 × 세로), 직접 그리기(10 m 칸에 점을 찍기). 넓이는 1만~400만 ㎡, 한 변은 50~3,000 m여야 하고, 안 되면 버튼이 이유를 말한다.
5. **큰 사업장은 `wide` 카메라로 본다.** 건물이 하나도 없는 큰 땅도 한눈에 보이도록 사업장 단계의 시점을 따로 둔다.
6. **돈은 `won()`으로 읽기 쉽게 쓴다**: 억·조 단위로 줄이고 단위를 붙인다. 화성 기본 구성은 조 단위가 된다(ADR-0051).

## 이유
- 사용자가 만들고 싶은 것은 "건물에 랙을 놓는 법"이 아니라 "데이터센터를 키우는 일"이다. 땅 → 건물 → 방 → 랙 → 서버의 순서를 도구가 따라가야 한다.
- 서버룸을 손으로 채우면 배선만으로 수백 번을 눌러야 한다. 현실의 표준 배치(짝지은 줄, 막은 복도, 이중 전원)를 한 번에 놓고, 사람은 그 뒤에 고친다.
- 빈 방에만 채우면 "내가 놓은 것이 사라졌다"는 일이 없다.

## 버린 대안
- **건물 안쪽만 고치게 두고 새 사업장은 불러오기로만**: 사용자가 처음부터 짓고 싶어 한다.
- **채우기가 기존 장비를 지우고 다시 놓기**: 되돌릴 수 있어도 잃는 것이 크다.
- **필지를 지도 위 실제 지번으로**: 실거래·공시지가를 읽을 수 없었다(ADR-0051).

## 결과
- 새 시험이 `fill.test.ts`, `new-site.test.ts`, `site.test.ts`, `prices.test.ts`에 있다.
- 채우기는 단위 시험과 물리 미리보기, 손으로 확인한 화면으로 검증했다. 채우기에는 UX 여정이 없다(새 사업장·땅 사기는 `site` 여정이 있다, ADR-0053).
- 직접 그리기 패드를 키보드와 화면 낭독기로 쓰는 것은 사람이 확인해야 한다.

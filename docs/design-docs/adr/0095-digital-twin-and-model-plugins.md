# ADR-0095 현실의 쌍둥이는 네 단계로 가고, 세계의 모델은 플러그인으로 바꿀 수 있다

## 맥락
중기적으로 "진짜 현실을 모델링해서 돌려 보고 싶은 사람"이 생긴다. 사용자가 만든 물리 모델(열·기류·고장 확률·파워 캐핑 곡선)을 세계에 끼워 쓸 수 있어야 한다(제품 책임자의 요구).

## 결정
1. **쌍둥이 네 단계.** ① 구조 쌍둥이(표준 교환 형식으로 구조만, 물리는 우리 모델) ② 보정 쌍둥이(실제 센서 이력으로 물리 보정, 화면에 "쌍둥이 vs 실제 오차" 상시 표시, 오차 큰 영역은 회색) ③ 거울 쌍둥이(현실의 알람·메트릭을 읽기 전용으로 흘려 넣고 섀도 모드로 나란히 비교) ④ 문 달린 쌍둥이(쌍둥이에서 제안 → 사람 승인 → 현실 실행, 영역별로 문을 하나씩). 쌍둥이는 자기 오차를 늘 말한다. 지금 지킬 것은 ①의 전제인 데이터 설계(ADR-0088)뿐.
2. **모델 플러그인.** 세계를 움직이는 모델(열·기류·고장·전력)은 "상태 + 시간 → 새 상태"의 순수 함수 자리이며 교체 가능하다. 계약: 입력(방의 장비·설정·현재 값, 시간 간격) → 출력(새 값). 파이썬 사이드카(HTTP/gRPC)로 붙을 수 있다. 조건 셋: 재현성(난수는 우리가 준 시드로), 시간 예산(넘으면 기본 모델로 대체하고 표시), 격리(모델이 죽어도 세계는 산다). 세계를 돌릴 때 방·영역별로 모델을 고른다.
3. **모델 대 모델.** 두 모델을 같은 세계·시나리오에 놓고 나란히 보여 주고, 실제 센서 이력이 있으면 오차로 비교한다(②의 씨앗).
4. 운영을 하는 모델(예측·탐지·판단)은 세계가 아니라 에이전트 쪽이며 툴(MCP)이나 에이전트로 이미 붙는다.

## 결과
REQ-091(모델 플러그인). 쌍둥이 ②~④는 오픈 뒤 로드맵이며 경영진 대시보드의 로드맵 줄에 적는다.

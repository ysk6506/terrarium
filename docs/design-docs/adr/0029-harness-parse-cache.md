# ADR-0029 하네스 파싱 캐시

## 맥락
`run-all`은 검사마다(아키텍처, 부채, 추적성, 커버리지 주석) 같은 TypeScript 파일을 각자 다시 파싱했다. 서버 단계에서 파일이 늘자,
2코어 환경에서 커버리지와 함께 전체 테스트를 돌릴 때 "run-all이 모든 검사를 돈다" 테스트가 20초 제한을 넘었다. 검사가 느리면 에이전트가
검사를 덜 돌리게 되고, 그것은 하네스의 목적(REQ-021, REQ-024)에 어긋난다.

## 결정
`ts-ast.ts`의 `parse(file, text)`가 결과를 기억한다. 같은 파일 이름에 **같은 내용**이 오면 이전 AST를 돌려주고, 내용이 다르면 새로 파싱한다.
검사의 판정은 바뀌지 않는다 — 같은 입력에 같은 AST다.

## 이유
- 한 번의 `run-all`에서 파일을 한 번만 파싱한다. 실측: 전체 검사 6.9초 → 4.9초, 테스트 안에서 20초+ → 6초.
- 내용 비교로 무효화하므로 테스트용 미니 저장소(같은 경로, 다른 내용)에서도 틀린 결과가 나올 수 없다.

## 버린 대안
- **테스트 제한 시간 늘리기**: 느린 것을 가린다. 저장소가 커지면 다시 넘는다.
- **검사를 병렬로**: 2코어에서는 이득이 작고 출력 순서가 흔들린다.

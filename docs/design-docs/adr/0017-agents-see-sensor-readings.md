# ADR-0017 에이전트가 보는 것

## 맥락
월드에는 "진짜 상태"(실제 흡기 온도)가 있다. 현실의 운영자는 진짜 상태를 직접 보지 못하고 센서·BMC·모니터링이 보고하는 값을
본다. 센서 오차 장애(`sensor_drift`)가 있을 때 툴이 진짜 상태를 그대로 보여 주면, 에이전트는 "알람은 33°C, 상태는 21°C"를
비교하는 것만으로 답을 알게 된다. 반대로 모니터링 알람이 진짜 값으로 계산되면 센서 오차는 알람을 만들지 않아 시나리오가 성립하지 않는다.

## 결정
1. 센서가 보고하는 값은 `core.world`의 함수(`reportedInletC`)가 정한다. 물리의 알람(모니터링), Redfish(BMC), 툴이 모두 이것을 쓴다.
2. 툴(`get_entity`, `facility_status`)은 관측 상태(`observedState`)를 돌려준다.
3. 오라클(채점)과 시나리오 조건은 진짜 상태를 본다.
4. 기본 제공 시나리오는 "에이전트가 투입될 때 기본 툴로 근본 원인이 보인다"를 명세 테스트로 보장한다.

## 이유
- 평가 대상은 "보고된 정보로 진실을 추론하는 능력"이다. 진실이 새어 나가면 측정이 무의미해진다.
- 측정값의 정의를 한 곳에 두면 BMC 화면, 알람, 툴 응답이 서로 어긋나지 않는다.
- 풀 수 없는 시나리오도 측정이 무의미하므로, 관측 가능성을 테스트로 묶는다.

## 버린 대안
- **툴에서 진짜 상태 노출**: 쉬운 정답 경로가 생긴다.
- **센서 오차를 Redfish에만 반영**: 모니터링 알람과 BMC 값이 서로 다른 세계를 보여 준다.

## 결과
새 "센서" 성격의 장애(예: 전력계 오차)를 추가할 때는 `world/sensors.ts`에 보고값 함수를 만들고 알람·파사드·툴이 그것을 쓰게 한다.

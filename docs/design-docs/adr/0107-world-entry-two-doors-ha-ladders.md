# ADR-0107 세계 만들기 입구를 둘로 가르고, 서비스부터는 층마다 HA 사다리에서 고른다

## 맥락
2차 피드백(#22~#24)에서 연수 님이 짚은 근본 원인: 빌더는 **데이터센터를 직접 지어 보고 싶은 사람**(타이쿤)과 **실험할 인프라가 필요할 뿐인 사람**을 한 메뉴에 넣었다. 그래서 랙 → 서버 → 서비스를 오른쪽 패널에서 하나하나 고르게 됐고, 두 사람 모두에게 불편했다. 또 ADR-0092의 아키텍처 카드(단일/활성-대기/3중/쿠버네티스/GPU 서빙 풀)는 현실의 HA 설계와 거리가 멀어 "최대한 현실처럼" 실험을 꾸밀 수 없었다. 마지막으로 사용자는 자기 운영 도메인 밖의 층(예: 네트워크 엔지니어에게 DB HA)은 고를 지식이 없을 수 있다.

승인된 목업: 세계 만들기 입구(문 둘 + 저장해 둔 세계), 서비스부터 세 화면, 패널 없는 직접 짓기. (2026-11-06, 연수 님 승인.)

## 결정
1. **입구는 질문 하나, 문 둘.** "무엇을 하려고 하세요?" → **실험할 인프라가 필요해요**(서비스부터, 3분, 빌더를 보지 않음) / **데이터센터를 직접 지어요**(부지 → 건물 → 서버룸 → 랙). 아래에 "저장해 둔 세계에서 시작"(실측 세계·표본·내 템플릿). ADR-0092 결정 1의 "새 세계 카드"는 이 입구로 대체한다.
2. **서비스부터 ①: 어떤 서비스가 멈추면 안 되나요.** 카드마다 멈추면 어떻게 되는지(대기 n건, 사람 n명, 라인 정지, 지연)와 따라오는 시나리오 수. 여러 개 고를 수 있다. 직접 적기는 이름·종류·시간당 피해.
3. **서비스부터 ②: 층마다 HA 사다리.** ADR-0092 결정 1의 아키텍처 카드를 **층 여덟 × 사다리**로 바꾼다. 왼쪽이 싸고 자주 멈추고 오른쪽이 비싸고 잘 안 멈춘다.
   - 네트워크: 레거시 계층형 → 3티어+이중화 → 리프-스파인(Clos) → SDN 오버레이 → 클라우드 네이티브 → AI 패브릭·자율 네트워크
   - 컴퓨트: 베어메탈 한 대 → +핫 스페어 → 가상화 클러스터(HA) → +자동 재배치(DRS) → 컨테이너 오케스트레이션 → 멀티클러스터·서버리스
   - 스토리지: 로컬 디스크 → 로컬 RAID+백업 → 공유 SAN·NAS → 듀얼 컨트롤러+멀티패스 → 분산 3벌 → 지역 복제
   - 데이터베이스: 단일+백업 → 액티브-패시브 → 공유 디스크 액티브-액티브 → 프라이머리-세컨더리 복제 → 자동 페일오버·다중 복제 → 분산 SQL·합의 → 클라우드 관리형 멀티 AZ
   - 애플리케이션: 프로세스 하나 → LB 뒤 N대(세션) → 무상태 N대+외부 세션 → 마이크로서비스+서킷 브레이커 → 서비스 메시+자동 스케일 → 멀티 리전 액티브-액티브
   - 전원: 단일 피드 → A+B → 2N UPS+발전기 → 2N+자동 전환+연료 48시간
   - 냉방: N → N+1 → 2N+컨테인먼트 → 액체 냉각+자동 절체
   - 사이트·DR: 서버룸 하나 → 서버룸 둘 → 건물 둘 → DR 사이트(웜) → 멀티 사이트 액티브-액티브
   고른 칩 아래 그 선택의 결과 한 줄. 오른쪽 "이 모양이면" 카드: 서버·VM·스위치·비용, 멈추는 고장 / 느려지는 고장 / 살리는 길, 맞는 시나리오 수(넘겨야 푸는 것 포함). 프리셋: 싸게 / 보통 / 멈추지 않게 / 우리 회사 표준(저장해 두기 패턴). 서비스마다 다르게 고를 수 있고 기본은 같은 모양.
4. **알아서.** 프리셋에도, 층마다도 "알아서"가 있다. 실험 설정의 "내 도메인"(ADR-0098)에 해당하는 층은 사용자가 고르고, 나머지 층은 서비스 종류와 다른 층에 맞춰 **알아서** 골라져 있다("운영하는 층 네트워크 · 컴퓨트 · 나머지 층은 알아서 골라져 있어요 · 바꾸기"). 알아서 고른 칩은 어떻게 골랐는지 한 줄로 말한다. 도메인을 아직 안 고른 사용자는 전부 알아서다.
5. **흉내 낼 수 없는 선택지는 점선.** 코어에 모델이 없는 선택지는 점선 칩으로 보이고 고를 수는 있지만 그 층의 시나리오가 생기지 않는다. 카드가 그렇게 말한다. 지금 기준 점선: SDN·클라우드 네이티브, DRS·컨테이너·서버리스, 멀티패스·분산 스토리지·지역 복제, 데이터베이스 층 전부, 무상태 이상 애플리케이션, DR 사이트·멀티 사이트.
6. **클로즈 베타 2차에 모델링할 층.** 데이터베이스 층(단일+백업 → 자동 페일오버까지)과 스토리지 HA(듀얼 컨트롤러·분산 3벌)는 "현실처럼" 실험하려면 빠질 수 없어 2차에 코어 모델·고장·툴을 넣는다. SDN·컨테이너·서버리스·DR 사이트·지역 복제·서비스 메시는 오픈 뒤 로드맵.
7. **서비스부터 ③: 서버는 몇 대예요.** 숫자 하나(빠른 선택 48 / 480 / 4,800 / 실측). 랙·서버룸·스위치·PDU·냉방기·kW는 고른 모양에 맞춰 자동으로 센다(리프-스파인이면 리프 n+스파인 m, A+B면 PDU 2배, N+1이면 냉방기 +1). 서비스가 쓰는 서버 수와 배경 서버 수를 따로 말한다. 멈추면 시간당 피해는 서비스별. 끝나면 "세계를 다 지었어요 — …" 한 줄과 **바로 실험 만들기 / 세계 둘러보기**.
8. **직접 짓기는 패널 없이.** 오른쪽 패널을 없앤다. 빈 U를 누르면 그 자리 옆에 "서버 넣기" 카드(종류·가격·전력, "여기에 넣기"), 꽂힌 서버를 누르면 작은 카드(서비스·전원·스위치, "서비스 바꾸기 / 빼기"). 서비스 올리기는 서비스 쪽에서 "어느 서버에서 돌아요?"로 3D의 서버를 찍는다. 아래 막대는 단계(부지 › 건물 › 서버룸 › 랙)와 그 단계의 합계만. 키보드 힌트는 첫 진입 오버레이 한 번 + "?". 피드백 #22(U 띠)는 랙 자체가 되고, #23·#24는 여기 포함된다.

## 결과
- ADR-0092 결정 1·2를 이 ADR이 대체한다(저장해 두기 패턴 결정 3은 그대로). ADR-0083의 빌더 오른쪽 패널은 지운다.
- 요구사항: REQ-094(세계 만들기 입구 둘·서비스부터 세 화면·HA 사다리·알아서), REQ-095(DB·스토리지 HA 층 모델). 클로즈 베타 차수는 `beta-rounds.md`에서 셋으로 다시 나눈다.

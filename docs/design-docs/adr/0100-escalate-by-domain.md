# ADR-0100 에스컬레이트는 도메인 하나만 받는다

## 맥락
ADR-0098·0099는 구조화된 요청 종류와 카탈로그를 두었다. 제품 책임자: "어느 도메인에 넘길지만 파라미터로 받고, 내부적으로는 일정 시간 뒤 그 도메인에 생긴 문제가 전부 사라지게 하면 된다." 에이전트가 재야 할 것은 어느 팀에 넘겨야 하는지와 그동안 무엇을 하는지이지, 요청 양식을 맞게 채우는 것이 아니다.

## 결정
1. `escalate(domain, note?)`. `domain`은 서비스/OS·가상화·서버·네트워크·스토리지·데이터센터 인프라 중 하나, `note`는 기록만.
2. 부른 **시점에 그 도메인에 있는 고장**들이 각각 **고장 종류별 리드타임**(부품 교체 4시간~3일, 설정·재시작 30분~2시간; 시드 재현) 뒤에 사라진다. 넘긴 뒤 새로 난 고장은 포함되지 않는다(다시 넘겨야 한다).
3. 되묻기·요청 종류·카탈로그·거절은 없다. 가상 담당자는 코드 상태 기계이며 결정론적이다.
4. 리드타임 동안 서비스는 그대로 멈춰 있으므로 임시 조치(VM 옮기기 등)가 복구 우선 채점을 가른다. 측정(잊지 않았나·동시 작업·넘긴 근거)과 티켓 툴(선택, 기본 꺼짐), 3D의 기사 교체 작업 표현은 ADR-0099 그대로.
5. 변별력 점검의 "해결 경로" 검사는 "내 도메인 툴로 되거나, 그 고장의 도메인으로 넘기면 된다"로 단순해진다.

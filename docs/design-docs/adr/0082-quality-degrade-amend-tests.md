# ADR-0082 느린 기계에서는 멈추지 않고 줄인다

## 맥락
클로즈 베타 사용자가 Windows PC에서 "세계가 버벅이고, 가장자리가 빛번짐 같고, 서버룸의 사람이 안 움직이고, 공기 흐름 화살표도 멈춰 있다"고 했다(피드백 5·7). 원인은 넷이었다.
1. 품질 조절기(ADR-0049)의 느린 기준이 40 ms(초당 25장)로 느슨했다.
2. 해상도 배율 2를 큰 모니터에서 그대로 써서 접촉 그림자(GTAO)가 수백만 픽셀을 돌렸다.
3. 틸트시프트 흐림이 모든 단계에서 세게 걸려 있었고, 그것이 "빛번짐"으로 보였다.
4. 프레임이 늦으면 `Strain`이 사람·방문객·공기 입자를 **아예 멈췄다.** 버벅이는 PC에서는 전부 서 있었다. 그리고 사용자가 화질을 고를 길이 주소의 `?quality=`뿐이었다.

## 결정
1. **기준을 조인다.** 느림 25 ms(초당 40장), 아주 느림 50 ms(초당 20장). 판단 창(앞 3장 버리고 8장 평균)과 1.5초 멈춤 기준은 그대로다.
2. **그리는 픽셀 수에 상한을 둔다.** 높음 300만, 낮음 200만, 최소 120만. 배율 = min(기기 배율, 품질의 배율 상한, √(상한 ÷ 캔버스 픽셀 수)), 0.5 밑으로는 내리지 않는다. 큰 모니터가 저절로 낮은 배율로 그린다.
3. **흐림을 품질 단계에 넣는다.** `blur`는 높음 0.5, 낮음 0.5, 최소 0이고 시점마다 정한 세기에 곱한다. 0이면 틸트시프트 패스를 뺀다. ADR-0049의 "틸트시프트는 모든 단계에서 같다"는 이 결정이 바꾼다.
4. **멈추지 않고 줄인다.** `Strain`은 정지 신호가 아니라 단계(0~3)다. 늦은 프레임이 1.2초 쌓일 때마다 한 단계 내려가고, 빠른 프레임이 6초 이어지면 한 단계 올라온다(내렸다 곧 다시 내려가면 기다림이 두 배, 최대 48초). 단계마다 공기 입자와 화살표, 서버룸의 사람, 사업장의 방문객이 절반이 되고(공기 입자는 방 전체로 600 → 300 → 150 → 75이고 2^단계 번째마다 하나만 남긴다; 방문객은 종류마다 하나는 남고, 걷는 사람은 한 명 이상 남는다) 갱신 간격이 길어진다. 자동 회전만 단계 2부터 쉰다. 움직임 줄이기 설정(`prefers-reduced-motion`)은 이전처럼 따로 멈춘다.
5. **사용자가 고른다.** 설정 화면(`/settings`)에 "그래픽: 자동 · 높음 · 가볍게". 자동은 위의 조절기이고, 높음은 `high` 고정, 가볍게는 `min` 고정이다(고정이면 판단하지 않는다). `localStorage`에 저장하고 주소의 `?quality=`가 앞선다. 조절기가 스스로 내리면 "그래픽을 가볍게 바꿨어요. 설정에서 되돌릴 수 있어요"가 화면 아래에 뜬다. ADR-0049가 버린 "화질 선택 메뉴"는, 실제 사용에서 주소로만 고를 수 있어 쓸 수 없다는 것이 드러나 이 결정으로 다시 연다. 기본은 여전히 자동이라 처음 열 때 멈추는 일은 없다.

## 이유
- 멈춘 세계는 고장 난 것으로 보인다. 줄어든 세계는 느린 기계의 사정으로 읽힌다. 사람이 걷고 화살표가 흐르는 것이 이 제품의 보여 줄 거리라서, 가장 느린 기계에서도 하나는 움직여야 한다.
- 픽셀 수는 모니터 크기와 배율의 곱이라 기계 성능과 상관없이 커진다. 배율이 아니라 픽셀 상한으로 묶어야 4K 모니터와 노트북이 비슷한 비용을 낸다.
- 빛번짐의 원인이 흐림이므로, 흐림은 효과를 빼는 단계에 넣어도 디자인(ADR-0037)을 해치지 않고 오히려 약하게 해야 한다.
- 단계는 올라올 수 있어야 한다. 한 번 느렸다고 영영 줄어든 채로 두면 일시적인 끊김(탭 전환, 셰이더 컴파일)에도 세계가 휑해진다. 대신 올라오는 데 오래 걸려 깜박이지 않는다.

## 버린 대안
- **방문객·사람을 계속 완전히 끄기**: 지금 문제 그 자체다.
- **화면 크기로만 줄이기**: 느린 이유는 크기가 아니라 기계일 때가 많다. 픽셀 상한은 크기를 보되 단계는 실제 프레임 시간으로 정한다.
- **품질 단계를 사용자에게만 맡기기**: 처음 열 때 이미 버벅인다. 기본은 자동으로 두고 고르는 길을 더한다.

## 결과
- 고쳐진 시험: `quality.test.ts`의 두 시험은 60 ms 프레임을 40 ms로 바꿨다. 같은 성질(한 번에 한 단계, 올라가지 않음)을 새 기준 사이의 값으로 잰다. 다른 시험은 그대로 통과한다.
- 새 시험: `quality-plan.test.ts`(픽셀 상한, 흐림, 새 기준, 고정), `strain.test.ts`(단계, 히스테리시스, 절반 규칙), `settings.test.ts`.
- 한계: 25 ms 기준이 그래픽 카드가 있는 PC에서 실제로 맞는지는 이 환경(소프트웨어 렌더링)에서 확인하지 못했다. 베타 사용자의 체감으로 본다.
- 한계: 단계 판단은 프레임 간격으로 하므로 그리는 일이 아닌 다른 일(다른 탭, 백그라운드 작업)로 느려진 것도 줄이기를 일으킨다.

# ADR-0161 생김새 견본 시험에서 막힌 열아홉 곳을 메운다 — 손질은 여덟 가지, 딸린 요청, 다듬어 견주기, 묶음의 출처

## 맥락
ADR-0144 14번은 단계 B의 첫 일을 커넥터가 아니라 생김새 견본 시험으로 정했다. 여덟 가지 생김새(엑셀 랙 위치·전원·냉방, Splunk의 SPL 결과, vROps, vCenter 목록 API, OpenStack, 스위치의 포트·묶음·이웃·세션)를 지어낸 데이터로 본떠 설계에 넣어 봤다. 기록은 `docs/design-docs/reality-shape-samples.md`다.

뼈대는 버텼다: 네 단, 줄과 열의 표, 잇는 틀 다섯, 근거 등급 셋. 막힌 곳은 열아홉 군데였고 모두 적어 두지 않은 빈칸이었다. 그대로 만들면 만드는 사람이 그 자리에서 정하게 되고, 정한 것이 소스마다 달라진다.

## 결정
1. **손질은 여덟 가지로 이름을 못박는다.** 줄로 펼치기, 열로 모으기(이름·값 줄을 열로), 나누기(구분자·자리·패턴), 옆으로 붙이기, 아래로 쌓기, 고르기, 위 값 잇기, 값 바꾸기(단위·값 사전·다듬기). ADR-0144 14번의 "정해진 몇 가지"가 이 여덟이다. 코드는 넣지 못한다. 여덟으로 안 되면 바깥에서 손질해 밀어 넣는다.
2. **모으기와 범위 펼치기는 넣지 않는다.** 실장도 격자와 범위를 적은 칸은 화면이 모양을 알아보고 목록 양식을 안내한다. 실장도 격자를 직접 읽게 된다면 손질이 아니라 파일 커넥터의 읽기 방식으로 더한다.
3. **파일 커넥터의 읽기 설정**에 머리 줄 범위(여러 줄), 합친 칸(덮는 칸 모두가 그 값), 데이터가 끝나는 곳을 둔다. 합친 칸을 채우는 것은 읽기이고 받은 그대로를 고치는 것이 아니다.
4. **HTTP 커넥터에 딸린 요청을 둔다.** 앞에서 받은 표의 줄마다 요청을 만들고, 요청에 쓴 값을 결과의 열로 붙인다. 깊이와 요청 수에 한도가 있고, 한도에 닿으면 잘린 채 적용하지 않고 멈춘다. 받은 그대로로 펼치는 규칙에 이름이 키인 묶음과 줄마다 JSON 한 덩이를 더한다. XML로만 묻는 API는 받지 않는다.
5. **SPL 결과의 빠진 열은 "모두 빈 값"이다.** 검색을 저장할 때 기대하는 열을 적어 둔다. 열이 빠졌다고 스키마 흔들림으로 멈추지 않고, 멈출지는 필수 속성과 사라짐 안전장치(ADR-0151)가 정한다.
6. **대응은 "줄마다 하나"와 "값마다 하나"를 가진다.** 값마다 하나에서는 겹친 키가 정상이고, 같은 키의 줄 사이에 속성이 어긋나면 문제다. 한 표가 여러 종류를 담으면 고르기와 값 사전으로 나누고, 사전에 없는 값은 목록으로 낸다.
7. **안 쓰인 줄을 센다.** 받은 줄 수 = 개체가 된 줄 + 선이 된 줄 + 문제 목록 + 어느 대응·규칙에도 안 쓰인 줄. 넷의 합이 맞아야 한다.
8. **모델에 없는 장비는 현실 표준 종류 "기타 실장 장비"로 받는다.** 자리와 전력만 있고, 여기에 기대는 것은 없다.
9. **같은 것 알아보기는 다듬어 견준다.** 정해진 다듬기(대소문자, 앞뒤 공백, 도메인 꼬리, 포트 이름)만 쓰고 원래 값은 그대로 둔다. 여러 값 속성(IP, MAC)은 하나라도 같으면 후보이고, 어떤 범위 안에서만 유일한 키는 범위와 묶은 키로 견준다. 둘 이상과 맞으면 합치지 않고 목록으로 낸다(ADR-0144 14번 그대로).
10. **관계 규칙은 양 끝의 종류 조건을 가진다.** 가리키는 상대의 종류가 줄마다 달라도 규칙 하나가 받는다. 상대가 둘 이상의 개체에 맞으면 잇지 않는다. 양쪽이 말하는 선은 한 번만 잇고 "양쪽이 말함·한쪽만 말함"을 적는다. 양쪽이 어긋나면 잇지 않고 목록으로 낸다. 모델에 없는 이웃은 만들지 않고 숫자로 낸다.
11. **묶음에서 "몇 개가 살아야 하나"에는 출처와 등급이 있다.** 소스가 말하면 사실(LACP의 최소 링크 수, 스토리지 정책의 값, 양식에 적은 수). 종류의 기본값이면 가정(LACP 1, 전원 A·B 1, 주·대기 1). 기본값이 없는 묶음(냉방, 병렬 UPS)은 모름이다. ECMP의 구성원은 경로표 한 장이 표로 오면 사실이고, 장비의 역할(잎·가지)에서 끌어내면 가정이다. 영향 범위의 답에는 가정과 모름을 지나갔는지가 붙는다.
12. **포트의 딸린 줄에 갈래와 "아래 포트"를 둔다**(물리, 쪼갠 포트, 묶음, 하위 인터페이스, 루프백). ADR-0156 2번을 넓힌다.
13. **OpenStack의 애그리거트는 `cluster`가 아니다.** 가용 영역이 호스트 무리이고(자동 재배치는 모름), 애그리거트는 호스트의 꼬리표이고, 인스턴스 HA 구역이 자동 재배치를 켠 무리다. ADR-0157 4번의 "맞지 않으면 중립 뜻 쪽으로 고친다"를 따른 첫 수정이다.
14. **읽기 전용 규칙은 그대로다**(ADR-0149). 읽기만 하는 역할로 필요한 것을 볼 수 없는 소스는 잇지 않고 밀어 넣기로 받는다.

## 이유
- 손질에 이름이 없으면 만드는 쪽이 필요할 때마다 하나씩 늘린다. 여덟으로 못박아야 "임의의 변환 도구가 되지 않는다"가 지켜진다.
- 모으기를 넣으면 손질이 계산이 되고, 무엇을 어떻게 모았는지가 출처에서 흐려진다.
- 합이 맞는지를 세지 않으면 못 읽은 줄이 조용히 사라진다. 제품 목표의 "정확하게"는 세계가 무엇을 빠뜨렸는지 아는 데서 시작한다.
- 살아야 하는 수를 지어내면 현실에 없는 여유가 영향 범위에 생긴다. 모름으로 두는 것이 ADR-0144 9번과 같은 원칙이다.

## 버린 길
- **손질에 식(式)을 허용**: 다섯 가지로 모자랄 때 가장 쉬운 길이지만, 식은 코드다. 시험할 수 없는 변환이 소스마다 쌓인다.
- **모델 밖 이웃을 빈 개체로 자동 생성**: 판은 채워져 보이지만 출처 없는 개체가 생기고, 다음 동기화에서 진짜 개체와 겹친다.
- **읽기 전용 확인을 소스에 따라 풀어 줌**: 한 번 풀면 규칙이 아니다.

## 확인한 것과 못 한 것
- 견본의 API 모양(vROps의 식별자 목록과 관계, vCenter 목록의 조건, OpenStack의 포트·애그리거트·가용 영역, OpenConfig의 묶음 번호와 최소 링크 수)은 설계 담당이 아는 대로 적었다. 프리셋을 만들 때 제품 문서와 대조한다.
- 위치 엑셀이 목록 모양인지 실장도 격자인지는 제품 책임자에게 묻는다. 답에 따라 2번의 "격자로 읽기"를 앞당긴다.
- ECMP 구성원을 경로표에서 받을 수 있는지는 소스를 정할 때 확인한다.

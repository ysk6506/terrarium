# ADR-0032 스케일 아웃과 스케일 업 (REQ-042)

## 맥락
REQ-042: 동시 실행 실험이 수백, 수천 건이 되어도 처리해야 하고, VM·컨테이너·파드를 더 붙여서(스케일 아웃) 하든 한 대를 키워서(스케일 업) 하든
설정만 바꾸면 되어야 한다. 지금까지는 세션이 서버 프로세스의 워커 스레드에서만 돌았고, 동시 실행 상한은 고정값(32)이었다.

실행 하나가 쓰는 자원을 따져 보면 길이 보인다. 실행 시간의 대부분은 에이전트(모델)를 기다리는 시간이고, 테라리움이 쓰는 CPU는
툴을 부를 때마다 세계를 한 걸음 굴리는 짧은 순간뿐이다. 그래서 병목은 둘이다. 하나는 세션이 차지하는 메모리와 CPU(노드를 늘려 푼다),
다른 하나는 모든 것을 한곳에 적는 저장소와 스케줄러(한 대에 둔다).

## 결정
1. **역할을 나눈다.** 같은 이미지, 같은 코드가 `role`로 달라진다.
   - `all`(기본): 지금처럼 한 프로세스가 전부 한다. 토큰을 주면 워커 노드도 받는다.
   - `control`: 화면·API·MCP·스케줄러·저장소를 맡고 세션은 직접 돌리지 않는다(워커 스레드 0개).
   - `worker`: 세션만 돌린다. 저장소가 없고, 컨트롤에 자기가 있다고 알린다.
2. **세션 호스트 뒤에 노드를 숨긴다.** 실행기는 이미 `SessionHost`(열기·부르기·끝내기)만 안다. 컨트롤은 `ClusterHost`를 호스트로 쓰고,
   그 아래에 자기 스레드(`WorkerHost`)와 원격 노드(`RemoteNode`)를 같은 자리에 놓는다. 실행기·채점·결과는 한 줄도 바뀌지 않는다.
3. **노드는 하트비트로 나타나고 침묵으로 사라진다.** 노드가 5초마다 `POST /cluster/v1/heartbeat`로 (id, 주소, 자리 수, 열린 수, 비우는 중 여부)를
   알린다. 20초(설정) 넘게 조용하면 없는 노드다. 정상 종료는 `leave`로 바로 알린다. 컨트롤은 노드 목록을 저장하지 않으므로
   컨트롤이 다시 떠도 몇 초 안에 노드가 다시 모인다.
4. **자리(capacity)가 곧 동시 실행 상한이다.** 컨트롤의 자기 스레드 자리 + 받는 중인 노드의 자리 합이 `maxRunning`을 정한다.
   노드가 붙으면 줄에 기다리던 실행이 바로 시작하고(`wake`), 빠지면 새 실행이 덜 시작한다. 사용자·하네스별 한도를 따로 정하지 않았다면
   자리의 1/4, 1/2(최소 8, 16)를 쓴다. 한 사람의 큰 실험이 큰 클러스터를 쓸 수 있고, 공정 큐(ADR-0024)는 그대로 다른 사람을 끼워 준다.
5. **배치는 가장 한가한 곳.** 새 세션은 사용률(열린 수 ÷ 자리)이 가장 낮은 곳으로 간다. 거절(가득 참, 비우는 중)이나 무응답이면 다음 곳으로 간다.
6. **세계는 노드마다 한 번만 보낸다.** 세션을 열 때 세계의 다이제스트만 보내고, 노드가 모르면(`409 blueprint_needed`) 그때 세계를 보낸다.
   노드는 다이제스트가 맞는지 확인하고 64개까지 기억한다. 같은 세계로 수천 번 도는 실험이 세계를 수천 번 보내지 않는다.
7. **노드가 죽으면 그 세션의 실행은 실패한다**(스레드가 죽을 때와 같다, ADR-0027). "세션을 돌리던 노드 ○○가 멈췄다"로 남고 채점하지 않는다.
   사람이 "다시 돌리기"로 이어간다. 실행을 다른 노드에서 이어서 돌리는 일은 하지 않는다. 세션 상태가 노드 메모리에 있고,
   중간 상태를 옮기는 비용과 복잡함이 크다.
8. **비우기(scale-in)**: 노드가 SIGTERM을 받으면 `draining`을 알려 새 세션을 끊고, 돌던 세션이 끝나기를 `drainSeconds`(기본 10분)까지 기다린 뒤
   `leave`하고 끝난다. 쿠버네티스는 `terminationGracePeriodSeconds`를 이보다 길게 둔다. 컨트롤과 연락이 끊긴 노드의 세션은 한 시간(설정) 만지는 사람이 없으면 버린다.
9. **스케일 업**: 한 노드(또는 `all` 프로세스)의 자리는 `스레드 수 × sessionsPerThread`(기본 32)다. 스레드는 `workers`(기본 CPU − 1)다.
   CPU를 늘리고 재시작하면 자리가 늘어난다. 고정 32였던 기본 상한은 이 값으로 대체된다.
10. **자동 확장 신호는 대기열이다.** 컨트롤의 `GET /metrics`(Prometheus 형식, 토큰 필요)가 실행 중·대기 수, 자리, 노드 수, 사용률,
    `terrarium_nodes_wanted`(지금 일을 다 담으려면 필요한 워커 수)를 낸다. CPU로 늘리면 안 된다: 대기 중인 실행이 쌓여도 CPU는 한가하다.
11. **인증**: 컨트롤↔노드는 공유 토큰(Bearer, 상수 시간 비교)이다. 토큰은 환경 변수로만 준다. 노드 주소는 http(s)이고 자격 증명이 없어야 한다
    (토큰이 거기로 가기 때문). 신뢰망 안을 전제로 하고, 구간 암호화가 필요하면 https 주소와 메시 TLS를 쓴다.
12. **요구사항·구조 변경**: REQ-042를 더한다. `server.cluster` 단위를 만들고(`core.*`, `server.runtime`만 import), `fastify`를 이 단위에도 허용한다.

## 이유
- 실행기가 이미 `SessionHost` 뒤에 있어서, 노드 추가는 새 호스트 하나로 끝난다. 이 경계를 지키면 단일 프로세스와 클러스터가 **같은 결과**를 낸다는 것을
  시험으로 보일 수 있다(HTTP로 돈 결과 = 프로세스 안에서 돈 결과).
- 상태를 컨트롤 한 곳에만 둔다. 노드가 상태 없는 일꾼이면 노드를 늘리고 줄이는 일이 안전하고 쉽다(파드 하나가 죽어도 그 파드의 실행만 영향).
- 자리가 상한을 정하게 하면 "서버를 늘렸는데 설정도 고쳐야 한다"가 없다.
- 하트비트 방식은 컨트롤이 노드를 찾아다닐 필요가 없다(쿠버네티스 서비스 디스커버리·DNS에 기대지 않는다). 방화벽은 노드→컨트롤 한 방향과
  컨트롤→노드 한 방향만 열면 된다.

## 버린 대안
- **메시지 큐(Redis, NATS, Kafka)로 세션 요청을 나눔**: 새 인프라를 요구한다. 세션은 요청-응답을 수십 번 주고받는 대화라서 큐에 잘 맞지 않는다.
- **쿠버네티스 Job을 실행마다 만들기**: 실행 수천 개를 파드 수천 개로 만들면 스케줄러가 먼저 지친다. 시작 지연(수 초)도 짧은 실행에는 크다. 워커를 오래 살려 두고 세션을 나눠 담는 쪽이 낫다.
- **컨트롤도 여러 대(고가용성)**: 저장소가 SQLite 한 파일이다(ADR-0025). 여러 대로 만들려면 저장소를 바꿔야 한다. 지금은 컨트롤 하나가 단일 장애점이고,
  재시작해도 노드가 스스로 다시 모이며 대기 중인 실행이 이어서 돈다. 컨트롤 이중화는 저장소 교체와 함께 별도 결정으로 미룬다.
- **실행을 노드 사이로 옮기기(이어 돌리기)**: 7번에서 이유를 적었다.
- **서비스 메시나 mTLS를 코드에 넣기**: 배포 환경의 몫이다. 코드는 https 주소와 토큰만 받는다.

## 결과
- 새 단위 `server.cluster`, 새 의존성 없음(fastify는 이미 있다, 압축은 `node:zlib`).
- 설정 `cluster` 블록, 환경 변수 `TERRARIUM_ROLE`, `TERRARIUM_CONTROL_URL`, `TERRARIUM_ADVERTISE_URL`, `TERRARIUM_NODE_ID`, `TERRARIUM_CLUSTER_TOKEN_ENV`.
- 배포 예시는 `deploy/`(Dockerfile, 쿠버네티스, KEDA, systemd). 이 환경에서는 도커와 쿠버네티스를 돌릴 수 없어서 **실제 클러스터에서의 검증은 하지 못했다**.
  대신 같은 코드를 프로세스 둘(컨트롤, 워커)로 띄워 HTTP로 이어 붙인 시험이 실행 대기, 노드 합류, 완료, 정중한 이탈을 확인한다.
- 같은 변경에서 첫 화면 용량 측정이 압축된 전송량을 재도록 고쳤고(웹 파일 압축을 서버가 한다), UX 하한을 처음 정했다(모든 면 98).

# ADR-0068 블록은 누르면 이어 붙고, 뻔한 문제는 버튼으로 고치고, 시험지 점검은 편집기에서 한다

## 맥락
제품 책임자가 말했다. 사람이 시나리오를 설계하고 만들기 쉬워야 하고, 테라리움의 목적은 LLM, 하네스, 툴 조합을 시험해 최적을 찾는 것이다.
편집기를 브라우저로 처음 쓰는 사람처럼 따라가 보니 막히는 곳이 셋 있었다.
- 팔레트에서 블록을 눌러 더하면 **이어지지 않은 채** 캔버스에 놓였다. 작은 점에서 점으로 선을 직접 그어야 했다. 빈 캔버스에서 시작한 사람은 블록을 셋 놓고도 "시작에서 이어지지 않아요" 경고를 받는다.
- 문제 목록은 "「에이전트 투입」 블록이 필요해요"라고 말만 하고 어떻게 고치는지는 사람이 알아야 했다.
- 시험지 점검(ADR-0067)은 코드와 시험으로만 있었다. 시나리오를 만드는 사람이 쓰는 곳에는 없었다.
홈의 첫 문구는 "진짜 장비를 건드리지 않고 에이전트의 장애 대응을 시험해 보세요"였는데, 이것은 장점이지 목적이 아니라는 지적을 받았다.

## 결정
1. **팔레트의 블록은 누르면 주된 줄 끝에 이어 붙는다.** 주된 줄은 시작에서 각 블록의 하나뿐인 "다음" 선을 따라간 마지막 블록이다. 출구가 여럿인 블록(분기, 조건 대기)에서는 어느 출구에 붙일지 사람이 정하므로 이어 주지 않는다. 끌어다 놓은 블록은 놓인 자리에 이어지지 않은 채 남는다. 두 동작은 `appendBlock`과 `addBlock`으로 나뉜다.
2. **뻔한 문제 옆에는 고치는 버튼을 둔다.** 에이전트 투입 블록이 없다는 문제는 "블록 넣기", 채점 기준이 없다는 문제는 "채점표 열기". 고칠 방법이 하나로 정해지지 않는 문제에는 버튼을 달지 않는다(추측해서 고치지 않는다).
3. **시험지 점검을 서버 API와 편집기 패널로 낸다.** `POST /api/scenarios/:id/calibrate`가 기준선 세 에이전트를 세션 호스트(워커)에서 돌려 점수와 경고를 돌려준다. 기준선의 순수한 부분(정답, 찍기 답, 판정)은 core에서 나누어 서버와 시험용 동기 실행이 같은 규칙을 쓴다. 고칠 곳이 남은 시나리오는 돌리지 않는다. 편집기는 경고 아래에 "채점표 열기"를 둔다.
4. **홈 첫 문구는 목적을 말하고 열 때마다 바뀐다.** 문구 여섯 개 중 하나가 무작위로 뜨고, 읽는 중에는 바뀌지 않는다. 쓰는 규칙은 토스 UX 라이터 인터뷰와 ADR-0050이다: 해요체, 제목은 한 호흡(24자 이하), 부제는 두 문장 이하, 잡초 뽑기, 자랑과 느낌표 없음. 시험이 이 규칙과 문구가 모델, 하네스, 툴, 에이전트, 점수를 모두 말하는지 확인한다.

## 버린 대안
- **홈 문구를 일정 시간마다 저절로 돌리기**: 읽는 중에 글이 바뀌고, 5초를 넘게 저절로 바뀌는 내용은 멈출 방법이 있어야 해서 눈에 띄는 조절 장치가 필요하다. 한 번 열 때 하나로 정했다. 돌리기를 원하면 멈춤 버튼과 함께 더한다.
- **끌어다 놓은 블록도 자동으로 잇기**: 사람이 놓은 자리에 놓겠다는 뜻이고, 어디에 이을지 알 수 없다.
- **분기 뒤에도 첫 출구에 이어 주기**: 사람 대신 시나리오의 의미를 정하게 된다.
- **점검을 저장 없이 편집 중인 문서로 돌리기**: 서버가 아는 것은 저장된 시나리오뿐이다. 미리 돌려 보기와 같이 저장한 뒤 돌린다.

## 한계
- 시험지 점검은 한 시드(1)로 돈다. 시드를 바꿔 보는 조작은 아직 없다.
- 고치는 버튼은 두 가지 문제에만 있다. 나머지 문제는 지금처럼 클릭하면 해당 블록을 고르는 것까지다.
- 홈 문구의 좋고 나쁨은 시험이 잴 수 없다. 길이, 말투, 빠진 말만 잰다.

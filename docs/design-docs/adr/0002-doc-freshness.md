# ADR-0002 문서 신선도 장치

## 맥락
문서는 늘어나는데 최신화가 안 되고, 뭐가 오래됐는지도 알 수 없었다.

## 결정
- 모든 문서는 `kind`, `status`, `last_verified`를 가진다. 종류별로 만료 기한이 있다 (guide 60일, plan 30일, reference 90일, spec 180일).
- 문서는 `covers`로 자기가 설명하는 코드를 선언한다. 그 코드의 지문(파이썬은 AST 기준이라 주석·포맷 변경에 안 흔들림)이 바뀌면 문서는 **낡은 문서**가 되어 실패한다.
- 낡은 문서를 고치는 유일한 방법은 읽고 고친 뒤 `reverify --note`를 실행하는 것이다. 무엇을 확인했는지가 기록된다.
- 깨진 링크, 없는 파일을 가리키는 경로, 색인에서 닿지 않는 고아 문서, 너무 긴 문서도 실패한다.
- ADR은 봉인된다. 본문이 바뀌면 실패하고, 바꾸려면 새 ADR로 대체한다.

## 이유
- "최신인가?"를 사람의 기억 대신 코드 지문과 날짜로 판정한다.
- `covers`를 좁게 잡을수록 오탐이 줄어든다. 넓게 잡으면 자주 낡아지므로 문서가 스스로 좁게 쓰게 된다.

## 버린 대안
- 날짜만으로 판정: 코드가 바뀌어도 모르고, 안 바뀌어도 불필요하게 만료된다. 둘을 함께 쓴다.
- 자동으로 지문을 갱신: 읽지 않고 갱신 버튼만 누르게 된다. 메모가 필요한 명령으로 막았다.

## 한계
`reverify`를 읽지 않고 실행하는 것은 막을 수 없다. 메모(`verification_log`)가 남아 리뷰할 때 흔적이 된다.

# ADR-0092 서비스부터 세계를 만들 수 있고, 만든 구성은 저장해 두고 다시 쓴다

## 맥락
세계 만들기는 전부 아래에서 위로(땅→건물→랙)였다. 운영자의 머릿속은 위에서 아래로다: 이 서비스가 멈추면 안 된다 → 어떤 아키텍처 → 그 밑에 무슨 인프라. 여러 번 만들 테니 템플릿으로 저장해 두고 그대로/조금 바꿔서 써야 한다(연수 님).

## 결정
1. **새 세계 카드 "서비스부터".** 세 화면: ① 어떤 서비스(템플릿 카드 또는 직접 적기: 이름·종류(요청 처리형/배치형/상태 저장형)·멈추면 시간당 얼마 또는 지연 얼마) ② 어떤 아키텍처(단일/활성-대기/3중/쿠버네티스/GPU 서빙 풀 카드, 카드마다 "무엇이 멈춰야 서비스가 죽나" 한 줄; 더 세밀하게는 노코드 캔버스 — 시나리오 편집기와 같은 블록 캔버스에 서비스·VM·DB·큐·로드밸런서) ③ 세계가 만들어짐(역산: 아키텍처 → VM·호스트·배치 규칙(이중화면 다른 랙·전원 계통·냉방 구역) → 랙·서버룸·전원·냉방 → 작은 사업장 또는 고른 실제 사업장의 빈 바닥; 결과 문장 "서비스 4개 · VM 36 · 서버 12 · 랙 4 · 사고 시 시간당 최대 피해 2억 원").
2. **시나리오가 같이 나온다.** 서비스와 아키텍처에서 "이 서비스를 죽이는 고장 n가지"를 계산해 시나리오 템플릿으로 제안한다.
3. **저장해 두기 패턴(앱 전체 공통).** 만들기 버튼 아래 "이 구성을 템플릿으로 저장"(이름만 묻고 나머지는 그대로), 세계 화면에서도 "템플릿으로 저장"과 "이 세계로 템플릿 만들기". 새 세계 첫 화면 맨 위에 "내 템플릿" 줄(최근순, 카드에 요약과 "지난주 씀"), 그 아래 팀 템플릿, 맨 아래 기본. 처음 온 사람에겐 줄이 없다. 카드에 "그대로 만들기 / 조금 바꿔서"(채워진 세 화면, 바꾼 칸에 점, "템플릿과 다른 점" 한 줄). 바꾼 뒤 "템플릿에도 반영"(v2) 또는 "새 템플릿으로". 세계마다 "템플릿 X v2에서 만들었어요". "팀에 공개" 토글. 지우면 7일 되돌리기, 만든 세계는 영향 없음. 같은 패턴을 툴 묶음·실험 설정·시나리오 세트·절차서·운영 지시문에 쓴다.

## 결과
REQ-089. 돈이 의미를 갖는 자리는 둘뿐이다: 사고 비용(ADR-0091)과 전기요금(ADR-0096).

# ADR-0024 공정 스케줄링

## 맥락
여러 사람이 여러 실험을 동시에 건다(REQ-032). 서버는 한 대(8 vCPU / 64 GB를 가정한다)다. 한 사람이 실행 100개짜리 실험을 걸었다고
다른 사람의 실행 1개가 그 뒤에 100번 기다리면 안 된다. 하네스 하나(예: 에이전트 게이트웨이)가 감당할 수 있는 동시 요청 수도
정해져 있다.

## 결정
- 자리가 하나 날 때마다 다음 실행은 **지금 돌고 있는 실행이 가장 적은 사람**의 것이다. 같으면 **가장 오래 전에 차례를 받은 사람**,
  그 사람 안에서는 먼저 건 것부터.
- 한도는 세 가지: 서버 전체(`maxRunning` 32), 사람당(`perUser` 8), 하네스당(`perHarness` 16, 하네스별로 덮어쓸 수 있음).
  한도에 걸린 실행은 건너뛰고 다음 후보를 본다(뒤의 실행이 앞질러 갈 수 있다).
- 정책은 순수 함수처럼 결정적이다(같은 입력 → 같은 순서). 서버 루프는 실행이 끝나거나 새로 들어올 때마다 이것을 부른다.
- 기본 한도는 "실행 시간 대부분은 모델 응답 대기"라는 가정에서 vCPU당 4개다. 8단계 용량 측정에서 확인하고, 틀리면 낮춘다.

## 이유
- "돌고 있는 수가 적은 사람 먼저"는 라운드 로빈처럼 공평하면서도, 이미 많이 쓰는 사람에게 자리를 더 주지 않는다.
- 하네스 한도가 없으면 한 하네스가 막혔을 때 다른 하네스의 실행까지 함께 멈춘다.
- 결정적이면 테스트로 공정성을 증명할 수 있다.

## 버린 대안
- **선착순(FIFO)**: 큰 실험 하나가 모두를 막는다.
- **가중 공정 큐(WFQ)·우선순위**: 작은 도구의 규모에 비해 설명하기 어렵고, 지금 요구사항에 우선순위가 없다.
- **실행마다 별도 컨테이너**: 64 GB 한 대에서 수십 개를 띄우기엔 무겁다. 실행은 워커 스레드에서 돈다(5단계).

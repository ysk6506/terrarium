# ADR-0108 서비스부터는 IAP 하나로 시작하고, 사다리의 칩마다 그림·설명 카드가 있다

## 맥락
ADR-0107을 목업으로 다듬으며 연수 님이 고친 것 셋. ① "어떤 서비스가 멈추면 안 되나요"의 카드(설계 검증 큐·EDA 라이선스)는 세입자의 일이라 데이터센터팀에게 안 와닿았고, 플랫폼 카드(사내 클라우드·쿠버네티스 플랫폼)도 결국 "클로즈 베타 참여자는 우리 파트원"이라 하나면 된다. ② "우리 회사 표준" 프리셋은 없다. ③ 층별 사다리에서 칩 하나를 고르면 그게 어떤 구조인지 그림과 설명이 옆에 떠야 한다. (목업 승인 2026-11-06.)

## 결정
1. **서비스부터 ①은 확인 화면이다.** "무엇을 떠받치는 세계인가요?" 아래 **IAP(IT Infra Agent Platform)** 카드 하나가 이미 골라져 있다. 카드는 세 층(위: 오케스트레이터·도메인 에이전트·토폴로지 그래프 DB·GoClaw 코어 / 가운데: 쿠버네티스 — 컨트롤 플레인 VM·워커 VM / 아래: 가상화 호스트·공유 스토리지·스위치)과 **멈추면** 네 줄(워커 VM 하나 → 파드가 옮겨감 · 컨트롤 플레인 → 새 배포·스케줄만 멈춤 · 호스트 하나 → 그 위 VM이 같이 멈춤 · 그래프 DB·스토리지 → 전부 멈춤)을 보인다. VM·호스트 수는 실제 IAP 구성으로 넣는다(연수 님이 알려 주는 값). 아래 "+ 서비스 더하기"(이름 · 무엇을 주나 · 멈추면 어떻게 되나)로 다른 서비스를 더한다. ADR-0107 결정 2의 서비스 카드 목록은 이것으로 대체한다.
2. **플랫폼의 피해는 등급으로 적는다.** 시간당 피해는 하나가 아니라 "배포만 막힘 / 에이전트 응답 없음 / 전부 멈춤"처럼 그 플랫폼이 멈추는 방식마다 따로다. 복구 우선 채점(ADR-0091)과 사고 비용은 등급별 값을 쓴다. 쿠버네티스가 알아서 하는 복구(파드 재스케줄)와 에이전트가 해야 하는 복구(VM 옮기기·DB 승격)를 채점이 구분한다.
3. **프리셋은 알아서 / 싸게 / 보통 / 멈추지 않게.** "우리 회사 표준"은 없다. 저장해 두기 패턴은 세계 단위(ADR-0092 결정 3)로만 쓴다.
4. **칩마다 구조 카드.** 사다리의 칩을 누르거나 올려 놓으면(호버·키보드 포커스) 오른쪽 위에 그 구조의 카드: 그림(SVG, 테마 토큰, 끊기면 어디가 끊기는지 × 하나, `aria-label` 글 설명) · 한 문단 · 잃어도 되는 것 / 잃으면 안 되는 것 / 이 층에서 생기는 고장 / 비용 · 옆 칩으로 가는 ← →. 여덟 층의 모든 칩(45개)에 카드가 있고, 점선 칩도 카드는 있다(끝에 "아직 흉내 낼 수 없어요"). 그 아래 "이 모양이면"은 여덟 층을 합친 결과로 역할이 다르다.
5. **2단계 제목은 서비스 이름으로.** "IAP는 어떻게 돌리나요?" 서비스가 둘 이상이면 서비스마다 한 번씩, 기본은 같은 모양.

## 결과
- REQ-094 문구에 IAP 기본 카드·피해 등급·칩 카드를 더한다. ADR-0107 결정 2·3의 프리셋 "우리 회사 표준"은 폐기.

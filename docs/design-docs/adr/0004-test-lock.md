# ADR-0004 테스트 잠금

## 맥락
에이전트는 테스트를 통과시키려고 테스트를 바꾸기도 한다. 기대값 수정, 단언 삭제, 허용 오차 완화, skip, 테스트 삭제, 설정으로 테스트 제외가 그 방법이다. OpenAI의 글은 이를 막는 방법을 다루지 않아 직접 설계했다.

## 결정
세 겹으로 막는다.
1. **정적 규칙**: 단언 없는 테스트, 항상 참인 단언, 실패를 삼키는 `except`, 부채 근거 없는 skip/xfail은 실패 (`TEST*`). pytest 옵션(`-k`, `--deselect`, ...)과 `conftest`의 수집 변경 훅, 커버리지 `omit`·제외 패턴은 실패 (`TCFG*`).
2. **테스트 잠금 파일**: 모든 테스트, 도우미, 픽스처, 기대값 데이터 파일의 구조 지문을 `test-lock.json`에 기록한다. 기존 항목이 바뀌거나 사라지면 실패하고, 메시지가 무엇이 약해졌는지(단언 수, 기대값, 허용 오차, skip)를 알려준다. 새 테스트는 `lock`으로 추가만 된다.
3. **수정 허가는 ADR로만**: 요구사항이 정말 바뀌었을 때만, `amends_tests`와 40자 이상의 `test_change_reason`을 적은 봉인된 ADR을 쓰고 `lock --amend`를 실행한다. CI는 기준 브랜치와 비교해서(`--base`) 잠금이 바뀌었는데 이번 변경에 새 ADR이 없으면 실패한다 (`TLOCK005`).

커버리지는 패키지별 하한을 가지며 하한은 올라가기만 한다 (`COV*`).

## 이유
테스트를 바꾸는 행동 자체를 막을 수는 없지만, 바꾸려면 **요구사항이 바뀌었다고 글로 주장해야** 하고 그 주장이 영구 기록에 남는다. 편법의 비용을 높이고 흔적을 남긴다.

## 한계
`harness/`와 ADR을 함께 고쳐 위조할 수 있다. 이는 ADR-0005(보호 경로, 코드 소유자 승인)로 저장소 바깥에서 막는다. 테스트 자체가 틀린 경우를 위해 절차가 존재한다.

# ADR-0053 토스의 결로 바꾼 화면과 새 여정

## 맥락
REQ-058은 "시각 디자인을 토스 쪽으로 바꾸는 일은 안을 보여 주고 사용자가 고른 것만 적용한다"고 정했다. 안 세 개(A·B·C)를 보여 주었고 사용자는 **"토스의 결 그대로"**(B)를 골랐다.
B는 밝은 회색 바탕, 흰 둥근 카드, 큰 둥근 버튼, 두꺼운 제목, 파란 강조의 모양이다.

## 결정
1. **B를 `apps/web/src/styles.css`에 적용한다.** 색·반지름·글자 크기를 모두 `:root` 토큰으로 두고, 어두운 모드도 같은 이름으로 따로 정의한다.
2. **접근성을 위해 값 몇 개를 B 시안에서 조정했다.**
   - 파랑은 시안의 밝은 #2f7bf5 대신 #1b64da를 쓴다. 흰 글자와 대비 4.5:1이 나와야 한다.
   - 보조 글자색, 좋음·주의·나쁨 색은 흰 카드 위에서 4.5:1이 나오도록 시안보다 어둡게 했다.
3. **컨트롤 바탕을 놓인 곳에 맞춘다(`--control`).** 회색 바탕 위의 버튼·입력칸은 한 단계 진한 회색, 흰 카드·창·사이드 패널 안은 옅은 회색이다. 같은 색이면 입력칸이 배경에 묻혀 안 보인다.
4. **숫자 묶음(`Figures`)은 개수에 맞게 나눈다.** 6개는 3개씩 두 줄, 5개 이하는 한 줄이고, 좁으면 쌓는다. 구분선은 칸의 오른쪽·아래 가장자리이고 바깥 선은 잘라 낸다.
5. **UX 측정에 `site` 여정을 더한다**(`JOURNEY_BUDGETS.site = 6`, `새 사업장 만들고 땅 사기`). 홈 → 세계 → 새 세계 → 크기로 정하기 → 이 모양으로 만들기 → 팔고 있는 땅 사기(들인 돈이 느는지 확인) → 되돌리기(원래대로인지 확인). 손 수 6.

## 이유
- 사용자가 고른 안만 적용한다는 규칙(REQ-025, REQ-058)을 따랐다.
- 대비 4.5:1은 기계가 재는 접근성 항목(axe)이다. 시안 색 그대로면 점수가 떨어지고 읽기도 어렵다.
- 새 화면(새 사업장, 땅 사기)을 측정하지 않으면 점수에서 안 보일 뿐 좋은 것이 아니다. 여정을 더해 같은 기준으로 잰다.

## 버린 대안
- 시안 색 그대로 쓰기: 접근성 대비가 모자란다.
- 채우기까지 새 여정으로 재기: 채우기는 방 단계 깊이 들어가야 해서 여정이 길어진다. 단위 시험으로 확인한다.

## 결과
- `harness/src/ux/score.ts`의 예산과 이름표에 `site`가 더해졌고, 측정 도우미(`ux-measurements.ts`)는 `JOURNEY_IDS`에서 만들어서 따로 고칠 것이 없다.
- 하한(`ux-floor.json`)은 다시 재서 점수가 같거나 오른 뒤에만 올린다.

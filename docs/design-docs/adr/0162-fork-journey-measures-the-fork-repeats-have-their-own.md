# ADR-0162 포크 여정은 포크만 재고, 반복은 자기 여정을 가진다

## 맥락
시드당 반복([ADR-0158](0158-repeats-per-seed-and-seed-level-statistics.md))을 지을 때 `fork` 여정에 두 걸음(상황 수 5 넣기, "3번" 누르기)과 흔들림 확인이 얹혔다. 그 뒤 UX 측정이 `fork 8/6`(손 8번, 예산 6)을 냈다. 한 여정이 "조건 바꿔 다시 돌리기"와 "같은 상황을 여러 번 돌리기" 두 일을 함께 잰 탓이다.

원인을 따라가 보니 제품은 맞게 움직인다. 포크는 원본의 상황 수와 반복 횟수를 그대로 물려받는다(`apps/web/src/logic/experiment-fork-counts.test.ts`가 지킨다). 여정이 포크하는 원본은 목록에서 처음 보이는 "알람 추적" 실험인데, 흐름 묶음에서는 `cancel` 여정이 남긴 20개 상황짜리 실험이다. 거기에 3번씩을 얹으면 60번이라 90초 안에 끝나지 않아서, 앞 작업이 상황 수를 5로 고치는 걸음을 더했다.

## 결정
1. **`fork` 여정은 다시 포크만 잰다.** 끝난 실험 열기 → "조건 바꿔 다시 돌리기" → 에이전트 바꾸기 → 시작 → 결과에 "원본과 견주면". 상황 수와 반복은 건드리지 않고, 포크 양식이 원본의 횟수(반복 1번, 바뀐 것은 에이전트뿐)로 시작하는지만 눈으로 확인한다. 예산 6은 그대로다.
2. **`repeat` 여정을 새로 둔다.** 흐름 묶음에서 `run` 바로 다음이다. 새 실험 양식에서 두 질문의 말과 실행 수 요약을 확인하고, 3번씩으로 시작해, 결과에서 흔들림 두 줄과 상황별 점·줄, 390px의 실행 표(옆으로 밀리지 않음, "들여다보기"가 화면 안)를 잰다. 예산은 정직한 가장 짧은 길의 손 수인 7이다(새 실험 1, 양식 확인 4, 3번 1, 시작 1). 양식 확인은 `run`에서 옮겨 와서 `run`은 다시 손 2번이다.
3. **측정 파일의 여정 목록에 `repeat`가 늘어난다.** `harness/src/ux/score.ts`의 예산과 이름표에 한 줄씩 더한다.

## 이유
한 여정은 한 가지 일을 잰다. 예산은 "그 일을 하는 데 필요한 손"이라서, 두 일을 섞으면 어느 쪽이 무거워졌는지 보이지 않는다.

## 대안과 버린 이유
- `fork` 예산을 8로 올린다: 예산을 올리면 손이 늘어난 까닭을 가린다.
- 여정이 `run`의 실험을 이름으로 골라 포크한다: 원본을 고르는 방식이라 별도의 결정이다. 실험 상태를 읽는 법도 이 결정 밖이다.

## 결과
여정은 13개에서 14개가 된다. 잠긴 시험은 바꾸지 않았다(`groups.test.ts`는 목록이 점수 쪽과 같은지만 본다). `docs/generated/ux-score.json`은 새 측정으로 다시 올려야 한다.

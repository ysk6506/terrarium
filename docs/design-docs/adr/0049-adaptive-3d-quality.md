# ADR-0049 3D 화질은 기계에 맞춰 스스로 낮추고, 긴 선택 목록은 찾아서 고른다

## 맥락
3D 무대(ADR-0040)는 그림자 4096, 접촉 그림자(AO), 4배 다중 표본, 틸트시프트 흐림, 가장자리 다듬기(SMAA)를 모두 켠 채 그린다. 그래픽 카드가 있는 컴퓨터에서는 가볍다.
그러나 그래픽 카드 없이 프로세서가 그림을 그리는 곳(원격 데스크톱, 서버, 소프트웨어 렌더링)에서는 한 장을 그리는 데 몇 초가 걸리고, 그동안 화면의 나머지(메뉴, 버튼, 입력)도 함께 멈춘다.
사내에서 가상 데스크톱으로 쓰는 사람이 있을 수 있고, UX 측정(`pnpm ux`)도 그래픽 카드 없는 브라우저에서 돌아서 3D가 있는 화면이 9~19초씩 걸리고 측정 자체가 끝나지 못했다.
`Quality`와 `QUALITY_LOW`는 있었지만 아무도 고르지 않았다.

같은 측정에서 큰 월드(화성 기본 구성, 개체 4만여 개)의 시나리오 화면이 탭 하나를 바꾸는 데 22초 걸렸다. 채점표의 "대상" 칸마다 월드의 모든 장비를 `<option>`으로 그렸기 때문이다.

## 결정
1. 화질은 세 단계다: `high`(승인된 안 C 그대로), `low`, `min`. 단계가 내려갈 때 빠지는 것은 값비싼 **효과**뿐이다: 접촉 그림자(AO), 그림자 지도 크기, 다중 표본, 가장자리 다듬기(SMAA), 그리는 속도의 상한, 그림 해상도의 상한.
   색, 모양, 건물, 하늘, 조명 방향, **틸트시프트 흐림**은 모든 단계에서 같다(ADR-0037: 같은 안 안의 세부 조정). 틸트시프트는 `min`에서도 한 장 비용이 거의 늘지 않아(측정: 초당 10.3장 → 9.7장) 남겼다.
2. 시작 화질: 주소에 `?quality=high|low|min`이 있으면 그것. 없으면 그래픽의 이름(`WEBGL_debug_renderer_info`)이 SwiftShader·llvmpipe·Basic Render·Software 등 **프로세서로 그리는 기계**면 `min`, 아니면 `high`.
   (첫 장이 수십 초 걸리는 기계에서는 그려 본 뒤에 판단하면 이미 늦기 때문이다.)
3. 실행 중 판단(`QualityGovernor`): 그래픽 카드가 한 장을 끝낼 때까지 기다려(`finish`) 그 시간을 재고, 앞 3장(셰이더 컴파일)은 버린 뒤 8장의 평균이 40 ms를 넘으면 `low`로, 90 ms를 넘으면 `min`으로 내린다.
   한 장이 1.5초를 넘으면 평균을 기다리지 않고 바로 내린다. **다시 올리지 않는다**(깜박임 방지). 재는 것은 그래픽 카드를 멈추게 하므로 처음과 바뀐 뒤에 한 번, 이후 240장마다 한 번만 재고, `min`에서는 재지 않는다.
4. **긴 선택 목록은 찾아서 고른다.** 선택지가 120개를 넘으면 목록 위에 "이름으로 찾기" 칸이 생기고, 목록에는 맞는 것 가운데 처음 100개만 보인다(고른 것은 늘 맨 앞에 남는다). 찾는 말은 이름이나 위치에 들어 있는 단어면 되고 여러 단어는 모두 들어 있어야 한다(`17라인 서버`).
   손이나 초점이 닿기 전에는 고른 것 하나만 그린다. 채점표에 대상 칸이 수백 개여도 화면이 가볍도록 하기 위해서다. 장비 선택지 목록은 월드 하나에 한 번만 만들어 둔다(`entityChoices`).

## 이유
- 효과를 빼는 것은 되돌릴 수 있는 일이고, 멈추는 화면은 쓸 수 없다. 사용자는 디자인을 바꾸는 것이 아니라 느린 기계에서도 쓸 수 있기를 바란다.
- 먼저 재면(런타임 판단) 느린 기계가 수십 초 멈춘다. 그래서 알려진 느린 기계는 이름으로 먼저 가려낸다.
- 재는 값은 그리기 함수가 돌아온 시간이 아니라 그래픽 카드가 끝낸 시간이다. 소프트웨어 렌더링에서는 그리기 함수가 곧바로 돌아오고 다음 장이 늦게 온다.
- 수만 개 가운데 하나를 스크롤해서 고르는 것은 느리기 전에 불가능하다. 찾을 수 있어야 쓸 수 있다.

## 버린 대안
- 화면 크기에 따라 줄이기: 느린 이유는 크기가 아니라 기계다.
- 화질 선택 메뉴: 사용자가 알아서 정하게 하면 처음 열 때 이미 멈춘다. 대신 주소의 `quality`로 직접 고를 수 있게만 열어 두었다.
- 긴 목록을 가상 스크롤하는 새 선택 부품: 기본 `<select>`의 키보드·스크린리더 동작을 다시 만들어야 한다. 찾기 칸과 기본 `<select>`를 함께 쓰는 쪽이 접근성 검사를 그대로 받는다.

## 결과
- 측정(소프트웨어 렌더링, 화성 기본 구성): 홈 화면 전시장이 `min`에서 초당 3.7장 → 10장 안팎(가장자리 다듬기가 가장 비쌌다). 화성 월드가 있을 때 `/worlds`로 가는 데 4.5초 → 2.6초, 7.0초 → 1.1초. 시나리오 채점표 탭 전환 22초 → 1.9초.
- 한계: `min`에서는 접촉 그림자, 가장자리 다듬기가 없고 해상도가 낮다. 그래픽 카드가 있는 컴퓨터에서 보는 모습과 완전히 같지 않다.
- 한계: 그래픽 이름을 가리는 브라우저에서는 `high`로 시작하고 판단은 실행 중에만 한다.
- 한계: 한 번 내려간 화질은 새로 고침 전까지 올라가지 않는다.
- 한계: 그래픽 카드가 있는 컴퓨터에서 `high`가 실제로 40 ms 안에 도는지는 이 환경에서 확인하지 못했다(그래픽 카드가 없다).

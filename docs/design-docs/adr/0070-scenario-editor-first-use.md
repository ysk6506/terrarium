# ADR-0070 시나리오 편집기는 처음 쓰는 사람이 10분 안에 돌아가는 시나리오를 만들게 한다

## 맥락
연수 님이 말했다. 시나리오 만드는 화면이 진짜 사용자 입장에서 쓰기 쉽고 모든 것이 직관적으로 이해되게 디자인됐는지 토스의 UX 철학으로 충분히 검토하라. "장애"라는 말은 돌려 쓰자.
[검토 문서](../scenario-editor-review.md)에 화면마다 본 것을 적었다. 요약하면: 템플릿이 셀렉트 한 줄에 눌려 있고 기본값이 빈 캔버스다. 위 막대에 큰 버튼이 셋이다. 팔레트가 흐름부터 보여 준다. 이름에 "장애"와 내부 코드가 보이고, 단위가 초와 분으로 섞여 있다. 좁은 화면은 말없이 망가진다.

## 결정
1. **템플릿은 카드로 고른다.** 묶음별 카드에 이름, 한 줄 요약, 난이도, 못 쓰면 이유. 첫 카드가 기본이고 빈 캔버스는 맨 끝이다.
2. **위 막대의 주된 버튼은 하나다.** 고친 것이 있으면 저장, 없으면 이 시나리오로 실험. 미리 돌려 보기는 조용한 버튼.
3. **팔레트는 일어나는 일부터.** 고장 → 설정 바꾸기 → 흐름 → 에이전트. "장애"라는 묶음 이름과 블록 이름은 "고장"으로 바꾼다 (고장 일으키기, 고장 고쳐지기, 고장 종류). 코어의 타입 이름(`inject_fault`, `FaultType`)은 그대로다. 바뀌는 것은 사람이 읽는 라벨뿐이다.
4. **사람에게 보이는 시간은 분이다.** 저장은 초. 폼, 캔버스 요약, 채점표, 타임라인이 같은 단위를 쓴다.
5. **내부 코드는 화면에 나오지 않는다.** 장비는 이름, 고장은 라벨, 조건은 문장, 툴 호출은 "10분 기다려요"처럼. 시험이 `apps/web/src/logic`의 글에 `_`가 든 영문 코드나 JSON이 없는지 본다.
6. **유지 시간은 선택지 둘이다.** 고쳐질 때까지 / n분 뒤 저절로 복구.
7. **"정답만 말하면 만점" 경고에는 조치 항목 더하기 버튼이 있다.** 제어 가능 요소표의 장애별 대응(`FAULT_RESPONSES`)으로 "이 조치를 하면" 카드를 채운다.
8. **좁은 화면은 말한다.** 900px 아래에서는 캔버스 대신 넓은 화면을 권하는 안내와 채점표·점검만 보인다.
9. 요구사항 REQ-071에 이 내용을 더한다.

## 버린 대안
- **대화형 만들기(한 문장씩 묻기)**: 좋지만 베타 전에 만들 크기가 아니다. 카드 템플릿과 이어 붙기로 먼저 막힘을 없앤다.
- **코어의 타입 이름까지 fault→failure 등으로 바꾸기**: 세계 모델, 파사드, 시험 수백 개가 그 이름에 기대 있다. 사람이 읽는 라벨만 바꾼다.
- **좁은 화면용 편집기**: 캔버스 편집은 좁은 화면에 맞지 않는다. 안내가 정직하다.

## 한계
- 와닿는지는 사람이 본다. 시험은 말, 단위, 코드 누출, 손 수만 잰다.
- 검토는 한 세계(화성 생성 세계)와 템플릿 둘로 했다. 다른 세계에서 템플릿 카드의 "못 쓰는 이유"가 길어지면 다시 본다.

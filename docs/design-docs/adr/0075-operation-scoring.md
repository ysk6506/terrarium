# ADR-0075 운영 채점은 물리가 보상하는 곳에만 넣고, 채점표는 사실만 말한다

## 맥락
내장 시나리오 7개가 정답만 말하면 만점이었다(ADR-0067). 조치 채점을 넣기 전에 물리가 실제로 어떻게 움직이는지 재 봤다(캠퍼스 샘플 세계, 템플릿마다 방치 / 정답 즉시 / 최선의 완화).
- 샘플 캠퍼스는 튼튼하다. 냉방기 2대 용량이 각 100 kW인데 부하는 수 kW라, 한 대가 멈춰도 흡기는 20.5°C에서 멈춘다. 어느 템플릿에서도 서버가 열 보호로 꺼지지 않는다.
- 채점표가 거짓을 말하는 곳이 있었다. "서버가 살아 있다"가 `powered`를 보는데, 에이전트가 끈 서버도 열 보호로 꺼진 서버도 `powered`는 참이다. 냉각 플랜트 정지의 "원인과 무관한 서버 전원 끄기" 금지는 유일한 완화(부하 덜기)를 벌한다. CDU 정지의 "재시작 금지"는 CDU를 다시 켜는 BACnet 쓰기를 벌한다. 상황 설명 두 곳("흡기 온도 경고가 번진다", "열 보호로 꺼졌다")은 그 세계에서 일어나지 않는 일을 말한다.
- 물리가 조치를 갈라 주는 곳은 셋이다. 정전에 배터리 열화를 더하면 20분 안에 서버를 끄느냐로 배터리가 0%냐 11%냐 갈린다. VM 폭주는 VM을 멈추면 알람이 풀린다. CDU 정지는 수랭 서버를 끄면 CPU가 75°C에서 32°C로 내려간다.
- 외기 온도는 상수(25°C)다. 네트워크 링크에는 지연·손실이 없고 경로 홉에 링크 id가 없다.

## 결정
1. **채점표는 사실만 말한다.** `servers-alive`류 조건은 `adminOn == true`와 `thermal_shutdown` 알람 없음으로 바꾼다. 냉각 플랜트 정지의 서버 전원 금지는 없애고, CDU 정지의 재시작 금지는 대상을 수랭 서버로 한정한다. 상황 설명은 그 세계에서 일어나는 것만 말한다.
2. **이력 조건 `event`를 더한다.** `{kind: "event", type, target?}`: 세계 사건 기록에 그 사건이 한 번이라도 있었는가. 오라클, 검증, 편집기(조건 편집기의 "무엇을 묻나")에 들어간다. "열 보호로 꺼진 적 없음"을 이것으로 쓴다.
3. **운영 채점을 셋에 넣는다.** 정전·발전기 기동 실패: `ups_battery_degraded{factor: 0.1}` 블록을 더하고, 최종 상태(UPS 배터리 ≥ 20%, 수랭·액침 서버 `powered`)와 필수 조치(`power_off`)를 채점한다. VM 폭주: 최종 상태(VM 멈춤 또는 `vm_cpu_high` 알람 없음)와 필수 조치(`power_off` 그 VM); 호스트 폭주로 번지는 조건 대기는 "VM이 멈췄거나 진단이 제출됨"으로 바꾼다. CDU 정지: 최종 상태(수랭 서버 CPU < 60°C)와 필수 조치(`power_off` 그 서버). 무게는 진단 50 / 최종 상태 20 / 조치 10 / 효율 20 안팎으로, 정답만 아는 기준 에이전트가 70점 아래가 되게 한다.
4. **나머지 넷은 진단 시나리오로 남긴다**(냉방기 정지, 팬 고장, 센서 오차, 냉각 플랜트 정지). 팬 고장에는 "서버 전원 끄기 금지"(VM이 같이 죽는다)를 더한다. 냉방기 정지에는 "다른 냉방기 설정 온도 낮추기" 필수 조치(10점)를 더하되, 샘플 캠퍼스에서는 온도 차이가 작다는 것을 문서에 적는다. 변별력 시험의 "정답만으로 만점" 목록은 넷으로 줄고 이름을 고정한다.
5. **`set_outdoor_temp` 블록을 만든다.** `WorldState.outdoorC`(기본 25), 명령 `outdoor.set`, 물리의 상수를 세계 값으로 바꾼다. 드라이쿨러·냉각탑은 기존 derate, 칠러도 25→40°C에서 1→0.85로 완만히 깎는다(응축기 부하). BACnet analog-input으로 읽고, 조건 `site.outdoorC`로 쓴다. 제어 가능 요소표에 줄을 더한다(에이전트는 못 바꾼다).
6. **`network_degrade`는 계획으로 둔다.** 링크 지연·손실과 경로의 링크 id가 먼저 필요하다. 오픈 단계의 일이다.
7. 요구사항 REQ-073.

## 버린 대안
- **샘플 캠퍼스를 더 뜨겁게 바꾸기(부하·밀도 올리기)**: 캠퍼스는 다른 시험 수십 개의 기준이다. 물리 골든도 깨진다. 뜨거운 세계는 실험자가 생성기로 만든다.
- **냉방기 정지에 "냉방 능력 저하 + 고부하" 조합을 넣어 조치를 보상하기**: 방치 55°C 대 조치 51°C로 차이가 2°C라 채점이 흔들린다.
- **network_degrade를 up/down만으로 흉내 내기**: 그건 이미 있는 link_down이다.

## 한계
- 운영을 재는 내장 시나리오는 넷(차단기 연쇄 포함)과 네트워크 설정 일곱이다. 자율 운영 실험은 자기 세계에서 시나리오를 만들어야 한다. 변별력 점검이 그 세계에서 뭐가 갈리는지 알려 준다.
- `event` 조건은 사건 종류와 대상만 본다. 시각 조건("N분 안에")은 없다.

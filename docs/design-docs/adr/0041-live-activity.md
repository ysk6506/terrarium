# ADR-0041 실시간 활동

## 맥락
사용자는 "실험마다 지금 어떤 하네스/에이전트/모델이 어느 장비에서 어떤 행동을 하고 있는지 실시간으로 세계에 보이면 좋겠다"고 했다(REQ-050).
이미 실험마다 서버 이벤트(SSE)가 있지만, 그것은 실험 페이지를 위한 흐름이다. 세계를 보는 사람은 실험이 아니라 **세계**를 구독하고 싶고, 그 세계에서 도는
모든 실험의 모든 실행을 한 화면에서 구분해 보고 싶다. 도구 호출은 장비를 인자로 부르지만(`id`, `server`, `unitId`, …) 어느 인자가 장비인지는 도구마다 다르다.

## 결정
1. **무엇을 건드리는지는 한곳에 적는다.** `core.tools`의 `TARGET_ARGS`가 도구마다 장비 id를 담는 인자를 적고, `callTargets`가 id를 인자 순서대로 중복 없이 뽑으며,
   `callEffect`가 호출을 `observe`(봄) / `act`(조작) / `wait`(기다림) / `answer`(답 제출)로 가른다. 변경 도구는 프로토콜 요청이면 GET이 아닐 때만 `act`다.
   카탈로그의 모든 도구가 `TARGET_ARGS`에 있고 그 인자가 실제로 있어야 한다는 것을 테스트가 지킨다.
2. **호출 이벤트에 `effect`와 `targets`를 싣는다.** 실험 이벤트(`ExperimentEvent`)에는 선택 필드로 더했고(예전 이벤트도 그대로 읽힌다), 세계 활동 이벤트
   (`ActivityEvent`: `start` / `call` / `end`)에는 필수다.
3. **세계마다 활동 스트림을 둔다.** `GET /api/worlds/:id/activity`(SSE). 실행기는 실행이 시작될 때 `start`(누가: 실험·소유자·하네스·에이전트·모델), 호출마다 `call`,
   끝날 때 `end`를 낸다. 늦게 연 화면이 지금 일하는 실행을 곧바로 알도록 구독 직후 **일하는 중인 실행의 `start`를 다시 보낸다**(`EventBus.workingIn`).
4. **누구인지는 최대 1초 기다린다**(`whoIs`). 하네스에게 에이전트 이름과 모델을 묻되 1초 안에 답이 없거나 실패하면 에이전트 id로 표시하고 실행은 막지 않는다.
5. **웹은 이벤트를 상태로 접는다**(`logic/activity.ts`). 실행마다 일꾼 하나: 색, 마지막으로 이름 댄 장비, 앞서 간 곳(궤적 6개), 마지막 호출. 시간은 바깥에서 받아
   같은 이벤트면 같은 상태다. 실행이 색보다 많으면 색을 나눠 쓰고(8색), 60개를 넘으면 오래된 것부터 그림에서 뺀다(실험 페이지에는 남는다).
   가만히 있은 지 12초가 지나면 흐리게 보인다.
6. **장비의 자리는 `spotOf`가 말한다**(`logic/world3d/spot.ts`). 방 안의 것은 방 평면에서, 랙에 꽂힌 서버는 랙 위치와 U 높이에서, 마당의 설비는 마당에서 찾는다.
   자리가 없는 것(VM, 데이터스토어)은 속한 것의 자리에 선다. 건물·층·방·사업장도 자리가 있다. 자리에는 건물과 층 번호가 있어 층이 펼쳐질 때 같이 따라 올라간다.
7. **그림**: 장비 위에 막대와 고리(보기는 숨 쉬듯 천천히, 조작은 빠르게, 기다림은 아주 느리게, 답 제출은 멈춘 고리, 실패는 붉은색), 지나온 곳을 잇는 궤적, 이름표
   (겹치면 밀어 낸다). 오른쪽 아래의 "지금 일하는 에이전트" 패널은 실행마다 에이전트·모델·하네스·실험과 지금 하는 일을 적고, 누르면 카메라가 그 장비로 날아간다.

## 이유
- 도구 호출은 이미 서버가 중계하는 유일한 사실이라서, 따로 장치를 심지 않고 거기서 뽑는다. 하네스는 바뀌어도 이 표시는 그대로다.
- 인자 표를 한곳에 두고 테스트로 카탈로그와 맞추면 새 도구를 더할 때 표시를 빠뜨릴 수 없다.
- 세계 단위 스트림이라 한 세계에서 실험 여러 개가 동시에 돌아도 한 연결로 모두 본다.
- 시작 재전송이 없으면 늦게 연 화면은 다음 호출이 올 때까지 아무도 일하지 않는 것처럼 보인다.

## 버린 대안
- 하네스가 자기 위치를 보고하게 하기: 하네스마다 다르고, 내부 하네스에는 손댈 수 없다.
- 실험 스트림을 웹이 여러 개 열어 합치기: 실험 목록을 먼저 알아야 하고 연결이 실험 수에 비례한다.
- 모든 호출을 저장했다가 되감기: 지금 보이는 것이 목적이다. 되감기는 실행 페이지의 타임라인이 맡는다.

## 결과
- 한계: `vcenter_request`·`vrops_request`는 장비를 지목하지 않아 마커는 없고 패널에만 보인다. 자리가 없는 장비(월드에 위치가 없는 것)도 마커 없이 패널에만 보인다.
- 한계: 마커는 깊이 없이 위에 그려지므로 건물 뒤에 있어도 보인다(어디서나 찾을 수 있게 한 선택이다).
- 활동 이벤트는 서버 메모리에서만 중계한다(재시작하면 일하던 실행이 보이지 않는다. 실행 자체는 저장소에 있다).
- 장면은 실행이 없으면 아무것도 그리지 않으므로 비용이 0이다. 마커가 있는 동안에는 계속 그린다.

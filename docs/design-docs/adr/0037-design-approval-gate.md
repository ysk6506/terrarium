# ADR-0037 디자인 승인 게이트와 승인된 안 C

## 맥락
REQ-025는 "사람 개입 없이 완성한다"였다. 사용자는 3D가 허접하다고 평가한 뒤 이렇게 말했다: 다른 결정은 모두 맡기되 **디자인은 여러 안을 보여 주고 승인받은 뒤에** 진행하라.
세 가지 안을 보였고 사용자는 **C**를 골랐다.

## 결정
1. REQ-025에 한 문장을 더한다: 화면의 시각 디자인(3D 포함)은 사용자가 고른 안으로만 바꾼다. 나머지 결정은 지금처럼 에이전트가 ADR로 남긴다.
2. 승인된 안 C는 "따뜻한 크림색 틸트시프트 미니어처 디오라마"다. 값은 다음과 같다.
   - 하늘 #f6efe2 / #f3e6d0 / #efe0c8, 모서리 둥글기 0.35, 기울기(틸트) 1, 해 #fff3df 강도 2.6
   - 강조색: 전원 #f2a516, 냉각 #2a9dd8, 네트워크 #6a7df0, 열 #e8603c
   - 에이전트 구분색: #e5446d, #6a4be6, #1aa37a
3. 새로운 시각 방향(다른 안, 큰 색·모양 변경)은 다시 사용자에게 보이고 승인받는다. 같은 안 안에서의 세부 조정은 승인 없이 한다.

## 이유
- 디자인은 취향이 갈려 에이전트가 혼자 정하면 되돌리는 비용이 크다. 그 밖의 결정은 되돌리기 쉽거나 기계가 검증한다.

## 버린 대안
- 디자인도 에이전트가 정하기: 사용자가 이미 한 번 "허접하다"고 했다.
- 모든 화면 변경에 승인받기: 작은 조정마다 멈추면 효율이 떨어진다.

## 결과
- 3D 장면 코드는 위 값을 한 곳(테마 파일)에서 읽는다.

# ADR-0016 시나리오 = 흐름 + 채점표

## 맥락
REQ-034는 시나리오를 노코드 워크플로처럼 끌어다 놓아 만들기를 요구한다. 시나리오에는 "무엇이 벌어지나"(장애 주입, 대기,
분기)와 "무엇이 정답인가"(진단, 조치, 금지 행동)가 함께 있다. 둘을 한 그래프에 섞으면 채점 블록이 "언제 실행되는지"가
모호해진다.

## 결정
1. 시나리오 문서는 `nodes`+`edges`(흐름)와 `expectations`(채점표)로 나눈다. 편집기는 흐름을 캔버스에, 채점표를 옆 패널에 둔다.
2. 블록 종류는 `BLOCK_SPECS` 한 표가 정한다. 시뮬레이터가 지원하지 않는 블록도 목록에 두되 `planned`와 이유를 달아 쓰지 못하게 한다.
3. 흐름에는 고리를 허용하지 않는다. 반복은 `조건 대기`(제한 시간 포함)로 표현한다.
4. 한 출구에서 여러 연결은 병렬 실행이다. 병렬 갈래가 다시 만나면 경고한다.
5. 무작위는 `(시드, 블록 id, 방문 횟수)`로 뽑는다.
6. 시나리오 digest는 위치·캡션·이름을 빼고 동작과 채점만 해시한다.
7. 실행 중 행동할 수 없는 블록은 기록하고 흐름을 계속한다.

## 이유
- 채점이 흐름과 떨어져 있으면 "끝났을 때 무엇을 보나"가 분명하다. 오라클은 채점표만 읽으면 된다.
- 고리가 없으면 실행이 늘 끝나고, 검증이 쉽고, 결과를 재현할 수 있다.
- 블록별 무작위 스트림은 시나리오를 고쳐도 기존 선택을 흔들지 않는다(실험 비교가 쉬워진다).
- 화면 정리로 digest가 바뀌면 같은 시나리오의 결과가 다른 벤치마크 집합으로 흩어진다.

## 버린 대안
- **채점 블록을 흐름 안에**: 시점 의미가 모호하고, "끝까지 지켜야 하는 조건"을 표현하기 어렵다.
- **고리 허용 + 실행 횟수 제한**: 작성자가 의도하지 않은 무한 반복을 막으려면 결국 임의의 한도가 필요하고, 그 한도가 결과를 바꾼다.
- **공유 난수 스트림 하나**: 블록 하나를 추가하면 뒤의 모든 무작위 선택이 바뀐다.

## 결과
`core.scenario`가 모델·검증·팔레트·실행기·기본 시나리오를 갖고, `core.oracle`은 채점표를 채점한다.
설계 설명은 [시나리오 모델](../scenario-model.md).

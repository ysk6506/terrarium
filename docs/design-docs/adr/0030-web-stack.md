# ADR-0030 웹 화면의 기술 선택

## 맥락
웹은 요구사항 열 가지를 한 곳에서 보여 준다. 3D 데이터센터 건설(REQ-006, REQ-035, REQ-036), 노코드 시나리오 편집기(REQ-033, REQ-034),
실험 만들기·실행·결과(REQ-030, REQ-037), 공유(REQ-038), 벤치마크(REQ-039), 포크(REQ-040). 서버 한 대가 정적 파일까지 내려 주고,
사용자는 데스크톱 브라우저를 쓴다. 화면의 질은 곧 UX(REQ-041)이므로, 무겁거나 느리거나 어긋나는 선택을 피한다.

## 결정
1. **빌드와 화면**: Vite 6, React 19, TypeScript. 결과물은 `apps/web/dist`이고 서버가 그대로 내려 준다. 개발 중에는 Vite가 `/api`를
   서버로 넘긴다.
2. **라우터는 직접 만든다**. 화면은 열 개뿐이고 주소와 화면이 일대일이다(`logic/router.ts`). 역사 API 위에 얇게 얹었고, 주소를
   만드는 함수와 읽는 함수가 한 표에 있어 둘이 어긋날 수 없다. 라이브러리를 들이지 않는다.
3. **3D는 three.js를 직접 쓴다**. 종류별 인스턴싱으로 그리기 호출이 장비 수와 무관하게 묶이고, 장면이 바뀔 때만 다시 그린다.
   React Three Fiber 같은 선언형 층은 쓰지 않는다. 장면 계산은 `logic/builder`(DOM 없이 시험된다)에, 그리기는 `ui/builder`에 둔다.
4. **편집기는 `@xyflow/react`**. 노드를 잇고 끌고 줌하는 일을 새로 만들 이유가 없다. 문서(시나리오)가 유일한 진실이고, 캔버스는
   그것을 보여 주고 변경을 `logic/scenario`로 돌려보낸다.
5. **3D와 편집기는 그 화면에 들어갈 때 내려받는다**(`lazy`). 첫 화면은 이 둘 없이 뜬다. 홈의 작은 3D 창도 그려질 때 내려받는다.
6. **물리 미리보기는 브라우저에서 돌린다**. 빌더의 "가동해 보기"는 코어의 물리를 그대로 가져와 10분을 계산한다(서버 왕복 없음, 같은 코드라
   서버의 결과와 같다).
7. **글꼴은 Pretendard Variable을 묶어 낸다**. 닫힌 망에서도 쓸 수 있어야 해서 외부 CDN을 쓰지 않는다. 쓰는 글자만 내려받는 분할 파일이다. 글꼴과 스타일은
   `index.html`이 불러서(`@import`) 코드가 CSS 파일을 import하지 않게 한다.
8. **화면의 상태는 훅과 컨텍스트**. 서버 상태는 `useAsync`와 실시간(SSE) 훅, 편집 상태는 `logic`의 순수 함수와 `History`. 전역 상태
   라이브러리는 쓰지 않는다.

## 이유
- 화면이 열 개, 서버 상태가 대부분이라 라우터·상태관리 라이브러리의 이득이 비용보다 작다. 대신 코드 줄 수와 지켜야 할 규칙이 줄어, 어떤
  코딩 에이전트가 이어받아도 읽을 수 있다.
- 3D와 편집기를 나중에 내려받으면 첫 화면이 이들의 무게(three.js 약 500 kB, React Flow 약 230 kB)를 지지 않는다.
- 계산을 `logic`에 두면 화면 없이 시험되고(`web.logic`은 커버리지 하한이 있다), 화면은 얇아진다(ADR-0012).

## 버린 대안
- **Next.js**: 서버 렌더링이 필요 없다. 서버는 이미 있고, 배포는 정적 파일 하나로 끝나는 쪽이 낫다.
- **React Router**: 화면 열 개에는 과하다. 주소 표와 시험 몇 개로 충분하다.
- **React Three Fiber**: 선언형이 편하지만 장비가 수천 대일 때 장면 갱신을 우리가 통제하기 어렵다.
- **Redux, Zustand**: 공유할 클라이언트 상태가 거의 없다.
- **글꼴 CDN**: 닫힌 망에서 막힌다.

## 결과
- `apps/web/package.json`에 `pretendard`(글꼴)를 더했다. 나머지(`react`, `react-dom`, `three`, `@xyflow/react`, `vite`, `@vitejs/plugin-react`)는
  이미 있었고, 제3자 표(`harness/config/architecture.yaml`)에 올라 있다. `pretendard`는 CSS로만 쓰여 코드가 import하지 않으므로
  표에 올리지 않는다.
- 한 화면의 함수가 길어지면 `DEBT020~023`이 막는다. 큰 화면은 조각으로 나눈다.
- 모듈의 공개 면은 `export *` 없이 이름을 적는다(`ARCH051`).

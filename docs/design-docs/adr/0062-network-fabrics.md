# ADR-0062 네트워크는 레거시와 클라우드 두 가지로 짓고, 클라우드는 케이블마다 BGP 세션이 선다

## 맥락
ADR-0061에서 스위치가 VLAN·MAC 표·경로를 갖게 했다. 그런데 제품 책임자가 짚었다. 사업장마다 네트워크 구조가 다르므로 제품은 "레거시 네트워크, 클라우드 네트워크, GPU 네트워크까지" 모델링해야 한다.
지금까지 만든 모양은 하나다. 랙마다 VLAN, 위쪽 스위치가 함께 쓰는 게이트웨이, 스위치 사이는 /31. 이건 오래된 캠퍼스 망의 모양이다. 클라우드 데이터센터는 다르게 짓는다. 말단 스위치가 위쪽 스위치마다 라우팅 케이블을 하나씩 갖고, 케이블마다 BGP로 이웃을 맺고, 모든 말단이 같은 게이트웨이 주소를 쓴다. 문제가 나는 곳도 다르다. 레거시는 VLAN과 스패닝 트리, 클라우드는 BGP 세션과 경로다.

## 결정
1. **패브릭 종류는 스위치 속성 `fabric`이 정한다.** 값은 `legacy`(기본)와 `cloud`. 같은 도메인(말단과 그 위쪽 스위치 묶음)의 스위치 중 아이디 순으로 처음 값을 가진 것이 도메인의 종류가 된다. 속성이 없으면 ADR-0061의 모양 그대로라서 이미 있는 월드와 테스트는 달라지지 않는다.
2. **클라우드의 설계는 여전히 케이블에서 나온다.** 말단의 위쪽 케이블은 모두 라우팅 포트(/31)가 되고, 말단의 VLAN 인터페이스는 anycast 게이트웨이(.1, 모든 말단이 같은 주소 규칙)가 되고, 기본 경로는 위쪽 이웃마다 하나씩(ECMP), 위쪽 스위치는 말단의 /24로 가는 경로를 갖는다.
3. **BGP 세션은 말단-스파인 케이블마다 하나다(eBGP).** AS 번호는 사설 4바이트 범위에서 정한다. 한 도메인의 스파인은 AS 하나를 같이 쓰고 말단은 하나씩 갖는다. 라우터 ID는 스위치 아이디 순서에서 정한다. 아무도 쓰지 않는다. 케이블이 정한다.
4. **세션 상태는 계산해서 얻는다.** 케이블이 살아 있고(링크 켜짐, 양쪽 전원) 어느 쪽도 `shutdown`하지 않았으면 `established`. 내 쪽이 껐으면 `shutdown`, 케이블·전원·상대의 shutdown 때문이면 `down`. 세션이 서 있을 때만 그 세션으로 배운 경로가 경로표에 있다. `ping`과 `traceroute`는 이 경로표를 그대로 따라간다. 정적 경로가 BGP 경로를 이긴다.
5. **바꾸는 길은 `net.set`의 `bgp` 한 가지다.** `neighbor <ip> shutdown`(NX-OS는 `neighbor <ip>` 아래 `shutdown`)과 `no` 형태. `router bgp <asn>`은 그 스위치의 AS와 같아야 들어간다. `neighbor … remote-as`는 케이블이 이미 정한 값일 때만 받는다. 배운 경로를 `no ip route`로 지우려 하면 "BGP로 배운 경로이고, 이웃을 shutdown해야 사라진다"로 거절한다.
6. **알람은 둘이다.** 아무도 껐는데 끊긴 서버는 `host_unreachable`(ADR-0061 그대로). 끈 스위치에는 `bgp_session_down`을 올리고 이웃을 이름과 주소로 말한다. 케이블이 끊기거나 전원이 나가서 선 세션은 기존 링크·전원 알람이 말하므로 겹치지 않는다. 알람은 (장비, 코드)당 하나라서 한 스위치의 shutdown 이웃은 한 알람에 모은다.
7. **레거시에서는 스패닝 트리를 계산해서 보여 준다.** 위쪽 스위치가 가장 좋은 브리지(우선순위 4096, 8192…), 말단은 기본 32768. 지금 트래픽을 나르는 케이블로 루트와 각 포트의 역할(root·designated·alternate)을 얻는다. 케이블을 뽑거나 루트의 전원을 내리면 트리가 다시 선다. 모든 VLAN이 같은 트리를 쓰고 비용은 홉 하나가 1이다(OS에 따라 10G 값으로 환산해 보여 준다). **보여 주기만 한다.** 막힌 포트가 `ping`의 길을 바꾸지는 않는다.
8. **EVPN·VXLAN은 읽기만 한다.** 말단의 anycast VLAN마다 VNI 10000+VLAN을 보여 주고, EVPN 요약은 이웃마다 경로 수(서버 MAC/IP와 VLAN별 경로)를 센다. 실제 경로 교환은 없다.
9. **생성기는 장비 묶음(family)마다 패브릭을 정한다.** generic·cobaltica는 레거시, halcyon·hanbit은 클라우드. 난수를 더 쓰지 않아서 같은 설정은 같은 월드를 낸다. 단일 방 생성기(`generateWorld`)는 레거시만 만든다. 사람이 `fabric` 속성을 직접 쓰면 그것이 이긴다.
10. **요구사항 REQ-065**를 더하고, REQ-064에서 스패닝 트리와 BGP를 "흉내 내지 않는다" 목록에서 뺀다.

## 버린 대안
- **BGP를 사람이 처음부터 쓰게 함**: 수천 대 월드에서 불가능하고, 이웃·AS 번호는 케이블에 이미 들어 있다.
- **BGP 상태를 월드에 저장**: 케이블·전원·설정이 바뀔 때마다 고칠 곳이 늘고 어긋난다. 계산으로 얻으면 어긋나지 않는다.
- **`no router bgp` 제공**: 지우면 경로가 사라지는데 설정 모양에서도 BGP를 빼야 한다. 설계가 BGP를 케이블에서 얻으니 "없는 BGP"를 표현하려면 설계 쪽을 바꿔야 해서 이번엔 넣지 않았다.
- **스패닝 트리로 길을 막음**: L2 경로 선택을 `ping`에 넣어야 하고 시나리오가 크게 흔들린다. 지금은 연결성이 같아서(루프는 막지만 도달성은 같다) 보여 주기만 해도 진단 문제로는 충분하다.
- **패브릭을 사업장 단위로만 정함**: 한 사업장 안에도 두 종류가 섞여 있다는 말에 맞지 않는다. 도메인 단위가 맞다.

## 한계 (솔직하게)
- 세션 협상, 경로 속성(MED, 커뮤니티, AS-path), 경로 필터, 시간에 따른 수렴, BGP 타이머는 없다. 세션은 즉시 서고 즉시 끊긴다. 메시지 수와 가동 시간은 이름에서 만든 값이다.
- EVPN 경로 수는 서버 수에서 센 추정값이다. 실제 EVPN 경로 종류(type 2, 3, 5)는 없다. VNI는 10000+VLAN으로 정해 두었다.
- 스패닝 트리는 모든 VLAN에 같은 트리다. PVST의 VLAN별 루트, 루트 가드, BPDU 가드, 포트패스트, MSTP 인스턴스는 없다. 비용은 홉당 상수다.
- `fabric` 값과 장비 묶음의 짝(generic→레거시 등)은 그럴듯한 규칙이지 실제 사업장의 구성이 아니다. 실제 구성을 가져올 때는 `fabric` 속성을 직접 쓴다.
- GPU 네트워크(InfiniBand·RoCE, rail-optimized)는 이 결정에 없다. GPU 카탈로그와 함께 다음 결정에서 다룬다.
- 사이트 사이 전용선은 아직 없다.

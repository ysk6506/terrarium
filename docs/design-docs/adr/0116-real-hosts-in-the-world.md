# ADR-0116 진짜 호스트 섞기 — 세계의 서버 몇 대는 실제 리눅스가 답한다

## 맥락
서비스/OS 층의 `run_command`는 허용 목록 명령만 세계 상태에서 출력을 **흉내** 낸다. OS 고장은 에이전트가 어떤 명령을 칠지 예측할 수 없어서 이 흉내의 한계가 가장 빨리 드러난다("이 명령은 아직 못 해요"). 연수 님 결정(2026-11-06): 오픈 뒤로 미루지 않고 지금 한다. 단, 세계 전체를 진짜로 만드는 게 아니라 **몇 대만** 진짜다.

## 결정
1. **진짜 호스트는 세계 개체의 한 속성이다.** 서버·VM 개체에 `real: { backend, address }`가 붙으면 그 개체로 가는 `run_command`는 흉내 대신 **실제 셸**로 간다. 나머지 수백 대는 흉내 그대로. 세계 만들기(직접 짓기·서비스부터 ③)에 "이 서버는 진짜로"(개수 입력, 기본 0)가 있고, 실험 결과·벤치마크 키에 "진짜 호스트 n대"가 표시된다.
2. **뒷단 둘.** `docker`(테라리움 서버가 컨테이너를 띄움 — 클로즈 베타 기본, 설치만 하면 됨)와 `ssh`(사용자가 자기 VM 주소·키를 연결 화면에 등록 — 팀 실험실 VM). 어댑터 인터페이스는 `exec(cmd, timeout)`, `inject(fault)`, `clear(fault)`, `probe()`(CPU·메모리·디스크·프로세스·시계·DNS를 읽어 세계 상태에 반영). 뒷단을 늘리는 건 어댑터 하나 추가다.
3. **고장도 진짜로 넣는다.** 흉내 OS 고장 10개 중 진짜 호스트에서 할 수 있는 것은 실제 명령으로 넣는다: 디스크 꽉 참(`fallocate`), 로그 폭주(쓰기 루프), 메모리 누수(할당 프로세스), 프로세스 재시작 반복(실패하는 유닛), 좀비 누적, DNS 실패(`resolv.conf`), 인증서 만료(만료 인증서 생성). **못 하는 것은 뒷단별로 정직하게 적는다**: 컨테이너에서 파일시스템 읽기 전용·NTP 어긋남·커널 패닉은 안 되고(권한·시계·커널 공유), `ssh` VM에서는 `remount ro`·`date -s`·`sysrq`로 된다. 안 되는 고장을 진짜 호스트에 넣으면 시나리오 검증이 "이 뒷단에서는 흉내로만 돼요"라고 말하고 흉내로 넣는다.
4. **상태의 주인은 진짜 호스트다.** 진짜 호스트의 디스크·메모리·프로세스는 `probe()`가 읽어 세계 상태에 쓴다(기본 10초마다, 툴 호출 직후 한 번 더). 서비스 건강·알람은 그 상태로 계산된다. 흉내 호스트와 같은 규칙.
5. **시간.** 진짜 호스트가 있는 실행은 **실시간만** 된다(빨리 감기 불가 — 실제 리눅스는 빨리 안 감긴다). 운영 모드에서 빨리 감기를 고르면 "진짜 호스트 n대가 있어 실시간으로 돌아요"로 바꾼다.
6. **재현과 리플레이.** 진짜 출력은 결정론이 아니다. 그래서 `run_command`의 **실제 출력을 사건 기록에 그대로 남기고**, 리플레이는 재실행이 아니라 기록 재생이다. 같은 실험을 다시 돌리면 다른 출력이 나올 수 있고, 벤치마크는 "진짜 호스트 포함" 세트를 흉내 세트와 섞지 않는다(키가 다름).
7. **안전.** 진짜 호스트는 격리된 컨테이너·실험실 VM만. 허용 목록은 적용하지 않지만(그게 목적), `reboot`·`rm -rf /` 같은 파괴 명령은 실행 뒤 `reset()`으로 호스트를 초기 상태로 되돌린다(컨테이너 재생성, VM은 스냅샷 복원 — `ssh` 뒷단은 스냅샷 명령을 등록할 때 받음). 실행이 끝나면 항상 `reset()`.
8. **측정에 더하는 것.** 흉내 호스트에서 "이 명령은 아직 못 해요"가 난 횟수를 결과에 같이 적어, 흉내의 빈틈을 어디서 메워야 하는지 보이게 한다(허용 목록 확장의 근거).

## 결과
- REQ-098(진짜 호스트 섞기) 추가. 구현 순서: 어댑터 인터페이스 + `docker` 뒷단 + `run_command` 분기 + `probe` → 고장 주입 7개 → 세계 만들기·연결 화면 → 실시간 강제·기록 재생 → `ssh` 뒷단.

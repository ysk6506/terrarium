# 용어집: 층별 말

[용어집](glossary.md)에서 나눈 문서다. 화면, 오류 문장, 문서에 쓰는 말의 기준은 그쪽 "쓰는 법"과 같다.

## SDN 오버레이와 클라우드 네이티브 네트워크에서 정한 말 (REQ-097, ADR-0107 결정 6, ADR-0115)

| 쓰는 말 | 쓰지 않는 말 | 뜻·어디서 |
|---|---|---|
| **오버레이** | 가상망, 위 네트워크 | 리프-스파인(언더레이) 위에 터널로 덮은 서비스별 가상 네트워크. 칩 이름은 "SDN 오버레이(VXLAN·EVPN)" |
| **언더레이** | 아래 네트워크, 물리망 | 오버레이가 달리는 스위치와 케이블. "언더레이 경로가 끊겼어요" |
| **세그먼트** | 가상 서브넷, 테넌트 망 | 서비스 하나의 오버레이(VXLAN 네트워크, VNI). "세그먼트가 끊겼어요", "일부 끊김 n곳" |
| **VTEP** | 브이텝, 터널 끝점 | 리프마다 있는 VXLAN 터널의 끝. 처음 나올 때 "VTEP(VXLAN 터널의 끝)"이라고 한 줄 풀어 준다 |
| **EVPN 세션** | EVPN 피어 | VTEP이 스파인과 맺는 BGP 세션. 오르내리면 "플랩". 끊긴 뒤 다시 맺는 데 BGP 타이머 90초가 든다 |
| **SDN 컨트롤러** | 컨트롤 플레인, 오케스트레이터 | 스위치에 설정을 미는 쪽. 액티브 / 스탠바이. 멈춰도 돌던 길은 돌고 새 설정만 못 민다("헤드리스") |
| **설정 동기화** (다시 동기화) | 싱크, 리프레시 | 컨트롤러가 스위치에 설정을 밀어 맞추는 일. 한 스위치에 닿지 못하면 "옛 설정이 남았어요"(리비전이 하나 뒤) |
| **가상 방화벽** | NFV, VNF | 서비스 앞에 선 가상 네트워크 기능. 넘치면 "지연이 n ms로 늘었어요" |
| **CNI 플러그인** | 파드 네트워크 에이전트 | 노드마다 파드의 네트워크를 만드는 프로그램. 죽으면 "그 노드의 파드가 통신하지 못해요" |
| **네트워크 정책** | 방화벽 룰, ACL | 서비스 사이의 호출을 허용(allow)하거나 막는(deny) 규칙. 잘못 배포하면 "그 서비스 사이만 끊겨요" |
| **인그레스** | 입구, 게이트웨이 | 밖에서 서비스로 들어오는 문. 닫히면 "밖에서 오는 요청만 막혀요, 안의 호출은 그대로예요" |
| **ECMP 경로 재계산** | 라우팅 재수렴 | 리프가 스파인 하나를 잃고 남은 쪽으로 터널을 옮기는 일. 멈춤 없이 일어난다 |

## 컨테이너 층에서 정한 말 (REQ-096, ADR-0107 결정 6, ADR-0114)

| 쓰는 말 | 쓰지 않는 말 | 뜻·어디서 |
|---|---|---|
| **컨트롤 플레인 / 워커** | 마스터 노드, 슬레이브 노드 | 파드를 어디에 둘지 정하는 노드(API·스케줄러·etcd)와 파드가 실제로 도는 노드. 카드의 "컨트롤 플레인 VM 3 · 워커 VM 6" |
| **워크로드** (디플로이먼트) | 앱, 배포 단위 | 파드를 몇 개 두겠다는 주문서. 서비스가 기댄다. 서비스의 "일감"(분당 요청 수)과는 다르다 — 코드에서는 `k8s_workload` |
| **파드** | 컨테이너 묶음 | 워크로드가 돌리는 하나. 상태는 Running · ContainerCreating · Pending · CrashLoopBackOff · ImagePullBackOff · Evicted |
| **레플리카** | 복제본(스토리지의 "복제본"과 헷갈리지 않게 파드 이야기에만) | 워크로드가 원하는 파드 수. "레플리카 3/4개만 돌아요" |
| **재스케줄** | 파드 이주, 마이그레이션 | 죽은 노드의 파드를 포기하고 다른 노드에 새로 만드는 일. 기본 5분 뒤(`pod-eviction-timeout`). "클러스터가 알아서 옮겼어요" |
| **쫓아내기** (Evicted) | 축출 | kubelet이 디스크나 자원이 모자라 노드의 파드를 내보내는 일. 파드는 Evicted로 남고 워크로드가 다른 노드에 새로 만든다 |
| **쿼럼** (etcd 쿼럼) | 정족수 | etcd 멤버의 과반. 없으면 API가 쓰기를 못 받아 새 배포·재스케줄이 멈춘다. "컨트롤 플레인 3개 중 2개가 멈추면 쿼럼을 잃어요" |
| **CrashLoopBackOff** | 크래시 루프 | 파드가 뜨자마자 죽기를 반복하며 기다리는 시간이 10초부터 5분까지 두 배씩 느는 상태 |
| **cordon / uncordon** | 격리, 차단 해제 | 노드에 새 파드가 오지 않게 막거나(cordon) 다시 받게 하는(uncordon) 일. 돌던 파드는 그대로 |
| **drain** | 비우기 | cordon 하고 노드의 파드를 모두 내보내는 일 |
| **롤아웃 재시작** | 재배포 | 파드를 하나씩 새것으로 바꾸는 일. 새 파드가 뜬 뒤에 옛 파드를 지운다 |
| **CNI** (네트워크 플러그인) | 파드 네트워크 | 파드끼리 통신하게 하는 노드의 플러그인. 죽으면 노드는 Ready, 파드는 Running으로 보이는데 통신이 끊긴다 |
| **DRS** (자동 재배치) | 로드 밸런싱 | 바쁜 호스트의 VM을 한가한 호스트로 알아서 옮기는 것. 옮기는 동안 그 VM이 잠깐 느려진다 |
## 애플리케이션 층에서 정한 말 (REQ-100, ADR-0107 결정 6, ADR-0121)

| 쓰는 말 | 쓰지 않는 말 | 뜻·어디서 |
|---|---|---|
| **서비스 호출** (`calls`) | 의존성, 종속 | 서비스가 다른 서비스의 답을 받아 일하는 관계. 상대가 멈추면 부르는 쪽이 느려진다(`critical`이면 멈춘다) |
| **로드 밸런서** | 부하 분산기, LB | 요청을 로테이션에 있는 백엔드에 나누는 것. 헬스 체크 3번 실패한 백엔드를 알아서 뺀다 |
| **백엔드** | 서버, 노드 | 로드 밸런서가 요청을 보내는 앱 인스턴스 하나 |
| **로테이션** | 풀, 순환 | 로드 밸런서가 요청을 보내는 백엔드의 모음. "빼기"는 이 모음에서 빼는 것 |
| **서킷 브레이커** | 차단기(전기 차단기와 헷갈리지 않게) | 상대가 계속 실패하면 호출을 막고 대체 응답을 내는 규칙. 닫힘·열림·반열림 |
| **사이드카** | 프록시 | 앱 인스턴스 옆에 붙어 호출을 대신 주고받는 프로세스(envoy) |
| **메시 컨트롤 플레인** | 메시 마스터 | 사이드카에 설정을 미는 쪽(istiod). 멈춰도 이미 흐르는 트래픽은 그대로다 |
| **재시도 폭주** | 재시도 폭풍 | 잘못된 설정으로 실패한 호출이 여러 번 재시도되어 호출 수가 몇 배로 불어나는 일 |
| **리전** | 지역, 데이터센터 | 서비스 한 벌이 통째로 서 있는 곳. 멀티 리전에서는 글로벌 로드 밸런서가 둘 사이를 나눈다 |
| **넘기기** (페일오버) | 절체 | 글로벌 로드 밸런서가 멈춘 리전을 빼고 다른 리전에만 트래픽을 보내는 일 |
| **복제 지연** | 레플리케이션 랙 | 리전 사이 데이터 복사가 밀린 시간. 길면 그 리전에서 읽는 값이 옛 값이다 |

## 가속기 층과 전원·냉방 확장에서 정한 말 (REQ-107, ADR-0130)

| 쓰는 말 | 쓰지 않는 말 | 뜻·어디서 |
|---|---|---|
| **패브릭** | 인피니밴드망 | 서버 밖에서 GPU 노드끼리 잇는 망. InfiniBand나 RoCE. 서버 안은 NVLink |
| **잡** | 작업, 태스크 | 스케줄러가 노드에 올리는 학습 한 건. 체크포인트마다 저장 |
| **체크포인트** | 저장점 | 학습 상태를 저장한 스텝. 잡이 죽으면 여기서부터 다시 해서 그 뒤 스텝을 잃는다 |
| **노드 빼기** (drain) | 노드 격리 | 새 잡이 그 노드에 올라가지 않게 하는 것. 고장은 그대로다 |
| **Xid** | GPU 에러 코드 | GPU가 보고하는 오류 번호. 79번은 "버스에서 떨어짐" |
| **랙 배터리** (BBU) | 랙 UPS | 랙마다 있는 배터리 모듈. 48V DC 버스로 랙 안에 전력을 나눈다 |
| **전력 캡** | 파워 리밋 | 서버가 쓸 수 있는 소비전력의 상한(W). 낮추면 성능과 발열이 같이 준다 |

## 사이트·DR과 합의·관리형 DB에서 정한 말 (REQ-106, ADR-0129)

| 쓰는 말 | 쓰지 않는 말 | 뜻·어디서 |
|---|---|---|
| **본 사이트 / 복구 사이트** | 메인 센터·백업 센터 | 지금 서비스를 돌리는 사이트와 대신 돌릴 사이트. 액티브-액티브에서는 "사이트 A / 사이트 B" |
| **복구 시간(RTO) / 잃어도 되는 쓰기(RPO)** | 다운타임 목표, 데이터 손실 허용치 | 사이트를 잃고 서비스가 다시 도는 데까지 약속한 시간 / 잃을 수 있는 쓰기의 시간만큼. 칩 카드의 "복구 목표" 줄 |
| **DR 콜드 / 웜 / 핫** | 콜드·웜·핫 스탠바이 | 복구 사이트가 꺼진 서버와 이미지뿐 / 서비스 절반이 대기 / 서비스 전부가 동기로 대기 |
| **멀티 사이트 액티브-액티브** | 이중화 센터, 양활 | 두 사이트가 함께 일하는 것. 한쪽이 죽으면 글로벌 밸런서가 빼고 서비스는 옮기지 않는다 |
| **전환 / 되돌리기 / 모의 훈련** | 절체, 페일백, DR 드릴 | 서비스를 다른 사이트로 옮기는 일 / 본 사이트가 온전해진 뒤 돌려놓는 일 / 옮기지 않고 걸릴 시간과 잃을 쓰기를 재는 일 |
| **사이트 간 회선 / 복제 스트림** | WAN, 레플리케이션 채널 | 두 사이트를 잇는 회선("정상 3ms", "끊겼어요") / 서비스·DB·볼륨 하나를 따라 복사하는 흐름(동기·비동기, 밀린 n초) |
| **지역 복제 볼륨** | 지오 레플리카 | 다른 사이트에 복사본이 있는 볼륨. "복사본을 올린다"는 복사본을 주인으로 만드는 것 |
| **합의 DB(리더·과반) / 관리형 DB(영역)** | 래프트 클러스터·쿼럼, 매니지드 DB·AZ | 노드 셋 이상이 투표로 리더를 정하고 과반이 살아야 쓰는 DB / 공급자가 돌보는 DB와 그 가용 영역 |

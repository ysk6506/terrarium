# 파워 캐핑 참고 — 실제로 검증된 것 (ADR-0096 구현 때 읽는다)

**반영: ADR-0130** — 아래 둘을 모델로 옮겼다(`set_power_cap`, 랙 단위 배분 `균등`·`부하 비례`, 측정, 시나리오 둘, 팬 속도 실험 설정). 옮긴 표와 한계는 [전원·냉방 사다리 확장](power-cooling-ladders.md#파워-캐핑-모델만-adr-0096-일부-구현). 전기요금 모델과 Redfish 파사드는 아직이다.

연수 님 팀이 2026년에 개발·검증한 기술(연수 님 전언, 2026-11-06). 오픈 뒤 [ADR-0096](adr/0096-power-capping.md)을 구현할 때 시나리오·물리·채점을 이것에 맞춘다.

## 무엇을 만들었나
데이터센터의 **전력 공급이나 냉각 용량이 모자라도** 서버 운영을 안정적으로 유지하기 위해, **랙 단위로 서버 소비전력을 자동 조정**하는 기술.

## 검증한 시나리오 둘
1. **전력 제한.** 랙에 할당된 전력 한도 안에서, 서버별 부하 상태·전력·성능 특성을 보고 소비전력을 **동적으로 배분**한다. 성능 손실을 최소화하면서 랙 전력 한도를 지킴을 확인했다.
2. **공조 부족.** 서버별 온도를 모니터링하고 파워 캐핑을 걸어 **온도 상승을 늦추고**, 과열로 서버가 멈출 위험을 줄여 서비스 운영 시간을 늘릴 수 있는 가능성을 확인했다.

## 정직한 한계(그대로 옮긴다)
- 공조 부족은 실제 공조 설비 대신 **서버 팬 속도를 낮춰** 냉각 성능 저하를 흉내 냈다.
- **제한된 서버 수와 워크로드**에서만 수행했다.

## 테라리움에 옮길 때
- ADR-0096의 시나리오 3종 중 둘은 위 둘과 같아야 한다: "랙 전력 한도 안에서 배분"(캡 → 스로틀 → 성능 손실 최소화, 한도 준수 채점)과 "냉방 부족 때 캡으로 버티기"(온도 상승 지연 시간 · 서비스 운영 연장 시간 채점). 셋째는 전기요금 절감(ADR-0096 원안).
- 에이전트가 하는 일: 랙 단위 캡 배분 결정(`set_power_cap`은 서버별), 서버별 부하·온도를 읽고 재배분. 기준 에이전트로 "균등 배분"과 "부하 비례 배분"을 둔다.
- 물리: 캡 → CPU/GPU 주파수 → 성능(처리량) → 발열은 이미 있는 서버 열 모델에 잇는다. 팬 속도를 낮춰 냉각 저하를 흉내 내는 것도 실험 설정의 한 방식으로 둔다(팀 검증과 같은 조건 재현).
- 측정: 한도 초과 횟수·시간, 성능 손실(처리량 대비), 온도 상승 지연(분), 과열 중단 회피 수, 서비스 운영 연장 시간.

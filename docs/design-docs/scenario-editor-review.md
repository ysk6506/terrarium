# 시나리오 편집기 검토 (REQ-071, ADR-0070)

## 어떻게 봤나

2026-11-04, 화성사업장 생성 세계에서 "냉방기 정지" 템플릿과 빈 캔버스로 시작해, 새 시나리오 대화상자 → 캔버스 → 블록 네 개의 폼 → 팔레트 전체 → 채점표와 항목 더하기 메뉴 → 미리 본 결과 → 좁은 화면(820, 390px) → 키보드 순서를 캡처하고, 토스 원칙 10가지(ADR-0050)로 한 화면씩 따졌다.
기준은 하나다. **테라리움을 처음 보는 인프라 엔지니어가 설명 없이 10분 안에 돌아가는 시나리오를 만들 수 있는가.**

## 잘 되어 있는 것

- 세계가 없으면 "먼저 세계가 있어야 해요"와 가는 길이 있다 (Explain Why).
- 쓸 수 없는 템플릿과 블록은 숨기지 않고 이유를 적는다 (Explain Why).
- 문제 목록은 누르면 그 블록으로 가고, 뻔한 문제에는 고치는 버튼이 있다 (Clear Action).
- 채점표는 합계를 늘 보여 준다 (Value First). 블록을 누르면 줄에 이어 붙는다 (Easy to Answer).

## 재는 법

- 1·2·3·11은 UX 여정 `author`와 `design`의 손 수가 줄거나 같아야 한다. 템플릿 카드로 바꾼 뒤 `design` 여정은 셀렉트 대신 카드를 누른다.
- 4·6·7·8·9는 화면 글에 `_` 가 든 영문 코드, `{"`, "초"가 단위로 쓰인 곳이 없는지 시험으로 본다 (apps/web/src/logic).
- 10은 `first-scenario.test.ts`에 "조치 항목 더하기 뒤에는 정답만 아는 기준선이 만점을 못 받는다"를 더한다.

## 구현 현황 (묶음 A, 웹만)

- 1: 새 시나리오 대화상자는 카드 목록(설비 / 네트워크·전원 설정 / 맨 끝에 조용한 빈 캔버스)이다. 못 쓰는 카드는 숨기지 않고 요약 자리에 이유를 적는다. 세계가 하나면 세계 고르기를 접는다. 묶음은 두 개다 (서버·가상화 묶음은 아직 나누지 않았다).
- 2: 위 막대의 `btn-primary`는 하나다. 고친 것이 있거나 남의 시나리오면 저장 / 내 사본으로 저장, 저장된 뒤에는 "이 시나리오로 실험"이고 "저장됨"은 조용한 표시다.
- 11: 900px 아래에서는 안내와 점검 패널만 보인다.
- 12: 블록 머리에 묶음 이름을 작게 붙였다 (시작과 메모는 제외).

## 구현 현황 (묶음 B, 편집기의 말·단위·누출)

- 3: 팔레트는 고장 → 설정 바꾸기 → 흐름 → 에이전트 순서다 (`GROUP_ORDER`, `CATEGORY_LABELS`). 캔버스 블록 머리의 묶음 이름도 같은 표를 읽는다.
- 4: 블록과 폼의 말은 용어집을 따른다: 고장 발생, 고장 복구, 고장 종류, 세부 설정, 상황 설명, 툴 호출 상한, 제한 시간. 고장에 정할 값이 없으면 "세부 설정" 칸을 보이지 않는다 (ADR-0072).
- 5: 고장의 지속 시간은 "복구 방식" 선택이다: 고쳐질 때까지(0초) / n분 뒤 저절로 복구(분 칸이 나타난다). `fields.ts`의 `recovery` 칸과 `recoverySeconds`.
- 6: 사람이 읽는 시간은 분이다. 저장은 초 그대로이고, 분으로 떨어지지 않는 값은 소수 한 자리로 보인다 (`units.ts`, 폼의 `stored: "seconds"` 칸). 캔버스 요약, 미리 본 결과, 검증 메시지, 채점표 카드가 같은 단위를 쓴다.
- 7: 채점표 카드의 한 줄은 장비를 이름으로, 고장을 라벨로, 조건을 `describeCondition` 문장으로 말한다 (`expectationText(e, index)`).
- 8: 미리 본 결과는 "10분 기다려요", "냉방기 정지 발생 (CRAH-1)", "대기 시작"처럼 문장이다. 이름이 겹치지 않고, 내부 id는 나오지 않는다.
- 9: 조건 편집기의 비교는 말만 보이고(같다, 다르다, 보다 크다, 보다 작다, 이상, 이하) 알람 단계는 심각/경고다. 조건 묶기는 "모두 맞을 때 / 하나라도 맞을 때"다.
- 10: 점검 경고 "정답만 말하면 만점이에요" 옆에 "조치 항목 더하기"가 있다 (`suggestedAction`). 고장의 첫 대응 행에서 첫 조치를 골라 "이 조치를 하면" 카드(점수 20)를 더하고 채점표를 연다. 고장이 원격으로 고쳐지지 않으면(`diagnose`) 설명이 빈 "끝났을 때 이 상태면" 카드를 더한다. 조치가 그 장비에 하는 것일 때만 대상을 채운다.
- 12: 새 시나리오 대화상자의 카드는 1200px 이상에서 세 열, 그 아래 두 열, 640px 아래 한 열이다.
- 말이 용어집을 어기지 않는지는 `editor-words.test.ts`가 본다 (ADR-0072).

## 구현 현황 (복구 우선 채점, REQ-088)

- 새 시나리오 카드는 세계가 작을 때(장비 600개 이하) 템플릿을 흔한 툴만 가진 에이전트로 한 번씩 돌려 보고, 정답 장비에 닿지 않는 카드에 "흔한 툴만으로는 원인에 닿을 수 없어요"를 요약 아래에 보인다. 카드는 한 장씩 차례로 점검해서 화면이 멈추지 않고, 점검이 끝나기 전에는 아무 말도 하지 않는다 (`useNoCommonPath`, `reachesAnswer`).
- 변별력 점검 패널은 기준 에이전트 점수 아래에 "서비스를 옮겨서 복구하는 길"과 "흔한 툴만으로 원인에 닿는 길"을 있음·없음으로 보이고, 없으면 경고 줄이 하나 더 는다.

## 구현 현황 (절차서 탭과 툴 고르기 점검, REQ-080, REQ-082)

- 편집기 위 막대의 탭이 흐름·채점표·**절차서** 셋이 되었다(괄호에 단계 수). 절차서 탭은 단계(할 일·확인할 것·쓰는 툴)를 쓰고 옮기고 지우며, **최고 궤적에서 초안 만들기**(끝난 실행이 없으면 그렇다고 말한다), **팀 SOP 붙여 넣기**(목록을 못 찾으면 한 단계로 넣고 알려 준다), 저장해 둔 절차서 불러오기를 가진다. 툴이 없는 단계는 점수를 세지 않는다는 말이 붙고, 절차서의 빈 단계·없는 툴은 고칠 곳(SC022, 경고)으로 올라온다. 규칙은 [툴 범위, 에스컬레이션, 절차서](tool-scope-and-sop.md#5-절차서sop).
- 변별력 점검 패널에 **툴 고르기 점검** 표가 더해졌다. 상황 열 가지 × 툴, ● 맞게 골랐어요 · ○ 못 골랐어요, 모호한 쌍은 "설비 현황과 차단기 리셋이 '전원이 끊겼어요'에서 둘 다 골라져요. 한쪽 설명에 '대신 무엇을 쓰나'를 적어 주세요"로 보인다. 쌍이 없으면 "설명으로 못 가리는 쌍이 없어요".

## 구현 현황 (내 도메인 밖이 원인, REQ-093)

- 새 시나리오 카드 묶음에 "내 도메인 밖이 원인"(서버 메모리 불량, 스위치 포트 불량)이 더해졌다. 카드는 요약 아래에 "원인은 서버 도메인 · 내 도메인 서비스/OS·가상화 권장" 한 줄을 보인다(`domainsLine`). 에이전트 투입 블록의 제한 시간 칸은 최대 5,760분(4일)까지 받는다.

## 세 번째 검토 — 질문으로 고르고, 문장으로 읽는다 (베타 피드백 18~21)

2026-11-06, 연수 님이 편집기를 써 보고 말했다. 블록이 너무 많아 스크롤이 압도적이고 뭘 해야 할지 생각이 안 난다(18), 블록이 무조건 맨 아래에 붙는다(19), Ctrl+C/V 같은 기본 조작이 없다(20), 채점표가 표라서 이해가 안 된다(21). 첫 번째·두 번째 검토는 "말과 순서"를 고쳤고, 이번에는 **무엇을 먼저 묻고 어떻게 읽히느냐**를 고쳤다. 승인된 목업은 [편집기와 연결 목업](mockups/editor-connections-mockup.html)이다.

|---|---|---|---|
| 18 | 팔레트가 블록 50여 개를 묶음별로 쭉 펼쳤다. 처음 온 사람은 "무엇부터"를 고를 수 없다 | **질문 셋**: "어디가 고장 나나요"(고장 발생·복구, 부하·설정·전원 같은 세계 바꾸기) / "에이전트가 뭘 하면 되나요"(에이전트 투입, 대기, 조건 대기, 분기, 메모) / "어떻게 채점하나요"(진단 맞히기, 조치 기대하기, 하면 안 되는 일, 끝났을 때 상태, 빠른 진단, 툴 호출 상한). 질문을 누르면 **그 질문의 블록만** 펼쳐지고 나머지는 접힌다. 질문마다 자주 쓰는 4~6개만 보이고 "더 보기 (N)"가 나머지(고장은 설비·서버 같은 영역별)를 연다. 검색은 세 질문 전체를 본다. 처음에는 아직 답하지 않은 첫 질문이 열려 있다 | 블록의 종류(분류)로 고르게 하면 설계자의 모델을 알아야 한다. "무엇을 정해야 하나"로 고르게 하면 지금 할 일이 보인다 (Easy to Answer, One Thing) |
| 18 | 채점 블록이 캔버스에 없고 채점표 탭 안에만 있어서 세 번째 질문의 답을 찾기 어려웠다 | 세 번째 질문의 블록은 **채점표의 줄**이다. 누르면 줄이 더해지고 채점표가 열린다 | 흐름과 채점이 한 팔레트에서 이어진다 (Context Based) |
| 19 | 새 블록이 무조건 줄 끝에 붙었다. 중간에 끼우려면 끌어서 이어야 했다 | 블록을 하나 고른 상태에서 팔레트를 누르면 **그 블록 바로 뒤**에 들어가고, 원래 뒤에 있던 블록이 새 블록 뒤로 이어진다. 아래 블록은 한 칸씩 내려간다. 고른 블록이 없으면 전처럼 끝에 붙는다. 팔레트 위 글이 지금 어디에 들어가는지 말한다 | 사람이 "여기 다음에"를 먼저 생각한다 (Casual Concept) |
| 20 | 복사·붙여넣기·되돌리기가 없었다 | 아래 표의 키. 입력 칸 안에서는 그 칸의 복사·붙여넣기·되돌리기가 먼저다. 캔버스 아래에 키 안내 한 줄, 고른 블록은 파란 굵은 테두리와 `aria-current`(노드 div에는 `aria-selected`가 허용되지 않아서 바꿨다, ADR-0141), 고르면 "고른 블록: …"을 읽어 준다 | 그래프 편집기에서 기대하는 기본 조작 (Clear Action) |
| 21 | 채점표가 "항목 더하기 → 종류 고르기 → 칸 채우기"인 표였다. 점수 숫자와 조건이 따로 놀았다 | **"이 시나리오는 무엇을 보나"**. 맨 위에 합격 문장("진단을 맞히고 60점 이상이면 합격이에요", 코어의 합격선을 읽는다), 줄마다 한 문장: "60점 · 원인이 CRAH-1, 고장이 냉방기 정지라고 진단하면". 문장 안의 **숫자는 그 자리에서 고치고**, **낱말(장비·고장·조치·조건)을 누르면** 그 줄의 자세한 칸이 문장 아래에 열린다. 정답 줄은 고장 블록에서 저절로 채워지고("고장 블록에서 저절로") 사람이 고쳐서 달라지면 "고장 블록에서 다시 채우기" 버튼이 나온다. 복구 우선 채점은 "서비스를 얼마나 빨리 되살렸는지로 채점해요 — 복구 시간 35점, …", 절차서는 "절차서 N단계를 순서대로 따랐는지도 봐요 — 점수에는 섞이지 않아요"라는 문장으로 위에 붙는다. 기준 에이전트 점검 결과(변별력)는 문장들 바로 아래에 있다 | 표는 데이터를 보여 주고, 문장은 의미를 보여 준다 (Value First, Casual Concept) |

### 키

| 키 | 하는 일 |
|---|---|
| Ctrl+C | 고른 블록을 복사한다(시작 블록은 못 한다) |
| Ctrl+V | 복사한 블록을 고른 블록 바로 뒤에 붙여 넣는다. 한 번 복사한 것은 계속 붙여 넣을 수 있다. 시나리오에 한 개만 둘 수 있는 블록(에이전트 투입)은 이유를 말하고 막는다 |
| Ctrl+D | 고른 블록을 그 바로 뒤에 복제한다 |
| Delete | 고른 블록을 지우고, 앞뒤 블록을 이어 줄을 끊지 않는다(시작 블록은 못 지운다). 캔버스 안에서 이음선을 고르고 누르면 이음선만 지운다 |
| Ctrl+Z / Ctrl+Y (Ctrl+Shift+Z) | 되돌리기 / 다시 하기. 되돌려서 사라진 블록이 고른 블록이면 선택이 풀린다 |
| Ctrl+S | 저장(남의 시나리오면 내 사본으로 저장) |

복사한 블록은 시스템 클립보드가 아니라 편집기 안에 있다(블록 그대로 설정까지 갖고 있고, 글자 칸의 붙여 넣기와 섞이지 않는다). 팔레트에서 캔버스로 끌어다 놓는 것은 그대로다. 여러 블록을 한 번에 고르는 것과 화살표로 옮기기는 아직 없다.

### 재는 법

- `logic/scenario/edit.test.ts`: 끼워 넣기(중간·시작 뒤·끝, 아래 블록이 내려감, 이음 점검에 걸리지 않음), 복제·복사·붙여넣기(새 id, 같은 설정, 한 개만 둘 수 있는 블록 막기), 지우며 잇기, 질문 셋(이름, 자주 쓰는 수, 모든 블록이 한 질문에 속함, 검색), 문장(정답 줄 자동, 숫자 토큰, 감점 부호, 합격 문장, 복구·절차서 문장).
- `logic/connection-places.test.ts`의 말 검사가 질문 이름·힌트·채점 블록 이름에 용어집이 버린 말과 "~습니다"가 없는지 본다.

## 아직 안 하는 것

- 블록을 여러 개 한꺼번에 고르기와 화살표로 옮기기(피드백 20의 나머지)는 아직 없다.
- 블록을 끌어 잇는 대신 대화형(한 문장씩 묻기)으로 만드는 방식은 베타 뒤에 본다.
- 캔버스 자동 정렬은 하지 않는다. 누르면 이어 붙는 것으로 대부분의 경우가 덮인다.

시나리오 목록의 각 줄에는 "지금 방식" 링크가 있어 그 시나리오의 현재 업무 표를 적는 화면(`/scenarios/:id/process`)으로 간다 (REQ-112, [프로세스 비교](process-compare.md)).

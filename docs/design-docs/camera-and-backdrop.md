# CCTV 자리 — 카메라 개체, 보는 자리, 배경 자리

이 문서는 설계예요. 아직 구현하지 않았고 당장 만들 계획도 아니에요. 나중에 서버룸의 CCTV를 세계에 놓고, CCTV를 센서로 써서 사실적인 배경까지 만들 수 있도록 **자리만 정해 둔 것**이에요. 결정은 [ADR-0139](adr/0139-camera-view-and-backdrop-slots.md), 쌍둥이의 큰 그림은 [ADR-0095](adr/0095-digital-twin-and-model-plugins.md), 모델 자리의 틀은 [물리 법칙이 닿는 자리와 모델 자리](physics-laws.md)예요.

## 한 줄로

카메라는 세계의 장비 하나예요. "카메라가 무엇을 보는가"와 "방이 어떻게 생겼는가"를 갈아 끼울 수 있는 자리 둘로 두면, 같은 세계가 시뮬레이션에서는 우리가 그린 그림으로, 쌍둥이에서는 진짜 CCTV 화면으로 돌아가요.

## 자리는 셋이에요

| 자리 | 무엇인가 | 기본 | 갈아 끼우면 |
|---|---|---|---|
| 카메라 개체 `camera` | 방 안에 놓인 장비. 위치·방향·화각이 있고 전원과 네트워크를 먹어요 | 없음(놓아야 생김) | 현실의 카메라 목록을 그대로 놓음 |
| 보는 자리 `sense.camera` | 카메라 하나가 지금 보는 것: 그림 한 장 + 읽어 낸 사실 | 세계 상태를 그 카메라 시점에서 그린 그림 | 올린 사진 위에 상태를 덧그림 → 진짜 CCTV 스냅샷 |
| 배경 자리 `scene.backdrop` | 3D에서 방 하나의 겉모습 | 지금의 코드로 그린 도형 | CCTV 사진을 표면에 입힘 → 한 번 스캔한 사실적 배경 |

세 자리는 서로 독립이에요. 카메라만 놓고 그림은 기본으로 써도 되고, 카메라 없이 스캔 배경만 끼워도 돼요.

## 1. 카메라 개체

### 놓기
- 종류 `camera`. 방 안의 좌표(m), 높이, 좌우·상하 각도, 화각, 해상도, 적외선 여부가 속성이에요.
- 네트워크 링크로 스위치에 연결돼요(PoE). **스위치나 전원이 죽으면 카메라도 꺼져요.** 물리와 모순되지 않게 기존 전원·네트워크 규칙을 그대로 따라요.
- 직접 짓기의 "놓기"에 CCTV가 생겨요. 세계를 자동으로 만들 때는 통로 양 끝과 문 위에 하나씩 놓아요.

### 시야 (코드로 계산)
- 카메라마다 **보이는 범위**를 계산해요: 화각 안에 있고 랙에 가려지지 않은 랙 앞면·통로·문·바닥.
- 방마다 **사각지대**(어느 카메라에도 안 보이는 랙)가 나와요. 직접 짓기에서 "이 방의 랙 24대 중 21대가 보여요"로 보여 줘요.
- 규칙 하나: **카메라는 시야 안의 것만 알려 줄 수 있어요.** 보는 자리가 무엇이든 시야 밖의 사실은 나오지 않아요.

### 상태와 고장
| 상태 | 뜻 |
|---|---|
| `online` | 켜져 있고 그림이 옴 |
| `lastFrameT` | 마지막 그림의 시각(시뮬레이션 시계) |
| `obscuredPct` | 가려진 정도 |

| 고장 | 증상 | 고치는 길 |
|---|---|---|
| 카메라 꺼짐 | 그림이 안 옴 | 전원·포트 확인, 재시작 |
| 렌즈 가림·오염 | 그림이 뿌옇거나 일부만 보임 | 현장 방문(물리) |
| 방향 틀어짐 | 엉뚱한 곳을 봄, 시야가 바뀜 | 현장 방문(물리) |
| 방 조명 꺼짐 | 적외선 없는 카메라는 캄캄함 | 조명 켜기 |
| 시각 어긋남 | 그림의 시각이 실제와 다름 | 시각 동기화 |

## 2. 보는 자리 `sense.camera`

### 계약
```
입력  = 카메라, 시각
출력  = 그림 한 장(PNG) + 읽어 낸 사실 목록
사실  = { 대상 개체, 무엇(표시등 색·문 열림·사람 있음·바닥의 물·연기), 값, 믿는 정도, 출처 }
규칙  = 시야 밖의 사실은 내지 않음. 꺼진 카메라는 아무것도 내지 않음
```

### 세 깊이
| 깊이 | 그림은 어디서 | 쓰는 곳 |
|---|---|---|
| ① 기본: 그린 그림 | 서버가 세계 상태를 그 카메라 시점에서 그려요. 표시등 색, 열린 문, 사람, 바닥의 물, 연기, 어둠이 보여요 | 모든 실험 |
| ② 사진 위에 덧그림 | 카메라마다 올린 실제 사진 한 장(사람 없는 빈 방)을 바탕으로 깔고, 달라지는 상태만 ①의 방식으로 덧그려요 | 실험(사실적인 그림이 필요할 때) |
| ③ 진짜 스냅샷 | 커넥터가 현실 CCTV에서 스냅샷을 읽어 와요(읽기 전용). 비전 모델이 사실을 읽어 내요 | 쌍둥이(거울 단계)만 |

### 채점을 지키는 규칙 (가장 중요)
제품 목표의 3번(같은 답안은 같은 점수)이 여기서도 이겨요.

- **실험에서는 ①과 ②만 써요.** 둘 다 "세계 상태 → 그림"의 순수 함수라서 같은 상태는 같은 그림이에요.
- **그림은 서버가 그려요.** 브라우저의 3D는 그래픽 카드마다 픽셀이 달라요. 에이전트에게 주는 그림은 서버의 소프트웨어 그리기(그래픽 카드 없이, 같은 입력에 같은 바이트)로 만들어요. 화면의 3D와 닮았지만 같은 코드가 아니에요.
- **준 그림은 실험 기록에 남아요.** 다시 채점은 기록을 읽어요.
- **진짜 스냅샷(③)으로 실험하려면 녹화해서 써요.** 스냅샷 묶음을 시나리오에 붙이면 고정된 입력이 되어 다시 돌릴 수 있어요. 살아 있는 CCTV는 순위 실험에 못 써요.
- **비전 모델의 판독은 세계를 바로 바꾸지 않아요.** 쌍둥이에서 카메라가 읽은 사실이 계측값과 다르면 "불일치" 사건으로 남겨요(예: 센서는 정상인데 표시등이 주황). 어느 쪽이 맞는지는 사람이나 에이전트가 판단해요.

### 에이전트 툴
| 툴 | 돌려주는 것 |
|---|---|
| `list_cameras(방)` | 카메라 목록, 켜짐 여부, 각자 보이는 랙 |
| `camera_snapshot(카메라)` | 그림 한 장, 시각, 보이는 범위. 읽기 전용, 다른 툴처럼 시뮬레이션 30초 |

- 툴 결과에 그림을 실을 수 있어야 해요. 지금 툴 결과는 JSON뿐이라 **그림 한 종류를 더하는 것**이 계약 변경이에요. 그림을 못 받는 에이전트에게는 같은 내용의 사실 목록을 글로 줘요.
- 시나리오의 "툴로 단서에 닿는가" 검사에 카메라가 들어가요. 그림으로만 알 수 있는 단서(센서는 정상인데 표시등이 주황, 문이 열려 있음, 바닥에 물)를 가진 시나리오를 만들 수 있어요. 그림을 보고 판단하는 에이전트를 평가하는 길이에요.

## 3. 배경 자리 `scene.backdrop`

방 하나의 겉모습을 바꾸는 자리예요. 개체와 상태는 그대로이고 **보이는 껍질만** 달라져요.

### 세 깊이
| 깊이 | 무엇 | 필요한 것 | 살아 있나 |
|---|---|---|---|
| ① 기본 | 코드로 그린 도형 | 없음 | 상태에 따라 늘 바뀜 |
| ② CCTV 사진을 표면에 입힘 | 카메라의 사진을 그 카메라 위치에서 빔프로젝터처럼 벽·바닥·랙 앞면에 비춤 | 카메라 위치 맞추기(아래), 사진 여러 장 | 주기적으로 새 사진으로 갈 수 있음 |
| ③ 스캔 배경 | 방을 한 번 걸으며 찍어 만든 사실적 3D(점 구름·메시 파일) | 스캔 파일, 좌표 맞추기 | 찍은 날에 멈춤("2026-10 스캔" 표시) |

### 왜 ②가 되나: 구조를 이미 알기 때문이에요
세계에는 랙·벽·바닥의 위치와 크기가 이미 있어요(쌍둥이 ①단계, 구조). 그래서 사진에서 입체를 새로 복원할 필요 없이 **아는 모양 위에 사진을 입히기만** 하면 돼요.

- **카메라 맞추기**: 사진 속의 점 네 개 이상(랙 모서리)을 세계의 좌표와 짝지으면 카메라의 정확한 위치·방향이 나와요. 짝짓기는 화면에서 클릭으로 해요.
- **사람 지우기**: 같은 카메라의 사진 여러 장에서 픽셀마다 가운데 값을 쓰면 지나가던 사람은 사라지고 빈 방만 남아요. 배경에는 사람이 원래 없어요.
- **안 보이는 면**: 어느 카메라에도 안 보이는 면은 기본 도형으로 남고 옅은 빗금으로 "안 보임"을 알려요. 지어내지 않아요.

### 상태는 껍질 위에 얹어요
- 배경이 사실적일수록 고장이 눈에 덜 띄어요. 그래서 상태(정상·경고·위험)는 지금처럼 개체의 윤곽선과 색 띠로 **배경 위에** 그려요.
- 클릭과 선택은 보이지 않는 논리 개체(상자)가 받아요. 배경은 그림일 뿐이에요.
- 배경과 세계가 어긋나면(랙이 옮겨졌는데 스캔은 옛것) 어긋난 개체에 "배경과 다름" 표시가 붙어요. 쌍둥이는 자기 오차를 늘 말해요(ADR-0095).

## 보안과 사람 (자리의 일부로 설계)

| 항목 | 규칙 |
|---|---|
| 방향 | 현실 CCTV는 읽기만 해요. 카메라를 돌리거나 설정을 바꾸지 않아요 |
| 머무는 곳 | 그림은 테라리움 서버 밖으로 나가지 않아요. 등록된 모델에게 그림을 보낼지는 세계마다 켜고 꺼요 |
| 사람 | 저장하거나 보여 주기 전에 사람을 가려요(기본 켜짐). 배경은 사람이 지워진 것만 써요 |
| 보관 | 스냅샷 보관 기간을 세계마다 정해요. 기본은 실험 기록에 든 것만 |
| 기록 | 누가 어느 카메라를 봤는지 남겨요(권한·감사 설계와 같은 장부) |

## 지금 지켜 둘 것 (나중에 싸게 만들려면)

지금 만들지 않아도 아래 넷은 다른 작업에서 깨지 않아요.

1. **좌표는 미터이고 개체 ID는 안 바뀐다.** 카메라 맞추기와 배경 맞추기가 여기에 기대요(ADR-0088).
2. **툴 결과에 그림을 더할 수 있게 둔다.** 툴 결과의 모양을 바꿀 때 "JSON만"을 전제로 굳히지 않아요.
3. **3D의 방은 껍질과 논리 개체가 나뉜다.** 방의 겉모습을 그리는 코드와 클릭·상태를 받는 코드를 섞지 않아요.
4. **종류 이름 `camera`, 자리 이름 `sense.camera`·`scene.backdrop`을 비워 둔다.**

## 만드는 순서 (요구가 확정되면)

| 단계 | 내용 | 어디에 쓰나 |
|---|---|---|
| A | 카메라 개체, 놓기, 시야·사각지대, 고장, 서버가 그리는 그림(①), 툴 둘, 그림 단서 시나리오 | 그림을 보는 에이전트의 평가. 현실 연결 없이 가치가 있음 |
| B | 사진 위에 덧그림(②), 카메라 맞추기 화면 | 사실적인 그림으로 실험 |
| C | 배경 자리: CCTV 사진 입히기(②), 스캔 파일(③), 좌표 맞추기, "배경과 다름" | 사실적인 3D |
| D | 진짜 CCTV 커넥터(읽기 전용), 비전 판독, 불일치 사건, 스냅샷 녹화 | 쌍둥이의 거울 단계 |

A는 시뮬레이션만으로 닫히고, B~D는 현실의 사진이 있어야 해요.

## 하지 않는 것

- 동영상 스트림을 실시간으로 3D에 틀지 않아요. 스냅샷(정지 그림)만 다뤄요.
- 고정 CCTV만으로 방의 입체를 복원하지 않아요. 각도가 모자라 품질이 낮아요. 입체는 세계의 구조에서 오고, 사진은 그 위에 입혀요.
- 카메라가 읽은 사실로 세계를 조용히 고치지 않아요. 불일치로 남겨요.
- 사람을 알아보지 않아요(누구인지). "사람이 있다"까지만 읽어요.

## 시험 (만들 때)

| 시험 | 내용 |
|---|---|
| 시야 | 랙 뒤의 랙은 안 보이고, 방향이 틀어지면 시야가 바뀐다. 보는 자리가 시야 밖의 사실을 내면 실패 |
| 물리 | 스위치나 전원이 죽으면 카메라가 꺼지고 그림이 안 온다 |
| 결정성 | 같은 세계 상태의 그림은 바이트까지 같다(서버 그리기). 그림을 쓴 실험의 다시 채점이 같다 |
| 단서 | 그림 단서 시나리오에서 정답 풀이가 카메라 툴을 거쳐 100점이다(REQ-110) |
| 사람 | 사람이 든 사진 묶음으로 만든 배경에 사람이 없다 |
| 불일치 | 계측값과 다른 판독은 세계 상태를 바꾸지 않고 사건으로 남는다 |

# 표준 모델 대조 (REQ-115·117 예정, ADR-0157)

현실의 데이터를 받는 모델이 한 회사 제품의 말에 묶이지 않게, 층마다 공개된 표준에서 뼈대를 빌려와요. 아직 만들지 않았어요. 아래 짝은 방향이고, 만들 때 각 표준 문서와 하나씩 대조해 확정해요.

## 원칙

1. **통째로 따르는 표준은 없어요.** 층마다 개체와 관계의 모양을 빌려올 표준을 하나씩 정해요.
2. **종류의 뜻은 플랫폼 중립이에요.** VMware, OpenStack, 그 밖의 가상화 플랫폼이 같은 종류로 들어와요. 플랫폼이 늘면 모델이 아니라 대응 표의 열이 늘어요.
3. **플랫폼 대응은 데이터예요.** 프리셋이 들고 있고 판이 있어요.

## 종류는 세 층이에요

| 층 | 무엇 | 시뮬레이션 | 영향 범위 |
|---|---|---|---|
| 시뮬레이션 핵심 종류 | 지금의 62종류. 물리·고장·툴이 붙어 있어요 | 해요 | 들어가요 |
| 현실 표준 종류 | 테라리움이 내놓는, 표준에 맞춘 종류. 포트, 포트 묶음, BGP 세션, 가상 스위치, 가상 라우터, 가상 포트, 서브넷, 볼륨 붙임, 기타 실장 장비(모델에 없는 장비의 자리와 전력) 같은 것 | 몰라요 | 들어가요(뜻을 테라리움이 정해요) |
| 사용자가 만드는 종류 | 기록만 되는 종류 (제안 단계, ADR-0150) | 몰라요 | 안 들어가요 |

현실 표준 종류는 실험 세계로 떠낼 때 시뮬레이터가 아는 것으로 접히거나(포트 → 스위치의 설정) "시뮬레이션이 모르는 것"으로 보고돼요(ADR-0156 9번).

## 층마다 빌려오는 뼈대

| 층 | 표준 | 가져오는 것 |
|---|---|---|
| 건물·공조 | Brick | 설비와 공간의 종류, "공급한다" 관계 |
| 서버 하드웨어·전원·열 | DMTF Redfish | 섀시·전원·열의 자원과 속성 이름 |
| 랙·실장·케이블 | NetBox의 모델 | 사이트·랙·장비·인터페이스·케이블의 모양 |
| 네트워크 토폴로지 | IETF RFC 8345 | 망·노드·링크·종단점(포트), 층을 겹치는 방법(아래 층의 무엇 위에 있는가) |
| L2 | IETF RFC 8944 | 종단점의 인터페이스 이름·VLAN·VXLAN, **포트 묶음(LAG)과 그 구성 종단점** |
| L3 | IETF RFC 8346 | 라우터 ID, 프리픽스 |
| 프로토콜 구성 | OpenConfig | 인터페이스·묶음(LACP)·BGP 이웃의 구성 모양 |
| 가상화(컴퓨트·가상 네트워크·가상 스토리지) | DMTF CIM의 가상 시스템 모델 | 호스트와 가상 시스템의 관계, 자원 풀과 거기서 나눠 받기 |
| 스토리지 | SNIA Swordfish | 풀과 볼륨 |
| 컨테이너 | 쿠버네티스 API | 클러스터·노드·워크로드 |
| 서비스·앱 | TOSCA, ServiceNow CSDM(참고) | 앱과 서비스의 층, 서비스가 무엇에 얹히는가 |
| 출처·조직·프로세스 | W3C PROV-O, W3C ORG, BPMN 용어 | 출처, 팀과 역할, 활동 |

## 관계의 말은 TOSCA에 맞춰요

관계 표(ADR-0144 11번)의 "뜻의 갈래"를 TOSCA의 관계 종류와 짝지어요. 다른 도구와 주고받을 때 같은 말이 돼요.

| 테라리움의 갈래 | TOSCA | 예 |
|---|---|---|
| 위에서 돈다 | HostedOn | VM → 호스트, 서비스 → VM |
| 필요하다 | DependsOn | 서비스 → DB |
| 이어진다·호출한다 | ConnectsTo | 서버 포트 → 스위치 포트, 서비스 → 서비스 |
| 붙는다 | AttachesTo | 볼륨 → VM |
| 묶인다 | (짝 없음. RFC 8944의 묶음 구성원, CIM의 구성 관계를 따라요) | 호스트 → 클러스터, 링크 → 포트 묶음 |
| 공급받는다 | (짝 없음. Brick의 "공급한다"를 따라요) | 랙 → PDU, 방 → 냉방기 |

## 가상화 플랫폼 대응

| 중립 뜻 | 테라리움의 종류 | VMware | OpenStack |
|---|---|---|---|
| 가상화 관리자 | `vcenter`(핵심) | vCenter Server | 리전의 제어부 |
| 호스트 | `server`(핵심) | 호스트(ESXi) | 하이퍼바이저(컴퓨트 호스트) |
| 호스트 무리 | `cluster`(핵심) | 클러스터 | 가용 영역(자동 재배치는 모름), 인스턴스 HA 구역(자동 재배치 켜짐) |
| 호스트의 꼬리표 | 속성 | 태그, 사용자 지정 속성 | 호스트 애그리거트 |
| 가상 머신 | `vm`(핵심) | 가상 머신 | 서버(인스턴스) |
| 가상 스위치 | 현실 표준 종류 | 분산 스위치, 표준 스위치 | (통합 브리지. 보통 드러나지 않아요) |
| 가상 네트워크 | `overlay_segment`(핵심) | 분산 포트 그룹, NSX 세그먼트 | 네트워크 |
| 서브넷 | 현실 표준 종류 | 세그먼트의 서브넷 | 서브넷 |
| 가상 포트 | 딸린 것(ADR-0156). 갈래와 "아래 포트"를 적어요(ADR-0161 12번) | VM의 가상 NIC, 분산 포트 | 포트 |
| 가상 라우터 | 현실 표준 종류 | NSX의 라우터(Tier-0·Tier-1) | 라우터 |
| 보안 규칙 | `network_policy`(핵심) | 분산 방화벽 규칙 | 보안 그룹 |
| 스토리지 풀 | `datastore`(핵심) | 데이터스토어(VMFS·NFS·vSAN) | 블록 스토리지의 백엔드·풀 |
| 가상 디스크 | `volume`(핵심) | 가상 디스크 | 볼륨 |

- `vcenter`라는 종류 이름은 그대로 둬요(바꾸면 시뮬레이터와 툴이 깨져요). 종류의 뜻을 "가상화 관리자"로 정하고 화면과 문서에서 그렇게 불러요.
- 호스트 애그리거트는 호스트 하나가 여럿에 들고 "고장 나면 여기서 다시 뜬다"는 뜻이 없어서 `cluster`가 아니에요(ADR-0161 13번, 처음에는 `cluster`에 맞춰 뒀다가 견본 시험에서 고쳤어요).
- 클라우드는 이 둘이에요. 다른 플랫폼이 정해지면 이 표에 열로 더해요. 열을 더할 때 중립 뜻에 맞지 않는 것이 나오면 그때 종류를 고쳐요(종류를 플랫폼에 맞추지 않아요).
- 이 표의 VMware·OpenStack 칸은 설계 담당이 아는 대로 적은 것이고, 만들 때 각 제품의 문서와 대조해요.

## 쿠버네티스와 VDI 대응 (ADR-0164)

쿠버네티스는 VMware의 것도 쿠버네티스 API의 모양으로 받아요.

| 중립 뜻 | 테라리움의 종류 | 쿠버네티스 (VMware의 것 포함) |
|---|---|---|
| 클러스터 | `k8s_cluster`(핵심) | 클러스터. VMware에서는 워크로드 클러스터 |
| 클러스터를 다스리는 클러스터 | `k8s_cluster` + "다스린다" 관계 | VMware의 관리 클러스터 |
| 노드 | `k8s_node`(핵심) | 노드 |
| 노드가 얹힌 곳 | "위에서 돈다" 관계 | 노드가 VM이면 그 VM(키 맞추기), 아니면 서버 |
| 워크로드 | `k8s_workload`(핵심) | 디플로이먼트, 스테이트풀셋 같은 것 |

VDI는 새 종류 없이 서비스 층으로 받아요.

| 중립 뜻 | 테라리움의 종류 | Citrix | VMware Horizon |
|---|---|---|---|
| VDI 서비스 | `service`(핵심) | 사이트 | 포드 |
| 데스크톱 풀 | `service`(핵심), 구성원은 "수로 말하는 묶음" | 딜리버리 그룹(머신 카탈로그에서 나옴) | 데스크톱 풀, 팜 |
| 데스크톱 | `vm`(핵심) | 데스크톱 머신 | 데스크톱 머신 |
| 브로커 | `app_instance`(핵심) | 딜리버리 컨트롤러 | 커넥션 서버 |
| 바깥 문 | `app_instance`(핵심) | 게이트웨이, 스토어프런트 | 게이트웨이 |

- 노드와 VM을 잇는 선이 있어야 설비에서 시작한 영향 범위가 호스트 → VM → 노드 → 워크로드로 이어져요.
- 풀은 "몇 개가 살아야 하나"가 없는 묶음이에요. 데스크톱 하나가 사용자 한 명이라서 영향을 수로 말해요("데스크톱 240대 중 60대").
- 이 두 표의 제품 칸도 설계 담당이 아는 대로 적은 것이고, 만들 때 각 제품의 문서와 대조해요.

## 시험 (만들 때)

| 시험 | 내용 |
|---|---|
| 짝 | 모든 종류와 관계 종류에 표준의 짝이 있거나 "짝 없음"과 이유가 적혀 있다 |
| 중립 | 플랫폼 대응 표의 모든 줄이 중립 뜻 하나를 가리키고, 한 플랫폼에만 있는 종류가 없다(있으면 이유가 적혀 있다) |
| 같은 세계 | 같은 구성을 VMware 모양과 OpenStack 모양의 지어낸 데이터로 넣으면 같은 종류·같은 관계의 세계가 된다 |
| 영향 | 현실 표준 종류를 지나가는 영향 범위가 처음부터 다시 따진 답과 같다(ADR-0156 6번) |

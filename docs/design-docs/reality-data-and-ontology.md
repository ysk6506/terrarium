# 현실 데이터와 모델

이 문서는 설계예요. 아직 구현하지 않았어요. 결정은 [ADR-0144](adr/0144-reality-data-pipeline-ontology-manager-world-kinds.md)예요. 앞선 결정은 [ADR-0084](adr/0084-topology-view.md)(가져오기를 다시 여는 조건), [ADR-0088](adr/0088-data-reuse.md)(불변 기록·버전·출처), [ADR-0095](adr/0095-digital-twin-and-model-plugins.md)(쌍둥이 네 단계)예요. 쓰는 말은 [데이터 용어집](glossary-data.md)을 따라요.

## 한 줄로

모델은 하나, 세계는 두 종류(현실 세계와 실험 세계), 데이터가 들어오는 길은 네 단(연결 → 수집 → 온톨로지 매니저 → 적용)이에요. 커넥터를 많이 만들지 않고 몇 개의 범용 커넥터 위에 프리셋을 쌓아요. 고가용성은 "누가 여기에 기대는가"가 생기는 단계에 맞춰 올려요.

## 전제

- 사내의 다른 온톨로지·로더 프로젝트는 설계에 넣지 않아요. 객체·링크·프로세스 모델을 가진 곳은 테라리움 하나예요.
- FalkorDB 연동은 없애요. 현실을 읽는 창(`sources/realimport`의 읽기 전용 포트)과 빈 곳 채우기·보고서는 남겨 새 파이프라인의 뼈대로 써요.
- 제품 목표(ADR-0138)의 3번, 채점이 늘 맞고 같다는 것이 이 설계에서도 이겨요.

## 1. 세계는 두 종류, 만들 때 정해져요

| | 실험 세계 | 현실 세계 |
|---|---|---|
| 상태가 어디서 오나 | 물리·고장·시나리오 | 현실 소스의 동기화 |
| 몇 개 | 많음, 쓰고 버림 | 현실 환경마다 하나 |
| 무엇을 할 수 있나 | 고장 넣기, 에이전트 실험, 채점, 가지치기, 빨리 감기 | 보기, 이력, 실험용 복사본 만들기 |
| 무엇을 못 하나 | 현실과 이어지지 않음 | 고장 넣기·시뮬레이션·에이전트 실험 |
| 지켜야 하는 것 | 결정성 | 잃지 않기, 출처, 권한, 감사 |

- **바뀌지 않아요.** 실험 세계가 현실 세계로 "전환"되지 않고, 현실 세계 안에서 실험하지도 않아요. 종류는 만들 때 정해지는 속성이에요.
- **길은 한 방향이에요.** 현실 세계의 어느 시각을 골라 복사해서 실험 세계를 만들어요(실험용 복사본). 실험 세계에서 일어난 일은 현실 세계로 돌아가지 않아요.
- **현실에 쓰지 않아요.** 테라리움은 현실 소스를 읽기만 해요. 쓰는 메서드가 포트에 없어요.
- **이름.** 이미 있는 "운영 모드"(끝이 없는 실험, REQ-090)와 섞이지 않게 새 종류는 "현실 세계"라고 불러요.

## 2. 평면 둘, 서로 닿지 않아요

| | 현실 평면 | 실험 평면 |
|---|---|---|
| 담는 것 | 연결, 원본 데이터셋, 매핑, 현실 세계와 이력 | 실험 세계, 실행, 채점, 벤치마크 |
| 저장소 | 따로(아래 6절) | 지금의 저장소 |
| 워커 | 동기화 워커 | 실험 워커 |
| 에이전트 | 닿을 수 없음 | 자기 실험 세계의 툴만 |

- 실험받는 에이전트와 하네스는 현실 평면의 API·저장소·자격 증명에 닿을 길이 없어요. 복사한 실험 세계만 봐요.
- 동기화가 실험 부하에 밀리지 않고 실험이 동기화에 밀리지 않게 워커 풀을 나눠요.
- 현실 세계에서 복사한 실험 세계는 원본의 권한과 등급을 물려받고, 복사할 때 이름 가리기를 고를 수 있어요(ADR-0088).
- 현실 평면은 설정으로 켜요. 기본은 꺼짐이고, 꺼져 있으면 지금의 테라리움과 같아요.

## 3. 데이터가 들어오는 길은 네 단이에요

소스를 잇는 일과 모델에 맞추는 일을 나누고, 그 사이에 원본 데이터셋을 둬요.

**사용자가 보는 층은 넷이에요(ADR-0165).** 층마다 화면과 저장되는 것과 버전이 따로 있어요. 뒤의 세 층이 온톨로지 매니저예요.

| 층 | 하는 일 | 저장되는 것 |
|---|---|---|
| 소스 | 잇고, 가져오고, 주기를 정해요 | 연결, 원본 데이터셋 |
| 정제 | 데이터셋을 다듬어 새 데이터셋을 만들어요(정제 연산 여덟 가지) | 정제한 데이터셋과 계보 |
| 온톨로지 매핑 | 어느 데이터셋이 어느 객체 타입이 되는지 정해요 | 객체 타입마다의 매핑 |
| 링크 정의 | 객체 타입 사이의 링크를 어떤 조건으로 만들지 정해요 | 링크 타입마다의 정의 |

아래 그림의 "온톨로지 매니저" 단이 정제·온톨로지 매핑·링크 정의 세 층이에요.

```
연결 ──▶ 수집 ──▶ [원본 데이터셋 저장] ──▶ 온톨로지 매니저 ──▶ [변경 목록] ──▶ 적용 ──▶ 세계
(어디에 어떻게)  (그대로 가져옴)        (정제 → 매핑 → 링크 정의)                 (세계와 이력)
```

| 단 | 아는 것 | 모르는 것 | 내놓는 것 |
|---|---|---|---|
| 연결 | 소스의 종류·주소·자격 증명 | 모델 | 닿는지, 무엇이 있는지 |
| 수집 | 소스의 테이블·경로·페이지 | 모델 | 원본 데이터셋의 스냅샷(고치지 않음, 시각·해시) |
| 온톨로지 매니저 | 모델, 컬럼과 속성의 매핑 | 소스에 닿는 법 | 객체·링크의 변경 목록과 문제 보고 |
| 적용 | 세계 | 소스 | 세계의 새 상태와 이력 |

나누면 얻는 것:
- 정제·매핑을 고쳐도 소스를 다시 긁지 않아요. 원본 데이터셋에서 다시 돌려요.
- 소스가 죽어도 마지막으로 받은 것으로 세계가 서 있어요.
- 소스의 컬럼이 바뀌면(스키마 변경) 수집은 되고 매핑에서 멈춰 알려요. 조용히 틀린 값이 세계에 들어가지 않아요.
- 속성 하나가 어느 소스의 어느 컬럼에서 언제 왔는지 끝까지 따라가요.

### 매핑: 데이터셋의 컬럼을 객체의 속성에

객체 타입마다 선언하는 데이터예요. 코드가 아니에요.

| 항목 | 내용 |
|---|---|
| 소스 | 이 타입이 오는 데이터셋(하나 이상) |
| 키 | 바뀌지 않는 ID가 되는 컬럼. 없으면 컬럼 여럿을 묶은 복합 키. 어떤 범위 안에서만 유일하면(랙 이름은 방 안에서) 범위를 넣은 복합 키 |
| 객체 수 | 행마다 하나, 또는 값마다 하나(방·열·랙처럼 다른 데이터셋의 컬럼으로만 나오는 것. 키가 겹치는 게 정상이고, 행 사이에 속성이 어긋나면 문제) |
| 타입 나누기 | 한 데이터셋에 여러 타입이 섞이면 필터와 코드 매핑으로 나눔. 코드 매핑에 없는 값은 목록으로 |
| 속성 | 컬럼 → 속성. 형 변환, 단위 변환, 기본값. 안 쓰는 컬럼은 "버림"으로 적음 |
| 링크 | 참조 컬럼 → 링크(예: 서버 데이터셋의 랙 이름 → 랙에 설치됨) |
| 중복 병합 | 같은 키가 여러 소스에 있으면 속성마다 어느 소스가 우선인지 |
| 출처 | 속성마다 소스·컬럼·받은 시각 |

미리보기는 처음 몇 행과 문제를 보여 줘요: 매핑 안 된 컬럼, 필수 속성 없음, 끊어진 참조, 키 중복, 범위를 벗어난 값. **합계도 보여 줘요**: 받은 행 수 = 객체가 된 행 + 링크가 된 행 + 문제 목록 + 어느 매핑·링크 정의에도 쓰이지 않은 행(미사용 행, ADR-0161 7번). 시뮬레이션에 필요한데 소스에 없는 것(전원·냉방 경로)은 가정으로 채우고 무엇을 가정했는지 보고해요. 이름이 비슷한 컬럼은 매핑을 제안하고, 모델이 등록돼 있으면 이끼가 제안을 설명해요. 정하는 것은 사람이에요.

### 현실에서 만들 때는 순서가 거꾸로예요

지어내는 세계는 위에서 아래로 가요: 서비스 → 아키텍처(사다리) → 크기 → 생성. 의미(이중화, 자동 재배치, DR)를 먼저 정하고 장비가 따라 나와요. 현실에서 만드는 세계는 아래에서 위로 가요. 있는 것이 먼저 들어오고 의미는 나중에 채워져요.

| 순서 | 하는 일 | 어디서 오나 |
|---|---|---|
| 1 | 있는 것: 장비·VM·위치·케이블 | 소스(매핑) |
| 2 | 구성: 클러스터의 HA·자동 재배치, 복제 방식, 다중 경로, 복제본 수 | 소스에 있으면 읽음. 모델에서는 객체의 속성과 링크의 역할이라 다른 속성과 같은 길로 들어와요 |
| 3 | 모양 알아보기: 사다리를 거꾸로 돌려 층마다 "이 세계는 이 칩으로 보여요"와 근거를 냄 | 코드(1·2에서 계산) |
| 4 | 빈 곳 채우기: 서비스가 어느 VM들인지, 무엇이 무엇에 기대는지, DR 계획과 목표 시간, 전원 A·B 경로, 담당 팀 | 사람이 아는 것. 링크를 직접 긋지 않고 데이터셋(소스)으로 넣어요 |
| 5 | 확인: 가정 보고서, 법칙 검사, 정답 풀이 검증 | 코드 |

- **모델과 말은 하나예요.** 두 길은 같은 세계 모델과 같은 사다리 칩에서 만나요. 현실 쪽 전용 빌더를 따로 두지 않고, 사다리 화면을 "읽기"로 다시 써요(칩 + 근거 + 모름).
- **모르는 것은 "모름"이에요.** 확인되지 않은 이중화를 있다고 치지 않아요. 있다고 치면 현실에는 없는 자동 복구가 실험에서 일어나 세계가 거짓말을 해요. 없다고 치지도 않아요. "모름"으로 두고 실험 전에 정하게 해요.
- **세계의 상태는 둘이에요.** 1~3까지면 "구조만 있는 세계"(보기·토폴로지·영향 범위). 4·5가 끝나면 "실험할 수 있는 세계". 무엇이 모자라 실험을 못 하는지 목록으로 보여 줘요.
- **알아본 칩을 고치는 것은 바로잡기예요.** 현실을 적은 것이므로 이유와 함께 남겨요. 복사한 실험 세계에서는 칩을 자유롭게 바꿔요("이 클러스터에 자동 재배치를 켜면?"). 이것이 실험용 복사본의 쓸모예요.

## 4. 커넥터: 많이 만들지 않아요

수백 종의 전용 커넥터는 만들지도 지키지도 못해요. 커넥터는 소스의 API가 바뀔 때마다 낡아요. 관리하기 쉬움은 커넥터 수가 아니라 아래 표의 아래쪽 줄에서 나와요.

| 층 | 내용 | 수 |
|---|---|---|
| 범용 커넥터 | 파일(CSV·엑셀·JSON. 헤더 행 범위·병합된 셀·데이터가 끝나는 곳을 읽기 설정으로), HTTP(인증·페이지네이션·JSON 경로로 뽑기·연쇄 요청: 앞 데이터셋의 행마다 요청하고 요청에 쓴 값을 컬럼으로 붙임), SQL, 푸시 수집(받는 주소·파일 놓는 곳) | 4 |
| 프리셋 | 범용 커넥터 위의 설정 모음: 요청 방법 + 정제 + 매핑. 코드가 아니라 데이터. Redfish, vCenter, vROps, NetBox, 쿠버네티스 API, SNMP처럼 테라리움이 이미 말을 아는 것부터 | 늘어남 |
| 생태계 | 공개된 커넥터 규약을 따르는 바깥 커넥터를 돌리는 범용 커넥터 하나. 필요가 확인되면 | 나중 |

- 프리셋은 "이 소스를 고르면 매핑이 미리 채워져 있다"는 경험을 줘요. 모델과 표준의 매핑이 있어서(5절) 표준을 따르는 소스의 프리셋은 싸요.
- 푸시 수집은 이미 다른 수집 도구가 있는 조직의 길이에요. 그 도구가 파일이나 주소로 넣어 주면 수집 단을 건너뛰고 원본 데이터셋부터 시작해요.
- 연결마다 보이는 것: 닿는지, 마지막 수집 시각과 건수, 스키마 변경, 자격 증명 만료, 이 소스를 쓰는 속성 수.

### 전용 커넥터가 푸는 것과 못 푸는 것

전용 커넥터는 **가져오는 일**(인증, 페이지네이션, 바뀐 것만 받기)을 풀어요. **의미를 맞추는 일**은 못 풀어요. 커넥터가 수백 종인 제품도 커넥터는 원본을 내려놓을 뿐이고, 모델에 닿기 전에 정제하는 단이 따로 있어요. 테라리움도 같아요. 정제는 온톨로지 매니저의 첫 층이고 화면에서도 따로 보여요: **정제 → 매핑(객체) → 링크 정의**.

다른 점은 정제를 작게 두는 거예요. 목적지가 정해져 있기 때문이에요. 아무 업무나 담는 모델이 아니라 IT 인프라의 정해진 타입이라서, 정제는 "서버에는 이름·랙·위치·전력이 필요해요. 어느 컬럼이에요?"처럼 목적지에서 거꾸로 물어요.

| 소스 | 길 | 사용자가 하는 일 |
|---|---|---|
| 구조가 정해진 것(vCenter, Redfish, NetBox, 쿠버네티스 API …) | 프리셋 = 요청 방법 + 정제 + 매핑이 미리 채워짐 | 주소와 자격 증명만 |
| 조직마다 다른 것(엑셀 대장, 자체 CMDB, 사내 포털) | 범용 커넥터 + 프로파일 보기 + 제안 | 정제와 매핑을 확인하고 고침 |

프리셋은 테라리움이 이미 흉내 내는 말(파사드)부터 만들어요. 그러면 **왕복 시험**이 돼요: 세계 → 파사드 → 프리셋으로 다시 읽기 → 같은 세계. 프리셋이 맞는지를 현실 장비 없이 늘 확인해요.

### 소스의 역할은 셋이에요

| 역할 | 답하는 물음 | 쓰는 곳 | 예 |
|---|---|---|---|
| 구성 | 무엇이 있고 어떻게 이어졌나 | 세계를 만들어요 | vROps(자원과 부모·자식), CloudVision(스위치와 이웃), Cisco NSO(장비·인터페이스·VLAN·BGP 이웃), Zabbix의 호스트·그룹·인터페이스 |
| 사건 | 과거에 무슨 일이 있었나 | 과거 사고를 시나리오로 재현하는 근거예요 | Zabbix의 문제 이력, Splunk의 검색 결과 |
| 실측 | 값이 시간에 따라 어떻게 움직였나 | 물리 프로필의 숫자와 곡선을 맞춰요(ADR-0137) | vROps·Zabbix의 지표 |

사건과 실측은 세계의 구조에 쓰지 않아요. 연결 화면은 이 소스가 어느 역할인지 먼저 말해요. 지금 만드는 길은 구성뿐이고, 사건과 실측은 따로 설계해요. 영상(CCTV, ADR-0139)은 테이블이 되지 않는 넷째 갈래이고 제안 단계예요.

### 읽기 전용은 세 겹으로 지켜요

읽을 때도 POST를 쓰는 소스가 있어요(JSON-RPC, 검색 작업, 걸러서 조회). "GET만 허용"으로는 읽기 전용을 지킬 수 없어요.

1. **프리셋의 허용 목록**: 프리셋마다 부를 수 있는 것만 적어요(Zabbix는 `*.get` 메서드, NSO는 GET, Splunk는 검색을 만들고 결과를 받는 것). 목록 밖의 요청은 만들어지지 않아요.
2. **소스 쪽 계정**: 읽기 전용 계정이어야 이어져요. 연결할 때 계정의 권한을 확인하고, 쓰는 권한이 보이면 잇지 않아요.
3. **범용 HTTP 커넥터**: GET만 해요. 읽는 POST는 프리셋 안에서만, 허용 목록과 함께 있어요. 쿼리 언어(SPL)는 관리자만 적고, 읽는 명령의 허용 목록으로 걸러요([소스 관리](source-management.md) 10절, ADR-0152). 소스의 위험 명령 검사를 끄지 않아요.

장비를 바꾸는 도구이기도 한 소스(NSO 같은)는 셋 중 하나라도 확인되지 않으면 잇지 않아요. 읽기만 하는 역할로 필요한 것을 볼 수 없는 소스도 잇지 않고, 푸시 수집으로 받아요(ADR-0161 14번).

### 어떤 모양으로 들어오든, 들어온 뒤의 모양은 하나로 좁혀요

소스의 종류를 미리 다 알 수는 없어요. 그래서 소스를 맞히려 하지 않고, 무엇이 오든 수집이 끝나면 **한 가지 모양**이 되게 해요. 모르는 것은 앞의 두 단(연결·수집)에 가두고, 정제·매핑·링크 정의는 그 한 가지 모양만 알아요.

| 모르는 것 | 가두는 방법 |
|---|---|
| 가져오는 방법(파일, API, DB, 그 밖의 무엇) | 범용 넷. 넷으로 안 되면 **푸시 수집**이 마지막 길이에요: 소스 쪽의 작은 스크립트가 행을 넣어 줘요. 그래서 "지원 안 하는 소스"는 없고, 낯선 소스는 바깥의 스크립트 하나로 연결돼요 |
| 모양(겹친 JSON, 한 값에 여러 값, 가로로 긴 테이블) | 원본 데이터셋은 늘 **행과 컬럼의 테이블**이에요. 겹친 것은 부모 테이블·자식 테이블로 펼쳐요(배열, 이름이 키인 맵, 행마다 JSON 한 덩이). 테이블 사이에는 **정제 연산 여덟 가지**만 둬요: 행으로 펼치기, 피벗, 컬럼 나누기, 조인, 유니온, 필터, 빈 값 채우기, 값 변환(단위 변환·코드 매핑·정규화). 코드는 못 넣어요. 그보다 복잡하면 바깥에서 정제해 푸시 수집으로 넣어요 |
| 의미(컬럼 이름, 단위, 무엇이 키인가) | 받은 데이터셋의 프로파일을 먼저 보여 줘요: 컬럼마다 채워진 비율, 유일한 값의 비율, 키로 쓸 만한 컬럼, 다른 데이터셋의 키와 값이 겹치는 컬럼. 매핑과 링크 정의를 여기서 제안해요 |
| 같은 것이 소스마다 다른 이름(호스트 이름, 자산 번호, 시리얼) | **중복 병합 규칙**: 타입마다 어느 컬럼들이 같으면 같은 객체인지 정해요. 비교할 때는 정해진 정규화(대소문자, 앞뒤 공백, 도메인 접미사, 포트 이름)를 거치고 원래 값은 그대로 둬요. IP·MAC처럼 값이 여럿인 속성은 하나라도 같으면 후보예요. 맞지 않거나 둘로 갈리는 것은 합치지 않고 목록으로 내요. 속성이 부딪치면 속성마다 우선 소스가 정해져 있어요 |
| 소스가 바뀜(컬럼이 사라짐, 형이 바뀜) | 수집은 되고 매핑에서 멈춰요. 세계는 그대로예요 |

- **일부러 안 하는 것**: 임의의 변환 코드를 돌리는 파이프라인 도구가 되지 않아요. 정제 연산은 정해진 여덟 가지뿐이에요.
- **먼저 샘플로 검증해요.** 종이 위의 첫 검증은 끝났고, 막힌 열아홉 곳을 메웠어요([샘플 검증](reality-shape-samples.md), ADR-0161). 단계 B의 첫 일은 커넥터가 아니라 샘플이에요: 실제 소스 다섯 가지쯤의 구조(컬럼 이름과 겹침 구조만 본뜬 지어낸 데이터)를 모아, 위 표로 세계 하나가 만들어지는지 종이 위에서 먼저 돌려 봐요. 안 되는 곳이 설계가 틀린 곳이에요. 진짜 데이터는 이 저장소에 넣지 않아요. 첫 샘플 세트는 vROps, CloudVision, Cisco NSO, Zabbix(5.0 이상), Splunk, 엑셀 자산 대장이에요. 링크가 요청 조건에 들어 있는 것, 깊게 겹친 것, 사건만 오는 것, 사람이 만든 테이블이 다 들어 있어요.

### 입구는 나누고, 뒤는 같이 써요

현실에서 만드는 길은 지어내는 길과 입구가 달라요. 묻는 순서가 반대이고(무엇을 원하나 ↔ 어디서 가져오나), 한 번 만들고 끝나지 않고 소스가 바뀔 때마다 되풀이되기 때문이에요.

**연결 → 수집 → 정제 → 매핑 → 링크 정의 → 알아보기·빈 곳 채우기 → 확인·적용 ↺**

| 나누는 것 | 같이 쓰는 것 |
|---|---|
| 만드는 입구와 화면 | 모델(객체 타입·링크 타입) |
| 저장 방식(원본 데이터셋과 이력) | 토폴로지 보기와 3D |
| 고치는 권한(현실 세계는 읽기 전용) | 시나리오·실험·채점 |

### 링크는 사람이 긋지 않고 링크 정의가 만들어요

현실 세계에서는 장비 사이의 링크를 하나씩 손으로 긋게 하지 않아요. 손으로 그은 링크는 출처가 없고, 다시 돌리면 사라지거나 소스와 어긋나고, 수천 개가 되면 아무도 맞는지 몰라요. 사용자는 링크가 아니라 **링크 정의**를 정하고, 조건은 아래 조건 유형에서 골라요.

| 조건 유형 | 뜻 | 예 |
|---|---|---|
| 키 일치 | 한쪽의 속성 값이 다른 쪽의 키와 같다 | VM의 "호스트" = 서버 이름 → `runs_on` |
| 위치 포함 | 한쪽이 다른 쪽 안에 있다 | 서버의 랙·U 위치 → 그 랙에 실장 |
| 연결 테이블 | 데이터셋의 한 행에 양쪽 키가 다 있다 | 케이블 대장, LLDP 이웃, PDU 콘센트 표 → `network`, `power` |
| 그룹 | 그룹 키가 같은 객체들이 한 그룹의 멤버다 | 클러스터 호스트 목록 → `member_of`, 역할 컬럼 → 액티브·스탠바이 |
| 기본 규칙 | 소스에 없을 때 흔한 구성으로 채운다(추정) | 랙의 서버는 그 랙의 PDU A·B에 |

- 링크 타입마다 쓸 수 있는 조건 유형, 꼭 있어야 하는 속성(역할 등), 카디널리티(VM은 서버 하나에, 서버는 PDU 하나나 둘에)가 링크 타입 표에 적혀 있어요. 링크 정의를 정하면 "만든 링크 4,102개 · 못 만든 링크 153개 · 카디널리티를 어긴 링크 12개"를 바로 보여 줘요.
- **링크에는 근거의 등급이 붙어요**: 사실(소스가 말함) / 가정(기본 규칙으로 채움) / 모름. 가정은 가정 보고서와 토폴로지 보기에 그렇게 보여요.
- **어느 시스템에도 없는 것도 데이터셋으로 들어와요.** 서비스가 어느 VM들인지, 무엇이 무엇에 기대는지, DR 계획 같은 것은 사람이 아는 것이지만, 화면에서 링크를 긋지 않고 데이터셋(파일 소스)으로 넣어요. 그러면 출처·버전·다시 돌리기가 다른 데이터와 같아요. 틀린 한두 행을 고치는 것도 이유를 적는 "바로잡기 데이터셋"이에요.
- **파생되는 것은 긋지 않아요.** "이 둘은 한 쌍", "이중화 2개 중 2개"는 링크의 수와 역할에서 계산해요. 다만 **최소 생존 수**(멤버 중 몇 개가 살아 있어야 유지되나)는 링크의 수에서 나오지 않아요: 소스가 말하면 사실, 타입의 기본값이면 가정, 기본값이 없으면(냉방, 병렬 UPS) 모름이에요. ECMP는 장비 설정에서 읽어요: 같은 이웃 그룹의 BGP 세션들이 멤버이고, 여러 경로를 같이 쓰게 돼 있으면 ECMP, 아니면 주·대기예요(ADR-0164).
- **링크 정의는 양 끝의 타입 조건을 가져요.** 가리키는 상대의 타입이 행마다 달라도(상위 설비, 부모·자식뿐인 링크) 링크 정의 하나가 받아요. 상대가 둘 이상에 맞으면 잇지 않아요.
- **양쪽이 말하는 링크는 한 번만 만들어요.** "양쪽 확인·한쪽만 확인"을 적고, 어긋나면 만들지 않고 목록으로 내요. 모델에 없는 이웃("미등록 이웃")은 객체로 만들지 않고 숫자로 내요.
- 손으로 잇는 편집(세계 편집기의 "고르면 꽂을 수 있는 곳을 가까운 순으로")은 지어내는 세계와 복사한 실험 세계에만 있어요.

## 5. 모델 관리

모델을 가진 곳이 테라리움 하나이므로 모델을 보고 넓히는 자리가 필요해요.

### 무엇이 모델인가
객체 타입(62)과 속성, 링크 타입(15)과 연결할 수 있는 규칙, 액션(툴 96개와 승인·넘기기), 프로세스 어휘(팀·역할·활동 유형·단계·티켓), 표준과의 매핑, 타입마다의 소스 매핑이에요.

### 핵심은 잠그고, 넓히는 길은 셋
내장 타입에는 **동작**이 붙어 있어요(물리, 고장, 툴). 의미를 바꾸면 시뮬레이션과 채점이 깨져요.

| 할 수 있는 것 | 시뮬레이션에 닿나 |
|---|---|
| 내장 타입에 속성 더하기(자산 번호, 계약, 담당 역할 …) | 아니요. 실려 다니고 보이기만 해요 |
| 새 객체 타입·새 링크 타입 만들기 | 예, 기본 단계로요. 고른 의미대로 영향 범위와 실험의 고장 전파에 들어가요(상태 전파·공통 알람·공통 조회 툴). 물리와 전용 툴은 없어요(ADR-0168) |
| 프로세스 어휘 더하기(새 팀, 새 활동) | 아니요. 프로세스 비교가 써요 |

내장 타입의 의미·규칙·액션은 읽기 전용이고 테라리움의 버전과 함께 바뀌어요. 그래서 넓힌 모델은 실험의 지문에 들어가지 않고 점수를 바꾸지 않아요.

### 링크 타입은 표 하나에서 나와요

지금 토폴로지 보기는 링크 타입의 규칙을 읽지 않고, 단의 순서와 링크의 방향이 코드에 손으로 적혀 있어요. 그래서 타일로 안 나오는 타입이 있고, 같은 단끼리나 거꾸로 가는 링크는 알림 없이 빠지고, 논리 링크 여러 타입이 같은 선으로 그려져요. 3D에는 논리 링크가 없어요.

링크 타입마다 한 행을 적는 표를 두고 토폴로지 보기·영향 범위·검증·모델 화면이 그 표를 읽어요.

| 표에 적는 것 | 예 (`service_on`) |
|---|---|
| 무엇과 무엇을 잇나 | 서비스 → VM·서버·스토리지 |
| 의미 | 호스팅 / 공급 / 의존·호출 / 이중화 그룹 / 관리 |
| 어느 보기에, 어느 방향으로 | 네트워크·가상화, 아래로 |
| 끊기면 영향이 넘어가나 | 예 |
| 역할 | 액티브 / 스탠바이 |
| 카디널리티 | 서비스 하나에 하나 이상 |
| 쓸 수 있는 조건 유형 | 키 일치, 그룹 |

- **토폴로지 보기**: 링크는 의미와 역할로 보여요(대기는 옅은 선. 점선은 이미 "끊김"이에요). 타일은 이중화를 숫자로 말해요("2개 중 2개 살아 있어요", 클러스터는 "자동 재배치 켜짐 · 호스트 4대"). 현실 세계의 확인 안 된 이중화는 "모름"이에요.
- **숨기지 않기**: 보기 위에 "링크 없는 것 N개 · 그리지 않은 링크 N개 · 이 보기에 없는 타입"을 숫자로 내고 누르면 목록이 나와요. 현실 데이터에서 링크 없는 타일은 "연결을 못 읽었다"는 신호예요.
- **3D는 물리만**: 3D는 "어디에 있나", 토폴로지 보기는 "무엇에 기대나"에 답해요. 고른 장비에 "여기에 기대는 서비스 N개" 한 줄만 더해요.
- **링크는 세 가지예요**: 내장 링크 타입은 읽기 전용이에요(동작이 붙어 있어요). 장비 사이의 링크 하나하나는 링크 정의가 만들어요(사용자는 조건 유형을 골라 정의를 정해요. 현실 세계에서 손으로 긋지 않아요). 사용자가 만든 링크 타입은 양 끝·조건·의미·카디널리티로 정의하고, 의미(호스팅, 의존, 연결, 공급, 이중화 그룹, 풀, 참고용)를 닫힌 목록에서 골라요. 고른 의미대로 토폴로지 보기에 그려지고 영향 범위에 들어가요(ADR-0165). 시뮬레이션의 동작을 붙이는 일은 물리 자리(ADR-0137)를 넓히는 일이고 여기서 하지 않아요.
- 채점과 물리는 바뀌지 않아요. 토폴로지 보기의 타입에 필드를 더하는 일이에요.

### 버전과 내보내기
- 모델에는 버전이 있고, 바꾸는 일은 이력에 남아요. 지우기 전에 "이 속성을 쓰는 매핑 3개와 세계 2개"처럼 닿는 곳을 보여 줘요.
- 스키마는 JSON 스키마 + JSON-LD 맥락으로 내보내요. 타입마다 표준의 무엇과 같은지 적어요.

| 층 | 매핑하는 표준 |
|---|---|
| 서버·전원·열 설비 | DMTF Redfish |
| 공조·건물·방 | Brick |
| 랙·실장·케이블 | NetBox 모델 |
| 네트워크 토폴로지 | IETF RFC 8345 |
| 가상화·쿠버네티스 | vSphere 객체 모델, 쿠버네티스 API |
| 출처·조직·프로세스 | W3C PROV-O, W3C ORG, BPMN 용어 |

매핑은 구현할 때 표준 문서와 하나씩 대조해 확정해요. 통째로 따르는 표준은 없어요.

### 프로세스 어휘
현행 단계 표의 "누가"와 "무엇을"은 자유 글이 아니라 어휘에서 골라요. 없으면 어휘에 더하고 다시 써요. 사람 개인은 넣지 않고 역할까지만 넣어요. 이미 적힌 표는 가장 가까운 항목을 제안해 옮겨요.

## 6. 저장소와 고가용성: 기대는 만큼만

현실 세계는 현실을 **읽기만** 해요. 테라리움이 멈춰도 현실의 장비는 그대로예요. 그래서 처음부터 무중단을 사지 않고, 잃지 않기를 먼저 사요.

| 수준 | 약속 | 방법 | 언제 |
|---|---|---|---|
| 0 | 한 번 가져와 실험 세계를 만든다 | 지금의 저장소, 파일 | 단계 B |
| 1 | 잃지 않는다, 다시 세울 수 있다 | 현실 평면 전용 관계형 DB(이력은 덧붙이기만), 원본 데이터셋은 파일·객체 저장소, 백업과 복구 연습, 원본 데이터셋에서 세계를 다시 만들 수 있음 | 단계 C |
| 2 | 멈추지 않는다 | DB 복제와 자동 승격, 동기화 워커 둘 이상, 여러 영역 | 누군가 현실 세계에 기대어 일하게 될 때 |

- 저장소를 직접 만들지 않아요. 검증된 DB의 복제를 써요. 테라리움은 저장소 포트 뒤에 어댑터를 하나 더 둬요.
- **파이프라인은 처음부터 다시 돌려도 안전하게** 만들어요: 소스마다 어디까지 받았는지 적고, 같은 변경을 두 번 적용해도 결과가 같고, 실패한 행은 따로 모으고, 같은 동기화가 두 곳에서 동시에 돌지 않게 잠가요. 수준 2로 올릴 때 파이프라인을 다시 쓰지 않아요.
- 잃어도 되는 것과 안 되는 것: 원본 데이터셋과 이력은 잃으면 안 돼요. 현재 상태는 그 둘에서 다시 만들 수 있어요.

## 7. 만드는 순서와 문

| 단계 | 내용 | 제품 목표 | 들어가는 문 |
|---|---|---|---|
| A | 스키마 내보내기와 표준 매핑, 프로세스 어휘, 읽기 전용 "모델" 화면, 링크 타입 표와 표에서 그리는 토폴로지 보기 | 지금 목표 안 | 진행 중인 부채(UX·커버리지)가 끝나면 |
| B | 연결(파일·HTTP) → 수집 → 정제·매핑·링크 정의 → **실험 세계 하나 만들기**. FalkorDB 제거 | 지금 목표 안 | A |
| C | 현실 세계: 계속 동기화, 이력, 스키마 변경 알림, 평면 분리, 실험용 복사본, 수준 1 | **목표를 넓히는 결정이 필요** | 권한·SSO 완료 + 현실 사고 재현 실험의 증거 |
| D | 수준 2, 생태계 커넥터, 새 타입 만들기, "이 액션을 하면?" 미리 돌려 보기 | 넓힌 목표 | 현실 세계에 기대는 사용자가 생김 |

- B까지는 "현실을 닮은 세계"를 만드는 길이라 지금 목표 안이에요. B에서도 파이프라인의 네 단과 출처는 처음부터 지켜요. 그래야 C가 덧붙이기가 돼요.
- C부터 테라리움은 현실의 데이터를 계속 들고 있어요. 보안·운영의 무게가 달라지므로 그때 제품 목표를 고치는 결정을 따로 해요.
- **현실 사고 재현 실험**: 과거의 실제 사고 몇 건을 B로 만든 세계에서 재현해, 세계가 현실처럼 움직이는지 봐요. 이것이 C로 가는 근거예요.

## 하지 않는 것

- 전용 커넥터를 수백 종 만들지 않아요.
- 고가용 저장소를 직접 만들지 않아요.
- 현실에 쓰지 않아요. 실험 세계의 결과가 현실로 흘러가는 자동 경로가 없어요.
- 내장 타입의 의미를 화면에서 고치게 하지 않아요.
- 실험받는 에이전트가 현실 평면에 닿게 하지 않아요.
- 현실의 데이터를 이 공개 저장소에 넣지 않아요. 시험은 지어낸 샘플로 해요.

## 지금 지켜 둘 것

1. 세계에 종류(실험·현실)를 적을 자리와, 속성마다 출처를 적을 자리.
2. 객체 ID는 안 바뀌고 소스의 키에서 정해져요.
3. 매핑은 데이터예요(버전이 있고, 내보내고 들여와요).
4. 저장소는 포트 뒤에 있어요. 실험 평면의 코드는 현실 평면의 포트를 가져오지 않아요(구조 검사로 강제).
5. 파이프라인의 단은 서로의 속을 모르고, 다시 돌려도 결과가 같아요.

## 시험 (만들 때)

| 시험 | 내용 |
|---|---|
| 단 분리 | 수집 코드는 모델을, 정제·매핑·링크 정의 코드는 소스 접속을 가져오지 않는다(구조 검사) |
| 다시 돌리기 | 같은 원본 데이터셋 + 같은 매핑 = 같은 세계. 두 번 적용해도 같다 |
| 스키마 변경 | 컬럼이 사라지거나 형이 바뀌면 매핑이 멈추고 세계는 그대로다 |
| 출처 | 모든 속성에서 소스·컬럼·시각까지 거슬러 간다 |
| 읽기 전용 | 프리셋의 허용 목록 밖 요청은 만들어지지 않는다. 범용 HTTP 커넥터는 GET만 한다. 쓰는 권한이 있는 계정으로는 이어지지 않는다(ADR-0149) |
| 평면 | 실험 세계의 툴·에이전트 경로에서 현실 평면의 저장소와 자격 증명에 닿는 길이 없다 |
| 지문 | 모델에 타입을 더해도 그 타입을 쓰지 않는 세계의 점수 분해가 바이트까지 같다. 실험은 세계의 버전(타입과 링크의 정의 포함)을 고정한다(ADR-0168) |
| 실험용 복사본 | 현실 세계에서 복사한 실험 세계는 정답 풀이 검증을 거치고, 원본은 바뀌지 않는다 |
| 왕복 | 세계를 파사드로 내보내고 그 프리셋으로 다시 읽으면 객체·속성·링크가 같은 세계가 된다(프리셋마다) |
| 링크 타입 표 | 모든 링크 타입이 표에 한 행 있고, 세계의 모든 링크는 토폴로지 보기에 그려지거나 "그리지 않은 링크"에 세어진다(합이 맞는다) |
| 한 엔진 | 어떤 고장이든 운영 세계가 답한 영향 범위와, 실험용 복사본에서 같은 고장을 냈을 때의 최종 상태가 같다. 사용자가 만든 링크 타입도 고른 의미대로 들어간다. 의미가 "참고용"인 링크만 영향이 넘어가지 않는다(ADR-0168) |
| 손으로 그은 링크 없음 | 현실 세계의 모든 링크는 원본 데이터셋 + 링크 정의에서 다시 만들어지고, 링크마다 정의와 등급(사실·가정)이 있다 |
| 카디널리티 | 카디널리티를 어긴 링크는 적용되지 않고 목록에 나온다 |
| 거꾸로 사다리 | 사다리로 지어낸 세계를 알아보기에 넣으면 지을 때 고른 칩이 그대로 나온다(모든 칩 조합). 구성을 지운 세계는 그 층이 "모름"으로 나온다 |

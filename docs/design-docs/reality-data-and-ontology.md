# 현실 데이터와 모델

이 문서는 설계예요. 아직 구현하지 않았어요. 결정은 [ADR-0144](adr/0144-reality-data-pipeline-ontology-manager-world-kinds.md)예요. 앞선 결정은 [ADR-0084](adr/0084-topology-view.md)(가져오기를 다시 여는 조건), [ADR-0088](adr/0088-data-reuse.md)(불변 기록·버전·출처), [ADR-0095](adr/0095-digital-twin-and-model-plugins.md)(쌍둥이 네 단계)예요.

## 한 줄로

모델은 하나, 세계는 두 종류(현실 세계와 실험 세계), 데이터가 들어오는 길은 네 단(연결 → 수집 → 대응 → 적용)이에요. 커넥터를 많이 만들지 않고 몇 개의 범용 커넥터 위에 프리셋을 쌓아요. 고가용성은 "누가 여기에 기대는가"가 생기는 단계에 맞춰 올려요.

## 전제

- 사내의 다른 온톨로지·로더 프로젝트는 설계에 넣지 않아요. 개체·관계·프로세스 모델을 가진 곳은 테라리움 하나예요.
- FalkorDB 연동은 없애요. 현실을 읽는 창(`sources/realimport`의 읽기 전용 포트)과 빈 곳 채우기·보고서는 남겨 새 파이프라인의 뼈대로 써요.
- 제품 목표(ADR-0138)의 3번, 채점이 늘 맞고 같다는 것이 이 설계에서도 이겨요.

## 1. 세계는 두 종류, 태어날 때 정해져요

| | 실험 세계 | 현실 세계 |
|---|---|---|
| 상태가 어디서 오나 | 물리·고장·시나리오 | 현실 소스의 동기화 |
| 몇 개 | 많음, 쓰고 버림 | 현실 환경마다 하나 |
| 무엇을 할 수 있나 | 고장 넣기, 에이전트 실험, 채점, 가지치기, 빨리 감기 | 보기, 이력, 가지 떠내기 |
| 무엇을 못 하나 | 현실과 이어지지 않음 | 고장 넣기·시뮬레이션·에이전트 실험 |
| 지켜야 하는 것 | 결정성 | 잃지 않기, 출처, 권한, 감사 |

- **바뀌지 않아요.** 실험 세계가 현실 세계로 "전환"되지 않고, 현실 세계 안에서 실험하지도 않아요. 종류는 만들 때 정해지는 속성이에요.
- **길은 한 방향이에요.** 현실 세계의 어느 시각을 떠내 실험 세계를 만들어요(가지 떠내기). 실험 세계에서 일어난 일은 현실 세계로 돌아가지 않아요.
- **현실에 쓰지 않아요.** 테라리움은 현실 소스를 읽기만 해요. 쓰는 메서드가 포트에 없어요.
- **이름.** 이미 있는 "운영 모드"(끝이 없는 실험, REQ-090)와 섞이지 않게 새 종류는 "현실 세계"라고 불러요.

## 2. 평면도 둘, 서로 닿지 않아요

| | 현실 평면 | 실험 평면 |
|---|---|---|
| 담는 것 | 연결, 받은 그대로의 데이터, 대응, 현실 세계와 이력 | 실험 세계, 실행, 채점, 벤치마크 |
| 저장소 | 따로(아래 6절) | 지금의 저장소 |
| 일꾼 | 동기화 일꾼 | 실험 일꾼 |
| 에이전트 | 닿을 수 없음 | 자기 실험 세계의 툴만 |

- 실험받는 에이전트와 하네스는 현실 평면의 API·저장소·자격 증명에 닿을 길이 없어요. 떠낸 실험 세계만 봐요.
- 동기화가 실험 부하에 밀리지 않고 실험이 동기화에 밀리지 않게 일꾼 풀을 나눠요.
- 현실에서 떠낸 실험 세계는 원본의 권한과 등급을 물려받고, 떠낼 때 이름 가리기를 고를 수 있어요(ADR-0088).
- 현실 평면은 설정으로 켜요. 기본은 꺼짐이고, 꺼져 있으면 지금의 테라리움과 같아요.

## 3. 데이터가 들어오는 길은 네 단이에요

소스를 잇는 일과 모델에 맞추는 일을 나누고, 그 사이에 "받은 그대로"를 둬요.

```
연결 ──▶ 수집 ──▶ [받은 그대로 저장] ──▶ 대응 ──▶ [변경 묶음] ──▶ 적용 ──▶ 세계
(어디에 어떻게)  (그대로 가져옴)              (모델에 맞춤)               (세계와 이력)
```

| 단 | 아는 것 | 모르는 것 | 내놓는 것 |
|---|---|---|---|
| 연결 | 소스의 종류·주소·자격 증명 | 모델 | 닿는지, 무엇이 있는지 |
| 수집 | 소스의 표·경로·페이지 | 모델 | 받은 그대로의 스냅샷(고치지 않음, 시각·해시) |
| 대응 | 모델, 열과 속성의 짝 | 소스에 닿는 법 | 개체·관계의 변경 묶음과 문제 보고 |
| 적용 | 세계 | 소스 | 세계의 새 상태와 이력 |

나누면 얻는 것:
- 대응을 고쳐도 소스를 다시 긁지 않아요. 받은 그대로에서 다시 돌려요.
- 소스가 죽어도 마지막으로 받은 것으로 세계가 서 있어요.
- 소스의 열이 바뀌면(스키마 흔들림) 수집은 되고 대응에서 멈춰 알려요. 조용히 틀린 값이 세계에 들어가지 않아요.
- 속성 하나가 어느 소스의 어느 열에서 언제 왔는지 끝까지 따라가요.

### 대응 (소스의 속성을 개체의 속성으로)

개체 종류마다 선언하는 데이터예요. 코드가 아니에요.

| 항목 | 내용 |
|---|---|
| 소스 | 이 종류가 오는 수집 결과(하나 이상) |
| 키 | 바뀌지 않는 ID가 되는 열. 없으면 여러 열을 묶음 |
| 속성 | 열 → 속성. 형 변환, 단위 변환, 기본값. 안 쓰는 열은 "버림"으로 적음 |
| 관계 | 참조 열 → 관계(예: 서버 표의 랙 이름 → 랙에 설치됨) |
| 합치기 | 같은 키가 여러 소스에 있으면 속성마다 어느 소스가 이기는지 |
| 출처 | 속성마다 소스·열·받은 시각 |

미리 보기는 처음 몇 줄과 문제를 보여 줘요: 대응 안 된 열, 필수 속성 없음, 끊어진 참조, 겹친 키, 범위를 벗어난 값. 시뮬레이션에 필요한데 소스에 없는 것(전원·냉방 길)은 가정으로 채우고 무엇을 가정했는지 보고해요. 이름이 비슷한 열은 짝을 제안하고, 모델이 등록돼 있으면 이끼가 제안을 설명해요. 정하는 것은 사람이에요.

### 현실에서 만들 때는 순서가 거꾸로예요

지어내는 세계는 위에서 아래로 가요: 서비스 → 아키텍처(사다리) → 크기 → 생성. 뜻(이중화, 자동 재배치, DR)을 먼저 정하고 장비가 따라 나와요. 현실에서 만드는 세계는 아래에서 위로 가요. 있는 것이 먼저 들어오고 뜻은 나중에 채워져요.

| 순서 | 하는 일 | 어디서 오나 |
|---|---|---|
| 1 | 있는 것: 장비·VM·위치·케이블 | 소스(대응) |
| 2 | 구성: 클러스터의 HA·자동 재배치, 복제 방식, 다중 경로, 복제본 수 | 소스에 있으면 읽음. 모델에서는 개체의 속성과 관계의 역할이라 다른 속성과 같은 길로 들어와요 |
| 3 | 모양 알아보기: 사다리를 거꾸로 돌려 층마다 "이 세계는 이 칩으로 보여요"와 근거를 냄 | 코드(1·2에서 계산) |
| 4 | 빈 곳 채우기: 서비스가 어느 VM들인지, 무엇이 무엇에 기대는지, DR 계획과 목표 시간, 전원 A·B 길, 담당 팀 | 사람(목록에서 고름). 어느 시스템에도 없는 것들이에요 |
| 5 | 확인: 가정 보고서, 법칙 검사, 정답 풀이 검증 | 코드 |

- **모델과 말은 하나예요.** 두 길은 같은 세계 모델과 같은 사다리 칩에서 만나요. 현실 쪽 전용 빌더를 따로 두지 않고, 사다리 화면을 "읽기"로 다시 써요(칩 + 근거 + 모름).
- **모르는 것은 "모름"이에요.** 확인되지 않은 이중화를 있다고 치지 않아요. 있다고 치면 현실에는 없는 자동 복구가 실험에서 일어나 세계가 거짓말을 해요. 없다고 치지도 않아요. "모름"으로 두고 실험 전에 정하게 해요.
- **세계의 상태는 둘이에요.** 1~3까지면 "구조만 있는 세계"(보기·토폴로지·영향 범위). 4·5가 끝나면 "실험할 수 있는 세계". 무엇이 모자라 실험을 못 하는지 목록으로 보여 줘요.
- **알아본 칩을 고치는 것은 바로잡기예요.** 현실을 적은 것이므로 이유와 함께 남겨요. 떠낸 실험 세계에서는 칩을 자유롭게 바꿔요("이 클러스터에 자동 재배치를 켜면?"). 이것이 가지 떠내기의 쓸모예요.

## 4. 커넥터: 많이 만들지 않아요

수백 종의 전용 커넥터는 만들지도 지키지도 못해요. 커넥터는 소스의 API가 바뀔 때마다 낡아요. 관리하기 쉬움은 커넥터 수가 아니라 아래 표의 아래쪽 줄에서 나와요.

| 층 | 내용 | 수 |
|---|---|---|
| 범용 커넥터 | 파일(CSV·엑셀·JSON), HTTP(인증·페이지 넘김·경로로 뽑기), SQL, 밀어 넣기(받는 주소·파일 놓는 곳) | 4 |
| 프리셋 | 범용 커넥터 위의 설정 묶음: 요청 방법 + 대응. 코드가 아니라 데이터. Redfish, vCenter, vROps, NetBox, 쿠버네티스 API, SNMP처럼 테라리움이 이미 말을 아는 것부터 | 늘어남 |
| 생태계 | 공개된 커넥터 규약을 따르는 바깥 커넥터를 돌리는 범용 커넥터 하나. 필요가 확인되면 | 나중 |

- 프리셋은 "이 소스를 고르면 대응이 미리 채워져 있다"는 경험을 줘요. 모델이 표준과 짝지어져 있어서(5절) 표준을 따르는 소스의 프리셋은 싸요.
- 밀어 넣기는 이미 다른 수집 도구가 있는 조직의 길이에요. 그 도구가 파일이나 주소로 넣어 주면 수집 단을 건너뛰고 "받은 그대로"부터 시작해요.
- 연결마다 보이는 것: 닿는지, 마지막 수집 시각과 건수, 스키마 흔들림, 자격 증명 만료, 이 소스를 쓰는 속성 수.

### 입구는 나누고, 뒤는 같이 써요

현실에서 만드는 길은 지어내는 길과 입구가 달라요. 묻는 순서가 반대이고(무엇을 원하나 ↔ 어디서 가져오나), 한 번 만들고 끝나지 않고 소스가 바뀔 때마다 되풀이되기 때문이에요.

**연결 → 수집 → 대응(개체 + 데이터에 있는 관계) → 알아보기·빈 곳 잇기 → 확인·적용 ↺**

| 나누는 것 | 같이 쓰는 것 |
|---|---|
| 만드는 입구와 화면 | 모델(개체·관계 종류) |
| 저장 방식(받은 그대로와 이력) | 토폴로지 판과 3D |
| 고치는 권한(현실 세계는 읽기 전용) | 시나리오·실험·채점 |

관계는 두 갈래로 들어와요. 데이터에 있는 관계(VM 표의 "호스트" 열)는 대응에서 개체 속성과 같이 정해요. 데이터에 없는 관계만 사람이 이어요. 세계 편집기의 "고르면 꽂을 수 있는 곳을 가까운 순으로"(지금은 전원·네트워크·냉방)를 논리 관계(서비스 구성, 의존, 대기 쌍)까지 넓혀 써요.

## 5. 모델 관리

모델을 가진 곳이 테라리움 하나이므로 모델을 보고 넓히는 자리가 필요해요.

### 무엇이 모델인가
개체 종류(62)와 속성, 관계 종류(15)와 이을 수 있는 규칙, 액션(툴 96개와 승인·넘기기), 프로세스 어휘(팀·역할·활동 유형·단계·티켓), 표준과의 짝, 종류마다의 소스 대응이에요.

### 핵심은 잠그고, 넓히는 길은 셋
내장 종류에는 **동작**이 붙어 있어요(물리, 고장, 툴). 뜻을 바꾸면 시뮬레이션과 채점이 깨져요.

| 할 수 있는 것 | 시뮬레이션에 닿나 |
|---|---|
| 내장 종류에 속성 더하기(자산 번호, 계약, 담당 역할 …) | 아니요. 실려 다니고 보이기만 해요 |
| 새 종류·새 관계 만들기("기록만 되는 종류") | 아니요. 내장 종류와 이을 수 있어요 |
| 프로세스 어휘 더하기(새 팀, 새 활동) | 아니요. 프로세스 비교가 써요 |

내장 종류의 뜻·규칙·액션은 읽기 전용이고 테라리움의 판과 함께 바뀌어요. 그래서 넓힌 모델은 실험의 지문에 들어가지 않고 점수를 바꾸지 않아요.

### 관계는 표 하나에서 나와요

지금 토폴로지 판은 관계 규칙을 읽지 않고, 단의 순서와 선의 방향이 코드에 손으로 적혀 있어요. 그래서 타일로 안 나오는 종류가 있고, 같은 단끼리나 거꾸로 가는 관계는 알림 없이 빠지고, 논리 관계 열 종류가 같은 선으로 그려져요. 3D에는 논리 관계가 없어요.

관계 종류마다 한 줄을 적는 표를 두고 판·영향 범위·검증·모델 화면이 그 표를 읽어요.

| 표에 적는 것 | 예 (`service_on`) |
|---|---|
| 무엇과 무엇을 잇나 | 서비스 → VM·서버·스토리지 |
| 뜻의 갈래 | 위에서 돈다 / 공급받는다 / 필요하다·호출한다 / 묶인다 / 다스린다 |
| 어느 판에, 어느 방향으로 | 네트워크·가상화, 아래로 |
| 끊기면 영향이 넘어가나 | 예 |
| 역할 | 액티브 / 스탠바이 |

- **판**: 선은 뜻의 갈래와 역할을 보여요(대기는 옅은 선. 점선은 이미 "끊김"이에요). 타일은 이중화를 숫자로 말해요("2개 중 2개 살아 있어요", 클러스터는 "자동 재배치 켜짐 · 호스트 4대"). 현실 세계의 확인 안 된 이중화는 "모름"이에요.
- **숨기지 않기**: 판 위에 "선 없는 것 N개 · 그리지 않은 관계 N개 · 이 판에 없는 종류"를 숫자로 내고 누르면 목록이 나와요. 현실 데이터에서 선 없는 타일은 "연결을 못 읽었다"는 신호예요.
- **3D는 물리만**: 3D는 "어디에 있나", 판은 "무엇에 기대나"에 답해요. 고른 장비에 "여기에 기대는 서비스 N개" 한 줄만 더해요.
- **세 층**: 내장 관계 종류는 읽기 전용(동작이 붙어 있어요). 장비 사이의 선 하나하나는 사용자가 데이터 대응이나 편집으로 정해요(규칙 안에서). 사용자가 만든 관계 종류는 "기록만"이라 옅게 그리고 영향이 넘어가지 않아요. 그런 관계에 동작을 붙이는 일은 물리 자리(ADR-0137)를 넓히는 일이고 여기서 하지 않아요.
- 채점과 물리는 바뀌지 않아요. 판의 타입에 칸을 더하는 일이에요.

### 판과 내보내기
- 모델에는 판이 있고, 바꾸는 일은 이력에 남아요. 지우기 전에 "이 속성을 쓰는 대응 3개와 세계 2개"처럼 닿는 곳을 보여 줘요.
- 스키마는 JSON 스키마 + JSON-LD 맥락으로 내보내요. 종류마다 표준의 무엇과 같은지 적어요.

| 층 | 짝짓는 표준 |
|---|---|
| 서버·전원·열 설비 | DMTF Redfish |
| 공조·건물·방 | Brick |
| 랙·실장·케이블 | NetBox 모델 |
| 네트워크 토폴로지 | IETF RFC 8345 |
| 가상화·쿠버네티스 | vSphere 개체 모델, 쿠버네티스 API |
| 출처·조직·프로세스 | W3C PROV-O, W3C ORG, BPMN 용어 |

짝은 구현할 때 표준 문서와 하나씩 대조해 확정해요. 통째로 따르는 표준은 없어요.

### 프로세스 어휘
현행 단계 표의 "누가"와 "무엇을"은 자유 글이 아니라 어휘에서 골라요. 없으면 어휘에 더하고 다시 써요. 사람 개인은 넣지 않고 역할까지만 넣어요. 이미 적힌 표는 가장 가까운 항목을 제안해 옮겨요.

## 6. 저장소와 고가용성: 기대는 만큼만

현실 세계는 현실을 **읽기만** 해요. 테라리움이 멈춰도 현실의 장비는 그대로예요. 그래서 처음부터 무중단을 사지 않고, 잃지 않기를 먼저 사요.

| 수준 | 약속 | 방법 | 언제 |
|---|---|---|---|
| 0 | 한 번 가져와 실험 세계를 만든다 | 지금의 저장소, 파일 | 단계 B |
| 1 | 잃지 않는다, 다시 세울 수 있다 | 현실 평면 전용 관계형 DB(이력은 덧붙이기만), 받은 그대로는 파일·객체 저장소, 백업과 복구 연습, 받은 그대로에서 세계를 다시 만들 수 있음 | 단계 C |
| 2 | 멈추지 않는다 | DB 복제와 자동 승격, 동기화 일꾼 둘 이상, 여러 영역 | 누군가 현실 세계에 기대어 일하게 될 때 |

- 저장소를 직접 만들지 않아요. 검증된 DB의 복제를 써요. 테라리움은 저장소 포트 뒤에 어댑터를 하나 더 둬요.
- **파이프라인은 처음부터 다시 돌려도 안전하게** 만들어요: 소스마다 어디까지 받았는지 적고, 같은 묶음을 두 번 적용해도 결과가 같고, 실패한 줄은 따로 모으고, 같은 동기화가 두 곳에서 동시에 돌지 않게 잠가요. 수준 2로 올릴 때 파이프라인을 다시 쓰지 않아요.
- 잃어도 되는 것과 안 되는 것: 받은 그대로와 이력은 잃으면 안 돼요. 현재 상태는 그 둘에서 다시 만들 수 있어요.

## 7. 만드는 순서와 문

| 단계 | 내용 | 제품 목표 | 들어가는 문 |
|---|---|---|---|
| A | 스키마 내보내기와 표준 짝, 프로세스 어휘, 읽기 전용 "모델" 화면, 관계 표와 표에서 그리는 판 | 지금 목표 안 | 진행 중인 부채(UX·커버리지)가 끝나면 |
| B | 연결(파일·HTTP) → 수집 → 대응 → **실험 세계 하나 만들기**. FalkorDB 제거 | 지금 목표 안 | A |
| C | 현실 세계: 계속 동기화, 이력, 흔들림 알림, 평면 분리, 가지 떠내기, 수준 1 | **목표를 넓히는 결정이 필요** | 권한·SSO 완료 + 현실 사고 재현 실험의 증거 |
| D | 수준 2, 생태계 커넥터, 새 종류 만들기, "이 액션을 하면?" 미리 돌려 보기 | 넓힌 목표 | 현실 세계에 기대는 사용자가 생김 |

- B까지는 "현실을 닮은 세계"를 만드는 길이라 지금 목표 안이에요. B에서도 파이프라인의 네 단과 출처는 처음부터 지켜요. 그래야 C가 덧붙이기가 돼요.
- C부터 테라리움은 현실의 데이터를 계속 들고 있어요. 보안·운영의 무게가 달라지므로 그때 제품 목표를 고치는 결정을 따로 해요.
- **현실 사고 재현 실험**: 과거의 실제 사고 몇 건을 B로 만든 세계에서 재현해, 세계가 현실처럼 움직이는지 봐요. 이것이 C로 가는 근거예요.

## 하지 않는 것

- 전용 커넥터를 수백 종 만들지 않아요.
- 고가용 저장소를 직접 만들지 않아요.
- 현실에 쓰지 않아요. 실험 세계의 결과가 현실로 흘러가는 자동 경로가 없어요.
- 내장 종류의 뜻을 화면에서 고치게 하지 않아요.
- 실험받는 에이전트가 현실 평면에 닿게 하지 않아요.
- 현실의 데이터를 이 공개 저장소에 넣지 않아요. 시험은 지어낸 표본으로 해요.

## 지금 지켜 둘 것

1. 세계에 종류(실험·현실)를 적을 자리와, 속성마다 출처를 적을 자리.
2. 개체 ID는 안 바뀌고 소스의 키에서 정해져요.
3. 대응은 데이터예요(판이 있고, 내보내고 들여와요).
4. 저장소는 포트 뒤에 있어요. 실험 평면의 코드는 현실 평면의 포트를 가져오지 않아요(구조 검사로 강제).
5. 파이프라인의 단은 서로의 속을 모르고, 다시 돌려도 결과가 같아요.

## 시험 (만들 때)

| 시험 | 내용 |
|---|---|
| 단 분리 | 수집 코드는 모델을, 대응 코드는 소스 접속을 가져오지 않는다(구조 검사) |
| 다시 돌리기 | 같은 받은 그대로 + 같은 대응 = 같은 세계. 두 번 적용해도 같다 |
| 흔들림 | 열이 사라지거나 형이 바뀌면 대응이 멈추고 세계는 그대로다 |
| 출처 | 모든 속성에서 소스·열·시각까지 거슬러 간다 |
| 읽기 전용 | 커넥터가 쓰는 요청을 만들 수 없다 |
| 평면 | 실험 세계의 툴·에이전트 경로에서 현실 평면의 저장소와 자격 증명에 닿는 길이 없다 |
| 지문 | 모델을 넓혀도(속성·새 종류·어휘) 같은 실험의 점수 분해가 바이트까지 같다 |
| 가지 | 현실 세계에서 떠낸 실험 세계는 정답 풀이 검증을 거치고, 원본은 바뀌지 않는다 |
| 관계 표 | 모든 관계 종류가 표에 한 줄 있고, 세계의 모든 선은 판에 그려지거나 "그리지 않은 관계"에 세어진다(합이 맞는다) |
| 기록만 | 사용자가 만든 관계 종류를 더해도 영향 범위와 점수 분해가 바이트까지 같다 |
| 거꾸로 사다리 | 사다리로 지어낸 세계를 알아보기에 넣으면 지을 때 고른 칩이 그대로 나온다(모든 칩 조합). 구성을 지운 세계는 그 층이 "모름"으로 나온다 |

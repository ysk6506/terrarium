# 웹 화면 (REQ-006, REQ-030~041)

## 무엇을 위한 화면인가

인프라·AI 엔지니어가 **세계를 짓고, 고장 시나리오를 만들고, 에이전트를 돌려 보고, 결과를 비교**한다. 화면의 주인공은
유리 상자 안의 작은 데이터센터다. 이름 그대로 테라리움: 밖에서 들여다보는 밀폐된 세계. 나머지 화면은 조용히 받쳐 준다.

## 토큰

사용자가 고른 **토스의 결**(안 B, [ADR-0053](adr/0053-toss-visual-b.md))이다. 밝은 회색 바탕에 흰 둥근 카드, 크고 둥근 버튼, 두꺼운 제목, 파란 강조.

|---|---|---|
| paper | `#F2F4F6` / `#121317` | 바탕 |
| surface | `#FFFFFF` / `#1C1E24` | 카드, 표, 대화상자, 옆 패널 |
| fill · fill-hover | `#F2F4F6`, `#E5E8EB` / `#262930`, `#30343C` | 컨트롤과 구분 띠의 바탕 |
| control · control-hover | 회색 바탕 위에서 `fill-hover`, `line-strong` / 흰 카드·창·패널 안에서 `fill`, `fill-hover` | 버튼·입력칸의 바탕. 놓인 곳보다 한 단계 진해서 묻히지 않는다 |
| ink · ink-2 · ink-3 | `#191F28` · `#4E5968` · `#5B6675` / `#F2F4F6` · `#B0B8C1` · `#8B95A1` | 글자(기본·보조·약한) |

| bad-soft · bad-soft-hover | `#FDECEC`, `#FBD9DA` / `#3D1D20`, `#4F262A` | 지우기 같은 위험한 버튼의 바탕과, 마우스를 올렸을 때 한 단계 진한 바탕 |

- 공기 흐름 지도의 찬 점·더운 점과 지도 위 랙 이름 테두리도 `--air-cold`, `--air-hot`, `--air-halo` 토큰이다(3D 안의 색과 맞춘 값).
- 글꼴: **Pretendard Variable**(번들, 쓰는 글자만 내려받는 분할 파일). 숫자는 `tabular-nums`. 한 가족만 쓴다. 본문 17px, 큰 숫자 30px(800), 제목은 두껍고 글자 사이를 조금 좁힌다.
- 모서리: 컨트롤 14px(`--radius-control`), 카드와 패널 22px(`--radius-panel`), 작은 컨트롤 10px, 3D 안의 유리 상자는 각진 모서리.
- 카드는 경계선 대신 옅은 그림자(`--card-shadow`)로 떠 있고, 떠 있는 것(메뉴·대화상자)만 큰 그림자를 쓴다.
- 눌리는 곳은 크게: 기본 버튼 높이 52px, 작은 버튼 36px, 입력칸 54px(옆 패널 안은 더 낮게). 숫자 묶음(`Figures`)은 6개를 3개씩 두 줄로 나눈다.
- 색 값(그림자, 막, 열 눈금 포함)은 `:root`의 토큰으로만 쓴다. 규칙 밖에 색 값을 직접 쓰면 UX 측정의 "디자인 토큰" 점수가 깎인다.

## 원칙

1. **하나만 화려하게.** 3D 세계(유리 상자 안의 바닥 타일, 랙, 열 색)만 눈길을 끈다. 나머지는 표와 목록, 넉넉한 여백.
2. **색은 뜻이다.** 열은 냉기→주의→위험 한 줄 눈금으로만, 합격·불합격은 상태 색으로만. 강조색(코발트)은 사람이 누를 수 있는 것과 고른 것.
3. **말은 사용자의 말로.** "블루프린트"가 아니라 "세계", "엔티티"가 아니라 "장비". 버튼은 일어날 일을 말한다("실험 시작", "조건 바꿔 다시 돌리기").
   빈 화면은 할 일을 알려 주고, 오류는 무엇이 왜 틀렸는지와 고치는 법을 말한다(서버의 한국어 메시지를 그대로 칸 옆에).
4. **못 하는 것은 숨기지 않는다.** 시뮬레이터가 아직 못 하는 블록·장애는 보이되 꺼져 있고, 이유가 함께 보인다(REQ-034).
5. **가볍게.** 3D는 종류별 인스턴싱으로 그리기 호출 수를 장비 수와 무관하게 묶고, 바뀔 때만 다시 그린다. 3D와 편집기는 그 화면에
   들어갈 때 내려받는다(REQ-036).
6. **긴 목록은 찾아서 고른다.** 선택지가 120개를 넘는 목록(월드의 장비)은 "이름으로 찾기" 칸이 위에 생기고 처음 100개만 보인다. 손이 닿기 전에는 고른 것 하나만 그린다(REQ-034, REQ-041, ADR-0049).
7. **말투는 해요체 하나, 한 화면에 한 가지 ([ADR-0050](adr/0050-toss-ux-principles.md)).** 문장은 "~해요"로 끝나고, 버튼은 "~하기", "확인", "다음", "닫기", "멈추기"로 말한다("취소"는 쓰지 않는다).
   버튼 `Button`의 `why`는 꺼진 이유를 `title`과 `aria-describedby`로 알린다. 누르는 곳은 높이 32 px, 너비 24 px 이상이다(문장 속 링크는 예외). 화면마다 주된 버튼은 하나다.
8. **보조 기기로도.** 3D 캔버스는 `role="application"`에 이름("…의 3D 보기")이 있고 `aria-description`이 키(Q·E 돌리기, +/- 확대, Esc 나오기)를 읽어 준다. 안내는 화면의 글이 아니라 속성에 둔다. 첫 화면에 새 글자를 그리면 그 글자의 글꼴 파일(약 25 kB)을 더 받아 예산을 넘긴다. 시나리오 캔버스의 안내, 블록, 이음선, 조절 버튼 이름도 한국어다. 같은 이름의 링크가 표의 줄마다 있으면 줄의 이름을 `sr-only`로 붙인다("실험하기 (냉방기 정지)").
9. **키보드로도.** 모든 조작에 포커스가 보이고, 빌더는 R(회전)·Delete·Esc·Ctrl+Z를 쓴다. 그 키 안내 카드와 "?" 단추는 900px 아래(바닥 시트 폭, 폰)에서는 나오지 않는다(REQ-111). 움직임은 사람의 동작에 답할 때만, `prefers-reduced-motion`을 따른다.

## 3D 세계 (REQ-006, REQ-036, [ADR-0040](adr/0040-site-layout-and-world-stage.md))

세계는 하나의 3D 미니어처다. 사업장 → 건물(층을 펼침) → 서버룸 → 랙 → 서버로 들어가고, 한 곳(`WorldStage`)이 세 화면에 쓰인다.

- **둘러보기**(홈의 진열장, 세계 페이지): 건물·방·랙을 누르면 들어가고, 위 막대가 어디 있는지 알려 준다. 끌면 돌리고 Shift나 오른쪽 끌기는 옮기고 휠은 확대한다.
- **짓기**(타이쿤 빌더): 빌더가 층(사업장 / 층 / 서버룸)을 주면 카메라가 그 층에 머물고, 포인터는 평면 좌표와 그 아래 물건을 알려 주며,
  선택 윤곽과 다음에 놓을 자리(유령)는 그림 위에 덧그린다. 건물이나 서버룸을 두 번 누르면 들어간다.
- **사업장 풍경**: 지도에서 옮긴 외곽선 안에 팹(파란 지붕)과 데이터센터(회색 자갈 지붕)가 흩어져 서고, 옆에 설비 마당, 길, 나무, 사람·고양이·새·승용차·화물차·탱크로리·고라니·너구리가 돈다.
  방문객은 장식일 뿐이라 화면이 느려지면 수가 줄지만(단계마다 절반, 종류마다 하나는 남는다) 멈추지는 않는다.
- **부지 배치와 동물**(REQ-105, [ADR-0128](adr/0128-campus-layout-and-animals.md), [설명](campus-layout.md)): 도로(폭 6 m) → 건물마다 주차장(서버 40대에 한 칸) → 칸 안의 차 → 3 m 떨어진 나무(울타리·길가 줄, 작은 숲) 순서로 깔려 어떤 것도 겹치지 않는다. 고양이와 새를 누르면 대답한다(고양이는 기지개·야옹·걷기·앉기, 새는 날아올라 한 바퀴). 소리는 설정의 "소리"로 끄고, 움직임 줄이기에서는 소리와 말풍선 한 줄만 나온다.
- **캠퍼스 꾸미기**(REQ-055, [ADR-0045](adr/0045-campus-decoration.md)): 건물 사이 빈 땅은 도로 격자에 맞춘 블록으로 나뉘어 사무동·기숙사·주차 건물·유틸리티동(냉각탑·굴뚝·배관)·탱크·운동장·연못·공원·공사장으로 채워진다. 용도는 건물과의 거리에 따라 정하고, 모든 것은 사업장 이름에서 정해져 열 때마다 같다. 사진을 베낀 것이 아니라 일반적인 캠퍼스를 흉내 낸 것이다.
- **지금 일하는 에이전트**(REQ-050, [ADR-0041](adr/0041-live-activity.md)): 세계 페이지와 빌더가 `/api/worlds/:id/activity`를 구독해, 실험이 돌아가는 동안 실행마다 색이 다른
  마커를 그 실행이 이름 댄 장비 위에 올린다(보기는 천천히 숨 쉬고, 조작은 빠르게, 기다림은 아주 느리게, 답 제출은 멈추고, 실패는 붉다). 지나온 곳은 궤적으로 잇고,
  이름표는 겹치면 밀려난다. 오른쪽 아래 패널이 실행마다 에이전트·모델·하네스·실험과 지금 하는 일을 적고, 누르면 카메라가 그 장비로 간다. 도는 실행이 없으면 아무것도 그리지 않는다.

- **온도와 공기 흐름**(REQ-072, [ADR-0074](adr/0074-airflow-map.md), [설명](airflow-map.md)): 데이터 홀 안에서 `WorldStage`는 `air` 입력을 받으면 `AirMap`을 얹는다. 처음에는 왼쪽 아래의 조용한 버튼 하나뿐이고(`AirDoor`, 첫 화면 묶음에 있어 늘 떠 있다), 누르면 **지도 모드**가 되어 빌더의 놓기·카드·아래 막대가 접히고 그림이 화면을 채운다(위 막대는 "돌아가기"와 주된 버튼 "시운전" 하나). 위에 조용한 선택 두 줄(3D / 위에서 본 지도, 흡기 온도 / 배기 온도 / 공기 흐름)과 늘 보이는 한 줄("냉방기 풍량과 랙 발열로 계산한 방향과 세기예요. 유체 해석(CFD)이 아니에요"), 옆에 접히는 카드(`.air-card`: 색 설명, 냉방기, 고른 랙, 가장 더운 곳, 시간 막대)가 뜬다.
  위에서 본 지도는 같은 장면을 정사영 카메라로 본 것이다. 새 스타일은 `styles.css`의 `air-*` 규칙뿐이고 토큰은 그대로다. 움직임 줄이기 설정에서는 멈춘 화살표만 보인다.

- **화질**(REQ-036, [ADR-0049](adr/0049-adaptive-3d-quality.md), 기준값은 [ADR-0082](adr/0082-quality-degrade-amend-tests.md)가 고쳤다): 그림은 세 단계(`high`·`low`·`min`)이고 내려갈 때 값비싼 효과가 빠지거나 줄어든다. 자세한 기준과 줄이기 단계는 아래 [그래픽 품질과 줄이기](#그래픽-품질과-줄이기)에 있다.

3D 계산(장면·카메라·좌표)은 `logic/world3d`에서 DOM 없이 테스트하고, `ui/world3d`는 three.js로 그리기만 한다. 정적인 풍경은 재질별로 하나의 메쉬로 합쳐 그리기 호출을 묶는다.

## 그래픽 품질과 줄이기

느린 기계에서도 세계가 **멈추지 않게** 두 가지를 따로 한다. 하나는 그림 자체를 가볍게 하는 것(품질 단계, `logic/world3d/quality.ts`, 엔진이 적용)이고, 다른 하나는 움직이는 꾸밈(사람·방문객·공기·자동 회전)을 줄이는 것(줄이기 단계, `logic/world3d/strain.ts`)이다. 사용자는 설정에서 고른다.

**품질 단계** — 값비싼 효과만 빠진다. 색·모양·조명 방향은 같다.

| | `high` | `low` | `min` |
|---|---|---|---|
| 접촉 그림자(AO) | 켬 | 끔 | 끔 |
| 그림자 지도 | 4096 | 1024 | 1024 |
| 그리는 속도 상한 | 없음 | 30장/초 | 12장/초 |
| 해상도 배율 상한 | 2 | 1.25 | 1 |
| **그리는 픽셀 상한** | 300만 | 200만 | 120만 |
| 다중 표본 | 4 | 2 | 0 |
| 가장자리 다듬기(SMAA) | 켬 | 켬 | 끔 |
| **틸트시프트 흐림 세기** (`blur`) | 0.5 | 0.5 | 0 (패스를 뺀다) |

- **픽셀 상한**: 그리는 배율 = min(기기 배율, 품질의 배율 상한, √(픽셀 상한 ÷ 캔버스 가로×세로)), 단 0.5 밑으로는 내리지 않는다(`pixelRatioFor`). 2560×1440 모니터가 배율 2로 그리면 1,470만 픽셀을 접촉 그림자와 함께 칠하게 되는데, 이 상한이 그것을 300만 안팎으로 묶는다. 창 크기가 바뀔 때마다 다시 계산한다.
- **흐림**: 시점마다 정한 세기(`view-look.ts`의 `TILT`)에 품질의 `blur`를 곱한다. 높음에서도 예전의 절반이고, 0이면 틸트시프트 패스 둘을 아예 뺀다. 가장자리가 빛번짐처럼 보이던 것이 이 흐림이었다.
- **스스로 가벼워지기**(`QualityGovernor`): 그래픽 카드가 한 장을 끝낼 때까지 기다려 시간을 재고, 앞 3장은 버린 뒤 8장의 평균이 **25 ms(초당 40장)를 넘으면 `low`로, 50 ms(초당 20장)를 넘으면 `min`으로** 내린다. 한 장이 1.5초를 넘으면 바로 내린다. 다시 올리지 않는다. 프로세서로 그리는 기계(SwiftShader 등)는 `min`으로 시작한다. 내려갈 때 화면 아래에 한 줄이 뜬다: "그래픽을 가볍게 바꿨어요. 설정에서 되돌릴 수 있어요"(`QUALITY_NOTICE`, 사람이 직접 고른 때는 뜨지 않는다).

**줄이기 단계** — 프레임이 늦으면 단계(0~3)가 내려가고, 단계마다 움직이는 것이 절반이 된다. 완전히 서는 단계는 없다.

| 단계 | 공기 입자 | 화살표(방 전체) | 서버룸 사람(최대 4) | 방문객(종류마다) | 갱신 간격 | 자동 회전 |
|---|---|---|---|---|---|---|
| 0 | 600 | 전부(예: 34) | 4 | 전부 | 1배 | 돈다 |
| 1 | 300 | 절반(17) | 2 | 절반 | 2배 | 돈다 |
| 2 | 150 | 4분의 1(9) | 1 | 4분의 1 | 3배 | **쉰다** |
| 3 | 75 | 8분의 1(5) | 1 | 8분의 1 | 4배 | **쉰다** |

- 입자와 화살표는 방 전체에 번호를 매겨 **2^단계 번째마다 하나만** 남긴다(`keptAmong`). 합이 정확히 절반(올림)이고 길마다 남기는 것이 아니라 방 전체에 고르게 퍼지며, 길이 몇 개 통째로 빠질 수 있다. 공기는 30번/초, 사람과 방문객은 20번/초가 1배다.
- 사람은 걷는 엔지니어가 먼저 남고, 기사, 관리자 순이다(`peopleKept`). 사람을 줄여도 한 명은 걷는다. 빠진 사람은 그려지지 않고 눌리지도 않는다.
- **단계 판단**(`Strain`, 엔진이 프레임마다 한 번 먹인다): 40 ms를 넘는 프레임의 길이를 더하고, 빠른 프레임은 그 4분의 1만큼 갚는다. 1.2초가 쌓이면 한 단계 내려간다. 빠른 프레임이 6초 이어지면 한 단계 올라온다. 올라온 지 30초 안에 다시 내려가면 다음 올라오는 기다림이 두 배가 된다(최대 48초). 그래서 두 단계 사이를 오가며 깜박이지 않는다.
- 움직임 줄이기 설정(`prefers-reduced-motion`)은 따로다: 사람은 서 있고 공기는 멈춘 화살표만 보인다.

**설정**(`/settings`, 왼쪽 메뉴 맨 아래, 이름 위): 화면은 `logic/settings.ts`의 `SETTING_DEFS`를 한 줄씩 그린다. 새 설정은 `Settings`에 키를 더하고 `SETTING_DEFS`에 한 줄을 더하면 된다. 고르면 `localStorage`의 `terrarium.settings`에 바로 저장한다(저장소가 막혀 있으면 이번 방문 동안만). 값은 3D 화면이 열릴 때 읽는다.

| 그래픽 | 하는 일 |
|---|---|
| 자동(기본) | 위의 "스스로 가벼워지기"를 따른다 |
| 높음 | `high`로 고정. 판단하지 않는다 |
| 가볍게 | `min`으로 고정. 판단하지 않는다 |

주소의 `?quality=high|low|min`이 있으면 저장된 설정보다 앞서고, 이때도 고정이다.

## 실험 결과의 상황과 반복 (REQ-118, [ADR-0158](adr/0158-repeats-per-seed-and-seed-level-statistics.md))

- **만들기 3단계**: 첫 질문 "서로 다른 상황을 몇 개 돌릴까요"(단위 개, 권장 5개, 도움말 "상황이 다르면 고장이 나는 때와 사람들이 답하는 시간이 달라져요. 3개부터 벤치마크 순위에 올라요.") 바로 아래 둘째 질문 "같은 상황을 몇 번씩 돌릴까요"(1번·3번·5번·직접 단추 하나, "직접"을 고를 때만 입력칸, 1~10). 요약 막대는 기본 1이면 "실행 5번", 3이면 "실행 15번 (상황 5개 × 3번씩)"이고 한도(60번)를 넘으면 막대가 이유를 말한다. 막대는 그 화면의 주 행동 막대 하나다.
- **결과** ([ADR-0171](adr/0171-result-page-answers-three-questions.md)): 머리에 제목, 한 문장(무엇을, 어느 세계에서, 누가 언제 돌렸는지, 얼마나 끝났는지), "조건 바꿔 다시 돌리기"·"내보내기"·"공유"가 있고, 그 밑에 탭 넷(요약 · 실행 N번 · 업무 비교 · 세계 범위)이 주소의 `?tab=`로 선다. **요약**은 차례대로 "잘했나"("N번 중 M번 합격했어요", "평균 X점, 오차 ±Y점. 합격은 …", 조용한 한 줄, 점 그림), 포크면 "원본과 견주면", "어디서 점수를 잃었나"(항목 막대와 한 문장), "상황마다"(줄은 상황, 열은 1번째·2번째 …, 칸은 점수와 합격·불합격, 갈린 줄은 "갈렸어요"), "다음에 해 볼 것"(조건이 맞는 것만)이다. 점 그림은 끝난 실행마다 점 하나를 0~100 선에 놓고 합격선을 점선으로 그으며 합격은 채운 동그라미, 불합격은 빈 네모이고 `role=img`의 글이 개수를 말한다. **실행**은 실행 표(640px 이하에서는 실행마다 두 줄)·나란히 보기·더 돌리기·시험한 조건·계보이고, **업무 비교**와 **세계 범위**는 있던 구역 그대로다("객체·링크·액션 표 내보내기"는 세계 범위에 남는다). 내보내기 창은 "무엇을 내보낼까요" 하나를 묻고 서버에 있는 보고서(HTML·Markdown·글)와 진단 기록만 고르게 한다. 운영 실험의 요약은 점수가 없다는 말과 실행으로 가는 길만 두고, 도는 실험은 점 그림과 표가 끝나는 대로 채워진다. 실행은 "번"으로 센다. 요약의 사슬은 순수 함수(`logic/result-*.ts`)가 만들고 시험이 있다.
- **순위표**: 실행 열에 "3번 / 상황 3개", 순위 없는 줄은 "상황 3개부터 순위에 올라요".

## 세계 만들기와 빌더의 말 (REQ-077, [ADR-0083](adr/0083-world-making-redesign.md))

검토와 원칙은 [세계 만들기 검토](world-builder-review.md)에 있다. 화면에 올라간 것만 적는다.
- (REQ-094가 대체함: 새 세계는 이제 입구 페이지와 서비스부터 세 화면이다 — 아래 "세계 만들기 입구와 직접 짓기".) **새 세계**는 카드 둘이었다: "사업장 그대로"(추천, 기본 포커스)와 "작게 시작". 사업장 그대로는 사업장 카드 여섯 + 규모(작게·보통·실제 그대로, 랙 수와 걸리는 시간) + 결과 문장("랙 N대 · 서버 약 N대 · 전력 약 N MW — 실제 화성사업장 규모예요") + 접힌 "더 정하기"(건물 · 서버룸 · 서버 세 묶음, 칸마다 한 줄)다. 이름과 "같은 세계 다시 만들기 번호"는 그 안이다. 규모는 앞 것보다 랙이 많아야 보인다(작은 사업장은 작게가 빠진다). 만드는 동안 단계 문장("사업장 짓는 중 → 서버룸 채우는 중 → 거의 다 됐어요")이 뜨고, 서버가 진행을 알려 주지 않아 시간을 따른다.
- **작게 시작**은 이름 하나로 땅 300 × 200 m, 데이터센터 하나, 빈 서버룸 하나(채우면 랙 24대)를 연다. 땅 모양은 접힌다. 처음 한 번 "둘러보기 할까요?"를 묻는다(브라우저에 기억).
- **빌더**(REQ-102, [ADR-0123](adr/0123-ladder-and-builder-focus.md), 목업 [ux-round3-mockup.html](mockups/ux-round3-mockup.html) 화면 3·4)는 주인공 하나다. 3D 그림이 화면이고 둘레에는 셋만 있다. 예전의 왼쪽 팔레트("여기서 할 일"), 위 통계 줄, 떠 있는 U 카드, 접히는 절 셋(크기와 모양 / 냉방과 전기 / 돈), 여덟 줄 키 안내는 없다.
  - **놓기**: 3D 왼쪽 위의 버튼 하나. 아무것도 고르지 않았을 때 주된 버튼(cobalt), 무엇이 골라져 있으면 보조 버튼이다(아래 막대의 "다 지었어요"는 떠나는 길이라 주된 버튼이 아니고, 여럿 가운데 고른 것은 `Button`의 `chosen`으로 보여 주며 주된 버튼이 아니다. ADR-0141). 누르면 작은 시트가 열리고 그 단계에 맞는 것만 보인다(서버룸 안: 랙 / 냉방기 / 전기 설비, 각각 작은 한 줄. 사업장: 땅 사기 / 건물 / 건물 밖 설비). 종류가 여럿인 것(냉방기·전기 설비·건물)은 고르면 다음에 종류를 묻는다. Esc나 바깥을 누르면 닫힌다. 무엇이 맞는지는 한 곳(`logic/builder/place.ts`)이 `toolsFor`에서 읽는다.
  - **카드는 고른 것이 있을 때만, 하나**: 이름 · 사실 한 줄("서버 20대 · 빈 곳 9U · 12.9 kW / 17.3 kW") · 랙이면 U 띠 · 일(돌리기 · 자동 배선 · 서버 넣기 · 지우기, 지우기는 위험색). 지우기는 자리에서 "안에 든 23개와 케이블도 같이 지워져요 — 지우기 / 그만"을 묻는다. 냉방과 전기의 사실은 필요한 곳의 그 한 줄에 접어 넣고, 돈은 아래 막대에 있다. 서버룸·건물을 고르면 같은 모양의 카드에 그 자리의 사실이 든다(`logic/builder/one-card.ts`, `ui/builder/OneCard.tsx`).
  - **아래 막대가 유일한 상태 줄**이다: 이동 경로(부지 › 건물 › 서버룸 › 랙) · 합계("랙 7대 (서버 랙 6 + 기반 랙 1) · 서버 120대 · 전원 여유 579 kW · 113억 원", 기반 랙은 줄마다 맨 앞의 스파인·스토리지 랙이다(REQ-111); 랙 안에서는 "이 랙 20대 · 4.2억 원 · 서비스 0개") · "?" · 서버룸으로 · 다 지었어요. "다음 할 일" 칩은 막대 위에 뜨고(`bottom: 막대 높이 + 14px`; 640px 이하와 토폴로지 보기에서는 판 위에 뜨지 않고 막대 안 "다 지었어요" 옆에 들어간다, ADR-0146), 그 위에 **"에이전트 5개가 일하는 중"** 한 줄 칩(`ActivityPanel`, 같은 에이전트는 "×5"로 묶고 누르면 칩 위로 목록이 열린다), 그 위에 이끼 알약이 선다(폰 너비에서는 아래 탭 줄 위에 선다). 1440·1280·1024·390px에서 셋과 막대가 겹치지 않는 것을 UX 여정 `own-card-only`가 잰다(REQ-111).
  - **시운전**: 위 막대의 주된 버튼은 "시운전 10분", 도는 중에는 "시운전 중 3/10분", 끝나면 위 가운데에 알약 "시운전 10분 · 알람 0건 · 가장 더운 곳 27°C · 전원 여유 579 kW"가 뜨고 버튼은 "다시 시운전"이 된다. 시운전 전 안내는 "시운전하면 …"이라고 말한다. (옛 이름은 "돌려 보기".)
  - **키 안내**는 처음 한 번 네 줄(R 돌리기 · Delete 지우기 · Ctrl+Z 되돌리기 · 두 번 누르기 안으로)과 "알았어요"다. 나머지는 "?" 뒤에 있다. 저장은 자동이고("저장됨 · 방금"), 서버룸은 처음 열릴 때 랙이 있는 첫 서버룸에서 열린다.
- **설정**의 화면 색은 `:root[data-theme]`로 건다(시스템은 속성 없음). **화면 폭**은 `--page`(1,200~1,440 px)이고 세계 보기와 실험 결과는 가득 채운다. 홈의 세계 보기는 폭 가득, 높이 60vh 이상.
- **서비스**: 서버·VM·스토리지를 고르면 작은 카드에 "서비스" 줄이 보이고(`ServerCards.tsx`), 서비스 이름을 누르면 그 서비스가 골라지며 "서비스 더하기"로 새 서비스를 단다. 서비스를 고르면 종류(요청 처리·배치·상태 유지)와 멈추면 시간당 피해(배치는 늦어지는 시간)를 고치고, 피해는 어림한 값이라는 안내가 붙는다.
- **실험 3단계**는 "서로 다른 상황을 몇 개 돌릴까요"(권장 5개), "에이전트가 쓸 도구"(묶음마다 한 줄과 "권장"), 접힌 "고급 설정"(시간 흐름·장비 API 버전)이다.

## 세계 만들기 입구와 직접 짓기 (REQ-094, [ADR-0107](adr/0107-world-entry-two-doors-ha-ladders.md)·[0108](adr/0108-world-entry-iap-and-chip-cards.md))

동작과 규칙은 [세계 만들기 입구와 서비스부터](world-entry.md)에 있다. 화면에 올라간 것만 적는다.
- `/worlds/new`는 질문 하나("무엇을 하려고 하세요?")와 문 둘, 아래 "저장해 둔 세계에서 시작"이다. **문은 글뿐인 카드**(제목 · 한 줄 · 메타 · 가는 말)다. 입구 그림은 비워 두고, 나중에 3D 렌더로 채운다(REQ-104, 제품 책임자 결정 2026-11-07). 서비스부터는 같은 페이지 안의 세 화면이고, 아래에 `we-bar`(position: fixed, `data-bottom-bar`)가 "이전 / 다음"(마지막 화면은 "세계만 만들기 / 실험 시작")을 둔다. 첫 화면은 **카탈로그 행**(이름 · 한 줄 · 만든 사람과 칭호 · 잠김/공유됨, 그림·돈 없음)과 카탈로그 시트다([카드](service-catalog.md)). 서비스가 둘 이상이면 둘째 화면이 서비스마다 한 번씩 나온다("서비스 2 / 2": 기본은 "같은 모양" 카드와 "따로 고르기" 링크, 누르면 컴퓨트·스토리지·데이터베이스·앱 네 층의 사다리가 열린다. [규칙](world-entry.md#서비스마다-다른-모양-adr-0108-결정-5-adr-0112)). 스타일은 `ui/pages/world-entry.css`(앱 토큰만 쓴다), 페이지와 함께 늦게 내려온다.
- 사다리의 칩은 라디오 그룹의 라디오다(`role=radiogroup`/`radio`, 화살표 키로 옮김). 칩을 올려 두거나 포커스하거나 누르면 오른쪽 카드(`aria-live`)가 바뀐다. 그림은 `aria-label`이 있는 SVG다. 점선 칩은 REQ-106부터 없다. 사이트 칩 카드에는 "복구 목표" 줄이 있다. 토폴로지 글리프에 쿠버네티스 클러스터·노드·워크로드 셋이 더해졌다.
- 빌더에는 **오른쪽 패널이 없다**. 왼쪽 "여기서 할 일"과 3D, 3D 위의 카드들(랙 정면·서버 넣기·서버 카드·서비스 카드·자세히 카드), 아래 막대(단계와 그 단계의 합계, "?")다. 토폴로지 보기와 공기 지도 모드도 같은 카드를 쓴다. 왼쪽 도구 상자의 접힌 "조작법 ?"는 아래 막대의 "?" 도움말로 합쳤다(3D 탭에서만, 첫 진입에 한 번 오른쪽 위에 저절로 뜨고 무언가를 고르면 닫힌다. 토폴로지 탭에는 뜨지 않는다. ADR-0146).

## 빌더 카드는 고른 물체 옆에 붙는다 (REQ-109, [ADR-0132](adr/0132-world-entry-sizing-and-ux-fixes.md))
3D 위의 카드(랙 정면·서버 넣기·서버 카드·서비스 카드·자세히 카드)와 아래의 **놓기** 시트는 같은 자리 규칙을 쓴다. 고른 물체의 화면 위치는 밖의 저장소(`anchorStore`)가 들고 있고, 월드 무대가 그릴 때마다 윤곽 상자 위쪽을 `view.screenOf`로 투영해 알린다(React 상태가 아니라 카메라를 돌려도 다시 그리지 않는다). 자리는 순수 함수 `placeCard`가 정한다: 물체 오른쪽 위, 모자라면 왼쪽·아래·위, 어디서든 화면 가장자리에서 16px 안쪽이고 너비는 `min(320px, 100vw - 32px)`이며 가로 스크롤은 없다. 900px보다 좁으면 아래에서 올라오는 시트이고, 놓기 시트는 놓을 자리를 가리지 않게 버튼 아래에 붙는다. 물체를 못 찾으면 마지막 자리를 쓰고 고름을 풀면 사라진다(`Anchored`가 카드 크기를 `ResizeObserver`로 잰다). 시험: `card-place.test.ts`(네 너비 1440·1280·1024·390)와 Playwright 걷기(`scrollWidth` ≤ `clientWidth`).

## 빌더의 돈 (REQ-059, [ADR-0051](adr/0051-real-world-prices.md))

빌더 위쪽의 "들인 돈"은 **보고 있는 층**의 합이다. 사업장을 보면 땅(산 땅만)과 모든 건물·방·장비이고, 층을 보면 그 층의 벽과 방 마감과 장비이며, 방을 보면 방 마감과 안의 장비다.
짓는 값(`structureCostM`)은 층의 바닥 넓이 × 용도 단가, 방의 용도별 마감, 컨테인먼트의 틀이고, 장비 값은 모델의 `costM`이다. 왼쪽 도구 상자의 건물·방·컨테인먼트 항목에는 "㎡당 N" 이,
장비 항목에는 값이 붙는다. 팔고 있는 땅을 고르면 넓이(㎡·평)와 값, 평당 값이 보이고, 새 사업장 만들기의 "땅값 기준"은 어느 시장의 값인지와 그 값을 얼마나 믿을지를 한 줄로 말한다.
단가와 값의 근거는 [현실의 가격](real-prices.md)에 있다.

## 서버룸과 건물의 크기 (REQ-075, [ADR-0079](adr/0079-room-resize.md), [ADR-0080](adr/0080-room-pieces.md))

방이나 건물을 고르면(방 안에서는 방 자체, 층에서는 건물) 두 가지 방법으로 크기를 바꾼다.

- **3D 화면**: 노출된 변마다 가운데에 흰 네모(손잡이)가 선다. 끌면 그 변이 타일(0.6 m, 건물은 5 m) 단위로 움직이고, 방의 변 바깥에는 파란 +가 서서 끌어내면 그 변에 조각이 붙는다.
  손잡이 위에 포인터를 올리면 힌트 줄이 "끌면 이 변이 움직여서 크기가 바뀌어요"(네모)나 "바깥으로 끌어내면 조각이 붙어요"(+)라고 말한다. 끄는 동안 힌트 줄이 "가로 × 세로 · 넓이 N m² · 건설비 +N"을 말하고, 놓일 자리가 초록(안 되면 빨강) 유령으로 보인다. 놓으면 한 번의 편집으로 기록에 들어가고 Ctrl+Z로 돌아간다.
  손잡이는 `logic/builder/handles.ts`가 층·방의 평면 좌표로 계산하고(`handlesFor`, `handlePlan`), 화면은 그리기만 한다(`PlanOverlay.setHandles`). 방의 윤곽 선택선은 조각이 있으면 합친 윤곽을 따라 그린다.
- **옆 패널**(`ui/builder/SizePanel.tsx`): 가로·세로 칸(Enter나 칸을 떠날 때 한 번 적용하고, 막히면 이전 숫자로 돌아간다), 방이면 본체·조각 1…n 중 고르는 칩, 조각을 골랐으면 "조각 떼기". 조각은 3D 화면의 테두리 +로만 붙인다(네 변 버튼은 없다). 아래에는 넓이(m²). 이 패널은 카드의 "크기 바꾸기"를 눌렀을 때만 카드 안에서 펼쳐진다(REQ-102).
  조각은 3D 화면에서 방을 한 번 더 눌러도 고른다.
- **막힐 때**: 토스트와 패널이 이유를 말한다("랙 3이 밖으로 나가게 돼요. 먼저 옮겨 주세요", "조각이 서로 겹쳐요"). 건물 바닥을 넘으면 "건물이 꽉 찼어요. 건물을 넓혀요"와 **건물 넓히기** 버튼,
  건물이 아직 안 산 땅을 넘으면 기존 문장과 **옆 땅 사기** 버튼이 붙는다. 랙을 놓을 빈 자리가 없을 때는 거절 문장 끝에 "서버룸이 꽉 찼어요. '서버룸 넓히기'로 넓혀요"가 붙고,
  서버룸 채우기 패널도 꽉 찬 방(생성된 세계 포함)에서 **서버룸 넓히기** 버튼으로 크기 칸에 데려간다. 이 화면의 주된 버튼은 늘 하나이고 크기 패널의 버튼은 모두 보조다.
- **그려지는 모양**: 방의 바닥(타일)은 조각마다 한 장씩 깔리고 이음매에는 선도 벽도 없다. 벽·유리·몰딩은 합집합의 윤곽을 따라 서고, 스프링클러 배관은 윗벽에서 가장 긴 변을 따른다.
  층·건물 단면과 방 안, 위에서 본 지도가 모두 같은 윤곽을 쓴다(`RoomScene.rects/outline/bounds`, 없으면 직사각형). 사람 경로는 `insideRoom`(core)과 `insideScene`(3D 쪽)으로 방 안인지 물으면 된다.
  생성된 세계는 직사각형 방 그대로이고, 조각은 사람이 붙인다.

## 실제 크기, 빈 바닥, 설비 (REQ-076, [ADR-0081](adr/0081-real-building-size.md))

지도에서 자리를 잡은 사업장의 건물(`props.sizeLocked`)은 **실제 크기**다. 손잡이도 크기 칸도 "건물 넓히기"도 없고, 건물을 옮길 수는 있다(`handlesFit`이 거절하고 `reshape`가 크기가 바뀌는 편집을 막는다). 건물 패널의 층 단추 줄에도 "층 더하기"가 없고 그 자리에 "실제 층수예요"가 적힌다(`Inspector.tsx`의 `Floors`).
직접 그린 사업장의 건물은 그대로 손잡이와 "건물 넓히기"가 있다. 그 사슬(방 → 건물 → 옆 땅)은 직접 그린 사업장에서만 산다.

- **빈 바닥 패널**(`RealSizePanel.tsx`의 `RealSizeNote`): 건물이나 방을 고르면, 또는 층·방 화면에서 아무것도 안 골라도 "이 건물은 실제 크기예요 · 이 층 빈 바닥 586 m² · 다른 층 9,699 m²"가 보이고(제목 줄 없이 한 번만, 카드 안에서)
  (직접 그린 건물은 첫 마디 없이), 층 바닥에서 방·베이·코어를 뺀 풀이와 빈 바닥이 있는 다른 층으로 가는 버튼이 붙는다. 계산은 `core.world.floorSpace`다.
- **옅은 초록**: 층 단면(건물을 연 그림)의 바닥에 방이 덮지 않은 바닥이 옅은 초록으로 깔린다(`FloorScene.bare`, `Materials.freeFloor`). 방을 고르면 "여기까지 늘릴 수 있다"가 보인다.
  코어가 차지하는 12%는 어디인지 정해진 자리가 없어서 초록에도 섞여 있다. 패널의 숫자(코어를 뺀 값)가 기준이다.
- **방을 넓힐 때**: 손잡이를 끌거나 크기 칸에 적거나 조각을 붙이면 방은 그 층의 빈 바닥 안에서만 자란다. 손잡이를 너무 멀리 끌면 빨갛게 되는 대신 **갈 수 있는 곳까지 가서 멈추고**
  (이진 탐색으로 타일 단위로 찾는다) 힌트 줄이 "… · 여기가 끝이에요"를 말한다. 놓으면 거기까지 적용되고 이유가 패널에 남는다.
  이유는 셋이다: 층이 꽉 찼으면 "이 층은 꽉 찼어요. 3F에 320 m² 비어 있어요"와 그 층으로 가는 버튼, 다른 층도 꽉 찼으면 "이 건물의 다른 층에도 빈 바닥이 없어요",
  벽이나 옆 방에 닿았는데 층에 빈 바닥이 남았으면 "건물 벽에 닿았어요. 이 층 빈 바닥 N m²는 다른 쪽에 있어요". 직접 그린 건물은 층이 꽉 차면 기존 "건물이 꽉 찼어요. 건물을 넓혀요"다.
- **랙 수**: 방이 커지면 크기 패널에 "랙 N대가 더 들어가요"(늘어난 바닥 ÷ 2.6 m²)가 보이고, 끄는 동안 힌트 줄에도 붙는다.
- **냉방과 전기**(REQ-102 전에는 오른쪽 패널의 접힌 절이었다. 지금은 절이 없고 카드의 사실 한 줄에 필요한 만큼만 든다. 아래는 설비를 나누는 규칙이다): 방의 랙을 식히는 설비(항온항습기·CDU·플랜트)를 "냉방"으로, 전기를 나르는 설비(수배전반·ATS·UPS·발전기)를 "전기"로 나눠 "항온항습기 6대 · 이 방 안", "CDU 2대 · 2F 기계실",
  "UPS 14대 · 2F 전기실"처럼 어디에 있는지와 함께 보여 주고(`roomSources`), 같은 층 기계실·전기실과 건물 밖 마당에 더 놓는 버튼을 준다(`outsideWays`).
  버튼은 그 방이나 사업장 화면으로 데려가 설비 도구를 손에 쥐여 준다. 마당은 건물 밖 설비(플랜트)를 놓는 원래 길이고, 옥상은 따로 두지 않았다.
- **전력 상한**: 사업장 화면에 "수전 용량 108 MW 중 89.7 MW를 쓰고 있어요"(추정 용량이면 "추정"과 설명)가 보이고, 랙의 장비·설비·서버룸 채우기·모델 바꾸기가 상한을 넘으면
  "전력이 모자라요. 108 MW 중 107.5 MW를 쓰고 있어요 (이 변경은 N kW를 더 써요)"로 막힌다(`assertPower`). 전력이 줄어드는 편집은 막지 않는다.

## 랙 안 — 실장 장면 (REQ-006, REQ-045, REQ-049, [ADR-0101](adr/0101-rack-containment-firmware-amend-tests.md))

랙을 누르면 카메라가 랙 앞 약간 비스듬한 자리(왼쪽 20°, 10° 위)로 와서 랙(실제 높이, 48U 랙도 포함)이 화면 높이를 거의 채운다. **서버룸 안만** 그린다: 사업장 마당·건물 바깥은 숨기고(`inRoomOnly`), 하늘 대신 방 벽 색 배경과 안개(`Engine.setBackdrop`, `ROOM_WALL`)와 가장자리 비네트(`.stage-vignette`)를 두며, 컨테인먼트 지붕·문은 투명하다. 같은 줄의 양옆 랙은 옅은 반투명 모양(불투명도 0.28)으로 남고 나머지 랙은 치운다. 틸트시프트는 약하게(0.25) 쓴다. 한 랙은 이렇게 그린다.

- **눈금**: 왼쪽·오른쪽 레일에 U 번호(1U가 맨 아래), 5U마다 굵은 눈금과 굵은 글자(`rulerTicks`; 텍스처 하나).
- **종류별 전면**(`logic/world3d/rack-front.ts`의 `frontOf`): 1U 서버는 드라이브 베이 8개 한 줄, 2U는 12개 두 줄, GPU 서버는 통풍 격자와 청록 띠, 스토리지는 베이 12개 × 줄, 스위치는 포트 24개 한 줄(2U면 48개)과 링크 LED. 베젤 색이 종류마다 다르다. 오른쪽에 전원 LED(초록, 경고·알람이면 주황, 전원이 없으면 꺼짐)와 네트워크 LED가 있다. **네트워크 LED는 활동이 있는 장비만**(`busyDevices`: 가상 머신이 도는 서버나 부하가 있는 서버, 그런 서버가 있으면 그 랙의 스위치와 스토리지) 0.4초마다 깜빡이고 나머지는 꺼져 있다. 줄이기 단계가 1 이상이거나 움직임 줄이기이면 깜빡이지 않고 켜져 있다.
- **빈 U**는 옅은 블랭크 패널이고, 맨 위 1U가 비어 있으면 ToR 스위치 자리로 옅은 파랑이다(`gapsOf`, `hasTor`).
- **케이블**은 뒤쪽 좌우 수직 트레이에 묶인 두 다발이다: 왼쪽 네트워크(파랑), 오른쪽 전원(빨강·검정). 장비마다 뒷면 포트에서 트레이까지 짧은 선이 하나씩만 있고, 개별 케이블 수백 개는 그리지 않는다.
- **서버를 누르면** 그 서버가 7 cm 나오고(주황 윤곽) 랙이 0.6초 돌아 뒷면이 보인다: 전원 공급장치(2~6개, 녹색 LED), 팬, 네트워크 포트, 전원선과 네트워크선. 같은 서버를 다시 누르면 앞면, 다른 서버를 누르면 그 서버로 바뀐다(뒷면 그대로). **Esc**는 서버를 넣고 앞면으로, 한 번 더 누르면 한 단계 위로 나간다. 오른쪽 패널은 기존 서버 정보 그대로다. 서버마다 앞뒤 어느 쪽에서도 눌린다. 움직임 줄이기에서는 바로 돈다.
- **안내**: 무대 아래 한 줄(`StageHint`)이 "서버를 누르면 랙이 돌아 뒷면이 보여요", 뒷면에서는 "같은 서버를 다시 누르면 앞면이 보여요. Esc를 누르면 서버를 넣어요"라고 말한다. 캔버스의 `aria-description`에도 한 문장이 있다.
- **그리기 비용**: 모든 것을 재질별로 합쳐 한 랙이 **그리기 호출 60회 이하**(그림자 포함, `RACK_DRAW_BUDGET`)다. 42U가 다 찬 랙(스위치·스토리지·GPU·2U·1U 섞임)을 시험이 34회로 세고(`rack-layer.test.ts`), 소프트웨어 렌더링 브라우저에서 서버 21대 랙을 실제로 세면 33회(메시 25 + 그림자 8)다.
- 가벼운 랙(묶음 랙)은 같은 모양으로 서버를 모델 한 종류로 되풀이한다. 액침 탱크는 서버가 냉각액에 잠긴 장면 그대로고 누를 서버가 없다.

## 컨테인먼트 안 (REQ-006, REQ-074, [ADR-0101](adr/0101-rack-containment-firmware-amend-tests.md))

방 층에서 컨테인먼트(닫힌 복도)를 누르면 그 컨테인먼트의 **지붕과 문이 0.6초 동안 투명해지며** 카메라가 복도 끝에서 눈높이(바닥 위 1.6 m)로 들어간다(움직임 줄이기에서는 바로). 안에서는 양쪽 랙 전면이 보이고 찬 복도(옅은 파랑 타일)와 더운 복도(따뜻한 색 바닥)가 바닥 색으로 나뉜다. 다른 컨테인먼트의 지붕과 문은 그대로 있다(`aisleBox`, `aislePose`는 `logic/world3d/aisle.ts`).

- **사람이 걷는다**: 이 모드에서만 그 컨테인먼트가 통행 가능 영역에 들어가고(`podBlocks(scene, except)`), 첫 엔지니어가 그 복도 가운데선을 순찰한다(`crewOf(scene, seed, inside)`). 그 밖에는 ADR-0078 그대로 컨테인먼트 안을 걷지 않는다.
- **나가기**: **Esc**나 무대 아래 **"복도 나가기"** 버튼(그 옆 줄이 "Esc를 누르거나 '복도 나가기'를 누르면 나가요"). 경로 줄에 방 다음 칸으로 "컨테인먼트 … 안"이 붙고, 그 앞 칸(방)을 누르면 나가진다. 다른 랙·방·건물을 누르거나 경로 줄로 옮겨 가도 나가진다.
- 건물 단면에서 컨테인먼트는 이전처럼 한 덩어리로 그려진다. 들여다보면 그 층의 지붕·문·기둥을 컨테인먼트마다 다시 합치고(그 컨테인먼트만 빼고), 빼낸 지붕·문은 따로 투명하게 만든다.
- 빌더(짓기)에서는 눌러도 들어가지 않는다(눌러서 고르는 곳이라서). 캔버스의 `aria-description`에 "랙에서 서버를 누르면 랙이 돌아 뒷면이 보이고, 컨테인먼트를 누르면 복도 안으로 들어가요."가 있다.

## 서버룸의 사람 (REQ-074, [ADR-0078](adr/0078-people-in-the-hall.md))

서버룸 안(빌더의 방 층, 둘러보기에서 방에 들어갔을 때)에는 사람이 있다. 엔지니어 한두 명이 통로를 오가고, 관제실에는 관리자가 책상에 앉아 있고(다른 방은 입구 쪽에 서 있고), 심각한 알람이 2분 넘게 이어지면 기사가 문으로 들어와 그 장비로 간다. 이름은 없고 옷 색만 다르다(엔지니어 남색, 관리자 회색, 기사 주황 조끼).
사람은 장면 꾸밈이다. 세계를 바꾸지 않고, 말풍선 어디에도 "고쳤어요"가 없다.

- **자리는 함수다**: `logic/world3d/crew.ts`(사람 만들기)와 `crew-plan.ts`의 `crewAt(crew, t, world)`가 시간과 "무슨 일이 있나"로 사람마다 자리·방향·자세(걷기·서기·일하기·앉기)와 가 있는 장비를 돌려준다. 상태를 들고 있지 않다. 평소에는 통로 가운데선을 왕복한다. 통로는 랙 줄 사이와 앞뒤이고, 컨테인먼트 안은 지붕과 유리에 가려 걷지 않는다(들여다보는 동안의 그 컨테인먼트는 예외다: 위의 "컨테인먼트 안" 절).
  알람이 난 장비(서버면 그 서버가 든 랙)가 있으면 가장 가까운 엔지니어가 걸어서(초속 1.2 m) 그 앞으로 가 "일하는 중" 자세를 취하고, 알람이 풀리면 순찰로 걸어 돌아간다. 실험 중 에이전트가 장비에 조치하면(활동 흐름의 마지막 조작) 같은 식으로 가서 일하고, 말도 "에이전트가 시킨" 쪽이다.
  길은 랙·설비·컨테인먼트 칸을 비켜 가는 최단 경로(`crew-route.ts`)이고, 방 윤곽 밖으로 나가지 않는다(`insideScene`). 움직임 줄이기에서는 모두 서 있고, 부른 장비 앞에는 서 있는다.
- **무슨 일이 있나**: 알람은 "시운전"이 기록한 순간마다 들어 있고(`PreviewFrame.alarms`), 공기 흐름 지도의 시간 막대를 끌면 그 순간의 알람으로 사람이 움직인다. 시간 막대를 안 쓰면 마지막 순간이다. 에이전트는 `useActivity`의 실행들이다(`crew-world.ts`가 방의 장비로 좁힌다).
- **말풍선**: 사람을 누르면(뒤의 장비는 선택되지 않는다) 머리 위에 한 줄이 4초 뜬다(`CrewBubble`, 사업장의 고양이·새를 눌렀을 때의 "야옹"·"짹"도 같은 모양으로 2초). 말은 `crew-lines.ts`에 상황별 3~5줄(평소 / 알람으로 가는 중 / 일하는 중 / 에이전트 조치 중 / 관리자 / 기사 / 다른 팀의 기사)이고, 같은 사람을 거듭 누르면 번갈아 나온다. 해요체, 이름·이모지·느낌표 없음. 말 묶음은 `crew-words.test.ts`가 용어집과 "고쳤다는 말 없음"을 지킨다.
- **다른 팀의 기사** (REQ-093, [도메인과 가상 담당자](domains-and-counterparts.md)): `escalate`로 넘긴 일의 현장 작업(부품 교체, 차단기 같은 방문)이 마지막 구간에 들어가면 기사가 문으로 들어와 그 장비 앞(심각한 알람이 부르는 자리와 같은 자리)까지 걸어가 일하는 자세를 취하고, 끝나면 문으로 걸어 나간다. 알람이 부르는 기사보다 먼저다. 말은 따로 있다("{장비} 작업하러 왔어요. 부품부터 꺼낼게요"). 원격 작업은 사람을 부르지 않는다. 기사를 부르는 것은 활동 흐름의 `partner` 사건(`PartnerWork`)이고, 달리는 중인 실험일 때 보인다.
- **비용**: 방 하나에 4명 이하, 메시는 사업장 사람과 같은 저폴리 인스턴스(역할마다 하나). 방을 볼 때만 있고, 프레임이 느리면 사람 수를 줄이고 덜 자주 그린다(서지는 않는다). 건물 단면에서는 그리지 않는다. 새 버튼은 없다.
  사람의 코드(`logic`의 `hallCrew` 이름공간과 `ui/world3d/crew-lazy.ts`)는 카메라가 방에 처음 들어갈 때 따로 내려받아 첫 화면 예산(700 kB)에 들지 않고, 공기 흐름 지도는 `AirDoor`의 버튼을 누르거나 그 위에 포인터를 올릴 때 계산과 그리는 코드까지 따로 내려받는다([설명](airflow-map.md)). 연결·벤치마크·실험·실행 화면도 처음 열 때 내려받아 첫 화면 예산 안에 든다.

## 실험 만들기의 툴 고르기, 사람 기다리는 중 카드 (REQ-080~082, [ADR-0087](adr/0087-tool-scope-escalation-sop.md))

실험 만들기 3단계(어떻게 시험할까요?)가 바뀌었다. 자세한 규칙은 [툴 범위, 에스컬레이션, 절차서](tool-scope-and-sop.md).

- **툴 고르기**(`pages/tool-picker.tsx`): 맨 위에 "이 시나리오에 필요한 툴 n개"와 칩, 아직 꺼 둔 것이 있으면 그 수, **필요한 것만 켜기** 버튼. 그 아래 검색 한 칸, 저장해 둔 묶음, 일곱 영역 카드(서버·전원·냉방·네트워크·가상화·관측·조치)가 접혀 있고 "2/5개 켬"이 보인다. 펼치면 툴마다 체크와 **흔함·드묾·없음 칩**(초록·노랑·빨강)이 있고, 드묾·없음을 켜면 "현실엔 거의 없는 툴이에요 — 이 툴의 가치를 재는 실험이 돼요"가 붙는다. 검색하면 맞는 툴이 있는 카드만 펼쳐진다. 키보드로 접기·체크·검색을 모두 할 수 있다.
- **고장 범위에 따른 시나리오 목록**(`pages/scenario-pick.tsx`): 1단계의 시나리오가 라디오 목록이다. "준 툴 안에서만"이면 풀 수 없는 시나리오는 회색이고 고를 수 없으며 이유("`restart_cooling_unit`이 없어서 풀 수 없어요")가 붙는다. "전부"면 고를 수 있고 이유와 "넘기기를 재는 실험이 돼요"가 붙는다.
- **넘기기 처리 · 고장 범위 · 절차서**(`pages/human-settings.tsx`): 3단계 툴 아래의 세 설정. 처리는 `ask_human`을 켜야 고를 수 있고, 정해 둔 답 칸은 "자동 응답"일 때만 나온다. 절차서의 "찾게 함"은 절차서 찾기 툴을 같이 켠다. 시나리오에 절차서가 없으면 그렇다고 알려 준다.
- **사람을 기다리는 중 카드**(`pages/escalation.tsx`): 홈 맨 위, 그 실험 화면, 그 실행 화면에 뜬다. 에이전트가 한 말, 최근 툴 호출 5개, 세계의 시간도 멈춰 있다는 안내, 그리고 탭 셋: **답만 하기**(글 입력), **대신 조치하기**(조작 일곱 가지 가운데 하나와 대상, 한 일 목록, "조치 끝, 에이전트에게 돌려주기"), **툴 더 주고 계속**(같은 툴 고르기, 이미 가진 툴은 켜진 채 고정). 또 **실행 끝내기**(한 번 더 묻는다). 2초마다 새로 읽는다.
- **결과 화면**(`pages/run-blocks.tsx`): "사람에게 넘긴 것"(넘긴 일 n번·기다린 시간·사람이 한 조치)과 "절차서 준수"(준수 %·단계 수행·순서·건너뜀, 단계별 했어요·순서가 달랐어요·건너뛰었어요) 블록이 복구 우선 숫자 카드 아래에 따로 선다. 점수에는 섞이지 않는다고 적혀 있다.
- **실험 만들기 2단계 MCP 안내**(`ui/pages/experiment-mcp.tsx`): 하네스와 에이전트를 고르면 그 아래 카드가 연결 종류에 맞게 달라진다. 실행형은 "실행을 시작하면 주소가 생겨요 · 등록 없음" 한 줄이고, 슬롯형은 "연결하고 슬롯 주소를 한 번만 등록해요" + 등록 여부("등록돼 있어요 ✓" / "아직 등록 안 했어요") + 주소·토큰 복사 + 세 줄 안내 + "등록했어요 · 연결 확인하기"(연결 다시 확인 API를 쓴다)이고, 등록돼 있으면 "등록돼 있어요 ✓"만 남는다. 두 경우 모두 "실행 주소와 슬롯 주소가 뭐가 달라요?"가 접혀 있다. 슬롯형인데 확인하지 않았으면 "툴 주소를 하네스에 한 번 등록하고 확인해 주세요"가 실험 시작을 막는다. 등록 표시는 이 브라우저에만 있다.
- **시나리오 편집기**: 흐름·채점표 옆에 **절차서** 탭(`scenario/Runbook.tsx`). 변별력 점검 패널에는 **툴 고르기 점검** 표(`scenario/ToolPickMatrix.tsx`)와 모호한 쌍이 더해졌다.

## 넘긴 일과 티켓 (REQ-093, [도메인과 가상 담당자](domains-and-counterparts.md))

실행 화면에는 다시 보기 아래, 채점표 위에 **"넘긴 일"** 구역이 있다(넘긴 일이 있을 때만). 도메인·고장·예상·진행(기다리는 중 / 작업 중 / 끝났어요)·끝난 때를 표로 보이고, 바로 아래에 넘긴 일마다 "임시 조치 / 마무리 / 동시 작업 / 넘긴 근거"를 한 줄씩 말한다(`logic/handoffs.ts`). 머리말 옆에 어느 도메인과 어떤 담당자 설정이었는지 적힌다. 티켓 툴을 켠 실험이면 그 아래에 **티켓 보드**(내가 할 것 / 기다리는 중 / 끝남 세 칸)가 있고, 저절로 만들어진 티켓에는 그렇게 적힌다. 달리는 중에도 같은 표가 호출마다 따라간다.
새 실험 3단계에는 **"내 도메인"**(여섯 가지 체크, 복수)이 있다. 고르면 그 도메인의 툴이 켜지고(`experiment.setDomains`) 아래에 **"SLA·예비 부품·팀"** 카드가 접힌 채 나온다: 벤더 SLA, 예비 부품, 일을 맡는 때, 야간·주말 가산, 바꾼 칸에 "바꿨어요", "기본값으로 되돌리기". 실험 요약에도 두 줄로 남는다. 시나리오 카드에는 "원인은 서버 도메인 · 내 도메인 서비스/OS·가상화 권장"이 붙는다.

## 운영 모드 화면 (REQ-090, [ADR-0094](adr/0094-operation-mode.md))

- **실험 만들기.** 1단계 맨 위의 "실험 종류"(사건 하나 / 운영)가 시나리오 고르기를 운영 설정으로 바꾼다: 운영 시간(8·24·48시간 버튼과 직접 입력), 시간(실시간 / 빨리 감기와 조용할 때의 배속), 고장은 어디서 와요(고장률 표의 조용함·보통·바쁨 / 이 세계의 시나리오 세트), 연쇄·동시 고장 확률. 3단계에는 "에이전트에게 주는 지시문" 칸, "권장안 넣기" 버튼, 권장안의 줄마다 "왜 이렇게 쓰나", 고른 하네스 종류에 맞는 주의, 저장해 두기(서버: 이름 붙여 저장·불러오기·이름 바꾸기·지우기), "알람마다 깨우기"(연결이 못 받으면 회색 + 이유), 툴 호출 상한이 있다. 오른쪽 요약은 "8시간 운영 · 빨리 감기 30배 · 공식 점수 아님"을 보인다.
- **중간 점검 카드.** 홈("지금 돌고 있는 운영")과 실험 화면에 운영이 도는 동안 "14시간째 · 열린 사건 1 · 놓친 알람 0 · 다음 담당자 완료 2시간 뒤". 실행 중 기록을 5초마다 다시 읽는다.
- **운영 결과.** 첫 줄이 서비스 가용률 · 놓친 알람 · 탐지 지연, 그 아래에 사건별 복구 시간 막대(못 끝낸 것은 빨강), 비용과 감시 숫자. 위에는 "8시간 운영 · 빨리 감기 30배 · 공식 점수 아님 · 운영 시간 끝(8시간)". 끝난 이유는 운영의 말이다: 운영 시간 끝(8시간) · 멈춤(사람) · 호출 상한(5,000회). 실행 목록·실험의 "끝난 이유"·카드도 같고, 실행 상태 "멈춤"은 운영에서 "멈춤(사람)"이다. 서버가 멈췄다 이어진 운영은 그 아래에 "서버가 다시 시작돼 3분 뒤 이어 갔어요"가 붙는다. 합격·채점표·진단 비교는 없다.
- **저장해 두기(`ui/presets.tsx`).** 지시문·툴 묶음·내 절차서가 같은 막대를 쓴다: 저장해 둔 것 고르기 · 불러오기 · 지우기, 고르면 "바꿀 이름"과 이름 바꾸기, 이름 붙여 저장(같은 이름이면 내용을 바꿔요). 지우면 7일 안에는 "되돌리기"가 나온다. 서버가 만든 사람별로 보관하므로 다른 브라우저에서도 보이고, 이 브라우저(localStorage)에 있던 옛 저장분은 처음 열 때 서버로 한 번 옮기고 지우며 "이 브라우저에 있던 저장분을 서버로 옮겼어요"를 알린다.
- **시간 막대.** 운영의 리플레이는 같은 막대에 "봤다" 점(알람을 보여 주는 조회만), "사람 개입" 점, 사건마다 발생에서 끝까지의 막대를 더한다.
- **연결 화면.** "운영 모드로 연결" 버튼이 설계 가이드(`/guides/operation`)로 간다. 가이드는 `docs/guides/operation-agent-guide.md`를 그대로 화면에 보인다(`logic/mini-markdown.ts`가 읽는다).

## 세계 순서·좋아요·칭호 (REQ-101, [ADR-0122](adr/0122-world-popularity-likes-titles.md), [설명](ranking-and-titles.md))

- 홈의 "지금 도는 운영" 아래 "세계"(카드 세 개, "전부 보기")와 `/worlds`(카드 전부)는 같은 카드를 쓴다. 위에 고르개 **인기 / 요즘 활발 / 새로 생김 / 내 세계**(기본 인기, 이 브라우저에 기억)와 순서의 뜻 한 문장이 있고, 세계가 없으면 홈은 구역을 감춘다. 카드는 이름, 하트와 개수(누르면 바로 바뀌고 서버가 바로잡는다), 근거 "실험 128번 · 좋아요 24 · 이번 주 +12", 만든 방법·규모, 만든 사람과 칭호다. 칭호는 `--fill` 알약 최대 둘(색·단계 없음)이고 눌러서 연 팝오버에 전부가 조건·날짜와 함께 나온다. 왼쪽 아래 내 이름 밑, 세계 카드, 실험 표의 만든 사람 칸에만 달고 홈의 "최근 실험" 표에는 달지 않는다. 계급은 아직 어디에도 안 나온다(대회 모드와 함께).

## 이끼 — 테라리움 도우미 (REQ-103, [ADR-0124](adr/0124-moss-assistant.md), [ADR-0125](adr/0125-moss-requires-model.md), [설명](moss.md))

오른쪽 아래의 조용한 "이끼" 버튼이 오른쪽 360px 패널을 열고(쪽에 `padding-right`를 줘 내용을 가리지 않는다, 머리는 "이끼 · 화면 이름", 질문 칩 셋은 화면 등록부 `apps/web/src/moss/registry.ts`에서), 처음 온 사람에게만 "처음이세요? 같이 만들어요"를 한 번 말한 뒤로는 알림도 팝업도 없다(`localStorage`, `try/catch`). 기본 모델이 없으면 이끼는 꺼져 있다([ADR-0125](adr/0125-moss-requires-model.md)): 홈 첫 화면 설명 아래 한 줄 "모델을 등록하면 이끼가 깨어나요 → 설정"(`/settings#models`, 흐름 안, 떠 있지 않다. ADR-0146)만 남고 패널·`Cmd+K`·`/`·"?"·첫 인사가 없다. `Cmd+K`·`/`는 같은 입력칸을 연다: 동작 이름과 맞는 짧은 글은 실행·이동, 문장은 질문. 결과·사다리·설정·실험 화면의 숫자와 용어 옆 작은 "?"(`MossAsk`, `MOSS004`)는 올려 보거나 포커스할 때만 보이고(터치는 늘 보인다) 누르면 질문을 채워 패널을 연다. 떠 있는 버튼은 아래 막대(`data-bottom-bar`) 위로 올라선다([설명](moss.md#화면에서의-자리-req-104)). 바꾸거나 시작·삭제하는 동작은 "이렇게 할게요" 카드의 **하기 / 그만**을 눌러야 하고, 여러 단계 일은 체크리스트로 보이며 사용자가 직접 누르면 "이어서 할까요?"로 멈추고, 동작 중 대상에 1초 동안 이끼 초록 테두리가 둘린다. 쪽의 버튼은 `data-moss-action` 또는 `data-moss-skip="이유"`를 달고(`MOSS002`), 새 쪽은 등록부에 칸을 더한다(`MOSS001`).

## 코드 구조

- `web.logic`: DOM 없이 테스트하는 모든 계산 — API 클라이언트, 경로, 빌더 편집 연산과 3D 장면 모델, 시나리오 ↔ 캔버스 변환, 실험 마법사 검증, 표시 형식. 커버리지 하한이 걸린다.

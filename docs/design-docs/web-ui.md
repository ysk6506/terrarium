# 웹 화면 (REQ-006, REQ-030~041)

## 무엇을 위한 화면인가

사내 인프라·AI 엔지니어가 **세계를 짓고, 장애 시나리오를 만들고, 에이전트를 돌려 보고, 결과를 비교**한다. 화면의 주인공은
유리 상자 안의 작은 데이터센터다. 이름 그대로 테라리움: 밖에서 들여다보는 밀폐된 세계. 나머지 화면은 조용히 받쳐 준다.

## 토큰

| 이름 | 값(밝음 / 어두움) | 쓰임 |
|---|---|---|
| paper | `#EDF1EE` / `#101B18` | 바탕. 서리 낀 유리처럼 차가운 회녹색 |
| surface | `#F8FAF9` / `#16241F` | 패널, 표 |
| ink | `#17302A` / `#E3ECE8` | 글자, 기본 버튼 |
| ink-2 | `#4E625C` / `#9DB2AA` | 보조 글자 |
| line | `#C8D3CE` / `#2A3B35` | 경계선 |
| cobalt | `#2F55D4` / `#7F9BFF` | 선택, 포커스, 링크 — 조작의 색 |
| 상태 | 정상 `#2F7D6D`, 주의 `#C9821A`, 위험 `#C43D2B`, 냉기 `#3A86C9` | 데이터의 색. 장식에 쓰지 않는다 |

- 글꼴: **Pretendard Variable**(번들, 쓰는 글자만 내려받는 분할 파일). 숫자는 `tabular-nums`. 한 가족만 쓴다.
- 크기: 13 · 14 · 16 · 20 · 26 · 34px (≈1.25배). 본문 16, 표와 편집기는 14.
- 모서리: 조작 요소 6px, 패널 10px, 3D 유리 상자는 각진 모서리. 모든 것에 같은 둥글기를 쓰지 않는다.
- 그림자 대신 경계선. 떠 있는 것(메뉴, 대화상자)만 그림자.

## 원칙

1. **하나만 화려하게.** 3D 세계(유리 상자 안의 바닥 타일, 랙, 열 색)만 눈길을 끈다. 나머지는 표와 목록, 넉넉한 여백.
2. **색은 뜻이다.** 열은 냉기→주의→위험 한 줄 눈금으로만, 합격·불합격은 상태 색으로만. 강조색(코발트)은 사람이 누를 수 있는 것과 고른 것.
3. **말은 사용자의 말로.** "블루프린트"가 아니라 "세계", "엔티티"가 아니라 "장비". 버튼은 일어날 일을 말한다("실험 시작", "조건 바꿔 다시 돌리기").
   빈 화면은 할 일을 알려 주고, 오류는 무엇이 왜 틀렸는지와 고치는 법을 말한다(서버의 한국어 메시지를 그대로 칸 옆에).
4. **못 하는 것은 숨기지 않는다.** 시뮬레이터가 아직 못 하는 블록·장애는 보이되 꺼져 있고, 이유가 함께 보인다(REQ-034).
5. **가볍게.** 3D는 종류별 인스턴싱으로 그리기 호출 수를 장비 수와 무관하게 묶고, 바뀔 때만 다시 그린다. 3D와 편집기는 그 화면에
   들어갈 때 내려받는다(REQ-036).
6. **키보드로도.** 모든 조작에 포커스가 보이고, 빌더는 R(회전)·Delete·Esc·Ctrl+Z를 쓴다. 움직임은 사람의 동작에 답할 때만, `prefers-reduced-motion`을 따른다.

## 화면 구조

```
┌──────┬───────────────────────────────────────────────┐
│ 홈   │  제목                              [주 동작]   │
│ 세계 │───────────────────────────────────────────────│
│ 시나 │                                               │
│ 리오 │  내용 (목록은 표, 편집기는 화면 전체)          │
│ 실험 │                                               │
│ 벤치 │                                               │
│ 마크 │                                               │
│ ──── │                                               │
│ 이름 │                                               │
└──────┴───────────────────────────────────────────────┘
```

| 경로 | 화면 | 요구사항 |
|---|---|---|
| `/` | 홈: 바로 할 일 세 가지, 내 최근 실험, 대기열 | REQ-030 |
| `/worlds`, `/worlds/:id` | 세계 목록과 만들기(짓기·사업장으로 생성·현실에서 가져오기), 타이쿤 빌더 | REQ-006, 009, 010, 035, 036 |
| `/scenarios`, `/scenarios/:id` | 시나리오 목록, 노코드 편집기(블록 + 채점표 + 미리 돌려 보기) | REQ-033, 034 |
| `/experiments`, `/experiments/new`, `/experiments/:id` | 실험 목록, 만들기, 실시간 진행과 결과·공유·포크·계보 | REQ-030, 037, 038, 040 |
| `/runs/:id` | 실행 하나: 타임라인, 툴 호출, 지표, 진단 대 정답, 하네스 트레이스 | REQ-037 |
| `/benchmarks` | 벤치마크 세트별 순위, 디지털 트윈 내보내기 | REQ-039, 015 |

## 코드 구조

- `web.logic`: DOM 없이 테스트하는 모든 계산 — API 클라이언트, 경로, 빌더 편집 연산과 3D 장면 모델, 시나리오 ↔ 캔버스 변환,
  실험 마법사 검증, 표시 형식. 커버리지 하한이 걸린다.
- `web.ui`: React 화면. 상태를 logic에 맡기고 그리기만 한다. 사용자 여정은 UX 하네스(Playwright)가 확인한다(REQ-041).

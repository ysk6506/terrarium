# 고장 종류별 리드타임 (ADR-0100)

`escalate(domain)`을 부르면 그 시점에 그 도메인에 있는 고장들이 **고장 종류별 리드타임** 뒤에 사라진다. 이 표가 그 리드타임의 근거이고, 구현은 `world/lead-times.ts`의 데이터 표(`LEAD_ROWS`)다. 값은 세계 시간이고, 분포는 로그정규(최소·보통·최대가 5·50·95 백분위)를 보통 값에서 둘로 나눈 것이라 세 값을 정확히 지나며, 뽑은 값은 최소~최대 안에 가두고 10분 단위로 맞춘다. 시드 `s`와 고장 `f`면 `s:lead:f`에서 항상 같은 값이 나온다. 아래 표의 값이 **기본값**이고 시험이 이 표와 코드가 같음을 센다.

## 일의 네 갈래
| 갈래 | 뜻 | 가산 | 예 |
|---|---|---|---|
| 원격(remote) | 네트워크로 하는 설정·재시작 | 없음 | OS 고장, 데이터베이스 고장 다섯, 오버레이 고장 여섯(터널 끊김만 방문), VM 폭주, 냉방 설정값 틀어짐, 펌웨어 올리기 실패 |
| 방문(visit) | 사람이 와야 하지만 부품은 필요 없다 | 야간·주말 | 차단기 트립, ATS 고착, 스토리지 경로 끊김, VXLAN 터널 끊김(막힌 스위치 포트) |
| 교체(replace) | 부품을 바꾼다 | 야간·주말 | 팬, PSU, 디스크, 메모리, 냉방기, 칠러, 스위치, 스토리지 컨트롤러, 분산 스토리지 노드 |
| 외부(external) | 건물 밖의 일이라 우리가 못 당긴다 | 없음 | 한전 정전 |

## 실험이 바꾸는 것, 안 바꾸면 이 표
새 실험 3단계의 "SLA·예비 부품·팀" 카드에서 네 가지를 바꾼다(`LeadTimeSettings`). 안 바꾸면 기본값이고, 결과와 실험 요약에 어떤 설정이었는지("기본값" 또는 "벤더 4시간 · 예비 부품 모두 없음 · 야간·주말 ×1.5 · 평일 낮에 시작") 남는다. 설정은 실험 조건(레시피)의 일부라 순위표의 세트를 가른다.
- **벤더 SLA**: 4시간 / 익일(기본) / 3일. 표의 "부품을 주문해야 하는" 값(아래 `주문` 열)에 0.25 / 1 / 3을 곱한다. 어느 쪽이든 1시간 아래로는 내려가지 않는다.
- **예비 부품**: 부품마다 기본값(아래 `예비 기본`) / 모두 있음 / 모두 없음. 있으면 현장 교체 범위(`예비` 열), 없으면 주문 범위를 쓴다.
- **야간·주말 가산**: 켜져 있으면(기본) 요청 시각이 평일 18시~익일 08시 또는 주말일 때 방문·교체의 **보통과 최대**에 ×1.5. 최소는 그대로다.
- **일을 맡는 때**: 평일 낮(화 10시, 기본) / 평일 밤(화 22시) / 주말(토 10시). 에이전트가 일을 맡은 순간이 이 시각이고, 거기서 세계 시간이 흐른 만큼 요일과 시각이 간다. 가산은 `escalate`를 부른 시각으로 정한다.

**계산 예 1 (예비 부품 있음·없음)**: 메모리 불량은 기본으로 예비가 있어 4시간 / 1일 / 3일이다. "모두 없음"이면 주문 범위 1일 / 2일 / 5일(익일 계약). 거기에 벤더 SLA를 4시간으로 하면 ×0.25라 6시간 / 12시간 / 30시간, 3일로 하면 ×3이라 3일 / 6일 / 15일이다. 예비가 있으면(기본·"모두 있음") SLA는 상관이 없다.

**계산 예 2 (주말)**: 같은 메모리 불량(예비 있음)을 평일 낮에 넘기면 4시간 / 1일 / 3일, 주말에 넘기면 4시간 / 1일 12시간 / 4일 12시간이다. 같은 날 원격으로 푸는 디스크 꽉 참(OS)은 주말이어도 15분 / 30분 / 1시간 그대로다.

## 공통 규칙
- **동시 요청**: 같은 도메인에 고장이 여러 개면 각각 따로 센다(담당자가 여럿이라고 본다). 다만 같은 장비의 고장은 가장 긴 것 하나로 묶는다.
- **나중에 생긴 고장**: 넘긴 시점에 있던 고장만 센다.
- **표준 벤더 SLA 가정**: 현장 응답 4시간, 부품 익일(NBD) — 기업 유지보수 계약의 흔한 조건이고 기본 설정이다.
- **마지막 구간이 일하는 구간이다**: 교체는 끝나기 30분 전부터 기사가 장비 앞에 있고, 방문은 20분 전, 원격은 10분 전부터 담당자가 작업을 시작한다. 3D와 토폴로지가 이 구간을 보인다.

## 정직한 한계
- 값은 업계 통상 SLA와 경험값이며 사내 계약·사업장 실측으로 바꿔야 한다. 지금 바꿀 수 있는 것은 위의 네 가지(벤더 SLA, 예비 부품 모두 있음·없음, 야간·주말 가산, 일을 맡는 때)뿐이다.
- 설계에 있던 **부품별 스페어 목록**(어떤 부품만 있나), **팀별 평일 주간·야간·주말 응답 시간**, **고장 종류별 직접 지정**(실측 티켓 이력)은 아직 없다. 실측 데이터가 쌓이면 이 표를 보정하는 것이 쌍둥이 ②의 일부다.
- 설정 변경류 실수(포트 shutdown, VLAN, 콘센트 꺼짐)는 세계의 고장 목록에 없어 넘겨도 풀리지 않는다. 표의 행은 남겨 두었다.
- 담당자의 되묻기·거절·우선순위 경쟁은 모델에 없다(ADR-0100).

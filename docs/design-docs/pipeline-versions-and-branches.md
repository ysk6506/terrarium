# 파이프라인의 버전과 브랜치 (REQ-115·116 예정, ADR-0166)

말은 [데이터 용어집](glossary-data.md)을 따라요. 아직 만들지 않았어요.

## 한 줄로

파이프라인(소스 설정 + 정제 + 매핑 + 링크 정의)은 저장할 때마다 버전이 남아요. 고칠 때는 브랜치에서 고치고, 미리보기 세계로 결과를 본 뒤 운영에 병합해요. 잘못됐으면 이전 버전으로 되돌려요.

## 1. 버전을 매기는 것은 셋이에요

| 무엇 | 한 버전이 담는 것 | 언제 새 버전이 생기나 |
|---|---|---|
| 파이프라인 | 소스 설정(비밀 값 제외), 정제, 매핑, 중복 병합 규칙, 링크 정의 전부 | 정의를 저장할 때. 누가·언제·왜를 같이 남겨요 |
| 스냅샷 | 한 번의 수집으로 받은 원본 데이터셋 | 수집할 때. 고치지 않아요 |
| 세계 | 객체와 링크 | 결과가 달라질 때 |

```
스냅샷 (소스 A 11/12 09:00) ─┐
스냅샷 (소스 B 11/12 09:05) ─┼─▶ 파이프라인 v14 ─▶ 세계 v203
스냅샷 (엑셀 11/10 올림)    ─┘
```

- 세계의 버전은 **어느 파이프라인 버전으로 어느 스냅샷들을 돌렸는지**를 적어요. 둘이 같으면 같은 세계가 나와요.
- "이 링크가 왜 사라졌나"에 둘 중 하나로 답해요: 소스의 데이터가 바뀌었다, 또는 정의가 바뀌었다.
- 파이프라인은 층마다가 아니라 통째로 버전을 매겨요. 층들이 서로를 가리키기 때문이에요. 화면은 층별로 무엇이 바뀌었는지 나눠 보여 줘요.

## 2. 브랜치: 운영에 영향 없이 고쳐 봐요

```
운영 브랜치   v12 ── v13 ── v14 ─────────────── v15 (병합)
                      └─ 브랜치 "bgp-링크-고치기" ─┘
                           └▶ 미리보기 세계 (관리자만 봄)
```

| | 운영 브랜치 | 브랜치 |
|---|---|---|
| 몇 개 | 하나 | 클로즈 베타는 하나("초안"), 오픈 베타부터 여럿 |
| 수집 | 주기에 따라 | 안 해요. 운영이 받아 둔 스냅샷을 써요 |
| 정의 고치기 | 병합으로만 | 자유롭게 |
| 결과 | 운영 세계 | 미리보기 세계 |
| 실험·영향 범위 조회 | 대상 | 대상 아님 |

- 브랜치가 소스에서 다시 가져오지 않으니 소스에 부하가 늘지 않고, 브랜치는 자격 증명을 갖지 않아요.
- 새 소스를 더하는 브랜치만 그 소스를 수동으로 한 번 수집해요. 주기는 병합된 뒤에 돌아요.
- 쓰지 않는 브랜치는 정해 둔 기간 뒤에 닫혀요.

## 3. 비교: 병합 전에 차이를 둘로 봐요

| 차이 | 보여 주는 것 |
|---|---|
| 정의의 차이 | 층별로 무엇이 바뀌었나. 예: "링크 정의 1개 변경: BGP 이웃의 조건" |
| 세계의 차이 | 객체 +12 / −0 / 속성 변경 340, 링크 +1,180 / −8, 문제 목록 31건 → 3건, 미사용 행 2,360 → 14 |

- 사라지는 객체와 링크는 목록으로 내려받을 수 있어요.
- 영향 범위가 달라지는 예를 몇 개 골라 보여 줘요("스파인 1대가 죽을 때: 영향 서버 0대 → 48대").

## 4. 병합과 충돌

- 병합은 수집 결과를 적용할 때와 같은 안전장치를 거쳐요([소스 관리](source-management.md) 3절): 객체가 10% 넘게 사라지면 멈추고, 사람이 확인해요.
- 브랜치가 갈라진 뒤 운영이 바뀌었으면, 먼저 최신 운영을 브랜치에 받아 미리보기를 다시 만들어요.
- 충돌은 항목 단위예요: 같은 데이터셋의 정제, 같은 객체 타입의 매핑, 같은 링크 타입의 정의를 양쪽이 고쳤을 때. 사람이 어느 쪽을 쓸지 골라요. 글자 단위로 섞지 않아요.

## 5. 되돌리기

- 이전 파이프라인 버전을 **새 버전으로 다시 올려요**. 이력은 지우지 않아요.
- 남아 있는 스냅샷으로 세계를 다시 만들어요. 다시 만든 세계도 새 버전이에요.

## 6. 쌓이는 운영 데이터

- 객체와 링크의 행마다 "언제부터 언제까지 이 값이었나"가 남아요. 지난 시점의 세계를 조회해요("11월 10일 14시의 토폴로지").
- 실험과 실험용 복사본은 세계의 버전을 고정해요. 운영 세계가 바뀌어도 실험의 조건은 그대로예요.
- 스냅샷은 소스마다 최근 것을 정해 둔 수만큼 보관해요. 남아 있는 세계 버전이나 실험이 가리키는 스냅샷은 지우지 않아요. 지워진 스냅샷이 필요한 세계 버전은 "다시 만들 수 없음"으로 표시해요.

## 7. 순서

| 때 | 들어가는 것 |
|---|---|
| 클로즈 베타 | 파이프라인 버전과 이력, 되돌리기, 브랜치 하나("초안"): 고치기 → 미리보기 → 비교 → 적용 |
| 오픈 베타 | 이름 붙인 브랜치 여럿, 충돌 고르기, 지난 시점 조회 화면 |

초안도 저장하는 모양은 브랜치와 같아요. 여럿으로 넓힐 때 다시 만들지 않아요.

## 하지 않는 것

- 데이터를 브랜치하고 병합하지 않아요. 병합하는 것은 정의예요. 데이터는 정의와 스냅샷에서 다시 만들어요.
- 운영 브랜치의 정의를 화면에서 바로 고치지 않아요.
- 미리보기 세계로 실험하지 않아요.

## 시험 (만들 때)

| 시험 | 내용 |
|---|---|
| 재현 | 같은 파이프라인 버전 + 같은 스냅샷 = 같은 세계 (행까지 같다) |
| 격리 | 브랜치에서 무엇을 고치고 돌려도 운영 세계와 운영 브랜치의 버전이 바뀌지 않는다. 브랜치의 경로에서 소스의 자격 증명에 닿는 길이 없다 |
| 비교 | 비교가 말한 세계의 차이와, 병합한 뒤 실제로 바뀐 것이 같다 |
| 병합 | 안전장치에 걸리는 병합은 적용되지 않고 운영이 그대로다. 양쪽이 고친 항목은 고르기 전에는 병합되지 않는다 |
| 되돌리기 | 되돌린 뒤의 세계가 그 버전을 처음 돌렸을 때의 세계와 같다(같은 스냅샷이 남아 있을 때) |
| 지난 시점 | 어느 시각을 조회하면 그 시각에 운영이던 세계 버전의 객체와 링크가 나온다 |
| 보관 | 세계 버전이나 실험이 가리키는 스냅샷은 지워지지 않는다 |

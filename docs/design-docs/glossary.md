# 용어집 (ADR-0071)

화면, 오류 문장, 문서에 쓰는 말의 기준이다. 코드의 타입 이름(`inject_fault`, `FaultType`)은 바꾸지 않는다. 바꾸는 것은 **사람이 읽는 말**이다.

## 쓰는 법
- 한국 사람이 일하면서 실제로 쓰는 말을 쓴다. 번역투("고쳐지기", "투입되다")와 만든 말은 쓰지 않는다. 확신이 없으면 **동료에게 말로 설명할 때 쓸 말**을 고른다.
- 버튼과 블록 이름은 명사형("고장 발생", "저장")이거나 "~하기"다. 문장은 해요체다 (ADR-0050).
- 전문 용어는 그 분야 사람이 쓰는 그대로 쓴다(VLAN, BGP, 차단기 트립). 풀어 쓸 수 있으면 풀고, 못 풀면 한 줄 설명을 곁에 둔다.
- 영문 코드, 내부 id, JSON은 화면에 나오지 않는다.

## 정한 말

| 쓰지 않는 말 | 쓰는 말 | 어디서 |
|---|---|---|
| 장애 주입 | **고장 발생** | 블록 이름 |
| 장애 해제 | **고장 복구** | 블록 이름 |
| 장애 종류 / 장애 세부값 | **고장 종류 / 세부 설정** | 블록 폼 |
| 장애 (묶음 이름, 홈 문구) | **고장**, 또는 실제로 일어나는 일("냉방기가 멈춰요") | 팔레트, 홈 |
| 장애 티켓·지시문 | **상황 설명** | 에이전트 투입 폼 도움말 |
| 시험지 점검 | **변별력 점검** | 편집기 패널 |
| 기준선 에이전트 / 기본 에이전트 셋 | **기준 에이전트** (아무것도 안 함 · 찍기 · 정답만 앎) | 변별력 점검 |
| 주입하다 / 투입되다 | 일으키다 / 맡기다 | 문장 |
| 유지 시간 0초 | **고쳐질 때까지** / **n분 뒤 저절로 복구** | 고장 발생 폼 |
| 툴 호출 한도 | **툴 호출 상한** | 에이전트 투입 폼 (채점표와 같은 말) |
| 제한 시간 (시뮬레이션) | **제한 시간** + 단위 "분" | 에이전트 투입 폼 |
| 미리 보기 | 미리 돌려 보기(옛 이름), 드라이런 | 시나리오 편집기의 버튼. 세계를 짓는 "시운전"과 다른 말이다 |
| 세계 | 그대로 (한 사업장이나 여러 사업장을 담은 가상의 데이터센터). 홈에서 한 번 풀어 말한다 | 전체 |
| 에이전트 투입 | 그대로 | 블록 이름 |

## 운영 모드에서 정한 말 (REQ-090, ADR-0094)

| 쓰는 말 | 쓰지 않는 말 | 어디서 |
|---|---|---|
| **운영** (정해진 시간 동안 맡는 실험) / **사건 하나** (시나리오 하나를 푸는 실험) | 연속 모드, 에피소드 | 실험 종류 |
| **실제 시간** | 벽시계, 월 클럭, 리얼 타임 | 시간 설명, 결과 |
| **실시간** / **빨리 감기** (조용할 때만 N배) | 가속, 타임랩스 | 시간 고르기 |
| **놓친 알람** (올라온 뒤 어떤 조회로도 보지 않은 알람) | 미확인 알람, 누락 | 결과 첫 숫자 |
| **탐지 지연** (고장이 난 뒤 처음 확인하기까지) | MTTD | 결과 첫 숫자 |
| **서비스 가용률** | SLA 달성률, 업타임 | 결과 첫 숫자 |
| **감시 주기** (알람을 확인한 간격의 중앙값) | 폴링 간격 | 결과 |
| **알람마다 깨우기** | 푸시, 웹훅 | 실험 변수 |
| **지시문** (에이전트에게 주는 운영 지침) | 시스템 프롬프트 | 실험 만들기 |

## 서버룸 크기에서 정한 말 (REQ-075, ADR-0079, ADR-0080)

| 쓰는 말 | 쓰지 않는 말 | 어디서 |
|---|---|---|
| **조각** (방에 변을 맞대 붙인 직사각형. 처음 직사각형은 "본체") | 확장부, 날개, 서브룸, 증축 | 방 크기 패널, 3D 손잡이 |
| **조각 덧붙이기** (3D 화면의 테두리 +를 끌어서) | 조각 추가 | 3D 손잡이, 방 크기 패널의 안내 |
| **조각 떼기** | 조각 삭제 | 조각을 고른 방 크기 패널 |
| **서버룸 넓히기** (방이 꽉 찼을 때 가는 길) / **건물 넓히기** | 확장하기, 증설 | 랙을 놓을 수 없을 때의 문장, 서버룸 채우기 |
| **가로·세로** (m) | 폭·깊이, 너비 | 크기 칸 |
| **넓이 N m²**, **건설비 +N** | 타일 N장, 타일 수량, 공사비 | 끌 때 안내 줄 |

문장은 이유를 먼저 말하고 해요체로 끝낸다: "랙 3이 밖으로 나가게 돼요. 먼저 옮겨 주세요", "건물이 꽉 찼어요. 건물을 넓혀요".

## 건물의 실제 크기와 빈 바닥에서 정한 말 (REQ-076, ADR-0081)

| 쓰는 말 | 쓰지 않는 말 | 어디서 |
|---|---|---|
| **실제 크기** ("이 건물은 실제 크기예요") | 고정 크기, 잠긴 크기, 크기 제한 | 건물·방 패널 |
| **빈 바닥** (층 바닥에서 방·클린룸 베이·코어를 뺀 만큼) | 여유 공간, 잔여 면적, 가용 면적 | 건물·방 패널, 끌 때 안내 줄, 층 단면의 옅은 초록 |
| **코어** (승강기·계단·복도) | 공용부, 유틸리티 공간 | 빈 바닥 설명 |
| **이 층은 꽉 찼어요. 3층에 320 m² 비어 있어요** | 면적이 부족합니다, 증설 불가 | 방을 넓힐 때 막히는 문장 |
| **랙 N대가 더 들어가요** (늘어난 바닥 ÷ 랙당 2.6 m²) | 수용 가능 랙 수, 랙 용량 | 방 크기 패널, 끌 때 안내 줄 |
| **냉방**, **전기** (방 패널의 접힌 절 "냉방과 전기") | 식히는 설비, 먹이는 설비, 지원 설비, 부대 설비 | 방 패널 |
| **수전 용량** (사업장이 한전에서 받는 전력) / **추정** (공개된 값이 없을 때) | 계약 전력, 전력 한도 | 사업장 화면, 막히는 문장 |
| **전력이 모자라요. 108 MW 중 107.5 MW를 쓰고 있어요** | 전력 부족, 용량 초과 | 랙·설비를 놓을 때 막히는 문장 |

문장은 이유를 먼저 말하고 해요체로 끝낸다. 방이 벽에 닿았을 때는 층이 꽉 찬 것이 아니므로 "건물 벽에 닿았어요. 이 층 빈 바닥 N m²는 다른 쪽에 있어요"라고 따로 말한다.

## 세계 만들기에서 정한 말 (REQ-077, ADR-0083)

| 쓰는 말 | 쓰지 않는 말 | 어디서 |
|---|---|---|
| **서버룸** | 데이터 홀, 데이터홀 (생성기가 짓는 방 이름까지) | 모든 화면 |
| **냉방 / 전기** | 식히는 설비 / 먹이는 설비 | 방 패널 |
| **사업장 그대로 / 작게 시작** (결과로 고르는 카드) | 직접 짓기, 사업장으로 생성, 현실에서 가져오기 | 새 세계 |
| **작게 · 보통 · 실제 그대로** (규모) | 상세 모델링 비율, 랙 채움 비율 | 새 세계 |
| **같은 세계 다시 만들기 번호** | 시드 | 더 정하기 |
| **다음: 서버룸 채우기** (다음 할 일 칩) | 가이드, 튜토리얼 | 빌더 |
| **고칠 곳 n건** | 경고 n개, 오류 목록 | 빌더 |
| **몇 번 돌릴까요 / 권장 5번** | 실행 횟수, 시드 목록 | 실험 3단계 |
| **화면 색: 시스템 · 밝게 · 어둡게** | 테마, 다크 모드 | 설정 |

### 숫자와 단위
- 숫자는 아라비아 숫자 + 단위로 쓴다: "랙 10,502대", "전력 90 MW", "1~20번". "랙 일곱 대", "1만 7천 대"는 쓰지 않는다. 네 자리 이상은 쉼표를 찍는다.
- 단위는 숫자에 붙인다: "24대", "30kW", "14.4 m". 단위 없이 떠 있는 숫자는 없다("연구동 3" → "연구동 3동").
- 한 문장에 숫자 표기가 둘이면 하나로 맞춘다. 어림은 "약"을 붙이고 두 자리까지만 센다("서버 약 190,000대").
- 같은 숫자를 한 화면의 두 군데에 보이지 않는다. 돈은 실험에 들어가는 숫자가 아니라서 숫자줄에서 뺀다.

### 글 잣대
해요체. "장애" 대신 "고장". 한 문장에 한 정보. "~할 수 있어요"를 겹쳐 쓰지 않는다. 시스템의 말을 쓰지 않는다. 버튼은 결과를 말한다("화성사업장 만들기"). 꺼진 버튼은 이유를 버튼에 적는다. 선택지는 결과로 말한다. 빈 상태는 상황 한 줄 + 버튼 하나. 설명 속에 따옴표로 버튼 이름을 쓰지 않는다. `world-words.test.ts`가 이를 기계로 읽는다.

## 서버룸의 사람에서 정한 말 (REQ-074, ADR-0078)

| 쓰는 말 | 쓰지 않는 말 | 어디서 |
|---|---|---|
| **엔지니어**, **관리자**, **기사** (역할만, 이름 없음) | 직원, 운영자, 작업자, 사람 이름 | 서버룸의 사람, 말풍선 |
| **순찰**, **살펴보는 중**, **일하는 중** | 점검 완료, 조치 완료 | 말풍선 |
| 사람은 보고 걷고 기다릴 뿐 **고쳤다고 말하지 않는다** | 고쳤어요, 복구했어요, 해결했어요 | 말풍선 (고치는 것은 시나리오와 에이전트뿐) |

## 토폴로지 보기에서 정한 말 (REQ-078, ADR-0084)

| 쓰는 말 | 쓰지 않는 말 | 어디서 |
|---|---|---|
| **토폴로지** (화면 이름), **층**: 전원 · 냉방 · 네트워크·가상화 | 레이어, 계층, 의존도 | 빌더 위 막대, 층 탭 |
| **영향 범위** (기대던 것을 잃은 곳) | 폭발 반경, 파급, blast radius | 상자 이름, 범례, 회색 타일 |
| **냉방이 그대로면 12분 뒤 심각(32°C)** | 12분 후 임계 도달 | 영향 범위 상자 |
| **묶음**(같은 상태의 장비를 접은 타일), **접힌 것**, **펼치기** | 클러스터, 그룹핑, 집계, 확장 | 타일 이름, 그린 타일 줄, 타일 설명 |
| **그린 타일 7개 · 접힌 것 16,565개** ("그린"은 그리다의 뒤) | 노드 7개, 렌더링된 요소 | 오른쪽 위 줄 |
| **정상 랙 408대**, **더워지는 중 랙 11대**(냉방 층), **영향 범위 랙 11대**(전원·네트워크 층), **알람 랙 3대**, **고장 냉방기 1대** (상태, 무엇, 몇) | 408개 랙(정상) | 묶음 타일 이름 |
| **에이전트가 만지는 곳** | 접근 중인 노드, 활성 엔티티 | 범례, 파랑 타일 |
| **멈췄어요**, **전기가 끊겼어요**, **차단기가 떨어졌어요** | 다운, 오프라인, 트립됨 | 타일 아래 상태 줄 |

상태 줄은 말 하나와 숫자 하나다("흡기 27.4°C", "92% 돌아가요", "배터리 61%"). 타일 이름은 장비 이름 그대로다.

## 글 점검에서 정한 말 (2026-11-04, 화면 글 2,888개를 뽑아 본 뒤)

같은 것을 다르게 부르던 짝은 한쪽으로 정했다. 왼쪽을 쓴다.

| 쓰는 말 | 쓰지 않는 말 | 왜 |
|---|---|---|
| 툴 | 도구 | 실험·채점표가 쓰는 말이고 에이전트 쪽 사람들이 "툴"이라 부른다. 연결 양식의 "도구"도 바꾼다 |
| 더하기 | 추가, 넣기 | 버튼은 "~하기" (ADR-0050). 블록도 "블록 더하기" |
| 지우기 | 삭제 | 서버가 권한 오류에 끼워 넣는 말까지 |
| 고치기 | 수정 | 같은 이유 |
| 멈추기 | 취소 | ADR-0050 |
| 세계 | 월드 | 노드 오류 두 군데 |
| 심각 / 경고 | 위험 / 주의 | 알람 단계 이름은 데이터센터 운영에서 쓰는 critical/warning 그대로 |
| 고장 종류 | 고장 유형, 장애 종류 | |
| 점수 | 배점 | |
| 채점표 (한 줄은 채점 항목) | 채점 기준 | |
| 이유 | 까닭 | |
| 알람 | 경보 | |
| 돌리기 / 시운전 | 가동, 돌려 보기(빌더, REQ-102 전) | 빌더의 "시운전 10분"도 |
| 연결할 수 없어요 | 닿을 수 없어요 | |
| 모두 맞을 때 / 하나라도 맞을 때 | 모두 참 / 하나라도 참 | 조건 묶기 |
| 조건이 맞으면 | 조건이 참이 되면 | |
| 내놓다 | 노출하다 | expose의 직역 |
| 일을 받다 | 투입되다 | "에이전트가 일을 받지 못해요" |
| 에이전트 (앱 안) / AI (홈 첫 문구) | | 홈은 처음 온 사람에게 말하고, 앱 안은 그 사람들이 쓰는 말이다. 홈의 시작 카드에서 하네스를 한 번 푼다: "모델을 움직이는 프로그램(하네스)" |
| 실험 (명사) / 시험하다 (동사) | | |

**사실이 어긋난 것**: 합격은 코어 `PASS_MARK`(60점)와 "진단을 냈다"는 조건으로 정해지는데 웹 화면 두 곳이 "70점"이라고 한다. 웹은 코어 상수를 읽어 "진단을 내고 60점 이상이면 합격이에요"라고 말한다.

**말투**: 사람에게 보이는 글은 해요체. 알람 문장(`net-alarms.ts`의 합니다체 9개)과 화면 두 곳의 한다체도 해요체로. 에이전트에게 주는 지시문은 한다체 하나로 통일한다("올라왔다. 원인을 찾아 조치하고 제출하라") — 과제 설명 칸에 사람도 읽지만, 그 글의 독자는 에이전트다.

## 아직 정하지 않은 말
- "세계"를 "데이터센터"로 바꿀지. 베타 사용자가 낯설어하면 바꾼다. 지금은 홈에서 한 번 풀어 말한다.

## 글 점검 (ADR-0073, 2026-11-04) — 편집기 밖의 글을 짝마다 고친 결과

"글 점검에서 정한 말"을 `apps/web`, `packages/core`, `apps/server`의 사람이 읽는 글에 적용했다. 타입 이름, 영어 툴 설명, 로그는 바꾸지 않았다. 숫자는 고친 글의 줄 수다.

| 짝 | 고친 곳 | 줄 |
|---|---|---|
| 도구 → 툴 | 연결 양식과 안내(서버 연결 방식 11개), 연결 화면, 오류 문장, 서버 게이트웨이 안내 | 46 |
| 추가·넣기 → 더하기 | 연결·층·실행 더하기, "대기열에 더하기", "실행을 더했어요", 서버 권한 오류, 검증 문장 | 12 |
| 삭제 → 지우기, 수정 → 고치기 | 서버 권한 오류("연결 지우기", "시나리오 고치기"…), API 요약 | 10 |
| 취소 → 멈추기 | "실험 멈추기", 실행 상태 라벨과 끝난 이유 "멈춤"(값 `cancelled`는 그대로), 분석 문장 | 7 |
| 월드 → 세계 | 노드 오류 문장 | 2 |
| 닿다 → 연결하다 | "연결할 수 없어요", "연결하지 못했어요", 상태 칩 "연결 안 됨" | 27 |
| 가동 → 돌리기·시운전 | 빌더 막대와 인스펙터, 토스트 | 11 |
| 노출·발견 → 내놓다·나오다 | 연결 양식 설명 | 7 |
| 배점·까닭·경보·고장 유형·채점 기준·한도 | 이유(실행 표), 알람(시나리오 요약), 고장 종류(분석 브리프), 채점표(검증·점수 요약·벤치마크), 상한 | 9 |
| 합니다체·한다체 → 해요체 | `net-alarms.ts` 알람 9문장, 세계 검증 한 문장, 연결 확인 두 곳 | 14 |
| 에이전트 지시문 → 한다체 하나 | 템플릿 시나리오의 지시문 15개("…올라왔다. … 제출하라.") | 15 |

**사실을 바로잡은 것**: 합격 문구는 코어 `PASS_MARK`를 읽어 "진단을 맞히고 60점 이상이면 합격이에요"라고 한다(실행 화면, 실험 화면). 70점은 틀린 숫자였다.

**고치지 않은 것**: 장비가 켜져 있다는 뜻의 "가동 중"·"가동 단계"(조건 칸 이름 세 개)는 운영에서 쓰는 말 그대로라 두었다. 캔버스 블록의 "주의" 표시는 알람 단계가 아니라 검증 경고라서 두었다. Hermes·GoClaw가 에이전트에게 주는 글은 사람이 쓰는 화면이 아니라서 두었다.

**지키는 방법**: `app-words.test.ts`(홈, 채점 라벨, 알람 문장, 고장, 합격 문구)와 `connector-words.test.ts`(연결 양식)가 쓰지 않는 말과 "~다" 끝맺음을 막는다.

| **멀티패스** | 다중 경로 | 호스트가 길 둘을 모두 이어 두고 한쪽이 죽으면 알아서 다른 쪽으로 바꾸는 것. 없으면 사람이 경로를 바꿔야 한다 |
| **복제본 n/m개** | 레플리카 수 | 분산 풀에서 지금 있는 완전한 복사본 수와 있어야 하는 수 |
| **재복제** | 리빌드, 리밸런싱 | 잃은 복제본을 남은 노드에서 다시 만드는 일. 하는 동안 느려진다. "다시 만드는 중 40%" |
| **클러스터가 알아서 복구** | 자동 복구됨 | 에이전트의 조치 없이 클러스터나 풀이 스스로 서비스를 살린 것. 복구 우선 채점이 에이전트가 한 복구와 가른다 |

## SDN 오버레이와 클라우드 네이티브 네트워크에서 정한 말 (REQ-097, ADR-0107 결정 6, ADR-0115)

| 쓰는 말 | 쓰지 않는 말 | 뜻·어디서 |
|---|---|---|
| **오버레이** | 가상망, 위 네트워크 | 리프-스파인(언더레이) 위에 터널로 덮은 서비스별 가상 네트워크. 칩 이름은 "SDN 오버레이(VXLAN·EVPN)" |
| **언더레이** | 아래 네트워크, 물리망 | 오버레이가 달리는 스위치와 케이블. "언더레이 경로가 끊겼어요" |
| **세그먼트** | 가상 서브넷, 테넌트 망 | 서비스 하나의 오버레이(VXLAN 네트워크, VNI). "세그먼트가 끊겼어요", "일부 끊김 n곳" |
| **VTEP** | 브이텝, 터널 끝점 | 리프마다 있는 VXLAN 터널의 끝. 처음 나올 때 "VTEP(VXLAN 터널의 끝)"이라고 한 줄 풀어 준다 |
| **EVPN 세션** | EVPN 피어 | VTEP이 스파인과 맺는 BGP 세션. 오르내리면 "플랩". 끊긴 뒤 다시 맺는 데 BGP 타이머 90초가 든다 |
| **SDN 컨트롤러** | 컨트롤 플레인, 오케스트레이터 | 스위치에 설정을 미는 쪽. 액티브 / 스탠바이. 멈춰도 돌던 길은 돌고 새 설정만 못 민다("헤드리스") |
| **설정 동기화** (다시 동기화) | 싱크, 리프레시 | 컨트롤러가 스위치에 설정을 밀어 맞추는 일. 한 스위치에 닿지 못하면 "옛 설정이 남았어요"(리비전이 하나 뒤) |
| **가상 방화벽** | NFV, VNF | 서비스 앞에 선 가상 네트워크 기능. 넘치면 "지연이 n ms로 늘었어요" |
| **CNI 플러그인** | 파드 네트워크 에이전트 | 노드마다 파드의 네트워크를 만드는 프로그램. 죽으면 "그 노드의 파드가 통신하지 못해요" |
| **네트워크 정책** | 방화벽 룰, ACL | 서비스 사이의 호출을 허용(allow)하거나 막는(deny) 규칙. 잘못 배포하면 "그 서비스 사이만 끊겨요" |
| **인그레스** | 입구, 게이트웨이 | 밖에서 서비스로 들어오는 문. 닫히면 "밖에서 오는 요청만 막혀요, 안의 호출은 그대로예요" |
| **ECMP 경로 재계산** | 라우팅 재수렴 | 리프가 스파인 하나를 잃고 남은 쪽으로 터널을 옮기는 일. 멈춤 없이 일어난다 |

## 컨테이너 층에서 정한 말 (REQ-096, ADR-0107 결정 6, ADR-0114)

| 쓰는 말 | 쓰지 않는 말 | 뜻·어디서 |
|---|---|---|
| **컨트롤 플레인 / 워커** | 마스터 노드, 슬레이브 노드 | 파드를 어디에 둘지 정하는 노드(API·스케줄러·etcd)와 파드가 실제로 도는 노드. 카드의 "컨트롤 플레인 VM 3 · 워커 VM 6" |
| **워크로드** (디플로이먼트) | 앱, 배포 단위 | 파드를 몇 개 두겠다는 주문서. 서비스가 기댄다. 서비스의 "일감"(분당 요청 수)과는 다르다 — 코드에서는 `k8s_workload` |
| **파드** | 컨테이너 묶음 | 워크로드가 돌리는 하나. 상태는 Running · ContainerCreating · Pending · CrashLoopBackOff · ImagePullBackOff · Evicted |
| **레플리카** | 복제본(스토리지의 "복제본"과 헷갈리지 않게 파드 이야기에만) | 워크로드가 원하는 파드 수. "레플리카 3/4개만 돌아요" |
| **재스케줄** | 파드 이주, 마이그레이션 | 죽은 노드의 파드를 포기하고 다른 노드에 새로 만드는 일. 기본 5분 뒤(`pod-eviction-timeout`). "클러스터가 알아서 옮겼어요" |
| **쫓아내기** (Evicted) | 축출 | kubelet이 디스크나 자원이 모자라 노드의 파드를 내보내는 일. 파드는 Evicted로 남고 워크로드가 다른 노드에 새로 만든다 |
| **쿼럼** (etcd 쿼럼) | 정족수 | etcd 멤버의 과반. 없으면 API가 쓰기를 못 받아 새 배포·재스케줄이 멈춘다. "컨트롤 플레인 3개 중 2개가 멈추면 쿼럼을 잃어요" |
| **CrashLoopBackOff** | 크래시 루프 | 파드가 뜨자마자 죽기를 반복하며 기다리는 시간이 10초부터 5분까지 두 배씩 느는 상태 |
| **cordon / uncordon** | 격리, 차단 해제 | 노드에 새 파드가 오지 않게 막거나(cordon) 다시 받게 하는(uncordon) 일. 돌던 파드는 그대로 |
| **drain** | 비우기 | cordon 하고 노드의 파드를 모두 내보내는 일 |
| **롤아웃 재시작** | 재배포 | 파드를 하나씩 새것으로 바꾸는 일. 새 파드가 뜬 뒤에 옛 파드를 지운다 |
| **CNI** (네트워크 플러그인) | 파드 네트워크 | 파드끼리 통신하게 하는 노드의 플러그인. 죽으면 노드는 Ready, 파드는 Running으로 보이는데 통신이 끊긴다 |
| **DRS** (자동 재배치) | 로드 밸런싱 | 바쁜 호스트의 VM을 한가한 호스트로 알아서 옮기는 것. 옮기는 동안 그 VM이 잠깐 느려진다 |

## 세계 인기와 칭호에서 정한 말 (REQ-101, ADR-0122)

| 쓰는 말 | 쓰지 않는 말 | 뜻·어디서 |
|---|---|---|
| **인기** | 핫, 랭킹, 트렌딩 | 세계의 기본 순서. 점수 = 최근 30일 실험 수 + 좋아요 수 + 다른 사람이 이 세계(템플릿)로 시작한 수. 카드에 "실험 128번 · 좋아요 24 · 이번 주 +12"로 근거를 보인다. 같은 점수는 만든 때가 나중인 세계가 앞 |
| **요즘 활발** | 급상승 | 최근 7일의 실험 + 좋아요 + 남이 시작한 수로 매긴 순서. 카드의 "이번 주 +n"이 이 수다 |
| **좋아요** | 추천, 즐겨찾기, 별 | 세계 카드의 하트. 사람마다 세계마다 하나, 누르면 켜고 끈다. 누른 사람 목록은 없다 |
| **칭호** | 뱃지, 레벨, 업적 | 활동으로 한 번 얻고 잃지 않는 이름. 이름에 조건의 숫자와 단위가 있다(실험 100번, 좋아요 10). 이름 옆에 최대 둘, 나머지는 프로필 팝오버. 단계도 색도 없다 |
| **계급** | 등급, 레벨 | Kaggle식 5단계(새싹 → 참가자 → 전문가 → 마스터 → 그랜드마스터). 메달 수로만 정해지고 **에이전트를 낸 사람**의 것이다. 모델만 있고 화면에는 아직 안 나온다(대회 모드와 함께, 지금은 모두 새싹) |
| **이끼** | 도우미, 챗봇, AI 비서 | 테라리움 사용을 돕는 도우미. 묻기·안내·대신 하기를 한다. 오른쪽 아래 버튼으로 열고, 먼저 말을 걸지 않는다. 기본 모델(LLM)을 등록해야만 켜지고, 없으면 설정으로 가는 알약만 남는다 |
| **등록된 동작** | 매크로, 자동 클릭 | 화면이 이끼에게 올려 둔 동작. 버튼이 쓰는 같은 일을 대신 하는 것이라 화면을 누르지 않는다. 바꾸거나 시작하는 동작은 "이렇게 할게요" 카드의 하기를 눌러야 한다 |
| **출처** | 근거, 참고 문헌 | 이끼의 답 밑에 접혀 있는 줄. 답에 쓴 문서 조각의 제목, 또는 "이 실행의 사건 기록" 같은 지금 화면의 상태 |
| **메달** | 상, 트로피 | 대회에서 순위의 백분위로 받는 금·은·동. 99명 이하면 상위 10·25·50%, 100명 이상이면 5·15·40%, 대회마다 금 최소 1개 |

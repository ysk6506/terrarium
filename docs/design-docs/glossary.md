# 용어집 (ADR-0071)

화면, 오류 문장, 문서에 쓰는 말의 기준이다. 코드의 타입 이름(`inject_fault`, `FaultType`)은 바꾸지 않는다. 바꾸는 것은 **사람이 읽는 말**이다.

## 쓰는 법
- 한국 사람이 일하면서 실제로 쓰는 말을 쓴다. 번역투("고쳐지기", "투입되다")와 만든 말은 쓰지 않는다. 확신이 없으면 **동료에게 말로 설명할 때 쓸 말**을 고른다.
- 버튼과 블록 이름은 명사형("고장 발생", "저장")이거나 "~하기"다. 문장은 해요체다 (ADR-0050).
- 전문 용어는 그 분야 사람이 쓰는 그대로 쓴다(VLAN, BGP, 차단기 트립). 풀어 쓸 수 있으면 풀고, 못 풀면 한 줄 설명을 곁에 둔다.
- 영문 코드, 내부 id, JSON은 화면에 나오지 않는다.

## 정한 말

| 쓰지 않는 말 | 쓰는 말 | 어디서 |
|---|---|---|
| 장애 주입 | **고장 발생** | 블록 이름 |
| 장애 해제 | **고장 복구** | 블록 이름 |
| 장애 종류 / 장애 세부값 | **고장 종류 / 세부 설정** | 블록 폼 |
| 장애 (묶음 이름, 홈 문구) | **고장**, 또는 실제로 일어나는 일("냉방기가 멈춰요") | 팔레트, 홈 |
| 장애 티켓·지시문 | **상황 설명** | 에이전트 투입 폼 도움말 |
| 시험지 점검 | **변별력 점검** | 편집기 패널 |
| 기준선 에이전트 / 기본 에이전트 셋 | **기준 에이전트** (아무것도 안 함 · 찍기 · 정답만 앎) | 변별력 점검 |
| 주입하다 / 투입되다 | 일으키다 / 맡기다 | 문장 |
| 유지 시간 0초 | **고쳐질 때까지** / **n분 뒤 저절로 복구** | 고장 발생 폼 |
| 툴 호출 한도 | **툴 호출 상한** | 에이전트 투입 폼 (채점표와 같은 말) |
| 제한 시간 (시뮬레이션) | **제한 시간** + 단위 "분" | 에이전트 투입 폼 |
| 미리 돌려 보기 | 그대로 | |
| 세계 | 그대로 (한 사업장이나 여러 사업장을 담은 가상의 데이터센터). 홈에서 한 번 풀어 말한다 | 전체 |
| 에이전트 투입 | 그대로 | 블록 이름 |

## 서버룸 크기에서 정한 말 (REQ-075, ADR-0079, ADR-0080)

| 쓰는 말 | 쓰지 않는 말 | 어디서 |
|---|---|---|
| **조각** (방에 변을 맞대 붙인 직사각형. 처음 직사각형은 "본체") | 확장부, 날개, 서브룸, 증축 | 방 크기 패널, 3D 손잡이 |
| **조각 덧붙이기** (왼쪽·오른쪽·위쪽·아래쪽) | 조각 추가 | 방 크기 패널 |
| **조각 떼기** | 조각 삭제 | 조각을 고른 방 크기 패널 |
| **서버룸 넓히기** (방이 꽉 찼을 때 가는 길) / **건물 넓히기** | 확장하기, 증설 | 랙을 놓을 수 없을 때의 문장, 서버룸 채우기 |
| **가로·세로** (m) | 폭·깊이, 너비 | 크기 칸 |
| **타일 N장**, **건설비 +N** | 타일 수량, 공사비 | 끌 때 안내 줄 |

문장은 이유를 먼저 말하고 해요체로 끝낸다: "랙 3이 밖으로 나가게 돼요. 먼저 옮겨 주세요", "건물이 꽉 찼어요. 건물을 넓혀요".

## 건물의 실제 크기와 빈 바닥에서 정한 말 (REQ-076, ADR-0081)

| 쓰는 말 | 쓰지 않는 말 | 어디서 |
|---|---|---|
| **실제 크기** ("이 건물은 실제 크기예요") | 고정 크기, 잠긴 크기, 크기 제한 | 건물·방 패널 |
| **빈 바닥** (층 바닥에서 방·클린룸 베이·코어를 뺀 만큼) | 여유 공간, 잔여 면적, 가용 면적 | 건물·방 패널, 끌 때 안내 줄, 층 단면의 옅은 초록 |
| **코어** (승강기·계단·복도) | 공용부, 유틸리티 공간 | 빈 바닥 설명 |
| **이 층은 꽉 찼어요. 3층에 320 ㎡ 비어 있어요** | 면적이 부족합니다, 증설 불가 | 방을 넓힐 때 막히는 문장 |
| **랙 N대가 더 들어가요** (늘어난 바닥 ÷ 랙당 2.6 ㎡) | 수용 가능 랙 수, 랙 용량 | 방 크기 패널, 끌 때 안내 줄 |
| **이 방의 냉방·전력은 어디서** / **식히는 설비**, **먹이는 설비** | 지원 설비, 부대 설비 | 방 패널 |
| **수전 용량** (사업장이 한전에서 받는 전력) / **추정** (공개된 값이 없을 때) | 계약 전력, 전력 한도 | 사업장 화면, 막히는 문장 |
| **전력이 모자라요. 108 MW 중 107.5 MW를 쓰고 있어요** | 전력 부족, 용량 초과 | 랙·설비를 놓을 때 막히는 문장 |

문장은 이유를 먼저 말하고 해요체로 끝낸다. 방이 벽에 닿았을 때는 층이 꽉 찬 것이 아니므로 "건물 벽에 닿았어요. 이 층 빈 바닥 N ㎡는 다른 쪽에 있어요"라고 따로 말한다.

## 서버룸의 사람에서 정한 말 (REQ-074, ADR-0078)

| 쓰는 말 | 쓰지 않는 말 | 어디서 |
|---|---|---|
| **엔지니어**, **관리자**, **기사** (역할만, 이름 없음) | 직원, 운영자, 작업자, 사람 이름 | 서버룸의 사람, 말풍선 |
| **순찰**, **살펴보는 중**, **일하는 중** | 점검 완료, 조치 완료 | 말풍선 |
| 사람은 보고 걷고 기다릴 뿐 **고쳤다고 말하지 않는다** | 고쳤어요, 복구했어요, 해결했어요 | 말풍선 (고치는 것은 시나리오와 에이전트뿐) |

## 토폴로지 보기에서 정한 말 (REQ-078, ADR-0084)

| 쓰는 말 | 쓰지 않는 말 | 어디서 |
|---|---|---|
| **토폴로지** (화면 이름), **층**: 전원 · 냉방 · 네트워크·가상화 | 레이어, 계층, 의존도 | 빌더 위 막대, 층 탭 |
| **영향 범위** (기대던 것을 잃은 곳) | 폭발 반경, 파급, blast radius | 상자 이름, 범례, 회색 타일 |
| **냉방이 그대로면 12분 뒤 심각(32°C)** | 12분 후 임계 도달 | 영향 범위 상자 |
| **묶음**(같은 상태의 장비를 접은 타일), **접힌 것**, **펼치기** | 클러스터, 그룹핑, 집계, 확장 | 타일 이름, 그린 타일 줄, 타일 설명 |
| **그린 타일 7개 · 접힌 것 16,565개** ("그린"은 그리다의 뒤) | 노드 7개, 렌더링된 요소 | 오른쪽 위 줄 |
| **정상 랙 408대**, **더워지는 중 랙 11대**(냉방 층), **영향 범위 랙 11대**(전원·네트워크 층), **알람 랙 3대**, **고장 냉방기 1대** (상태, 무엇, 몇) | 408개 랙(정상) | 묶음 타일 이름 |
| **에이전트가 만지는 곳** | 접근 중인 노드, 활성 엔티티 | 범례, 파랑 타일 |
| **멈췄어요**, **전기가 끊겼어요**, **차단기가 떨어졌어요** | 다운, 오프라인, 트립됨 | 타일 아래 상태 줄 |

상태 줄은 말 하나와 숫자 하나다("흡기 27.4°C", "92% 돌아가요", "배터리 61%"). 타일 이름은 장비 이름 그대로다.

## 글 점검에서 정한 말 (2026-11-04, 화면 글 2,888개를 뽑아 본 뒤)

같은 것을 다르게 부르던 짝은 한쪽으로 정했다. 왼쪽을 쓴다.

| 쓰는 말 | 쓰지 않는 말 | 왜 |
|---|---|---|
| 툴 | 도구 | 실험·채점표가 쓰는 말이고 에이전트 쪽 사람들이 "툴"이라 부른다. 연결 양식의 "도구"도 바꾼다 |
| 더하기 | 추가, 넣기 | 버튼은 "~하기" (ADR-0050). 블록도 "블록 더하기" |
| 지우기 | 삭제 | 서버가 권한 오류에 끼워 넣는 말까지 |
| 고치기 | 수정 | 같은 이유 |
| 멈추기 | 취소 | ADR-0050 |
| 세계 | 월드 | 노드 오류 두 군데 |
| 심각 / 경고 | 위험 / 주의 | 알람 단계 이름은 데이터센터 운영에서 쓰는 critical/warning 그대로 |
| 고장 종류 | 고장 유형, 장애 종류 | |
| 점수 | 배점 | |
| 채점표 (한 줄은 채점 항목) | 채점 기준 | |
| 이유 | 까닭 | |
| 알람 | 경보 | |
| 돌리기 / 돌려 보기 | 가동 | 빌더의 "10분 가동"도 |
| 연결할 수 없어요 | 닿을 수 없어요 | |
| 모두 맞을 때 / 하나라도 맞을 때 | 모두 참 / 하나라도 참 | 조건 묶기 |
| 조건이 맞으면 | 조건이 참이 되면 | |
| 내놓다 | 노출하다 | expose의 직역 |
| 일을 받다 | 투입되다 | "에이전트가 일을 받지 못해요" |
| 에이전트 (앱 안) / AI (홈 첫 문구) | | 홈은 처음 온 사람에게 말하고, 앱 안은 그 사람들이 쓰는 말이다. 홈의 시작 카드에서 하네스를 한 번 푼다: "모델을 움직이는 프로그램(하네스)" |
| 실험 (명사) / 시험하다 (동사) | | |

**사실이 어긋난 것**: 합격은 코어 `PASS_MARK`(60점)와 "진단을 냈다"는 조건으로 정해지는데 웹 화면 두 곳이 "70점"이라고 한다. 웹은 코어 상수를 읽어 "진단을 내고 60점 이상이면 합격이에요"라고 말한다.

**말투**: 사람에게 보이는 글은 해요체. 알람 문장(`net-alarms.ts`의 합니다체 9개)과 화면 두 곳의 한다체도 해요체로. 에이전트에게 주는 지시문은 한다체 하나로 통일한다("올라왔다. 원인을 찾아 조치하고 제출하라") — 과제 설명 칸에 사람도 읽지만, 그 글의 독자는 에이전트다.

## 아직 정하지 않은 말
- "세계"를 "데이터센터"로 바꿀지. 베타 사용자가 낯설어하면 바꾼다. 지금은 홈에서 한 번 풀어 말한다.

## 글 점검 (ADR-0073, 2026-11-04) — 편집기 밖의 글을 짝마다 고친 결과

"글 점검에서 정한 말"을 `apps/web`, `packages/core`, `apps/server`의 사람이 읽는 글에 적용했다. 타입 이름, 영어 툴 설명, 로그는 바꾸지 않았다. 숫자는 고친 글의 줄 수다.

| 짝 | 고친 곳 | 줄 |
|---|---|---|
| 도구 → 툴 | 연결 양식과 안내(서버 연결 방식 11개), 연결 화면, 오류 문장, 서버 게이트웨이 안내 | 46 |
| 추가·넣기 → 더하기 | 연결·층·실행 더하기, "대기열에 더하기", "실행을 더했어요", 서버 권한 오류, 검증 문장 | 12 |
| 삭제 → 지우기, 수정 → 고치기 | 서버 권한 오류("연결 지우기", "시나리오 고치기"…), API 요약 | 10 |
| 취소 → 멈추기 | "실험 멈추기", 실행 상태 라벨과 끝난 이유 "멈춤"(값 `cancelled`는 그대로), 분석 문장 | 7 |
| 월드 → 세계 | 노드 오류 문장 | 2 |
| 닿다 → 연결하다 | "연결할 수 없어요", "연결하지 못했어요", 상태 칩 "연결 안 됨" | 27 |
| 가동 → 돌리기·돌려 보기 | 빌더 막대와 인스펙터, 토스트 | 11 |
| 노출·발견 → 내놓다·나오다 | 연결 양식 설명 | 7 |
| 배점·까닭·경보·고장 유형·채점 기준·한도 | 이유(실행 표), 알람(시나리오 요약), 고장 종류(분석 브리프), 채점표(검증·점수 요약·벤치마크), 상한 | 9 |
| 합니다체·한다체 → 해요체 | `net-alarms.ts` 알람 9문장, 세계 검증 한 문장, 연결 확인 두 곳 | 14 |
| 에이전트 지시문 → 한다체 하나 | 템플릿 시나리오의 지시문 15개("…올라왔다. … 제출하라.") | 15 |

**사실을 바로잡은 것**: 합격 문구는 코어 `PASS_MARK`를 읽어 "진단을 맞히고 60점 이상이면 합격이에요"라고 한다(실행 화면, 실험 화면). 70점은 틀린 숫자였다.

**고치지 않은 것**: 장비가 켜져 있다는 뜻의 "가동 중"·"가동 단계"(조건 칸 이름 세 개)는 운영에서 쓰는 말 그대로라 두었다. 캔버스 블록의 "주의" 표시는 알람 단계가 아니라 검증 경고라서 두었다. Hermes·GoClaw가 에이전트에게 주는 글은 사람이 쓰는 화면이 아니라서 두었다.

**지키는 방법**: `app-words.test.ts`(홈, 채점 라벨, 알람 문장, 고장, 합격 문구)와 `connector-words.test.ts`(연결 양식)가 쓰지 않는 말과 "~다" 끝맺음을 막는다.

# 권한 (클로즈 베타 1차, ADR-0174)

초대한 사용자가 둘 이상이 되는 순간 필요한 것이에요. **만드는 순서의 가(신원·판정 한 곳·막기)와 나(공개 범위·공유 링크 목록)와 다(감사 기록)까지 만들었고**, 라와 마는 아직이에요(9절). 말은 [용어집](glossary.md)을 따라요.

## 한 줄로

누구인지는 SSO를 맡은 프록시가 알려 주고 테라리움은 그 프록시만 믿어요. 만든 사람이 공개 범위(나만 / 우리 파트 / 모두)를 정하고, 바꾸는 일은 만든 사람과 관리자만 해요. 바꾼 일은 모두 감사 기록에 남아요.

## 만들기 전의 사실 (가 단계가 고친 것은 오른쪽에)

| 무엇 | 만들기 전 | 가 이후 |
|---|---|---|
| 신원 | 이름 문자열 하나. 프록시 헤더가 어디서 왔는지 확인하지 않아요. 헤더가 없으면 "anonymous"로 통과해요 | 고쳤어요(프록시 모드는 비밀 값과 401) |
| 직접 적는 이름 | 누구나 남의 이름을 적을 수 있어요. 남의 세계·연결을 바꾸고 지울 수 있어요 | 혼자 쓰는 개발용으로 남았어요. 남의 이름을 적을 수 있는 건 그대로예요(그래서 "권한이 없는 방식") |
| 읽기 | 거의 전부 모두에게 열려 있어요 | 범위대로 걸러요(나 단계, 3절) |
| 남의 자격 증명 | 남이 만든 연결로 대화·실험을 돌릴 수 있어요(봉인된 토큰이 대신 쓰여요) | 막았어요. 연결 확인·대화·유지·모델 확인과 그 연결로 실험 만들기·복제는 그것이 보이는 사람만, 화면에서 만든 연결은 처음 값이 "나만"이라 만든 사람과 관리자만(설정 파일의 연결은 로그인한 누구나) |
| 기본 모델 | 누구나 바꿀 수 있어요. 모든 사용자의 도우미 질문이 그 모델로 가요 | 관리자와 그 모델의 주인만, 범위가 "모두"인 모델만(나 단계, 3절) |
| 공유 링크 | 누구나 남의 실험에 만들 수 있고, 화면에서 만든 링크는 만료가 없고, 목록이 없어요 | 만드는 건 실험을 만든 사람과 관리자만, 만료는 30일. 목록도 같은 사람만(나 단계) |
| 관리자·그룹·감사 기록 | 없어요 | 관리자와 그룹은 생겼어요. 감사 기록은 다 단계가 만들었어요(6절) |

## 1. 누구인지

```
사용자 ─▶ 프록시(SSO 로그인을 맡음) ─▶ 테라리움
            └ 헤더로 넘김: 로그인 ID, 이름, 그룹 + 프록시만 아는 비밀 값
```

- **프록시 모드가 클로즈 베타의 방식이에요.** 프록시는 Keycloak 같은 표준(OIDC) SSO에 붙어요. 테라리움은 특정 SSO에 묶이지 않아요.
- 테라리움은 **프록시의 비밀 값**이 맞는 요청만 믿어요. 비밀 값이 없거나 틀리면 401이에요. 헤더가 없다고 "anonymous"로 통과시키지 않아요.
- 보는 사람은 넷을 가져요: **로그인 ID**(바뀌지 않는 값. 소유를 여기에 적어요), 보이는 이름, 그룹들, 역할.
- 이름 "anonymous"는 아무도 못 써요. 한글 이름은 한 가지 유니코드 꼴로 맞춰 견줘요.
- **직접 적는 이름 방식은 혼자 쓰는 개발용으로만 남아요.** 화면에 "권한이 없는 방식"이라고 보이고, 관리자는 이렇게 가려요(ADR-0152). (가) 설정에 `adminTokenEnv`가 있으면 그 토큰을 보낸 요청만 관리자예요. 루프백이어도 토큰이 없으면 관리자가 아니에요. (나) 없으면 **이 기계 자신(루프백 주소 127.0.0.1·::1)에서 온 요청만** 관리자예요. 주소는 소켓에서 읽고 `X-Forwarded-For` 같은 헤더는 믿지 않아요(`trustProxy`는 꺼져 있어요). 다른 주소에서 온 요청은 관리자가 될 수 없어요. 그래서 `pnpm dev`로 혼자 쓰는 사람은 화면에서 기본 모델 정하기와 세계 가져오기를 그대로 해요. 같은 기계의 역방향 프록시 뒤에 두면 모든 요청이 루프백으로 보이니, 그렇게 둘 때는 프록시 모드나 토큰을 쓰세요. 프록시 모드에서는 루프백이 아무 뜻이 없고 관리자는 목록과 그룹에서만 나와요. `GET /api/meta`의 `user.roles`에 `admin`이 들어 있는지로 화면이 관리자 버튼을 보이거나 숨길 수 있어요.
- 실험받는 에이전트가 부르는 주소(`/mcp/runs/...`)와 공유 링크(`/r/...`)는 로그인 밖이에요. 추측할 수 없는 토큰이 지켜요(ADR-0044 그대로).

## 2. 역할은 둘

| 역할 | 누구 | 할 수 있는 것 |
|---|---|---|
| 사용자 | 로그인한 모든 사람 | 만들기, 자기 것 바꾸기, 볼 수 있는 것 보기와 복제하기 |
| 관리자 | 서버 설정의 로그인 ID 목록, 또는 SSO의 관리자 그룹 | 남의 것 바꾸기·지우기(이유를 적어요), 기본 모델 정하기, 설정 파일로 만든 연결의 버전 관리, 감사 기록 보기 |

## 3. 공개 범위는 셋

만든 사람이 정하고 언제든 바꿔요.

| 범위 | 볼 수 있는 사람 |
|---|---|
| 나만 | 만든 사람, 관리자 |
| 우리 파트 | 만든 사람과 같은 그룹에 든 사람, 관리자 |
| 모두 | 로그인한 모든 사람 |

| 무엇 | 처음 값 | 까닭 |
|---|---|---|
| 세계, 시나리오, 실험 | 모두 | 서로 견주는 것이 이 제품의 쓸모예요. 순위표는 "모두"인 실험만 써요 |
| 연결, 모델 등록 | 나만 | 자격 증명이 딸려 있어요 |
| 저장해 둔 툴 묶음·절차서, 서비스 카드 | 지금대로(자기 것, 서비스 카드는 공유 켜기) | |

- **저장 모양**: 범위는 `scope`(`private`·`group`·`everyone`)와 `group`이에요. "모두"는 필드를 적지 않아요(없으면 모두로 읽어요). 그래서 예전 기록과 새 "모두" 기록이 바이트까지 같아요.
- **그룹**을 고르려면 만든 사람이 그 그룹에 들어 있어야 해요. 그룹이 하나도 없는 사람이 "우리 파트"를 고르면 까닭과 함께 거절해요(400).

- **그룹은 SSO가 알려 주는 대로 써요.** 테라리움에서 그룹을 만들거나 고치지 않아요. SSO가 그룹을 주지 않으면 "우리 파트"는 화면에 없어요.
- **딸린 것은 범위를 물려받아요.** 실행, 보고서, 사건, 텔레메트리, 내보내기, 넘기기 카드는 그 실험의 범위를 따라요. 활동 스트림도 같아요.
- **볼 수 없는 것은 없는 것처럼 답해요.** 하나를 물으면 404, 목록에는 없어요. 읽기 규칙은 `may`의 한 곳(`see`)에 있고, 세계·시나리오·실험은 저장소 쿼리에서 걸러요(`visibleTo`). 순위표·세계 인기·좋아요·칭호는 "모두"인 것만 세요.
- **쓰려면 볼 수 있어야 해요.** 남의 세계에 시나리오를 만들거나, 남의 연결로 대화·실험을 돌리려면 그것이 내게 보여야 해요. 그래서 "나만"인 연결의 자격 증명은 남이 빌려 쓸 수 없어요. 시나리오 만들기, 실험 만들기·복제·빠른 실험, 연결 확인·대화·유지, 모델 확인이 모두 그래요.
- **모두의 기본 모델은 범위가 "모두"인 모델만 될 수 있어요.** "나만"·"우리 파트" 모델은 기본으로 정할 수 없고(400, 이유가 실려요), 기본 모델의 범위를 "모두"보다 좁히려 해도 거절해요("먼저 다른 모델을 기본으로 정해 주세요"). 저절로 기본이 되는 건 "모두" 모델이 처음 생길 때뿐이고, 기본을 지우면 가장 먼저 등록된 "모두" 모델로 넘어가요(없으면 모두의 기본은 없어요). 한 사람에게 보이는 기본은 모두의 기본이 있으면 그것, 없으면 그 사람이 볼 수 있는 모델 중 가장 먼저 등록된 것이에요(`defaultFor`, `runtime/models.ts`; 이끼가 이 함수를 써요). 그래서 모델 하나를 혼자 쓰는 개발 모드는 그대로 돌고, 남의 "나만" 모델의 키는 남의 호출에 쓰이지 않아요. 관리자의 대신 고르는 기본도 남의 "나만" 모델은 세지 않아요.
- 범위를 좁히면 이미 만들어진 남의 실험은 그대로 남되, 좁혀진 것(세계·연결)의 내용은 더 보이지 않아요. 남의 실험에 저장된 스냅샷은 그 실험 주인에게 그대로 읽혀요.

## 4. 바꾸는 일

| 일 | 누가 |
|---|---|
| 바꾸기, 지우기, 범위 바꾸기(`changeScope`, 한 함수로만), 실험 멈추기·더 돌리기, 넘기기 카드에 답하기 | 만든 사람, 관리자 |
| 시나리오 보정 표시 남기기 | 시나리오를 만든 사람, 관리자 |
| 현재 업무 표 적기 | 시나리오를 만든 사람, 관리자 (먼저 적은 사람이 아니에요) |
| 모두의 기본 모델 정하기 | 관리자, 그 모델의 주인 (범위가 "모두"인 모델만) |
| 연결 확인·대화·유지, 모델 확인 | 그것이 보이는 사람 (설정 파일의 연결은 로그인한 누구나. 모두의 기본 모델은 범위가 "모두"라 누구나) |
| 좋아요 | 로그인한 사람(한 사람에 하나가 이제 진짜예요) |

판정은 한 곳에서 해요: "이 사람이 이 일을 이것에 해도 되나". 길목마다 따로 적지 않아요.

## 5. 공유 링크

- 만드는 사람은 그 실험을 만든 사람과 관리자예요.
- 처음 만료는 30일이에요. 만들 때 바꿀 수 있어요(1일~365일).
- 실험 화면에서 그 실험의 링크 목록을 보고 끊어요(`GET /api/experiments/:id/shares`, 만든 사람과 관리자만). 기간이 지난 링크는 목록에 없어요.
- 링크를 받은 사람은 로그인 없이 보고서만 봐요(지금대로).

## 6. 감사 기록

다 단계(ADR-0193)가 만들었어요. 화면은 라 단계예요. API는 [HTTP API](http-api.md#감사-기록-adr-0193-권한)에 있어요.

- **덧붙이기만 해요.** 고치거나 지우는 길이 없어요. 관리자도 못 해요. 하나뿐인 지우기는 보관 기간(`audit.retentionDays`, [서버 운영](operations.md))이 지난 기록을 지우는 배경 정리이고, 정리했다는 기록이 하나 남아요.
- **한 기록에는** 시각(주입한 시계의 것. `Date.now()`가 아니에요), 누가(로그인 ID, 그때의 보이는 이름, 신원 출처, 관리자인지), 무엇을(닫힌 목록의 일 이름), 무엇에(종류와 ID, 그때의 이름·주인·범위), 결과(`allowed`·`denied`·`failed`)와 막히거나 실패한 까닭(닫힌 목록), 요청 ID, 범위·그룹·역할·주인·공유를 바꿨다면 그 칸들의 앞과 뒤가 들어 있어요.
- **적는 것**: 바꾸는 길 전부(기본 모델 정하기, 공유 링크 만들기와 끊기, 실험 시작과 멈춤, 관리자만 하는 일 포함), 어느 길에서든 막힌 시도(401·403·"볼 수 없어서 404"를 구별해서), 관리자가 남의 "나만"·"우리 파트"인 것을 본 일(목록은 건수 하나), 프록시 로그인 실패(호출한 쪽 주소와 함께), 감사 기록을 보거나 내려받은 일.
- **적지 않는 것**: 비밀 값·토큰·프록시 비밀 값, 요청 본문, 세계·시나리오·실행·행의 내용. 보낸 칸의 **이름**은 적을 수 있고, **값**은 범위·그룹·역할·주인·공유 칸만 적어요. 시험이 길마다 입력에 알아볼 수 있는 비밀 값을 심고 기록에 없는지 봐요.
- **기록하는 곳은 하나예요.** 핸들러는 아무것도 적지 않아요. 판정(`may`, `allow`, `mustSee`)이 막힌 자리에서 요청의 메모에 적어 두고, 모든 길이 지나는 앱의 등록 함수가 요청이 끝날 때 기록자(`Auditor`)로 써요. 새 길은 `AUDIT_CLASSES`에 `records: change | read-override | none`을 적어야 하고 `none`은 이유가 있어야 해요. 없으면 타입 검사와 `audit-classes.test.ts`가 실패해요.
- **쓰기가 안 될 때**(저장소가 기록을 못 받을 때): 바꾸는 요청은 **하기 전에** 막아요. 503과 "감사 기록을 남길 수 없어서 이 일을 하지 않았어요…"를 줘요. 읽기는 그대로 답하고 실패를 지표로 세고 로그에 행동 이름과 결과만 남겨요. 막힌 시도도 막힌 채로 답해요. 한계: 확인한 뒤 쓰는 사이에 깨지면 일은 끝났고 기록이 없어요. 이때는 "일은 끝났지만 감사 기록을 남기지 못했어요"라고 말해요([서버 운영](operations.md)).
- **로그인 전의 실패는 접어서 써요.** 쓰기가 안 될 때 바꾸는 요청을 막는 설계라서, 로그인 없이 실패 줄을 끝없이 쌓을 수 있으면 디스크를 채워 모든 변경을 막는 지렛대가 돼요. 그래서 로그인 전의 실패(`unauthenticated`·`proxy_secret_missing`·`proxy_secret_wrong`·`proxy_login_missing`)는 (호출한 쪽 주소, 까닭)마다 1분에 한 줄만 쓰고 그 줄의 `detail.count`에 그 1분의 횟수를 남겨요. 줄은 그 1분이 끝난 뒤(또는 서버가 멈출 때) 써요. 이런 줄은 모두 합쳐 1분에 `audit.preAuthLinesPerMinute`(기본 60)줄까지예요. 넘으면 그 분의 나머지는 지표(`terrarium_audit_suppressed_total`)로만 세고, 서버가 쓴 `audit.limit` 줄 하나가 "상한에 닿았다"와 버린 횟수를 말해요. 접힌 줄과 버린 횟수는 지표에는 남지만 줄로는 남지 않아요.
- **보는 사람**: 관리자는 목록과 JSON Lines 파일(거르기: 시간 범위, 누가, 일, 종류와 ID, 결과. 새것부터, 쪽 나눔)을 봐요. 다른 사람은 **자기가 만든 것**에 있던 일을 누가·언제·무엇을·어떻게 끝났나로만 봐요. 기록을 보거나 내려받은 일도 기록돼요.

## 8. 이미 있는 데이터

클로즈 베타는 새 데이터로 시작해요. **범위가 없는 예전 기록은 종류와 상관없이 "모두"로 읽어요**(세계·시나리오·실험·연결·모델 등록 모두). 연결과 모델 등록의 새 기록 처음 값은 "나만"이지만, 예전 기록을 갑자기 숨기지 않으려는 것이에요. 소유자가 없는 기록(예전 기본 세계)은 범위가 없으면 로그인한 누구나 봐요. 관리자가 필요하면 범위 바꾸기로 좁혀요. SQLite는 스키마 3판이 `scope`·`grp` 열(세계·시나리오는 `owner`도)을 더해요([서버 운영](operations.md)). 알파에서 직접 적은 이름으로 만든 것을 옮겨야 하면, 관리자가 이름을 로그인 ID에 맞춰 주는 명령으로 옮겨요. 칭호와 좋아요는 옮기지 않아요(이름을 믿을 수 없던 때의 것이에요).

## 9. 만드는 순서

| 순서 | 무엇 |
|---|---|
| 가 (**만들었어요**) | 신원 굳히기(프록시 비밀 값, 401, 로그인 ID·그룹·역할), 판정을 한 곳으로, 확인 없이 바꾸던 길 막기, 활동 스트림에 로그인 |
| 나 (**만들었어요**) | 공개 범위(읽기 거르기, 물려받기, 쓰려면 볼 수 있어야), 공유 링크 목록과 만료 고르기 |
| 다 (**만들었어요**) | 감사 기록(덧붙이기만, 기록하는 곳 하나, 관리자의 목록·파일, 내 것의 제한된 보기) |
| 라 | 화면 |
| 마 | 프록시와 Keycloak을 실제로 띄워 로그인부터 실험까지 도는 시험, 배포 절차서 |

### 가 단계에서 만든 것과 알려진 한계

- **설정**은 [서버 운영](operations.md#사용자-식별-자리)에 있어요. **길마다 정책**과 정책별 길 수는 [HTTP API](http-api.md#누가-부를-수-있나-adr-0174-권한)에 있어요.
- **판정은 한 함수**예요: `may(viewer, action, resource)`(`apps/server/src/runtime/permissions.ts`). 일의 이름은 닫힌 목록(`ACTIONS`, 계약)이고, 길이 자기 일의 이름을 `ROUTES`에 적어요. 길마다 정책이 있는지는 시험이 계약 전부를 걸어 확인해요.
- **소유는 로그인 ID로 견줘요.** 저장되는 `owner`가 로그인 ID예요. 보이는 이름은 `meta`에 있고 목록에는 아직 ID가 나와요(라 단계에서 이름으로 바꿔요). 웹의 "내 것" 표시는 나 단계부터 `meta.user.id`로 견줘요.
- **직접 적는 이름 방식**은 이름이 없는 요청도 하나의 "anonymous" 사용자로 통과시켜요(예전과 같아요). 이 사용자는 만들고 바꿀 수 있지만 좋아요는 못 눌러요. 이름으로 "anonymous"를 적으면 이름이 없는 것으로 쳐요. 프록시 모드에서는 이 사용자가 없어요.
- **관리자 목록은 NFC 꼴 그대로 견줘요**(대소문자는 구분해요). 로그인 ID가 SSO마다 대소문자를 달리 주면 목록을 SSO가 주는 꼴로 적어요.
- **설정 파일의 연결**은 관리자만 버전을 고쳐요. 화면(웹)은 아직 그 버튼을 숨기지 않아서, 사용자가 누르면 403이 보여요(라 단계).
### 나 단계에서 만든 것과 알려진 한계

- **읽기 규칙**은 `may(viewer, "see", resource)`와 같은 규칙의 순수한 꼴 `seen(sight, record)`(`packages/core/src/experiments/scope.ts`)예요. 저장소는 `visibleTo`로, 길은 `Gate`(`runtime/gate.ts`)로 같은 규칙을 써요.
- **범위 바꾸기는 `changeScope` 한 함수**(`runtime/scoping.ts`)를 지나고, 길도 하나예요: 다섯 종류 모두 `PUT /api/<worlds|scenarios|experiments|connections|models>/:id/scope`(`{ scope, group? }`). 기존 고치기 길은 범위를 받지 않아요(연결의 범위만 바꾸려고 설정을 다시 보내지 않아요). 감사 기록은 이 함수가 적어 둔 앞과 뒤를 요청이 끝날 때 써요(다 단계).
- **모델 이름은 두 곳에서만 유일해요**: 만든 사람 자신의 등록 안에서, 그리고 "모두"로 만든 등록 사이에서요(`Models.nameTaken`). 남의 "나만"·"우리 파트" 모델은 이름을 견주지 않아서, 같은 이름을 적었을 때의 충돌(409)로 그 모델이 있다는 사실이 새지 않아요. 그래서 두 사람이 같은 이름의 "나만" 모델을 따로 가질 수 있어요. 모델은 이름이 아니라 ID로 가리켜서(기본 모델, 이끼, 확인) 이름이 겹쳐도 헷갈리지 않아요. "나만" 모델의 범위를 "모두"로 넓힐 때 같은 이름의 "모두" 모델이 있으면 409예요.
- 웹의 "내 것" 표시는 이제 `meta.user.id`로 견줘요. 범위를 고르는 화면은 라 단계예요. 응답에는 `scope`, `group`, `canChangeScope`(연결·모델은 `sharing`)가 이미 있어요.
- 프록시가 보낸 이름·그룹 헤더가 UTF-8 그대로 오면(Node가 Latin-1로 읽은 것) 다시 맞춰 읽어요.

### 다 단계에서 만든 것과 알려진 한계

- **저장**: 감사 기록은 `ExperimentStore`와 다른 자기만의 항구(`AuditStore`: `append`·`ready`·`query`·`sweep`)예요. 메모리와 SQLite(표 `audit_log`, 스키마 4판)가 있고, 실험 쪽 코드는 이 항구를 받지 않아서 쓸 수 없어요. 기록자만 받아요.
- **같은 판에서 읽는 길 셋**: `GET /api/audit`(관리자), `GET /api/audit/export`(관리자), `GET /api/audit/mine`(로그인한 누구나, 자기가 만든 것만). 정책 표에 있어요.
- **로그인 실패의 까닭**(비밀 값 없음·틀림·로그인 ID 없음)은 기록에만 구별돼 있고 호출한 사람에게는 모두 같은 401이에요. 막힌 시도는 401·403·"볼 수 없어서 404"가 서로 다른 까닭으로 적혀요.
- **ID는 확인된 것만 적어요.** 주소에 적힌 ID는 조회가 있다고 확인한 뒤에만 기록에 들어가요. 없는 ID나 토큰이 기록에 새지 않아요.
- 한계: 관리자가 남의 것을 읽은 일을 `twinDiagnoses`·`twinBrief`·`listEscalations`에서는 기록하지 않아요(여러 실험을 합쳐 읽는 길이라 한 사람의 것을 가릴 수 없어요. `AUDIT_CLASSES`에 이유가 있어요).
- 한계: 로그인 전의 실패는 접어서 쓰므로 한 주소가 1분에 몇 번 틀렸는지는 줄의 `count`로만 알 수 있고, 상한을 넘은 주소는 줄 없이 지표로만 세요.
- 한계: `/metrics`는 클러스터 토큰이 있을 때만 열려서, 토큰 없는 한 대짜리 서버에서는 감사 지표가 길로 나오지 않아요.
- 한계: `GET /api/audit/mine`의 항목에는 일과 결과 말고도 대상의 종류와 ID, 이름이 있어요. 화면이 "무엇에 한 일인지"를 보여 주려면 필요해서예요.
- 한계: 쓰기가 안 될 때 확인과 쓰기 사이에 깨지는 틈이 있어요(6절).

## 다음에 할 일

- 자원은 공개 범위와 별도로 자원마다 맡은 일(주인, 편집, 승인 같은)을 사람이나 무리에게 줄 수 있게 돼요. 같은 문서 13절이 맡은 일을 정해요.

## 하지 않는 것

- 테라리움이 SSO와 직접 로그인 절차를 주고받지 않아요(프록시가 해요).
- 테라리움에서 그룹을 관리하지 않아요.
- 사람 이름을 하나하나 적는 접근 목록을 두지 않아요. 범위 셋이에요.

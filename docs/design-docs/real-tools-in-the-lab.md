# 진짜 툴을 실험장에 붙이기 (REQ-128~134, [ADR-0204](adr/0204-real-tools-run-against-the-lab.md))

이 문서는 설계예요. 아직 만들지 않았어요. 만든 것이 생기면 그 절에 무엇을 어떻게 만들었는지 적어요.

## 0. 한 문장

에이전트가 현실에서 쓰는 **바로 그 툴**을, 툴의 코드는 고치지 않고 향하는 곳만 실험장으로 돌려서 쓰게 해요. 테라리움은 고수준 툴을 따라 만들지 않고, 장비와 플랫폼의 **저수준 API를 흉내 내는 데** 집중해요.

## 1. 왜

- 현실의 툴은 여러 시스템의 저수준 API를 한 번에 불러 데이터를 정제해 주는 것이 많아요. 그런 툴을 테라리움 안에 하나씩 따라 만들 수 없어요. 툴은 끝없이 늘고, 저수준 프로토콜은 몇 개로 닫혀 있어요.
- 실험장에서 다른 툴을 쥐여 주면 다른 에이전트를 시험한 셈이에요. 에이전트는 툴의 이름, 설명, 인자, 답의 모양을 보고 움직여요. "맡겨도 되나"의 판정([설계](trust-experiments.md))이 현실에서도 통하려면 툴이 같아야 해요.
- 고장 중에는 저수준 API가 느려지거나 끊겨요. 그때 고수준 툴이 어떻게 답하는지가 장애 대응에서 중요한데, 따라 만든 툴로는 재현되지 않아요.

## 2. 지금 있는 것과 없는 것

만들기 전에 코드를 조사했어요(2026-11-13).

| 있는 것 | 없는 것 |
|---|---|
| 파사드 여섯: Redfish, vCenter, vROps, SNMP, BACnet, 스위치 CLI와 HTTP API. 요청과 응답의 모양이 프로토콜 그대로다 | 파사드는 네트워크 주소로 열려 있지 않다. `redfish_request` 같은 툴 호출로만 닿는다 |
| 에이전트가 툴을 받고 부르는 길이 한 곳으로 모여 있다(세션의 툴 목록과 호출, MCP 끝점) | 밖의 툴 서버를 내주는 장치, 툴의 겉모습만 바꿔 끼우는 장치 |
| 채점의 "조치"는 세계의 사건에서 나온다. 툴 이름에 기대지 않는다 | 객체 종류 62, 링크 15, 고장 97은 코드에 닫힌 목록이다. 모르는 종류가 든 세계는 거절한다 |
| 조치 관문, 권한 수준, 규칙([ADR-0199](adr/0199-action-gate-two-levels-four-rules.md)) | 관문은 내장 툴의 호출 자리에만 있다 |
| "지금 하는 방식" 표(누가·무엇을·몇 분·종류) | 표의 단계가 객체 타입이나 툴과 이어져 있지 않다. 합계 셋만 견준다 |

파사드가 바꿀 수 있는 것도 아직 좁아요. Redfish는 넷(재시작, 펌웨어 올리기, 콘센트, 차단기), vCenter는 VM 전원뿐이에요. 무엇부터 넓힐지는 5절의 발자국이 정해요.

## 3. 모양: 앞문과 뒷문

```
에이전트 ──▶ 앞문(테라리움) ──▶ 실험용 툴 서버(진짜 툴 코드) ──▶ 뒷문(테라리움이 흉내 내는 장비 API)
                 │                                                  │
                 └─ 실험장 툴: 진단, 넘기기, 묻기, 승인 요청, 기다리기 ─┴─▶ 세계
```

| 자리 | 하는 일 |
|---|---|
| **실험용 툴 서버** | 사용자가 띄워요. 현실에서 쓰는 MCP 툴 서버와 같은 코드이고, 장비 주소만 테라리움의 뒷문을 향해요. 현실의 자격 증명을 갖지 않아요 |
| **앞문** | 에이전트가 붙는 MCP 끝점이에요. 실험용 툴 서버의 툴을 이름·설명·인자 그대로 내주고 호출을 넘겨요. 호출을 기록하고, 세계 시간을 흘리고, 한 번에 하나씩 넘겨요. 현실에서 사람이나 다른 시스템이 맡는 일(진단 내기, 다른 팀에 넘기기, 사람에게 묻기, 승인 요청, 기다리기, 사건 보기)은 지금처럼 앞문이 직접 내줘요 |
| **뒷문** | 실행마다 여는 장비 API 끝점이에요. 파사드가 답해요. 세계를 바꾸는 요청은 여기서 관문과 승인을 거쳐요 |

에이전트 쪽에서 현실과 달라지는 것은 붙는 주소 하나예요.

**앞문이 왜 필요한가.** 시험 감독관을 떠올리면 돼요. 학생이 계산기를 감독관 몰래 쓰면 무엇을 몇 번 눌렀는지 알 수 없어요. 그래서 계산기를 감독관 책상을 거쳐서만 쓰게 해요. 에이전트가 실험용 툴 서버에 직접 붙으면 테라리움 눈에는 어디선가 저수준 요청 몇 개가 날아온 것만 보여요. 그러면 세 가지를 못 해요.

- **적기**: 에이전트가 어떤 툴을 몇 번 불렀는지, 뒷문에 온 요청 다섯 개가 호출 한 번인지 다섯 번인지 몰라요. 채점과 프로세스 비교가 안 돼요.
- **시계 돌리기**: 세계는 에이전트가 한 번 움직일 때마다 시간이 흘러요. 호출을 못 보면 언제 돌릴지 몰라요.
- **맡긴 범위 지키기**: 어느 호출이 막혔는지 남기려면 호출을 알아야 해요.

**앞문이 직접 내주는 툴.** 진단 내기, 다른 팀에 넘기기, 승인 요청 같은 것은 현실에서 티켓 시스템이나 사람에게 가요. 실험용 툴 서버에는 없고, 있어도 진짜 티켓이 나가면 안 돼요. 그래서 이 툴들은 테라리움이 내주고 가상 담당자와 승인하는 상대가 답해요.

### 관문의 자리

조치 관문은 "세계를 바꾸는 요청이 세계에 닿기 직전의 한 곳"이에요([ADR-0199](adr/0199-action-gate-two-levels-four-rules.md)). 내장 툴에서는 그곳이 세션의 호출 자리이고, 밖의 툴에서는 뒷문이에요. 판정은 같은 것을 써요.

- 밖의 툴이 조회인지 조치인지는 미리 알 수 없어요. 그 호출 동안 뒷문에 도착한 요청으로 정해요: 쓰기 요청이 하나라도 있으면 조치이고, 대상은 요청이 향한 장비예요.
- "보기만"이나 허가 없는 조치는 뒷문이 진짜 장비가 권한 없음을 답하는 모양으로 거절해요. 그 고수준 호출은 막힌 호출로 기록돼요. 툴이 그 거절을 에이전트에게 어떻게 전하는지도 시험의 일부예요.
- 한 호출이 여러 장비에 쓰다가 일부만 거절되면 일부만 적용돼요. 현실에서도 그래요. 기록에 어느 요청이 통과했고 어느 것이 막혔는지 남아요.
- 규칙(조치 전에 본다, 영향 범위를 본다, 조치 뒤에 확인한다)은 뒷문에 도착한 읽기와 쓰기로 세요. 툴이 안에서 먼저 읽고 쓰면 "봤다"로 세요. 본 것은 본 것이에요.

### 세계 시간과 같은 결과

- 세계 시간은 앞문의 호출 단위로 흘러요(지금 내장 툴과 같은 규칙). 뒷문 요청은 그 호출의 세계 시각에서 답해요.
- 앞문은 고수준 호출을 한 번에 하나만 넘겨요. 겹치면 줄을 세워요.
- 채점은 지금처럼 기록에서 나오니, 같은 기록은 언제 채점해도 같은 점수예요.
- 같은 실험을 **다시 돌렸을 때** 같은 기록이 나오는지는 툴 코드에 달려요(안에서 요청을 나란히 보내거나 다시 시도하면 순서가 달라질 수 있어요). 그래서 실행 기록과 판정 기록에 툴 서버의 지문(서버가 알려 준 이름과 버전, 툴 목록의 해시)을 적고, 밖의 툴을 쓴 실험은 "다시 돌리면 달라질 수 있음"을 표시해요. 숨기지 않아요.
- 앞문은 넘긴 호출을 벽시계로 기다리는 한도를 둬요. 걸리면 에이전트 탓이 아니라 실험장 한계로 적어요.

## 4. 현실을 건드리지 않는다는 약속

제품 목표의 "현실 장비를 건드리지 않고"는 이 설계에서 절반이 사용자가 띄운 서버의 설정에 달려요. 주소 하나가 현실을 향한 채 "스스로 조치" 실험을 돌리면 진짜 장비가 꺼져요. 테라리움은 남의 네트워크를 막을 수 없으니, **감지하고 멈춰요**.

| 장치 | 뜻 |
|---|---|
| **붙일 때 점검** | 툴 서버를 실험에 쓰려면 먼저 점검을 통과해야 해요. 테라리움이 본보기 세계를 열고, 서버가 뒷문에 닿는지와 툴 목록을 받아요 |
| **샌 호출 감지** | 뒷문 요청이 있어야 하는 툴(발자국으로 앎)이 뒷문 요청 없이 답을 돌려주면, 밖을 읽었거나 밖에 썼을 수 있어요. 그 실행을 바로 멈추고 "밖으로 샌 호출"로 적어요. 점수를 내지 않아요 |
| **발자국이 없는 툴** | 처음 보는 툴의 첫 호출이 뒷문 요청 없이 끝나면 같은 식으로 멈춰요. 뒷문을 쓰지 않는 것이 맞는 툴(계산만 하는 툴)은 붙일 때 사용자가 그렇게 적어요 |
| **뒷문의 토큰** | 뒷문은 실험 자리의 토큰만 받아요. 현실의 자격 증명이 필요 없으니 실험용 서버에 넣지 않아요 |
| **안내** | 실험용 서버는 가짜 자격 증명으로, 현실망에 닿지 않는 곳에 띄워요. 안내서에 적어요 |

감지는 막는 것이 아니에요. 이미 나간 요청은 되돌릴 수 없어요. 그래서 붙일 때 점검과 안내가 먼저예요.

## 5. 실험 자리, 발자국, 능력 목록

### 실험 자리

실험용 툴 서버 하나는 한 번에 세계 하나만 향해요. 이 묶음이 **실험 자리**예요: 뒷문의 기준 주소 하나, 토큰 하나, 툴 서버 하나.

- 실행은 자리를 차례로 써요. 동시에 도는 실행 수는 자리 수예요. 내장 툴만 쓰는 실험처럼 수십 개를 한꺼번에 돌리지 못해요. 새 실험 화면이 걸릴 시간을 미리 말해요.
- 툴이 장비 주소를 받는 방식은 사용자의 일이에요(설정, 조회, 환경 변수). 주소가 코드에 박힌 툴은 붙일 수 없어요. 뒷문의 주소 모양(장비마다 경로인지 호스트 이름인지)은 만들 때 본보기 툴 서버로 정해요.

### 발자국

밖의 툴이 호출될 때마다 뒷문에 도착한 요청을 툴별로 모아요: 어느 프로토콜의 어느 경로를 몇 번, 읽기인지 쓰기인지, 그중 **흉내 내지 못한 것**.

- 흉내 내지 않는 경로는 "없음"으로 답하지 않아요. 툴이 "그 장비는 없다"로 잘못 읽어요. "실험장이 흉내 내지 않는 기능"임을 알 수 있는 답을 주고 실험장 한계로 적어요.
- 발자국은 손으로 적는 매핑을 대신해요. "이 고수준 툴 하나가 저수준 호출 몇 개인가"를 재서 알아요.
- 프로세스 비교에서는 앞문의 호출 하나가 단계 하나예요. 안에서 저수준 요청을 몇 번 했는지는 펼쳐 볼 수 있어요.

### 능력 목록

테라리움이 무엇을 흉내 내는지를 판 번호가 붙은 문서로 내놓아요: 프로토콜과 프로파일, 경로와 메서드(읽기/쓰기), 행동이 있는 객체 종류, 낼 수 있는 고장 종류, 알려진 단순화.

- 밖에서는 툴의 발자국을 이 목록에 대어 "이 툴은 실험장에서 돌 수 있다 / 일부만 / 못 한다"를 계산해요. 사람이 칠하지 않아요.
- 무엇부터 넓힐지도 여기서 나와요: 여러 툴이 부르는데 목록에 없는 경로가 먼저예요.

## 6. 툴마다 세 가지 길

| 길 | 언제 | 판정에 적히는 것 |
|---|---|---|
| **같은 툴** | 툴이 테라리움이 흉내 내는 프로토콜만 쓴다 | 현실과 같은 툴로 본 결과 |
| **겉모습 입히기** | 인자를 그대로 넘기기만 하는 얇은 툴(원격 명령 실행 같은 것). 밖의 이름·설명·인자를 테라리움 내장 툴에 입힌다. 서버를 띄우지 않아도 된다 | 이름이 같은 툴로 본 결과. 답의 모양은 다를 수 있음 |
| **내장 툴** | 프로토콜 흉내가 없는 영역(쿠버네티스, DB, 앱), 밖의 제품 없이 혼자 도는 실험 | 테라리움의 툴로 본 결과 |

- 내장 툴은 남아요. 다만 새 고수준 툴을 내장으로 더하지 않아요. 새로 필요한 것은 저수준 흉내예요.
- 겉모습 입히기는 실험 조건에 표로 받아요: 밖의 툴 이름, 설명, 인자 → 안쪽 툴과 인자 대응. 데이터를 정제하는 툴에는 쓰지 않아요(정제를 두 번 적게 돼요).
- 한 실험에 세 길이 섞일 수 있어요. 판정 기록에 툴마다 어느 길이었는지 적어요.

## 7. 밖의 제품과 주고받는 문서 다섯

업무 프로세스를 정의하고 현실에서 운영하는 일은 다른 제품의 것이에요([ADR-0192](adr/0192-terrarium-returns-to-its-first-goal.md)). 그 제품과는 판이 붙은 문서 다섯으로 이어져요.

| 문서 | 방향 | 담는 것 |
|---|---|---|
| **표준 판** | 들어옴 | 객체와 링크 타입의 식별자, 그리고 타입마다 "테라리움의 어느 종류의 하나인가" |
| **능력 목록** | 나감 | 5절 |
| **세계 스냅샷** | 들어옴 | 객체, 링크, 속성, 근거 등급(REQ-121). 타입은 표준 판의 식별자로 |
| **업무 의뢰** | 들어옴 | 프로세스의 어느 스텝들을 시험하는지, 스텝마다 누가 하는지(에이전트, 사람, 다른 팀, 물리 작업), 승인 스텝, 걸리는 시간, 사람이 하던 방식, 실험 자리와 겉모습 표 |
| **판정 기록** | 나감 | 판정과 근거(REQ-122), 스텝마다 걸린 시간과 사람 손이 간 수, 툴마다 어느 길이었는지, 실험장 한계 |

- **테라리움은 밖의 제품을 부르지 않아요.** 실험은 받은 문서의 판을 고정해 돌아요. 밖의 제품이 테라리움의 API로 의뢰를 넣고 판정을 받아 가는 것은 돼요.
- **안쪽 이름은 그대로 두고 경계에서 번역해요.** 코드와 잠긴 시험에 박힌 종류, 링크, 툴, 고장의 이름을 표준 식별자로 바꾸지 않아요. 번역표는 경계 네 곳(세계 받기, 능력 목록, 업무 의뢰, 판정 기록)에만 있어요.
- **모르는 타입**: "어느 종류의 하나"가 적혀 있으면 그 종류로 움직여요. 없으면 거절하지 않고 받아서, 행동이 없는 객체로 두고 보고해요. 그 객체에 닿는 스텝은 시험하지 않은 것으로 판정에 나와요.
- **업무 의뢰가 실험 조건이 돼요**: 누가 하는지 → 맡기는 범위, 승인 스텝 → 승인 규칙과 승인하는 상대, 다른 팀과 물리 작업 → 가상 담당자와 걸리는 시간, 사람이 하던 방식 → 프로세스 비교의 기준. 테라리움은 순서를 그리거나 고치지 않아요. 받은 대로 조건으로 옮길 뿐이에요.
- 밖의 제품이 없어도 테라리움은 혼자 돌아요. 지어낸 세계, 내장 툴, 손으로 적은 "지금 하는 방식" 표가 그대로예요.

## 8. 하지 않는 것

- 고수준 툴을 따라 만들기, 정제 로직을 조합으로 다시 적기.
- 현실 시스템에 연결하기, 현실의 자격 증명 갖기.
- 사용자가 밖에서 새로 만든 타입이나 액션의 행동을 저절로 만들어 내기. "어느 종류의 하나"까지만 받아요.
- 실험용 툴 서버를 대신 띄워 주기. 띄우는 것은 사용자의 일이고, 테라리움은 붙이는 법과 점검을 줘요.
- 프로세스를 그리거나 고치기.

## 9. 순서

얇게 끝까지 한 줄을 먼저 세워요. 저장소 안에 **본보기 툴 서버**(Redfish 요청 여러 개를 묶어 정제해 주는 지어낸 고수준 툴 두셋)를 두고, 그것을 붙여 실험 하나를 끝까지 돌려요.

| 순서 | 무엇 | 끝났다는 증거 |
|---|---|---|
| 1 | 뒷문 한 줄: 실험 자리 하나, Redfish 끝점, 토큰, 흉내 내지 않는 경로의 답 | 본보기 툴 서버의 요청이 세계를 읽고 바꾼다 |
| 2 | 앞문 한 줄: 밖의 툴 서버 등록, 툴 내주기와 넘기기, 호출 기록, 세계 시간, 관문을 뒷문에 | 본보기 툴로 푼 시나리오의 점수 분해가 내장 툴로 푼 것과 같다. "보기만"에서 쓰기가 막힌다 |
| 3 | 샌 호출 감지, 붙일 때 점검, 발자국 | 뒷문을 거치지 않고 답하는 본보기 툴이 실행을 멈춘다 |
| 4 | 능력 목록 내보내기, 판정 기록에 툴마다의 길 | 본보기 툴의 발자국을 목록에 대어 돌 수 있음이 계산된다 |
| 5 | 겉모습 입히기 | 밖의 이름으로 부른 호출이 내장 툴과 같은 사건을 남긴다 |
| 6 | vCenter, vROps, 스위치 HTTP API 끝점. 그다음 발자국이 말하는 순서로 흉내 넓히기 | 프로토콜마다 본보기 요청의 왕복 |
| 7 | 표준 판과 번역, 모르는 타입 받기(스냅샷 한 줄과 함께) | 표준 식별자로 적힌 세계가 열리고 모르는 타입이 보고된다 |
| 8 | 업무 의뢰 받기, 스텝마다의 측정 | 의뢰 하나가 실험 조건이 되고 판정 기록에 스텝별 값이 나온다 |

SNMP, BACnet, SSH를 진짜 소켓으로 여는 일은 이 순서 밖이에요. 그 프로토콜을 쓰는 툴은 겉모습 입히기나 내장 툴로 가요.

## 시험 (만들 때)

| 무엇 | 어떻게 |
|---|---|
| 밖의 툴을 쓰지 않는 실험은 그대로다 | 지문, 점수 분해, 기록이 바이트까지 같다 |
| 같은 일을 두 길로 풀면 점수가 같다 | 본보기 툴과 내장 툴로 같은 조치를 해서 점수 분해를 견준다 |
| 관문이 뒷문에서 듣는다 | "보기만"에서 본보기 툴의 쓰기가 거절되고 막힌 호출로 남는다 |
| 샌 호출이 실행을 멈춘다 | 뒷문 없이 답하는 툴, 발자국과 다른 툴 |
| 흉내 내지 않는 경로가 한계로 남는다 | "없음"이 아닌 답, 기록의 한계 줄 |
| 한 번에 하나 | 겹친 호출이 줄을 서고 기록의 순서가 정해져 있다 |
| 모르는 타입 | 받아서 보고하고, 닿는 스텝이 시험하지 않은 것으로 나온다 |

# 설정 변경 시나리오 (REQ-068, ADR-0065)

## 한 줄로

고장 시나리오는 "부품이 망가졌다"를 만든다. 설정 시나리오는 **"누군가 설정을 바꿨다"** 를 만든다. 포트를 엉뚱한 VLAN에 꽂았고, 점검하다 포트를 껐고, 콘센트를 내렸다. 서버는 멀쩡한데 닿지 않는다.

## 비유로 이해하기

건물 관리인이 사무실 문패를 잘못 바꿔 단 상황이다. 사무실(서버)도, 복도(케이블)도 멀쩡하다. 그런데 택배(패킷)가 문패 따라 가다 엉뚱한 층에 선다. 부서진 곳이 없으니 "고장 알람"은 없고, **"저 서버에 연락이 안 돼요"** 라는 증상만 남는다. 에이전트는 문패(설정)를 읽고 원래대로 돌려야 한다.

## 블록 여섯 개

| 블록 | 하는 일 | 운영자가 치는 것 |
|---|---|---|
| 스위치 포트 끄기/켜기 | 포트 하나를 관리자가 끄거나 켠다 | `shutdown` / `no shutdown` |
| 포트 VLAN 바꾸기 | 접근 포트의 VLAN을 바꾼다 | `switchport access vlan` |
| VLAN 인터페이스 끄기/켜기 | 게이트웨이(SVI)를 끄거나 켠다 | `interface Vlan… shutdown` |
| BGP 이웃 끄기/켜기 | 이웃 하나의 세션을 내린다 | `neighbor … shutdown` |
| 정적 경로 지우기 | 손으로 적은 경로 하나를 지운다 | `no ip route` |
| PDU 콘센트 끄기/켜기 | 콘센트 하나를 내린다 | PDU의 콘센트 제어 |

블록은 새 월드 명령을 만들지 않는다. 이미 있는 `link.admin`, `net.set`, `outlet.set`을 낸다.

## 값은 쓰지 않고 고른다

사람이 포트 번호나 IP를 외워 쓰게 하면 틀린 값이 실행에서야 드러난다. 그래서 위에서 스위치를 고르면, 아래 칸은 **그 스위치가 실제로 가진 것**을 보여 준다.

- 포트 → "srv-a1 (포트 3번)" 처럼 케이블로 이어진 장비 이름
- VLAN 인터페이스 → "VLAN 100 서버망 (10.0.0.1/24)"
- BGP 이웃 → "sp1 (172.16.0.5, AS 65001)"
- 정적 경로 → "10.0.0.0/23 → 172.16.0.0"
- 콘센트 → "1번 — srv-a1"

목록은 케이블이 설계한 네트워크에서 나온다(`netChoices`, `planOf`). 고를 것이 없는 스위치는 빈 상자를 보여 주지 않고 이유를 말한다("BGP를 쓰지 않아요 (클라우드·GPU 패브릭의 leaf와 spine만 써요)"). 스위치를 다른 것으로 바꾸면 이전 스위치의 목록에서 고른 값은 지워진다(`setParam`). 같은 스위치를 다시 고르면 그대로 둔다.

## 손으로 만들 때

팔레트에서 설정 블록을 누르면 주된 줄 끝에 이어 붙는다(`appendBlock`). 끌어다 놓으면 놓은 자리에 이어지지 않은 채 남는다(`addBlock`). 이어 붙는 규칙은 [측정의 신뢰](measurement.md)와 ADR-0068에 있다.

## 검증과 실행

- **검증**: `netBlockProblem`이 `net_pick`마다 값이 목록에 있는지 본다. 없으면 "고를 수 있는 것"을 여섯 개까지 보여 준다. 목록은 한 값이 다른 값에 기대므로 매개변수 하나로는 못 보고 블록 전체에서 본다. `paramProblem`은 문자열이나 숫자인지만 본다.
- **실행**: `netCommands`가 지금 스위치의 설정(`netModelOf`)을 읽고 명령을 만든다. 앞 블록이나 에이전트가 이미 바꿨을 수 있기 때문이다. SVI는 주소를 그대로 두고 `shut`만 바꾼다. 포트 VLAN은 케이블에서 포트 번호를 찾는다. BGP는 이웃 이름에서 주소를 찾는다.
- **채점**: 에이전트가 `network_cli`로 스위치 설정을 바꾸면 행동 `config_change`가 된다. 포트 끄기·켜기는 `port_off`/`port_on`이고 케이블 대상 또는 스위치 이름으로 맞는다.

## 실수에 이름이 있다

`MISTAKE_SPECS`는 엉뚱한 VLAN, 꺼진 포트, 꺼진 SVI, 꺼진 BGP 이웃, 지워진 경로, 꺼진 콘센트를 가진다. 고장 종류와 같은 자리(진단의 정답)에 들어간다. 오라클은 ID나 한국어 이름 둘 다 정답으로 센다.

## 내장 템플릿 일곱 개

`NETWORK_TEMPLATES`(기존 `SCENARIO_TEMPLATES`와 따로 둔다)가 월드에 맞는 대상을 골라 만든다.

1. 서버 포트가 엉뚱한 VLAN에 있어요 (보통)
2. 서버 포트를 실수로 껐어요 (쉬움)
3. 게이트웨이 VLAN 인터페이스가 꺼졌어요 (어려움) — 쌍이 서로 받쳐 주므로 둘 다 끈다
4. 코어의 정적 경로가 지워졌어요 (어려움) — 경로가 여럿(ECMP)이면 모두 지운다
5. BGP 이웃 하나가 꺼졌어요 (보통) — 클라우드·GPU 패브릭 월드에서만
6. GPU 서버의 레일 하나가 끊겼어요 (어려움) — GPU 패브릭 월드에서만
7. PDU 콘센트가 꺼졌어요 (쉬움)

과제 문장에는 증상만 있고 원인 스위치 이름이 없다. 맞는 대상이 없는 월드에서는 `unavailable`이 이유를 말한다. 각 템플릿은 시험이 (가) 알람이 에이전트에게 닿기 전에 서 있고 (나) 스위치 명령으로 되돌리면 점수를 받고 (다) 서버를 끄고 찍으면 훨씬 낮은 점수인 것을 확인한다.

## 한계

- 호스트 이름·배너 같은 통신과 무관한 설정, VLAN 신규 생성, 트렁크 허용 목록 변경, 스패닝 트리 설정 블록은 없다.
- 이 일곱 템플릿은 조치(되돌리기)를 채점하는 시나리오다. 정답만 아는 기준 에이전트는 65점이다. 시설 쪽에서 조치를 채점하는 시나리오는 [시나리오 모델](scenario-model.md)에 있다.
- 설정 실수 여럿을 겹치는 내장 템플릿은 없다. 블록을 이어 직접 만들어야 한다.
- 편집기의 목록은 내장 카탈로그로 계산한다. 사용자 정의 카탈로그를 쓰는 월드에서는 서버 쪽 검증이 최종이다.
- 이미 올라 있는 `bgp_session_down` 알람은 처음 메시지를 간직해서, 나중에 이웃을 더 끄면 메시지가 갱신되지 않는다.

# 제어 가능 요소표 (REQ-069, ADR-0066)

## 한 줄로

테라리움에서 **사람(시나리오)이 바꿀 수 있는 것**과 **에이전트가 바꿀 수 있는 것**이 어긋나면 점수가 거짓이 된다. 그래서 바꿀 수 있는 것을 한 장의 표로 적고, 표가 참인지 시험이 매번 확인한다.

## 비유로 이해하기

방송국 조정실의 스위치 패널을 떠올리자. 패널에는 스위치마다 라벨이 붙어 있다. 라벨이 있어도 연결이 안 된 스위치가 있으면 눌러도 소용없고, 연결은 됐는데 라벨이 없으면 아무도 모르고 누른다. 이 표는 **라벨과 연결을 맞춰 보는 점검표**다. 시험은 스위치를 하나씩 실제로 눌러 보고 불이 들어오는지 본다.

## 표

각 줄: 어떤 조작이고, 시나리오가 어떤 블록으로 만들고, 에이전트가 어떤 길로 하고, 채점에는 어떤 행동으로 보이는가.

| 무엇을 | 대상 | 시나리오 블록 | 에이전트의 길 | 채점에 보이는 행동 |
|---|---|---|---|---|
| 서버 전원 | 서버 | 전원 켜기/끄기 | 서버 전원 제어, Redfish 요청 | 전원 끄기, 전원 켜기, 재시작 |
| 가상 머신 전원 | VM | 전원 켜기/끄기 | vCenter 요청 | 전원 끄기, 전원 켜기, 재시작 |
| 냉방기 켜기/끄기 | 냉방기 | 전원 켜기/끄기 | 냉방기 재시작, BACnet 요청 | 전원 끄기, 전원 켜기, 재시작 |
| 냉각 플랜트·발전기 켜기/끄기 | 냉각 플랜트, CDU, 발전기 | 전원 켜기/끄기 | BACnet 요청 | 전원 끄기, 전원 켜기, 재시작 |
| 스위치·스토리지 전원 | 스위치, 스토리지 | 전원 켜기/끄기 | 없음 — 현장에서는 전원 분배기 콘센트로 끈다. 에이전트는 PDU 콘센트 줄을 쓴다. | — |
| 냉방 설정 온도 | 냉방기 | 냉방 설정 온도 | 냉방 설정 온도 변경, BACnet 요청 | 냉방 설정 변경 |
| 차단기 리셋 | PDU, 분전반 | 고장 발생(차단기 트립) | 차단기 리셋, Redfish 요청 | 차단기 리셋 |
| PDU 콘센트 | PDU | PDU 콘센트 끄기/켜기 | Redfish 요청 | 콘센트 끄기, 콘센트 켜기 |
| 서버 펌웨어(BMC·BIOS) 올리기 | 서버 | 없음 — 시나리오는 올리기를 시키지 않고, 실패만 고장 발생 블록(펌웨어 올리기 실패)으로 만든다. | Redfish 요청(UpdateService의 SimpleUpdate) | 펌웨어 올리기 |
| 호스트의 프로세스·서비스 다시 시작 (REQ-087) | 서버, VM | 없음 — 운영자의 조치로만 일어난다. 고장은 고장 발생 블록으로 만든다. | 호스트에서 명령 실행(`systemctl restart`), 서비스 다시 시작 | 프로세스 다시 시작, 서비스 다시 시작 |
| 호스트 디스크 비우기 (REQ-087) | 서버, VM | 없음 | 호스트에서 명령 실행(`rm /var/log/…`, `logrotate -f`) | 디스크 비우기 |
| 파일시스템 다시 마운트 (REQ-087) | 서버, VM | 없음 | 호스트에서 명령 실행(`mount -o remount,rw /`) | 파일시스템 다시 마운트 |
| 호스트 재부팅 (REQ-087) | 서버, VM | 없음 | 호스트에서 명령 실행(`reboot`) | 재시작 |
| 서비스를 대기 쪽으로 옮기기 (REQ-086) | 서비스 | 없음 | 서비스 대기 쪽으로 옮기기 | 서비스를 대기 쪽으로 옮기기 |
| VM을 다른 서버로 옮기기 (REQ-086) | VM | 없음 | VM 다른 서버로 옮기기 | VM 다른 서버로 옮기기 |
| 스위치 포트 끄기/켜기 | 네트워크 케이블 | 스위치 포트 끄기/켜기 | 스위치 CLI, Arista eAPI 요청, Cisco NX-API 요청, SNMP 요청 | 포트 끄기, 포트 켜기 |
| 스위치 설정 (VLAN, SVI, 경로, BGP) | 스위치 | 포트 VLAN 바꾸기, VLAN 인터페이스 끄기/켜기, 정적 경로 지우기, BGP 이웃 끄기/켜기 | 스위치 CLI, Arista eAPI 요청, Cisco NX-API 요청 | 스위치 설정 변경 |
| 외기 온도 | 사업장 | 외기 온도 바꾸기 | 없음 — 날씨는 운영자가 바꿀 수 없다. 시나리오가 폭염이나 한파를 만들 뿐이고, 에이전트는 BACnet 외기 온도 입력으로 읽기만 한다. | — |
| 서버·VM 부하 | 서버, VM | 부하 변경 | 없음 — 일감은 운영자가 바꾸는 설정이 아니라 실험이 만드는 상황이다. 에이전트가 건드리면 정답이 사라진다. | — |

서비스와 호스트 조치(REQ-086·087, [서비스·OS 층](service-os-layer.md))는 월드 명령 `host.act`·`service.failover`·`service.restart`·`vm.migrate`다. 호스트 조치는 한 명령에 네 갈래(프로세스 다시 시작, 디스크 비우기, 다시 마운트, 재부팅)라 표에서 줄을 나눠 적었다.

월드 명령 가운데 운영자의 것이 아닌 것은 이름이 붙어 있다: 고장 발생·복구(시나리오), 열 보호 종료(물리 엔진), 알람 올리기·지우기(모니터링), 기록.

## 시험이 보장하는 것

`tests/spec/controllability.test.ts`가 표를 세 방향에서 확인한다.

1. **표가 월드와 같다.** 캠퍼스 월드의 모든 엔티티에 명령을 실제로 보내 받아들여진 종류가 줄에 적힌 종류와 정확히 같다. 새 종류가 명령을 받게 되면 표를 고칠 때까지 실패한다.
2. **빠진 길이 없다.** 월드를 바꾸는 툴은 모두 어느 줄의 길이다. 행동 종류는 모두 어느 줄에서 나온다. 운영 블록은 모두 어느 줄에 있거나 "아직 지원하지 않음"이다.
3. **길마다 실제로 된다.** 줄의 길 스물일곱 개를 각각 실제 툴 호출로 구동한다. 호출 전에는 바뀌지 않았고, 호출 후에는 바뀌었고, 세션이 그 행동 종류와 대상으로 기록했다.

## 고장마다 에이전트가 할 수 있는 일

시나리오 작성자가 "이 고장에서 에이전트에게 무엇을 기대할 수 있나"를 보는 표다. 어떤 툴로도 못 하는 조치를 점수에 넣지 않게 한다.

| 고장 | 에이전트가 할 수 있는 것 | 쓰는 길 |
|---|---|---|
| 차단기 트립 | 고칠 수 있어요 | 차단기 리셋 |
| 냉방기 정지, 냉방 능력 저하 | 피해를 줄일 수 있어요 | 냉방 설정 온도, 서버 전원 |
| 설정 온도 틀어짐 | 피해를 줄일 수 있어요 | 냉방 설정 온도 |
| 냉각 플랜트 정지 | 피해를 줄일 수 있어요 | 냉방 설정 온도, 서버 전원 |
| 냉각 플랜트 능력 저하, CDU 정지, CDU 펌프 고장, 냉각수 누설, 액침 순환 정지 | 피해를 줄일 수 있어요 | 서버 전원 |
| 한전 정전, 발전기 기동 실패, 자동절체반 고착 | 피해를 줄일 수 있어요 | 서버 전원 |
| 수전 중단 | 피해를 줄일 수 있어요 | 냉각 플랜트·발전기 켜기/끄기, 서버 전원 |
| 서버 팬 고장, CPU 폭주 | 피해를 줄일 수 있어요 | 서버 전원 |
| VM CPU 급증 | 피해를 줄일 수 있어요 | 가상 머신 전원 |
| 디스크 꽉 참 (REQ-087) | 고칠 수 있어요 | 호스트에서 명령 실행(로그 지우기) |
| 로그 폭주, 좀비 프로세스 누적, 시간 동기 어긋남, DNS 실패 | 고칠 수 있어요 | 호스트에서 명령 실행(해당 프로세스 다시 시작), 서비스 다시 시작 |
| 파일시스템 읽기 전용 | 고칠 수 있어요 | 호스트에서 명령 실행(다시 마운트) |
| 메모리 누수, 프로세스 재시작 반복, 커널 패닉 | 피해를 줄일 수 있어요 | 서비스 대기 쪽으로 옮기기, 서비스 다시 시작 |
| 인증서 만료 | 진단하고 사람을 불러요 | — |
| UPS 배터리 열화, PSU 고장, 온도 센서 오차, BMC 무응답, 네트워크 링크 다운, 스위치 고장, 디스크 고장 | 진단하고 사람을 불러요 | — |

설정 실수(엉뚱한 VLAN, 꺼진 포트 등)는 고장이 아니라 설정 블록이 만들고 같은 명령으로 되돌린다. [설정 변경 시나리오](config-scenarios.md)를 본다.

## 아직 없는 것 (정직하게)

- **시나리오 쪽**: 네트워크 품질 저하(지연·손실) 블록은 팔레트에 "아직 지원하지 않음"으로 있다. 링크의 지연·손실 모델과 경로 홉의 링크 id가 먼저 필요하다. 외기 온도 블록은 이제 된다(REQ-073): 세계의 외기 온도가 냉각 플랜트의 용량을 깎고(드라이쿨러·냉각탑은 기존 감쇠, 칠러도 25~40°C에서 1배에서 0.85배로) 방의 외피 열 교환에 들어가며, 물리 골든은 기본값 25°C에서 그대로다.
- **에이전트 쪽**: UPS 모드(바이패스), 자동절체반 수동 전환, CDU 펌프 속도·설정 온도, 디스크 교체, 서버 BMC 재시작. 현장 운영자는 하는 조작이지만 월드에 명령이 없다.
- 발전기의 `Unit-Enable`은 자동(AUTO)과 끔(OFF)이다. 수동 기동은 없다.
- 각 길은 요청 한 가지로 구동한다. 프로토콜의 모든 변형(Redfish `ResetType` 전부 등)은 아니다.
- "피해를 줄일 수 있어요"는 선언이다. 실제로 줄이는지는 일부만 시험한다. 정전(배터리를 낡게 한 경우)의 서버 전원, VM 폭주의 가상 머신 전원, CDU 정지의 수랭 서버 전원은 실제로 줄이고, 내장 시나리오가 그 조치를 채점한다(REQ-073, [측정의 신뢰](measurement.md)). 냉방기 정지의 설정 온도는 샘플 캠퍼스에서 차이가 작다.

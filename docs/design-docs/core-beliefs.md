# 핵심 신념 (Golden Principles)

OpenAI의 하네스 엔지니어링 글에서 가져온 원칙을 이 프로젝트에 맞게 줄였다.
말이 아니라 **기계가 강제**할 수 있는 것만 규칙으로 두고, 강제할 수 없는 것은 신념으로만 둔다.

1. **저장소가 유일한 지식원이다.** 채팅·구두 합의는 없는 것이다. 결정은 ADR, 요구사항은 `REQ`.
2. **지도는 짧게, 깊이는 링크로.** AGENTS.md는 120줄 이하 (`DOC050`).
3. **경계는 엄격히, 안쪽은 자유롭게.** 레이어·공개 API·외부 라이브러리 범위만 강제한다.
4. **오류 메시지가 곧 교육이다.** 모든 검사는 `problem`과 `fix`를 말한다.
5. **문서는 스스로 낡았음을 증명해야 한다.** 코드는 `covers`, 다른 문서와 결정은 `follows` 지문과 만료 기한. 확인했다는 기록이 아니라 확인할 수 있는 주장(가리키는 것의 존재, 센 숫자)으로 바꾼다.
6. **실패한 테스트는 코드의 잘못이다.** 테스트는 잠겨 있고, 바꾸려면 요구사항이 바뀌었다는 ADR이 필요하다.
7. **부채는 적어야 존재할 수 있다.** 장부, 기한, 예산, 래칫. 매번 조금씩 갚는다.
8. **지루한 기술을 쓴다.** 에이전트가 완전히 이해할 수 있는 의존성만. 새 의존성은 범위를 정해 가둔다.
9. **같은 입력, 같은 결과.** 시뮬레이터는 결정적이어야 벤치마크가 재현된다 (REQ-001).
10. **사람의 취향은 규칙으로 승격한다.** 리뷰에서 반복된 지적은 린터나 테스트가 된다.

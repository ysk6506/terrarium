# 소스 관리 (REQ-115 예정, ADR-0151)

[현실 데이터와 모델](reality-data-and-ontology.md)의 "연결" 단을 날마다 굴리는 데 필요한 기본 기능이에요. 아직 만들지 않았어요. 연결을 다루는 방식은 이미 있는 [연결 화면](web-ui-connections.md)과 ADR-0043(비밀 보관·판·정리)을 그대로 따라요.

## 한 줄로

소스마다 얼마나 자주 받을지 정하고, 받은 것은 안전장치를 거쳐 세계의 새 판이 되고, 무슨 일이 있었는지는 기록으로 남아요.

## 1. 동기화 주기는 소스마다 정해요

| 방식 | 뜻 | 맞는 소스 |
|---|---|---|
| 손으로만 | "지금 동기화"를 누를 때만 | 엑셀 대장(새 파일을 올리면 한 번) |
| 간격 | 15분 ~ 7일마다 | API 소스. 기본은 하루 한 번 |
| 정해진 시각 | 매일 03:00, 요일 고르기 | 업무 시간을 피해야 하는 소스 |

- 프리셋이 기본 주기를 제안해요. 구성은 자주 바뀌지 않아서 기본이 길어요.
- 가장 짧은 간격은 15분이에요. 소스에 주는 부담을 지키려는 거예요.
- 소스마다 "지금 동기화", "잠시 멈춤"(이유를 적어요)이 있고, 다음 실행 시각이 보여요.
- 한 소스의 동기화는 한 번에 하나만 돌아요. 전체로도 동시에 도는 수에 한도가 있어요.
- 서버가 꺼져 있던 동안 놓친 주기는 켜질 때 한 번만 따라잡아요. 몰아서 여러 번 돌지 않아요.

## 2. 동기화 한 번은 기록 하나예요

| 걸음 | 남는 것 |
|---|---|
| 수집 | 받은 줄 수, 걸린 시간, 받은 그대로의 해시 |
| 대응 | 이어진 것 · 못 이은 것 · 개수가 안 맞는 것 |
| 차이 | 더해짐 · 바뀜 · 안 보임 (각각 몇 개) |
| 적용 | 세계의 새 판, 또는 "바뀐 것 없음" |

결과는 셋 중 하나예요: 됨 / 멈춤(받았지만 적용하지 않음) / 안 됨. 멈춤과 안 됨에는 이유 한 줄과 고치는 법이 붙어요. 기록은 90일 동안 남아요.

## 3. 자동으로 적용하기 전에 거치는 안전장치

| 상황 | 하는 일 |
|---|---|
| 받은 것이 지난번과 같다 | 새 판을 만들지 않아요 |
| 처음 동기화, 또는 대응을 고친 뒤 첫 동기화 | 사람이 차이를 보고 적용해요. 그 뒤부터 자동이에요 |
| 열이 사라지거나 형이 바뀌었다 | 대응에서 멈춰요. 세계는 그대로예요 |
| 한 번에 너무 많이 사라졌다(기본 10% 넘게) | 적용하지 않고 "확인이 필요해요"로 멈춰요. 소스가 빈 답을 준 사고로 세계가 비는 것을 막아요 |
| 개체가 소스에서 안 보인다 | 바로 지우지 않고 "안 보임"으로 표시해요. 세 번 연속이면 지워요 |
| 수집이 안 됐다 | 간격을 늘려 세 번 다시 해 보고, 안 되면 다음 주기를 기다려요. 연속 다섯 번이면 스스로 멈추고 알려요 |
| 자격 증명이 만료됐다 | 다시 해 보지 않고 바로 알려요 |

## 4. 신선도를 숨기지 않아요

- 소스마다 "마지막으로 받은 때"가 보여요. 주기의 두 배를 넘기면 "낡음"이에요.
- 세계와 토폴로지 판에 "이 세계의 데이터는 3시간 전 것이에요"가 보여요. 속성마다 출처와 받은 시각을 따라갈 수 있어요.

## 5. 세계의 판과 실험

- 적용할 때마다 세계의 새 판이 생기고, 판마다 차이 요약이 붙어요.
- 실험은 시작할 때의 판에 묶여요(이미 있는 실험 스냅샷). 세계가 그 뒤에 바뀌어도 그 실험의 점수는 바뀌지 않아요. 제품 목표의 "채점이 늘 맞고 같다"가 이렇게 지켜져요.
- 동기화되는 세계는 손으로 고치지 않아요. 고친 것이 다음 동기화에 덮이기 때문이에요. 바꿔 보고 싶으면 떠내서(복사해서) 해요.
- 여러 소스가 한 세계를 채우면 수집은 소스마다 따로 돌고, 적용은 세계마다 한 줄로 서요.

## 6. 연결 자체의 관리

이미 있는 연결의 방식을 그대로 써요(ADR-0043).

- 비밀 값은 봉인해 두고 되돌려 주지 않아요. 화면에는 "설정됨"만 보여요. 사내 게이트웨이용 헤더를 붙일 수 있어요.
- **연결 확인**은 셋을 봐요: 닿는가, 읽기 전용 계정인가(ADR-0149), 무엇이 있는가.
- 만든 사람만 고쳐요. 고치면 판이 오르고 무엇이 달라졌는지 남아요. 주기·대응·규칙도 같아요.
- 소스를 지울 때는 그 소스에서 온 개체를 어떻게 할지 물어요. 기본은 세계에 남기고 "출처 없음"으로 표시해요.
- 받은 그대로는 최근 10판 또는 30일까지 두고, 차지하는 크기를 보여 줘요.
- 쓰이지 않는 연결을 30일 뒤 지우는 규칙은 소스 연결에는 적용하지 않아요.

## 7. 한눈에 보는 화면

소스 목록의 한 줄: 이름 · 역할(구성·사건·실측) · 상태(정상 / 낡음 / 멈춤 / 안 됨) · 마지막으로 받은 때 · 다음 실행 · 채우는 세계 · 개체 수. 문제가 있는 소스가 위로 와요. 이 화면이 답하는 물음은 하나예요: "어느 소스를 봐야 하나?"

## 하지 않는 것 (지금)

- 메일·메신저 알림. 알림은 제품 안의 배너와 목록이에요.
- 서버 여러 대에서의 중복 실행 막기와 고가용성. 서버 한 대를 전제로 해요(ADR-0150의 제안 목록).
- 소스 쪽에 쓰기. 커넥터는 읽기만 해요.

## 시험 (만들 때)

| 시험 | 내용 |
|---|---|
| 주기 | 가짜 시계로: 간격·정해진 시각·놓친 주기 한 번 따라잡기·한 번에 하나 |
| 같으면 그대로 | 받은 것이 같으면 세계의 판이 늘지 않는다 |
| 큰 변화 | 사라짐이 한도를 넘으면 적용되지 않고 세계가 바이트까지 그대로다 |
| 안 보임 | 한두 번 안 보인 개체는 남고 세 번째에 지워진다. 다시 보이면 표시가 풀린다 |
| 실험 고정 | 동기화로 세계가 바뀐 뒤에도 앞선 실험을 다시 채점하면 점수 분해가 바이트까지 같다 |
| 비밀 | 어느 응답·기록·내보내기에도 비밀 값의 평문이 없다 |
| 다시 해 보기 | 만료된 자격 증명은 다시 해 보지 않는다. 연속 실패는 스스로 멈춘다 |

# 소스 관리 (REQ-115 예정, ADR-0151)

[현실 데이터와 모델](reality-data-and-ontology.md)의 "연결" 단을 날마다 굴리는 데 필요한 기본 기능이에요. 아직 만들지 않았어요. 연결을 다루는 방식은 이미 있는 [연결 화면](web-ui-connections.md)과 ADR-0043(비밀 보관·판·정리)을 그대로 따라요.

## 한 줄로

소스마다 얼마나 자주 받을지 정하고, 받은 것은 안전장치를 거쳐 세계의 새 판이 되고, 무슨 일이 있었는지는 기록으로 남아요.

## 1. 동기화 주기는 소스마다 정해요

| 방식 | 뜻 | 맞는 소스 |
|---|---|---|
| 손으로만 | "지금 동기화"를 누를 때만 | 엑셀 대장(새 파일을 올리면 한 번) |
| 간격 | 15분 ~ 7일마다 | API 소스. 기본은 하루 한 번 |
| 정해진 시각 | 매일 03:00, 요일 고르기 | 업무 시간을 피해야 하는 소스 |

- 프리셋이 기본 주기를 제안해요. 구성은 자주 바뀌지 않아서 기본이 길어요.
- 가장 짧은 간격은 15분이에요. 소스에 주는 부담을 지키려는 거예요.
- 소스마다 "지금 동기화", "잠시 멈춤"(이유를 적어요)이 있고, 다음 실행 시각이 보여요.
- 한 소스의 동기화는 한 번에 하나만 돌아요. 전체로도 동시에 도는 수에 한도가 있어요.
- 서버가 꺼져 있던 동안 놓친 주기는 켜질 때 한 번만 따라잡아요. 몰아서 여러 번 돌지 않아요.

## 2. 동기화 한 번은 기록 하나예요

| 걸음 | 남는 것 |
|---|---|
| 수집 | 받은 줄 수, 걸린 시간, 받은 그대로의 해시 |
| 대응 | 이어진 것 · 못 이은 것 · 개수가 안 맞는 것 |
| 차이 | 더해짐 · 바뀜 · 안 보임 (각각 몇 개) |
| 적용 | 세계의 새 판, 또는 "바뀐 것 없음" |

결과는 셋 중 하나예요: 됨 / 멈춤(받았지만 적용하지 않음) / 안 됨. 멈춤과 안 됨에는 이유 한 줄과 고치는 법이 붙어요. 기록은 90일 동안 남아요.

## 3. 자동으로 적용하기 전에 거치는 안전장치

| 상황 | 하는 일 |
|---|---|
| 받은 것이 지난번과 같다 | 새 판을 만들지 않아요 |
| 처음 동기화, 또는 대응을 고친 뒤 첫 동기화 | 사람이 차이를 보고 적용해요. 그 뒤부터 자동이에요 |
| 열이 사라지거나 형이 바뀌었다 | 대응에서 멈춰요. 세계는 그대로예요 |
| 한 번에 너무 많이 사라졌다(기본 10% 넘게) | 적용하지 않고 "확인이 필요해요"로 멈춰요. 소스가 빈 답을 준 사고로 세계가 비는 것을 막아요 |
| 개체가 소스에서 안 보인다 | 바로 지우지 않고 "안 보임"으로 표시해요. 세 번 연속이면 지워요 |
| 수집이 안 됐다 | 간격을 늘려 세 번 다시 해 보고, 안 되면 다음 주기를 기다려요. 연속 다섯 번이면 스스로 멈추고 알려요 |
| 자격 증명이 만료됐다 | 다시 해 보지 않고 바로 알려요 |

## 4. 신선도를 숨기지 않아요

- 소스마다 "마지막으로 받은 때"가 보여요. 주기의 두 배를 넘기면 "낡음"이에요.
- 세계와 토폴로지 판에 "이 세계의 데이터는 3시간 전 것이에요"가 보여요. 속성마다 출처와 받은 시각을 따라갈 수 있어요.

## 5. 세계의 판과 실험

- 적용할 때마다 세계의 새 판이 생기고, 판마다 차이 요약이 붙어요.
- 실험은 시작할 때의 판에 묶여요(이미 있는 실험 스냅샷). 세계가 그 뒤에 바뀌어도 그 실험의 점수는 바뀌지 않아요. 제품 목표의 "채점이 늘 맞고 같다"가 이렇게 지켜져요.
- 동기화되는 세계는 손으로 고치지 않아요. 고친 것이 다음 동기화에 덮이기 때문이에요. 바꿔 보고 싶으면 떠내서(복사해서) 해요.
- 여러 소스가 한 세계를 채우면 수집은 소스마다 따로 돌고, 적용은 세계마다 한 줄로 서요.

## 6. 연결 자체의 관리

이미 있는 연결의 방식을 그대로 써요(ADR-0043).

- 비밀 값은 봉인해 두고 되돌려 주지 않아요. 화면에는 "설정됨"만 보여요. 사내 게이트웨이용 헤더를 붙일 수 있어요.
- **연결 확인**은 셋을 봐요: 닿는가, 읽기 전용 계정인가(ADR-0149), 무엇이 있는가.
- 만든 사람만 고쳐요. 고치면 판이 오르고 무엇이 달라졌는지 남아요. 주기·대응·규칙도 같아요.
- 소스를 지울 때는 그 소스에서 온 개체를 어떻게 할지 물어요. 기본은 세계에 남기고 "출처 없음"으로 표시해요.
- 받은 그대로는 최근 10판 또는 30일까지 두고, 차지하는 크기를 보여 줘요.
- 쓰이지 않는 연결을 30일 뒤 지우는 규칙은 소스 연결에는 적용하지 않아요.

## 7. 관리자만 해요

- 소스 연결, 주기, 손질·대응·관계 규칙, 모델 관리는 **관리자 기능**이에요. 권한이 생기면 관리자가 권한을 준 사람만 해요.
- 지금은 서버 설정의 관리자 목록으로 정해요. 신원이 사내 SSO 프록시에서 올 때만 이름을 믿어요. 이름을 직접 적는 방식(로그인 없는 지금)에서는 이름만으로 관리자가 될 수 없고, 서버에 둔 관리자 토큰을 넣어야 해요.
- 현실에서 만든 세계는 관리자가 "공개"하기 전까지 관리자만 봐요. 공개하면 다른 사람이 보고 복사할 수 있어요. 소스의 비밀 값과 받은 그대로는 공개해도 관리자만 봐요.

## 8. 복사해서 실험해요

- 현실에서 만든 세계에서는 직접 실험하지 않아요. **복사**해서 실험 세계를 만들어요.
- 복사는 범위를 골라서 해요(장소, 클러스터, 한 서비스가 기대는 것들). 현실에서 만든 세계는 수천만 개체까지 갈 수 있고 실험 세계의 한도는 개체 10만이라서, 통째로 복사하는 길은 없어요(ADR-0154). 범위의 가장자리에서 끊긴 관계는 "범위 밖"으로 표시해요.
- 복사본은 보통의 실험 세계예요. 손으로 고칠 수 있고, 원본이 바뀌어도 바뀌지 않아요. 어느 판에서 떴는지 기억하고 "원본이 3판 앞서 있어요"를 보여 줘요.
- 원본의 "모름"은 복사할 때 정해요: 흔한 방식으로 채우거나(무엇을 가정했는지 보고서로 남아요) 비워 두고 사람이 채워요.
- 실험에 쓰기 전에는 다른 세계와 같은 검사(법칙 검사, 정답 풀이 검증)를 거쳐요.

## 9. 엑셀: 위치·전원·냉방이 들어오는 주된 길

- 방·열·랙·장비 위치, 전원 계통, 냉방 계통은 대부분 엑셀로 들어와요. 다른 소스가 일부를 줄 수도 있어요.
- **양식을 내려받을 수 있어요**(랙 위치, 전원 계통, 냉방 계통). 양식대로 채우면 대응을 따로 정하지 않아도 돼요. 양식이 아닌 엑셀도 받아서 대응으로 맞춰요(시트 고르기, 머리 줄 범위, 합친 칸은 덮는 칸 모두의 값, 데이터가 끝나는 곳).
- **못 읽는 모양은 이름을 대요**: 랙을 그림처럼 그린 실장도 격자, 범위를 한 칸에 적은 것("A열~D열"). 화면이 알아보고 목록 양식을 안내해요([생김새 견본 시험](reality-shape-samples.md)).
- 새 파일을 올리면 한 번 동기화돼요. 지난 파일과의 차이를 보여 주고 같은 안전장치를 거쳐요.
- 같은 장비가 엑셀(위치·전원)과 다른 소스(구성)에 함께 있어요. 그래서 **같은 것 알아보기 규칙**과 속성마다 이기는 소스가 첫 걸음부터 필요해요.

## 10. Splunk: SPL로 가져와요

- 검색 하나가 표 하나예요. SPL은 관리자가 적어요. 구성(자산·연결)도 사건도 실측도 같은 길로 와요.
- 지키는 것은 세 겹이에요.
  1. Splunk 쪽 계정이 읽기 전용 역할이에요. 이것이 본선이에요. 매크로와 저장된 검색 안은 테라리움이 들여다볼 수 없기 때문이에요.
  2. 테라리움은 SPL의 명령을 허용 목록으로 봐요. 읽는 명령만 통과해요. Splunk가 위험하다고 정한 명령(`collect`, `delete`, `dump`, `map`, `mcollect`, `meventcollect`, `outputcsv`, `outputlookup`, `run`, `runshellscript`, `script`, `sendalert`, `sendemail`, `tscollect`)과 모르는 명령은 거절해요.
  3. Splunk의 위험 명령 검사를 끄지 않아요.
- 검색마다 시간 범위와 받는 줄 수에 한도가 있어요. 한도에 닿으면 잘린 채 적용하지 않고 멈춰요.
- 검색을 저장할 때 **기대하는 열**을 적어 둬요. Splunk는 값이 없는 열을 결과에서 빼기 때문에, 빠진 열은 "모두 빈 값"으로 보고 멈출지는 필수 속성과 사라짐 안전장치가 정해요(ADR-0161 5번).
- 사건에서 구성을 뽑는 검색은 그 시간 범위에 말한 것만 보여요. 화면은 시간 범위를 동기화 주기의 세 배보다 길게 잡으라고 권해요.

## 11. 관측성: 수집이 잘 도는지 밖에서도 보여요

수집을 맡기려면 세 물음에 바로 답할 수 있어야 해요: 지금 괜찮은가, 왜 안 됐나, 점점 나빠지고 있나.

### 지표를 내보내요
이미 있는 지표 주소(실행·노드 지표를 내는 곳, Prometheus 글 형식)에 수집 지표를 더해요. 팀이 쓰는 모니터링이 긁어 가서 그리고 알려요. 그래서 테라리움은 메일·메신저 알림을 직접 만들지 않아요.

| 지표 | 답하는 물음 |
|---|---|
| 마지막으로 받은 때, 낡음 비율(나이 ÷ 주기) | 지금 최신인가 |
| 동기화 횟수(됨·멈춤·안 됨), 연속 실패 수 | 잘 돌고 있나 |
| 걸음마다 걸린 시간(수집·손질·대응·차이·적용) | 어디가 느려지나 |
| 받은 줄 · 더해짐 · 바뀜 · 안 보임 | 양이 평소와 같은가 |
| 못 이은 것 · 모름 · 개수가 안 맞는 것 | 대응과 규칙이 아직 맞나 |
| 확인을 기다리는 멈춤 수, 밀린 동기화 수 | 사람이 봐야 할 것이 쌓였나 |
| 소스에 보낸 요청의 지연·응답 코드·제한 걸림 | 소스가 힘들어하나 |
| 받은 그대로의 크기, 스케줄러의 맥박 | 테라리움 자신은 괜찮은가 |

지표의 이름표는 소스까지만 붙여요. 개체마다 붙이지 않아요(수천만이라 지표가 터져요).

### 데이터가 평소와 다른지 봐요
동기화마다 받은 표의 생김새를 지난번과 견줘요. 멈추게 하는 것은 3절의 안전장치이고, 여기는 "평소와 달라요"를 알리는 자리예요.

| 신호 | 보는 것 |
|---|---|
| 신선도 | 주기대로 받았나 |
| 양 | 줄 수가 지난번과 크게 다른가 |
| 생김새 | 열이 생기거나 사라지거나 형이 바뀌었나 |
| 분포 | 열마다 채워진 비율과 겹치지 않는 비율이 달라졌나 |
| 이음 | 못 이은 비율이 늘었나 |
| 출처 | 속성이 어느 소스의 어느 열에서 언제 왔나 |

### 기록과 추적
- 로그는 구조화해서 남기고 실행·소스·걸음의 이름표를 붙여요. **비밀 값과 줄의 내용은 로그에 찍지 않아요.** 수와 이름만 찍어요.
- 동기화 한 번은 추적 하나예요. 걸음과 소스 요청이 그 안의 마디가 돼요. 실험 실행에 이미 쓰는 방식(traceparent)과 같아요.
- 누가 소스·주기·대응·규칙을 바꿨는지는 감사 기록에 남아요.

### 화면
소스 상세에 "최근 30번" 띠(됨·멈춤·안 됨, 걸린 시간, 줄 수의 흐름)가 있고, 한 번을 누르면 걸음마다의 시간과 무슨 일이 왜 있었는지가 나와요.

## 12. 한눈에 보는 화면

소스 목록의 한 줄: 이름 · 역할(구성·사건·실측) · 상태(정상 / 낡음 / 멈춤 / 안 됨) · 마지막으로 받은 때 · 다음 실행 · 채우는 세계 · 개체 수. 문제가 있는 소스가 위로 와요. 이 화면이 답하는 물음은 하나예요: "어느 소스를 봐야 하나?"

## 하지 않는 것 (지금)

- 메일·메신저 알림. 알림은 제품 안의 배너와 목록이에요.
- 서버 여러 대에서의 중복 실행 막기와 고가용성. 클로즈 베타는 서버 한 대를 전제로 해요. 운영으로 바꾼 세계의 고가용은 오픈 베타예요(REQ-116, ADR-0153). 그때 덧붙일 수 있게 현실 데이터의 저장을 실험의 저장과 섞지 않고, 동기화를 "누가 지금 돌리는가"를 한 곳에서 정해요.
- 소스 쪽에 쓰기. 커넥터는 읽기만 해요.
- 실시간 상태(온도·전력·알람의 지금 값)를 받아 쌓기. 쓸 곳은 액션을 돌리기 전에 대상과 이어진 개체의 상태를 확인하는 일인데, 액션을 현실의 툴과 잇는 일을 미뤘으므로 함께 미뤄요(ADR-0150). 그때는 쌓아 둔 값이 아니라 그 순간 소스에 물은 값으로 확인하는 길로 설계해요. 누가 이어진 개체인지는 관계 표에서, 소스에서 무엇인지는 개체의 출처에서 나와요.

## 시험 (만들 때)

| 시험 | 내용 |
|---|---|
| 주기 | 가짜 시계로: 간격·정해진 시각·놓친 주기 한 번 따라잡기·한 번에 하나 |
| 같으면 그대로 | 받은 것이 같으면 세계의 판이 늘지 않는다 |
| 큰 변화 | 사라짐이 한도를 넘으면 적용되지 않고 세계가 바이트까지 그대로다 |
| 안 보임 | 한두 번 안 보인 개체는 남고 세 번째에 지워진다. 다시 보이면 표시가 풀린다 |
| 실험 고정 | 동기화로 세계가 바뀐 뒤에도 앞선 실험을 다시 채점하면 점수 분해가 바이트까지 같다 |
| 비밀 | 어느 응답·기록·내보내기에도 비밀 값의 평문이 없다 |
| 다시 해 보기 | 만료된 자격 증명은 다시 해 보지 않는다. 연속 실패는 스스로 멈춘다 |
| 관리자 | 관리자가 아니면 소스·대응·규칙·모델을 바꾸는 요청이 거절된다. 이름을 직접 적는 방식에서는 토큰 없이 관리자가 되지 않는다 |
| 공개 전 | 공개하지 않은 현실에서 만든 세계는 관리자가 아닌 사람의 목록·보기·복사에 나오지 않는다 |
| 복사 | 복사본을 고쳐도 원본이 바이트까지 그대로다. 원본이 동기화돼도 복사본이 그대로다 |
| SPL | 허용 목록 밖 명령이 든 검색은 Splunk에 보내지지 않는다. 줄 수 한도에 닿은 결과는 적용되지 않는다 |
| 지표 | 동기화를 돌린 뒤 지표의 수가 실행 기록의 수와 같다. 실패를 넣으면 지표·상태·기록이 같은 말을 한다 |
| 로그 | 로그·지표·추적 어디에도 비밀 값과 줄의 내용이 없다 |
| 이름표 | 지표의 이름표에 개체 ID가 없다 |
| 엑셀 양식 | 양식대로 채운 파일은 대응 없이 세계가 된다. 머리 줄이 바뀌면 멈춘다 |

# 샘플 검증 (REQ-115 예정, ADR-0161)

[현실 데이터와 모델](reality-data-and-ontology.md)이 "커넥터보다 먼저 샘플로 검증한다"고 정한 그 검증이에요. 코드는 없고 종이 위에서 했어요. 쓰는 말은 [데이터 용어집](glossary-data.md)을 따라요.

## 한 줄로

여덟 가지 소스의 구조를 설계에 넣어 봤어요. 뼈대(네 단, 행과 컬럼의 테이블, 링크 조건 유형 다섯, 근거 등급 셋)는 버텼어요. 막힌 곳은 열아홉 군데였고, 모두 "모양을 하나로 좁히는 일"에서 정해 두지 않았던 부분이었어요. ADR-0161로 메웠어요. 받지 못하는 모양 셋은 화면이 이름을 대고 나가는 길을 알려 줘요.

## 어떻게 했나

- 샘플은 컬럼 이름과 겹침 구조만 본뜬 **지어낸** 데이터예요. 실제 데이터는 이 저장소에 없어요.
- 샘플마다 같은 물음을 차례로 던졌어요: 원본 데이터셋이 테이블이 되나 → 정제로 목적지 모양이 되나 → 다른 소스의 같은 것을 중복 병합하나 → 링크 정의가 링크를 만드나 → 이중화 그룹이 적히나.
- 막히면 설계가 틀린 곳으로 적었어요. 샘플을 설계에 맞게 고치지 않았어요.
- 제품 API의 자세한 모양은 설계 담당이 아는 대로 적었어요. 프리셋을 만들 때 제품 문서와 하나씩 대조해요.

| 샘플 | 본뜬 구조 | 역할 |
|---|---|---|
| 1 | 엑셀 랙 위치 대장 (양식이 아닌 것) | 구성 |
| 2 | 엑셀 전원 계통 | 구성 |
| 3 | 엑셀 냉방 계통 | 구성 |
| 4 | Splunk의 SPL 결과 | 구성·사건·실측 |
| 5 | vROps의 자원과 링크 | 구성 |
| 6 | VMware vCenter의 목록 API | 구성 |
| 7 | OpenStack (컴퓨트·네트워크·블록 스토리지) | 구성 |
| 8 | 스위치의 포트·포트 그룹·이웃·BGP 세션 (OpenConfig 모양, 이웃 테이블) | 구성 |

## 샘플마다 걸어 본 것

### 1. 엑셀 랙 위치 대장

```
     A         B     C      D            E        F        G
1  | 위치                 | 장비                          | 전원     |   ← 병합된 셀
2  | 전산실    열    랙   | 장비명       종류     U위치   | 용량     |
3  | 전산실 A  A열   A03  | esx-a03-01   서버     12-13   | 0.8kW    |
4  |                      | sw-a03-t1    스위치   42      | 0.3kW    |   ← 빈 셀은 "위와 같음"
5  |                      | PP-A03-1     패치패널 44      |          |
.. | 합계                                                 | 1.1kW    |
```

- 헤더가 두 행이고 셀이 병합돼 있어요. 세로로 병합한 "전산실 A"는 여러 행을 덮어요. 합계 행이 섞여 있어요. → **막힘 1**
- 병합하지 않은 빈 셀을 "위와 같음"으로 쓰는 사람의 버릇이 있어요. → **막힘 6**(빈 값 채우기)
- "12-13", "U12~13", "0.8kW"는 컬럼 나누기와 값 변환(단위 변환)으로 돼요. 못 읽는 행은 문제 목록으로 가요. 버텼어요.
- 방·열·랙은 자기 데이터셋이 없어요. 장비 행의 컬럼으로만 나와요. 매핑의 미리보기는 키 중복을 문제로 본다고 적혀 있어서, 랙 하나가 행 40개에 나오면 문제 40건이 돼요. → **막힘 8**
- 한 시트에 서버·스위치·패치 패널이 "종류" 컬럼으로 섞여 있어요. 값은 조직의 말이에요("L4", "방화벽"). → **막힘 9**
- 패치 패널, KVM, 다른 부서 장비는 모델의 타입에 없어요. 버리면 랙의 빈 자리와 전력 합이 틀려져요. → **막힘 10**
- 랙 이름 "A03"은 방마다 있어요. 키는 (방, 랙) 복합 키여야 하고, 장비가 랙을 가리킬 때도 복합 키로 가리켜요. → **막힘 13**
- 엑셀은 "esx-a03-01", 가상화 관리자는 "esx-a03-01.dc.example.internal", 감시 도구는 "ESX-A03-01"이에요. 글자 그대로 비교하면 세 객체가 돼요. → **막힘 12**
- **못 받는 모양**: 랙을 그림처럼 그린 실장도(컬럼이 랙, 행이 U, 셀이 장비 이름, 여러 U는 병합된 셀). 행으로 펼칠 수는 있지만, 한 장비의 여러 행을 "U 12부터 2U"로 모으는 정제 연산이 없어요. → **막힘 7**

### 2. 엑셀 전원 계통

```
설비명      종류      상위 설비    계통   용량
TR-1        변압기    수전-1       A      2000kVA
UPS-A       UPS       TR-1         A      500kVA x 3 (N+1)
PDU-2F-A1   분전반    UPS-A        A      250A

랙     A계통 분전반/차단기    B계통 분전반/차단기
A03    PDU-2F-A1 / 12         PDU-2F-B1 / 12
```

- "상위 설비"는 같은 데이터셋의 다른 행을 가리키는데, 가리키는 것의 타입이 행마다 달라요(변압기, UPS, 분전반). → **막힘 14**
- 랙 테이블은 A·B가 옆으로 나란해요. 링크 정의 둘(A 컬럼, B 컬럼)에 역할을 하나씩 못박으면 돼요. 버텼어요.
- 서버의 전원 장치가 랙의 어느 콘센트에 꽂혔는지는 엑셀에 거의 없어요. 기본 규칙("랙의 서버는 그 랙의 A·B에")이 가정 등급으로 메워요. 전원 장치가 하나뿐인지 모르는 장비는 "모름"이에요. 버텼어요.
- "500kVA x 3 (N+1)"은 사람이 읽는 글이에요. 이중화 그룹의 최소 생존 수는 링크의 수에서 나오지 않아요. → **막힘 16**

### 3. 엑셀 냉방 계통

```
설비명        종류     방         담당 구역     냉수 계통
CRAH-2F-A-1   항온기   전산실 A   A열~D열       1차
CH-1          냉동기   기계실     -             1차 (N+1)
```

- 냉방은 장비에서 장비가 아니라 설비에서 공간(방·열)으로 이어져요. 랙은 자기가 놓인 공간을 거쳐 받아요. 위치 포함 조건과 링크 타입 표의 "공급"으로 돼요. 버텼어요.
- **못 받는 모양**: "A열~D열"처럼 범위를 한 셀에 적은 것. 컬럼 나누기는 A와 D를 꺼낼 뿐 B와 C를 만들지 못해요. → **막힘 7**
- N+1의 N은 전원과 같아요. → **막힘 16**

### 4. Splunk의 SPL 결과

```
index=net sourcetype=lldp | stats latest(remote_port) as remote_port by host, local_port, remote_host

host    local_port     remote_host        remote_port
sw01    Ethernet1/1    SW02.corp.local    Eth1/49
sw01    Ethernet1/2    10.20.0.7
```

- 검색 하나가 데이터셋 하나라는 틀이 그대로 맞아요. 여러 값이 든 값은 행으로 펼치면 돼요. 버텼어요.
- 값이 없는 셀은 행에서 빠지고, 어느 행에도 값이 없으면 그 컬럼이 통째로 안 와요. "컬럼이 사라지면 멈춘다"가 거짓 경보를 내요. → **막힘 5**
- 사건에서 뽑은 구성은 "그 시간 범위에 말한 것"이에요. 하루 조용했던 장비가 사라져 보여요. 세 번 안 보여야 지우는 안전장치와 10% 사라짐 멈춤이 막아요. 검색의 시간 범위를 동기화 주기의 세 배보다 길게 잡으라고 화면이 권해요. 버텼어요.
- 이웃이 이름이 아니라 IP로만 와요("10.20.0.7"). IP 하나로 장비를 찾아야 하는데, 장비는 IP를 여럿 가져요. → **막힘 13**
- "Ethernet1/1"과 "Eth1/49"는 같은 표기법의 두 얼굴이에요. → **막힘 12**
- 한도에 닿아 잘린 결과는 적용하지 않고 멈춰요(소스 관리 10절). 버텼어요.

### 5. vROps의 자원과 링크

```
자원:   identifier, resourceKey.name, resourceKey.adapterKindKey, resourceKey.resourceKindKey,
        resourceKey.resourceIdentifiers[] = { identifierType.name, value }
링크:   자원 하나마다 따로 묻거나 여럿을 한 번에 물음 → (부모 identifier, 자식 identifier)
```

- `resourceIdentifiers`는 이름·값 행의 목록이에요. 자식 테이블로 펼치면 세로로 긴 테이블이 되고, 매핑이 쓰려면 이름마다 컬럼이 되어야 해요. 정제 연산 다섯 가지에는 그 반대(가로를 세로로)만 있어요. → **막힘 6**(피벗)
- 링크에 타입이 없어요. 부모·자식뿐이고, 의미는 양 끝의 자원 타입에서 나와요(호스트 → VM이면 "호스팅", 클러스터 → 호스트면 "이중화 그룹"). → **막힘 14**
- 어느 링크 정의도 쓰지 않은 행이 얼마나 남았는지 보이지 않으면, 못 읽은 것이 조용히 사라져요. → **막힘 11**
- 링크는 자원마다 따로 물어야 와요. → **막힘 2**
- vROps의 identifier는 vROps 안에서만 쓰는 번호예요. 다른 소스와 맞추는 키는 펼친 식별자 둘(가상화 관리자의 ID + 그 안의 객체 ID)을 묶은 복합 키예요. → **막힘 13**

### 6. VMware vCenter의 목록 API

```
VM 목록:    vm, name, power_state, cpu_count, memory_size_MiB        ← 어느 호스트인지 없음
호스트의 VM: VM 목록을 "이 호스트의 것만"이라는 조건으로 다시 물음
VM 상세:    nics = { "4000": { mac_address, backing: { type, network } }, ... }   ← 번호가 키인 맵
            disks = { "2000": { backing: { vmdk_file: "[ds1] vm/vm.vmdk" }, capacity } }
```

- VM이 어느 호스트에 있는지는 응답의 컬럼이 아니라 **요청의 조건**에 있어요. 호스트마다 묻고, 물을 때 쓴 호스트를 결과의 컬럼으로 붙여야 링크가 생겨요. → **막힘 2**
- `nics`와 `disks`는 배열이 아니라 번호가 키인 맵이에요. "겹친 것은 자식 테이블로"가 배열만 말하고 있었어요. → **막힘 3**
- "[ds1] vm/vm.vmdk"에서 데이터스토어 이름은 패턴으로 나누면 나와요. 버텼어요.
- 물리 NIC가 어느 가상 스위치의 업링크인지, 그 NIC의 이웃 스위치 포트가 무엇인지는 이 목록 API에 없고 XML로 묻는 옛 API에만 있어요. → **막힘 4**
- vSAN은 호스트의 디스크로 만든 스토리지예요. 호스트 몇 대를 잃어도 되는지는 정책의 값이에요. → **막힘 16**

### 7. OpenStack

```
서버:    id, name, OS-EXT-SRV-ATTR:hypervisor_hostname, OS-EXT-AZ:availability_zone,
         addresses = { "net-a": [ { addr, OS-EXT-IPS-MAC:mac_addr } ] },
         os-extended-volumes:volumes_attached[] = { id }
포트:    id, network_id, device_id, device_owner, fixed_ips[] = { subnet_id, ip_address }, binding:host_id
그룹:    애그리거트 = { name, availability_zone, hosts[] }
```

- `addresses`는 네트워크 이름이 키인 맵이에요. → **막힘 3**
- 포트의 `device_id`는 `device_owner`에 따라 서버를 가리키기도 하고 라우터를 가리키기도 해요. → **막힘 14**
- 호스트 하나가 애그리거트 여럿에 들어요. 가용 영역은 하나예요. 애그리거트는 배치할 때 쓰는 태그이지 "고장 나면 여기서 다시 뜬다"는 의미가 없어요. 표준 모델 대조 문서의 매핑 표가 애그리거트와 가용 영역을 모두 `cluster`에 맞춰 둔 것은 틀렸어요. → **막힘 17**
- 호스트 이름과 배치 정보는 관리자 역할에게만 보여요. 읽기만 하는 역할이 없는 버전의 클라우드에서는 "읽기 전용 계정이어야 잇는다"를 지킬 수 없어요. → **막힘 19**
- 같은 구성을 VMware 모양과 OpenStack 모양으로 넣으면 같은 타입·같은 링크가 되는지는 17을 고치면 돼요.

### 8. 스위치의 포트·포트 그룹·이웃·세션

```
포트:      장비, name, 속도, 포트 그룹 번호(aggregate-id), 설명
포트 그룹: 장비, name(Port-Channel10), lacp 방식, min-links, MLAG 번호(두 스위치에 걸친 것)
이웃:      장비, 내 포트, 상대 장비 표시(이름 또는 MAC), 상대 포트 표시(이름 또는 MAC 또는 번호)
세션:      장비, 이웃 주소(IP), 이웃 AS, 이웃 그룹(peer-group)
```

- 포트·포트 그룹·세션이 장비의 하위 항목 행으로 들어오는 것은 ADR-0156 2번 그대로예요. 버텼어요.
- 포트에도 유형이 있어요: 물리 포트, 하나를 넷으로 쪼갠 포트, 포트 그룹, 서브 인터페이스, 루프백. 포트 그룹과 서브 인터페이스는 기반 포트 위에 올라가요. 하위 항목 행에 유형과 "기반 포트"를 적을 컬럼이 없었어요. → **막힘 18**
- 이웃 테이블은 상대를 이름으로도, MAC으로도, 번호로도 말해요. 이름은 표기가 달라요("Ethernet1/1", "Eth1/1", "Et1/1"). → **막힘 12, 13**
- 같은 링크를 양쪽이 한 번씩 말해요. 한쪽만 말하기도 하고(서버는 말이 없음), 둘이 어긋나기도 해요. 상대가 모델에 없는 장비이기도 해요. → **막힘 15**
- BGP 세션의 상대는 IP예요. 그 IP가 어느 장비의 어느 포트인지 찾아야 세션이 링크 위에 얹혀요. → **막힘 13**
- LACP는 `min-links`가 최소 생존 수를 직접 말해요. 두 스위치에 걸친 포트 그룹은 MLAG 번호가 같은 것끼리 한 그룹이에요. 그룹 조건의 키를 (MLAG 영역, 번호) 복합 키로 하면 돼요. 버텼어요.
- ECMP가 켜져 있는지와 누가 멤버인지를 어디서 읽을지 정해 두지 않았어요. → **막힘 16** (답: 장비 설정이에요. 같은 이웃 그룹의 BGP 세션들이 멤버이고, "여러 경로를 몇 개까지 같이 쓰는가"가 2 이상이면 ECMP예요. ADR-0164)

## 막힌 곳과 고친 것

| # | 단 | 막힌 것 | 고친 것 (ADR-0161) |
|---|---|---|---|
| 1 | 수집 | 엑셀의 두 행 헤더, 병합된 셀, 합계 행 | 파일 커넥터의 읽기 설정: 헤더 행 범위, 병합된 셀은 덮는 셀 모두의 값, 데이터가 끝나는 곳 |
| 2 | 수집 | 링크가 요청의 조건에 있거나 자원마다 따로 물어야 옴 | HTTP 커넥터의 **연쇄 요청**: 앞 데이터셋의 행마다 요청하고, 요청에 쓴 값을 결과의 컬럼으로 붙여요. 요청 수에 한도 |
| 3 | 수집 | 이름이 키인 맵, 행마다 JSON 한 덩이 | 원본 데이터셋으로 펼치는 규칙에 더해요(키는 컬럼 하나가 돼요) |
| 4 | 수집 | XML로만 묻는 API | 받지 않아요. 같은 내용을 vROps 프리셋이나 푸시 수집으로 받아요 |
| 5 | 수집 | SPL 결과에서 빈 컬럼이 통째로 빠짐 | 검색을 저장할 때 기대하는 컬럼을 적어 둬요. 빠진 컬럼은 "모두 빈 값"이고, 멈출지는 필수 속성과 사라짐 안전장치가 정해요 |
| 6 | 정제 | 다섯 가지로 모자라고 "붙이기"가 두 뜻 | 여덟 가지로 이름을 못박아요(아래 표) |
| 7 | 정제 | 실장도, 범위를 적은 셀 | 모으기와 범위 펼치기는 넣지 않아요. 화면이 모양을 알아보고 목록 양식을 안내해요 |
| 8 | 매핑 | 여러 행이 한 객체 | 매핑에 "행마다 하나"와 "값마다 하나"를 둬요. 값마다 하나에서는 키 중복이 정상이고, 행 사이에 속성이 어긋나면 문제예요 |
| 9 | 매핑 | 한 데이터셋에 여러 타입, 조직의 말 | 필터와 코드 매핑. 코드 매핑에 없는 값은 목록으로 |
| 10 | 매핑 | 모델에 없는 장비 | 현실 표준 타입 "기타 장비": 위치와 전력만 있고, 여기에 기대는 것은 없어요 |
| 11 | 매핑 | 아무도 집지 않은 행 | "어느 매핑·링크 정의에도 쓰이지 않은 행 N개"(미사용 행)를 타입 쌍별로 내요 |
| 12 | 중복 병합 | 표기가 다른 같은 이름 | 정해진 정규화 후 비교: 대소문자, 앞뒤 공백, 도메인 접미사, 포트 이름. 원래 값은 그대로 둬요 |
| 13 | 중복 병합 | IP·MAC처럼 여럿인 키, 어떤 범위 안에서만 유일한 키 | 값이 여럿인 속성은 "하나라도 같으면", 범위가 있는 키는 복합 키로 |
| 14 | 링크 정의 | 가리키는 상대의 타입이 행마다 다름 | 링크 정의에 양 끝의 타입 조건을 둬요. 둘 이상에 맞으면 잇지 않고 목록으로 |
| 15 | 링크 정의 | 양쪽이 말하는 링크, 한쪽만 말하는 링크, 모델 밖 이웃 | 한 번만 잇고 "양쪽 확인·한쪽만 확인"을 적어요. 어긋나면 잇지 않아요. 모델 밖 이웃은 숫자로 내요 |
| 16 | 이중화 그룹 | 최소 생존 수의 출처 | 소스가 말하면 사실, 타입의 기본값이면 가정, 기본값이 없으면 모름. ECMP는 장비 설정에서 읽어 사실이고, 이웃 그룹이 설정에 없어 역할로 묶었을 때만 가정(ADR-0164) |
| 17 | 모델 | OpenStack 애그리거트를 `cluster`에 맞춤 | 매핑 표를 고쳐요: 가용 영역은 호스트 그룹, 애그리거트는 호스트의 태그, 인스턴스 HA 구역이 자동 재배치를 켠 그룹 |
| 18 | 모델 | 포트의 유형과 층 | 하위 항목 행에 유형과 "기반 포트" 컬럼 |
| 19 | 읽기 전용 | 읽기만 하는 역할이 없는 소스 | 규칙은 그대로예요(잇지 않아요). 길은 푸시 수집이에요 |

### 정제 연산은 여덟 가지예요

| 연산 | 하는 일 | 샘플 |
|---|---|---|
| 행으로 펼치기 | 한 값에 든 여러 값, 옆으로 늘어선 컬럼을 행으로 | 4, 5 |
| 피벗 | 이름·값 행을 이름마다 컬럼으로 | 5 |
| 컬럼 나누기 | 구분자, 위치, 패턴으로 한 컬럼을 여러 컬럼으로 | 1, 6 |
| 조인 | 키가 같은 두 데이터셋의 컬럼을 합침 | 5, 7 |
| 유니온 | 컬럼이 같은 데이터셋들을 한 데이터셋으로 | 8 |
| 필터 | 조건에 맞는 행만 | 1, 7 |
| 빈 값 채우기 | 빈 값을 바로 위 행의 값으로 | 1 |
| 값 변환 | 단위 변환, 코드 매핑, 정규화 | 1, 2 |

코드는 여전히 못 넣어요. 여덟 가지로 안 되면 바깥에서 정제해 푸시 수집으로 넣어요.

## 설계가 버틴 곳

- **네 단과 원본 데이터셋**: 여덟 샘플 모두 행과 컬럼의 테이블로 내려앉았어요(막힘 3을 더한 뒤).
- **링크 조건 유형 다섯**: 새 조건 유형이 필요하지 않았어요. 모자란 것은 링크 정의의 조건과 뒷정리였어요(14, 15).
- **근거 등급 셋**: 엑셀에 없는 콘센트 연결, 기본값으로 채운 이중화 그룹, 역할에서 끌어낸 ECMP가 모두 "가정"에 들어가요.
- **중복 병합이 첫 단계**: 여덟 샘플 모두 다른 소스의 같은 장비나 같은 위치와 맞춰야 했어요.
- **안전장치**: 사건에서 뽑은 구성의 빈틈(4)을 이미 있는 것들이 막아요.

## 못 받는 모양과 나가는 길

| 모양 | 화면이 하는 말 | 나가는 길 |
|---|---|---|
| 실장도 | "이 시트는 랙 그림처럼 보여요" | 목록 양식으로 옮겨 올리기 |
| 범위를 적은 셀 | "이 셀은 범위예요. 하나씩 적어야 읽어요" | 냉방·전원 양식(구역마다 한 행) |
| XML로만 묻는 API | 프리셋에 없음 | vROps 프리셋, 푸시 수집 |

실장도를 직접 읽는 기능은 만들지 않아요. 위치 엑셀은 한 행에 장비 하나인 목록으로 와요(ADR-0164).

## 만들 때의 시험

| 시험 | 내용 |
|---|---|
| 샘플 | 이 문서의 여덟 샘플을 지어낸 파일로 두고, 각각 수집 → 정제 → 매핑 → 링크 정의를 돌려 기대한 객체·링크·문제 목록이 나온다 |
| 합 | 받은 행 수 = 객체가 된 행 + 링크가 된 행 + 문제 목록 + 미사용 행 (샘플마다) |
| 정규화 | 표기만 다른 이름이 한 객체가 되고, 정규화해도 다른 이름은 합쳐지지 않는다 |
| 양쪽 | 양쪽이 말한 링크는 하나이고, 어긋난 링크는 이어지지 않는다 |
| 이중화 그룹의 출처 | 최소 생존 수가 소스에 있으면 사실, 기본값이면 가정, 없으면 모름으로 적힌다 |
| 같은 세계 | 같은 구성의 VMware 모양과 OpenStack 모양이 같은 타입·같은 링크의 세계가 된다 |

# UX를 숫자로 재는 법 (REQ-041)

Peter Morville의 UX Honeycomb 7개 면을 각각 0~100점으로 자동 측정한다. 측정은 실제 브라우저(Playwright)에서
사람이 하는 일을 그대로 수행하며, 점수는 docs/generated 폴더의 ux-score 파일에 쌓이고 면마다 하한이 있다(래칫).

| 면 | 질문 | 측정 방법 |
|---|---|---|
| Useful 유용함 | 사람이 하려는 일을 끝까지 할 수 있나 | 핵심 여정(세계 짓기, 시나리오 설계, 실험 실행·취소, 결과 공유, 대시보드 비교, 포크 재실행, 세계 가져오기)의 성공 비율 |
| Usable 사용성 | 쉽게 할 수 있나 | 여정별 클릭·입력 수를 목표 예산과 비교, 잘못된 입력에 즉시 안내가 뜨는지 |
| Desirable 매력 | 쓰고 싶게 생겼나 | 디자인 토큰 준수율(임의 색상 금지), 긴 작업의 진행 표시, 3D 프레임 예산 달성 |
| Findable 찾기 쉬움 | 기능을 찾을 수 있나 | 모든 기능이 홈에서 2단계 이내인지, 명령 팔레트가 한/영 키워드로 찾는지 |
| Accessible 접근성 | 누구나 쓸 수 있나 | axe-core 위반(심각·치명 0개), 키보드만으로 핵심 여정 수행, 대비, 움직임 줄이기 설정 존중 |
| Credible 신뢰 | 믿을 수 있나 | 모든 수치에 출처(오라클/ClickStack/테라리움)와 시각 표시, 오류는 원인과 해결책을 말하는지, 빈 화면이 이유를 말하는지 |
| Valuable 가치 | 결정에 도움이 되나 | 결과 화면이 기준선·순위와 비교해 주는지, 완료 후 핵심 발견까지 걸리는 단계 수, 포크가 한 번에 되는지 |

점수 계산과 여정 정의는 `harness/src/ux/`에 있고, 측정이 바뀌면 이 문서도 함께 바꾼다.

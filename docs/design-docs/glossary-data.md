# 용어집: 데이터 파이프라인과 온톨로지 매니저 (ADR-0167)

[용어집](glossary.md)의 "쓰는 법"을 그대로 따라요: 일하면서 실제로 쓰는 말을 쓰고, 만든 말은 쓰지 않아요. 이 영역을 쓰는 사람은 인프라와 데이터를 다루는 관리자예요. 그래서 조인, 피벗, 필터, 브랜치처럼 그 사람들이 이미 쓰는 말을 그대로 써요. 문장은 해요체로 쉽게 쓰고, 처음 나오는 말에는 한 줄 설명을 붙여요.

이전 설계 문서와 결정 기록(ADR-0144~0165)은 오른쪽 열의 말을 썼어요. 봉인된 결정 기록은 고치지 않으니, 읽을 때 이 표로 옮겨 읽어요.

## 층과 데이터

| 쓰는 말 | 뜻 | 이전에 쓴 말 (쓰지 않음) |
|---|---|---|
| **소스** | 데이터를 가져오는 곳 | |
| **원본 데이터셋** | 소스에서 가져온 그대로의 테이블 | 받은 그대로 |
| **정제** | 데이터셋을 다듬어 새 데이터셋을 만드는 일 | 손질 |
| **데이터셋** | 이름과 계보가 있는 테이블. 원본도 정제한 것도 데이터셋 | 받은 표 |
| **행 / 컬럼 / 값** | 테이블의 가로줄 / 세로줄 / 한 칸의 내용 | 줄 / 열 / 칸 |
| **매핑** | 데이터셋의 컬럼을 객체 타입의 속성에 잇는 일 | 대응, 짝짓기 |
| **객체 타입 / 객체** | 온톨로지의 종류(서버, VM) / 그 하나하나 | 개체 종류 / 개체 (이미 있는 화면의 말. 객체로 옮긴다, ADR-0170) |
| **링크 타입 / 링크** | 객체 타입 사이의 관계 종류 / 그 하나하나 | 관계 종류 / 선 |
| **파이프라인** | 소스 설정 + 정제 + 매핑 + 링크 정의를 합친 것 | |
| **푸시 수집** | 바깥의 스크립트가 데이터를 넣어 주는 방식 | 밀어 넣기 |
| **연쇄 요청** | 앞 요청의 결과마다 다음 요청을 보내는 것 | 딸린 요청 |
| **하위 항목** | 장비에 속한 포트·포트 그룹·BGP 세션 같은 것 | 딸린 것 |
| **스키마 변경** | 소스의 컬럼이 사라지거나 형이 바뀐 것 | 스키마 흔들림 |

## 정제 연산 8가지

| 쓰는 말 | 하는 일 | 이전에 쓴 말 (쓰지 않음) |
|---|---|---|
| **행으로 펼치기** | 한 값에 든 여러 값, 옆으로 늘어선 컬럼을 행으로 (언피벗) | 줄로 펼치기 |
| **피벗** | 이름·값 행을 이름마다 컬럼으로 | 열로 모으기 |
| **컬럼 나누기** | 구분자·위치·패턴으로 한 컬럼을 여러 컬럼으로 | 나누기 |
| **조인** | 키가 같은 두 데이터셋의 컬럼을 합침 | 옆으로 붙이기 |
| **유니온** | 컬럼이 같은 데이터셋들을 한 데이터셋으로 | 아래로 쌓기 |
| **필터** | 조건에 맞는 행만 | 고르기 |
| **빈 값 채우기** | 빈 값을 바로 위 행의 값으로 | 위 값 잇기 |
| **값 변환** | 단위 변환, 코드 매핑(조직의 말 → 정해진 값), 정규화 | 값 바꾸기, 값 사전, 다듬기 |

## 객체 매핑

| 쓰는 말 | 뜻 | 이전에 쓴 말 (쓰지 않음) |
|---|---|---|
| **키** | 객체를 하나로 가리키는 컬럼(들). 여러 컬럼이면 복합 키 | 묶은 키 |
| **중복 병합** | 여러 소스의 같은 장비를 한 객체로 합치는 일 | 같은 것 알아보기 |
| **정규화 후 비교** | 대소문자·공백·도메인 접미사·포트 이름 표기를 맞춘 뒤 비교 | 다듬어 견주기 |
| **우선 소스** | 속성 값이 소스마다 다를 때 이기는 소스 | 이기는 소스 |
| **미사용 행** | 어느 매핑·링크 정의에도 쓰이지 않은 행 | 안 쓰인 줄 |
| **기타 장비** | 모델에 없는 장비를 받는 객체 타입(위치와 전력만) | 기타 실장 장비 |

## 링크 정의

링크 타입 하나는 넷으로 정의해요: **양 끝의 객체 타입, 조건, 의미, 카디널리티**(한쪽에 몇 개까지 이어지나).

| 조건 유형 | 뜻 | 예 | 이전에 쓴 말 (쓰지 않음) |
|---|---|---|---|
| **키 일치** | 한쪽의 속성 값이 다른 쪽의 키와 같다 | VM의 host = 서버의 이름 | 키 맞추기 |
| **위치 포함** | 한쪽이 다른 쪽 안에 있다 | 서버의 랙·U 위치 → 그 랙 | 담김 |
| **연결 테이블** | 데이터셋의 한 행에 양쪽 키가 다 있다 | 케이블 대장, LLDP 이웃, PDU 콘센트 표 | 끝점 짝, 이음 데이터셋의 한 줄이 두 끝을 말한다 |
| **그룹** | 그룹 키가 같은 객체들이 한 그룹의 멤버다 | 같은 장비에서 포트 그룹 번호가 같은 포트 | 묶음, 같은 값끼리 한 무리 |
| **기본 규칙** | 소스에 없을 때 흔한 구성으로 채운다(추정) | 랙의 서버는 그 랙의 PDU A·B에 | 관례 |

| 링크의 의미 | 영향이 넘어가는 방식 | 이전에 쓴 말 (쓰지 않음) |
|---|---|---|
| **호스팅** | 아래가 죽으면 위도 죽는다 (VM → 서버) | 위에서 돈다 |
| **의존** | 상대가 죽으면 영향을 받는다 (서비스 → DB) | 필요하다 |
| **연결** | 네트워크로 이어져 있다 (포트 ↔ 포트) | 이어진다 |
| **공급** | 전원·냉방을 받는다 (랙 → PDU) | 공급받는다 |
| **이중화 그룹** | 멤버 중 **최소 생존 수** 이상이 살아 있으면 유지된다 | 묶음, 몇 개가 살아야 하나 |
| **풀** | 멤버 하나하나가 따로 쓰인다. 영향을 대수로 말한다 (데스크톱 240대 중 60대) | 수로 말하는 묶음 |
| **참고용** | 그리기만 하고 영향은 넘어가지 않는다 | 기록만 |

근거 등급은 그대로 **사실 / 가정 / 모름**이에요. 양쪽 소스가 같은 링크를 말하면 "양쪽 확인", 한쪽만 말하면 "한쪽만 확인"이에요. 모델에 없는 상대는 "미등록 이웃"이에요.

## 버전과 브랜치 (ADR-0166)

| 쓰는 말 | 뜻 | 이전에 쓴 말 (쓰지 않음) |
|---|---|---|
| **버전** | 파이프라인이나 세계의 저장된 한 시점 | 판 |
| **스냅샷** | 한 번의 수집으로 받은 원본 데이터셋 | |
| **브랜치** | 운영에 영향 없이 파이프라인을 고쳐 보는 작업 공간 | 가지, 떠내기 |
| **운영 브랜치** | 운영 세계를 만드는 파이프라인. 하나뿐 | |
| **미리보기 세계** | 브랜치의 파이프라인으로 만들어 본 세계 | |
| **비교** | 브랜치와 운영의 차이 (정의의 차이, 세계의 차이) | |
| **병합** | 브랜치의 변경을 운영 브랜치에 넣는 일 | |
| **되돌리기** | 운영 브랜치를 이전 버전으로 돌리는 일 | |
| **실험용 복사본** | 운영 세계의 한 버전에서 범위를 골라 만든 실험 세계 | 가지 떠내기, 복사해서 실험 |

## 시뮬레이션 단계 (ADR-0168)

| 쓰는 말 | 뜻 |
|---|---|
| **정밀 시뮬레이션** | 물리, 시간, 타입 전용 고장, 전용 툴까지 움직이는 타입 (핵심 타입) |
| **기본 시뮬레이션** | 상태 전파, 공통 알람, 공통 조회 툴로 움직이는 타입 (그 밖의 모든 타입) |
| **경계 밖** | 범위를 골라 복사할 때 한도 때문에 자른 바깥. 늘 살아 있다고 가정하고 화면에 밝힘 |
